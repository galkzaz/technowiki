Many problems involve minimizing or maximizing a target value:
find the shortest path, get the maximum profit, etc. They’re called
optimization problems. When the solution is a sequence of
choices, we often use a strategy called branch and bound. Its
aim is to gain time by quickly detecting and discarding bad choices.

Branch and Bound (B&B) is an algorithmic strategy for solving optimization problems over a search space. Typically:
- Combinatorial optimization
- NP-hard problems
- Decision trees with many possibilities

Instead of exploring all possibilities, B&B:
1. Branches → systematically explores candidate solutions
2. Bounds → computes an optimistic estimate of how good a branch can be
3. Prunes → discards branches that cannot beat the best solution found so far

Core Idea: Never explore a subtree if you can prove it cannot contain a better solution.

Branch and Bound is an algorithmic technique used to solve optimization problems, particularly combinatorial and NP-hard problems. Its efficiency depends fundamentally on the use of bounds to eliminate parts of the search space that cannot contain an optimal solution.

Branch & Bound is built on this idea:
- Exact solution = hard
- Relaxed version = easy
- Relaxed version gives bound
- Use bound to eliminate impossible branches

This idea appears everywhere:
- Linear relaxation in Integer Programming
- Minimum spanning tree lower bound in TSP
- Heuristics in A*

Branch and Bound explores a state-space tree where:
- Each node represents a partial solution.
- Branching generates subproblems.
- A bounding function estimates how good a solution within a subtree could be.

Branch & Bound works because:
It uses mathematics to prove that certain parts of the search space are useless.
Without bounds → it becomes brute force.
With strong bounds → it becomes powerful.

At all times, the algorithm maintains:
- An incumbent solution (the best feasible solution found so far).
- A bound value for each node.

A node is pruned if its bound indicates that it cannot improve upon the incumbent.

In this context, two types of bounds are used:
- Upper bounds
- Lower bounds
Their roles depend on whether the problem is a maximization or minimization problem.

To understand how bad choices are detected, we first need to learn the concepts of upper and lower bounds.
## Upper and Lower Bounds
Bounds refer to the range of a value. An upper bound sets a limit on how high the value can be. A lower bound is the least one can hope for: it guarantees the value is equal to it or greater.

We can often easily get suboptimal solutions: a short path, but maybe not the shortest; a big profit, but maybe not the biggest.
These solutions provide bounds to the optimal solution. For instance, the shortest route between two places is never shorter than
their straight linear distance. The linear distance is thus a lower bound of the shortest driving distance.

In Branch & Bound, we are solving an optimization problem.
Two values are always maintained:
1. Bound of a node (optimistic estimate)
2. Best solution found so far (incumbent)

Depending on the problem type:
| Problem Type | Bound Type Used |
| ------------ | --------------- |
| Maximization | Upper Bound     |
| Minimization | Lower Bound     |

### Bounds in Maximization Problems
Consider a maximization problem: maximize f(x), We want to maximize value.

#### Upper Bound (UB)
For a node *N*, the **upper bound** is an optimistic estimate of the maximum objective value achievable from any solution in the subtree rooted at N.

UB = the maximum value we could possibly achieve from this subtree (optimistically).

Formally:
$$
UB(N)≥true optimal value in subtree of N
$$
The upper bound must never underestimate the best possible value. It may overestimate safely. It may not be achievable.

It answers the question: What is the largest value this subtree could possibly produce?(What is the best we could ever do from here?).

#### Lower Bound (LB)
In maximization, the lower bound is the value of the best feasible solution found so far.

LB = value of the best feasible solution found so far.
$$
LB=best known solution value
$$
This value is guaranteed to be achievable.

It answers: What is the best we already know we can achieve?
#### Pruning Rule (Maximization)
A node N is pruned if:
$$
UpperBound(node)≤BestKnownSolution
$$
Or
$$
UB(N)≤LB 
$$
Then: This subtree cannot improve the solution → prune it.

This means:
Even under the most optimistic assumption, the subtree cannot produce a better solution than the one already found.

Because even its best-case scenario is worse than what we already have.

For Example (Knapsack) ,Suppose:
- Best solution so far = 90
- Now we examine a node:
- Current value = 50
- Remaining capacity = 5
- Using fractional knapsack, we compute:
- Upper bound = 75
- Since: 75\<90 
- Even in the most optimistic case, we can’t beat 90.
So we prune.

### Bounds in Minimization Problems
Now consider a minimization problem: minimize f(x). suppose we want to minimize cost.

The roles of upper and lower bounds are reversed(Everything flips).

#### Lower Bound (LB)
For a node *N*, the **lower bound** is an optimistic estimate of the smallest objective value achievable in its subtree.

LB = smallest possible cost we could achieve from this subtree (optimistically).
$$
LB(N)≤true optimal value in subtree of N
$$
The lower bound must never overestimate the minimal possible value. It may underestimate safely.

#### Upper Bound (UB)
In minimization, the upper bound is the value of the best feasible solution found so far.

UB = cost of best feasible solution found so far.
$$
UB=best known feasible solution
$$
#### Pruning Rule (Minimization)
A node *N* is pruned if:
$$
LowerBound(node)≥BestKnownSolution
$$
Or 
$$
LB(N)≥UB
$$
Then prune. Because even in the best case, this branch is worse.

This means:
Even in the best possible case, the subtree cannot produce a better (smaller) solution than the current best.

### Interpretation of Bounds
For any subtree, the true optimal solution lies within an interval defined by its bounds.

Maximization:
$$
LB≤true optimum≤UB
$$
Minimization:
$$
LB≤true optimum≤UB
$$
Pruning occurs when this interval proves that improvement is impossible.

Think of it as a range:
For a subtree, the true optimal solution lies somewhere between:
$$
Lower Bound≤True Optimum≤Upper Bound
$$
In maximization:
- Upper bound = optimistic ceiling
- Best known = confirmed floor

If ceiling ≤ floor → impossible to improve.

Suppose:
Best solution so far = 90

Now consider nodes:
```
Node A → UB = 120 → promising
Node B → UB = 95  → promising
Node C → UB = 75  → prune
```
Node C cannot possibly beat 90.

For maximization:
Upper bound must never be too small.
If it underestimates, we might prune a branch that actually contains the optimal solution.
That would make the algorithm incorrect.

We computed upper bound using fractional knapsack:
Even though the real problem is 0/1, we allowed fractions.
Why?
Because:
Fractional knapsack always gives a value ≥ real 0/1 solution.
So it is a valid upper bound.

### Constructing Bounds
Bounds are typically obtained by solving a relaxed version of the problem.
Examples:
- In 0/1 Knapsack, a fractional knapsack relaxation provides an upper bound.
- In Traveling Salesman Problem, a minimum spanning tree provides a lower bound.
- In integer programming, a linear programming relaxation provides bounds.

The relaxed problem must satisfy two properties:
1. It is easier to solve than the original problem.
2. Its solution provides a valid bound

### Importance of Bound Quality
The efficiency of Branch and Bound depends heavily on the tightness of bounds.
- Loose bounds → little pruning → near-exhaustive search.
- Tight bounds → significant pruning → efficient search.

A strong bounding function can dramatically reduce the effective search space.

In Branch and Bound:
- Bounds provide mathematical guarantees about the best possible outcome of a subtree.
- In maximization:
    * Upper bound estimates the best possible value.
    * Lower bound is the best known feasible solution.
- In minimization:
    * Lower bound estimates the best possible value.
    * Upper bound is the best known feasible solution.
- Pruning occurs when bounds prove that improvement is impossible.

Thus, bounds serve as the fundamental mechanism that transforms exhaustive search into an intelligent, directed exploration of the solution space.

### Mathematical Summary
For maximization:
$$
Prune if UB(node)≤BestSolution
$$
For minimization:
$$
Prune if LB(node)≥BestSolution
$$
## Why It’s Needed
Many problems have exponential search spaces:
- Traveling Salesman Problem
- 0/1 Knapsack
- Assignment Problem
- Integer Programming

Brute force explores all possibilities: O(2n), O(n!), etc. 

Branch and Bound reduces the search dramatically by pruning.

## Core Components
The Three Core Components
### Branching
Split the problem into smaller subproblems.

Example (Knapsack):
- Take the item
- Don’t take the item

This creates a search tree.

### Bounding
For each node in the search tree:
- Compute a bound — an optimistic estimate of the best possible solution in that subtree.

Important:
- For maximization → bound is an upper bound.
- For minimization → bound is a lower bound.

If the bound is worse than the best solution already found → prune.

The quality of the bound function determines efficiency.
- Weak bound → little pruning → near brute force.
- Strong bound → massive pruning → fast.

Designing good bounds is often the hardest part.

### Pruning
If:
```
bound(node)≤best_solution 
```
Then:
That branch cannot improve the answer → stop exploring it.

This is what makes B&B powerful.

Without pruning: Full exponential tree

With B&B: Large parts chopped off early

Search space shrinks dramatically.


At each node:
1. Compute current partial solution.
2. Compute bound.
3. If bound ≤ best → prune.
4. Otherwise → branch further.

## Step by Step Example: 0/1 Knapsack
Suppose:
Capacity = 10

Items:
| Item | Weight | Value |
| ---- | ------ | ----- |
| A    | 5      | 50    |
| B    | 4      | 40    |
| C    | 6      | 30    |

We want to: Maximize value subject to total weight ≤ 10

We build a decision tree:
```
            {}
          /      \
      take A    skip A
      /    \       ...
```
At each node:
- We compute current value
- We compute upper bound (using fractional knapsack idea)
- If upper bound ≤ best known value → prune

We never explore useless branches.

## Where Branch and Bound Fits Among Algorithm Strategies
| Strategy            | Used For                      | Nature               |
| ------------------- | ----------------------------- | -------------------- |
| Divide & Conquer    | Break independent subproblems | Structural splitting |
| Dynamic Programming | Overlapping subproblems       | Store & reuse        |
| Greedy              | Locally optimal choice        | Fast, may fail       |
| Backtracking        | Explore all possibilities     | Prune only invalid   |
| **Branch & Bound**  | Optimization search           | Prune suboptimal     |

## Backtracking vs Branch & Bound
Backtracking:
- Prunes when solution is invalid.

Branch & Bound:
- Prunes when solution is valid but provably not optimal.

That’s the key difference.

## Role in Algorithm Strategy Hierarchy
Think of B&B as Intelligent brute force. It’s still exponential in worst case.
But in practice, with good bounds:
- It can be dramatically faster.
- It solves many practical NP-hard problems efficiently.

It is widely used in:
- Industrial optimization solvers
- Integer Linear Programming
- Scheduling
- Routing

## How It’s Implemented
Typically uses:
- Recursion
- Priority queue (best-first search)
- Depth-first search with pruning

Variants:
1. Depth-first Branch and Bound
2. Best-first Branch and Bound
3. Least-cost Branch and Bound

Goal: Choose a subset of items with total weight ≤ 5 that maximizes total value

In the classical 0/1 Knapsack problem:
- Each item has a weight wi and value vi.
- The knapsack has capacity W.
- Each item must be taken entirely or not taken at all.
- The goal is to maximize total value without exceeding capacity.

This problem is combinatorial and NP-hard.
To solve it efficiently using Branch and Bound, we need bounds.

**Greedy Knapsack as a Lower Bound**
Suppose we apply the following greedy strategy:
- Sort items in decreasing order of value-to-weight ratio vi​/wi​.
- Insert items completely (no fractions) until no more items fit.
Let:
$$
G=profit returned by greedy_knapsack
$$
Since this produces a feasible 0/1 solution, we know:
$$
G≤OPT 
$$
where OPT is the optimal 0/1 solution.
Thus:
The greedy solution provides a lower bound on the optimal profit.
It may be suboptimal, but it is guaranteed achievable(the profit given by greedy_knapsack is a lower bound to the optimal profit (it may or may not be close to the optimal profit).).

**Powdered (Fractional) Knapsack**

Now consider a relaxed version of the problem:
- Items are divisible (like powder).
- Fractions of items are allowed.

This is known as the fractional knapsack problem.
It can be solved optimally by a simple greedy strategy:
1. Sort items by decreasing value-to-weight ratio.
2. Insert items fully while possible.
3. Insert a fraction of the next item if necessary.

POWDERED_KNAPSACK(items, W):

    sort items in decreasing order of value/weight ratio

    bag_weight ← 0
    bag_value ← 0

    for each item i in sorted items:

        if bag_weight = W:
            break

        weight_taken ← min(W - bag_weight, i.weight)

        bag_weight ← bag_weight + weight_taken
        bag_value ← bag_value + weight_taken * (i.value / i.weight)

    return bag_value

**Why Fractional Knapsack Gives an Upper Bound**

Adding the restriction that items are indivisible can only make
the highest possible profit decrease because we’ll have to replace
the last added item with something worth less. This means pow-
dered_knapsack gives an upper bound of the optimal profit
with indivisible items.

Let:
```
F=profit from powdered_knapsack
```
Observe:
- The fractional problem has fewer constraints.
- Every feasible 0/1 solution is also feasible in the fractional problem.
- But the fractional problem allows additional solutions (partial items).
Therefore:
```
OPT≤F 
```
This means:
The fractional solution provides an upper bound on the optimal 0/1 profit.

Why the Upper Bound is Valid
Consider the last item added in the fractional solution.
In the fractional version:
- We may take a portion of it.

In the 0/1 version:
- We must either take the entire item or not take it.

If we take it entirely:
- Capacity may be exceeded.

If we reject it:
- We lose value.

Thus:
The indivisibility constraint can only reduce the achievable value.

Hence:
$$
Fractional solution≥0/1 optimal solution
$$
For the 0/1 knapsack:
```
Greedy0/1≤OPT≤Fractional 
```
In words:
- Greedy gives a lower bound
- Fractional gives an upper bound

**Role in Branch and Bound**

In Branch and Bound:
- The current best feasible 0/1 solution is the lower bound
- The fractional knapsack value computed at a node is the upper bound

We prune a node if:
$$
UpperBound(node)≤LowerBound
$$
because that subtree cannot improve the current best solution.

The fractional knapsack solution is not meant to be implemented as the final answer to the 0/1 problem.
Its purpose is to:
Provide a tight and efficiently computable upper bound to guide pruning.
The tighter this bound, the more effective the Branch and Bound algorithm becomes.

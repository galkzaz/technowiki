Recursion is an algorithm design strategy where a problem is solved by reducing it into **smaller instances of the same problem**.

A recursive algorithm typically:

1. Solves a simple version directly (**base case**)
2. Breaks the problem into smaller subproblems
3. Calls itself on those subproblems
4. Combines the results

Recursion is a technique where an algorithm solves a problem by:

* Solving smaller instances of the same problem
* Combining their results
* Stopping at a base case

Formally: A recursive algorithm defines the solution in terms of itself on smaller inputs. This mirrors mathematical induction and many problem structures in CS.

We say there's recursion when a function delegates work to clones of itself. A recursive algorithm will naturally come to mind for
solving a problem defined in terms of itself. For example, take the famous Fibonacci sequence.

Using recursion requires creativity for seeing how a problem can be stated in terms of itself.

Recursion is:

* A problem-solving lens
* A bridge between math and code
* The natural language of algorithm design

Algorithm strategies (Divide & Conquer, DP, Backtracking, etc.) are essentially structured ways of using recursion effectively.

Recursive algorithms have base cases, when the input is too small to be further reduced. 
- Base cases for fib are numbers `1` and `2`; 
- for palindrome, they're words with one or zero characters.

For example, take the famous Fibonacci sequence. It starts with two ones, and each subsequent number is the sum of the two previous numbers:
1, 1, 2, 3, 5, 8, 13, 21, … How do you code a function that returns the nth Fibonnacci number?
```
function fib(n)
    if n ≤2
        return n
    return fib(n -1 ) + fib(n -2 )
```

```
function palindrome(word)
    if word.length ≤1
        return True
    if word.first_char ≠ word.last_char

    w ← word.remove_first_and_last_chars
    return palindrome(w)
```

## Core Idea

A recursive function solves a problem by trusting that the **same function** can solve smaller versions of it.

Instead of writing loops explicitly, recursion expresses the solution in terms of:

* **self-reference**
* **problem reduction**
* **repeated decomposition**

## Core components of any recursive algorithm

Every correct recursive algorithm has:

1. **Base case**
   * The smallest input that can be solved directly
   * Prevents infinite recursion
2. **Recursive case**
   * The problem reduced to smaller subproblems
3. **Progress toward the base case**
   * Each recursive call must move closer to termination

If any of these are missing → the algorithm is incorrect.

## General Structure of Recursion

```text
function recursive(problem):
    if base_case(problem):
        return simple_answer

    smaller_problem = reduce(problem)

    partial_result = recursive(smaller_problem)

    return combine(partial_result)
```
**Two Essential Parts**

1. **Base Case**

The stopping condition. Without it, recursion would continue forever.

Example:

```text
factorial(0) = 1
```

---

2. **Recursive Case**

The function calls itself with a smaller/simpler input.

Example:

```text
factorial(n) = n × factorial(n-1)
```

## Recursive Thinking

A recursive thinker asks:

> “Can I define this problem using a smaller version of itself?”

This usually involves:

* shrinking input size
* moving toward base case
* trusting recursive calls


## Example: Factorial Recursion

Suppose we want to compute: $4!$

Using recursion:

$$
n! = n\times (n-1)!
$$
Base case: $0! = 1$

Compute:

```text id="q6sazs"
function factorial(n):

    if n == 0:
        return 1

    return n * factorial(n - 1)
```

**Important Observation**

The recursive calls execute in two phases:

| Phase        | Description               |
| ------------ | ------------------------- |
| Call Phase   | Recursive calls go deeper |
| Return Phase | Results return backward   |

When recursion goes deeper: computation is postponed

Example:

```text id="a6q3xm"
4 * factorial(3)
```

The multiplication cannot happen until:

```text id="k2t8yr"
factorial(3)
```

finishes first.

That is why recursion naturally uses a stack.

## How Recursion Works Internally

Each recursive call is placed on the **call stack**.

The system stores:

* parameters
* local variables
* return address

Example stack growth:

```text
factorial(4)
factorial(3)
factorial(2)
factorial(1)
factorial(0)
```

Then calls return backward:

```text
factorial(0) returns 1
factorial(1) returns 1
factorial(2) returns 2
factorial(3) returns 6
factorial(4) returns 24
```

## Common Recursive Strategies

### 1. Linear Recursion

One recursive call per function call.

Example:

* factorial
* linked list traversal

```text
f(n) → f(n-1)
```

---

### 2. Binary / Multiple Recursion

More than one recursive call.

Example: Fibonacci

```text
fib(n) = fib(n-1) + fib(n-2)
```
$$
F_n = F_{n-1} + F_{n-2}
$$
Recursive tree:

```text
fib(5)
├── fib(4)
│   ├── fib(3)
│   └── fib(2)
└── fib(3)
```

---

### 3. Divide and Conquer

Split problem into independent parts.

Examples:

* Merge Sort
* Quick Sort
* Binary Search

Structure:

```text
divide
→ recursively solve subproblems
→ combine results
```

---

### 4. Backtracking

Recursively explore possibilities and undo choices.

Examples:

* N-Queens
* Sudoku
* Permutations
* DFS search

Pattern:

```text
choose
explore recursively
undo choice
```

## Examples
### Example — Binary Search Recursion

Binary Search repeatedly halves the problem.

Core relation:

T(n)=T\left(\frac{n}{2}\right)+c

Pseudo-code:

```text
function binary_search(A, left, right, target):

    if left > right:
        return NOT_FOUND

    mid = (left + right) / 2

    if A[mid] == target:
        return mid

    if target < A[mid]:
        return binary_search(A, left, mid-1, target)

    return binary_search(A, mid+1, right, target)
```

## Why Recursion Is Powerful

Recursion is useful when problems are naturally:

* hierarchical
* self-similar
* divide-and-conquer based

Examples:

* Trees
* Graph traversal
* Divide and conquer algorithms
* Backtracking
* Dynamic programming
* Mathematical definitions


## When to Use Recursion

You should consider a recursive approach if:

* The problem can be naturally defined in terms of a smaller version of itself (e.g., a tree node is just a root with smaller trees as children).
* Code readability and maintainability are more critical than absolute peak performance.
* The depth of the recursion is guaranteed to be shallow enough to avoid stack overflow errors.

## Recursive vs. Iterative Comparison

While any recursive algorithm can be written using a loop (iteration) and a stack data structure, recursion is often preferred for its expressiveness.

**Recursion**:

* Expresses problem structure
* Matches mathematical definitions
* Easier to reason about correctness

**Iteration**:

* Often more memory-efficient
* Better control over stack usage
* Preferred in performance-critical code

This simplicity comes at a price. Recursive algorithms spawn numerous clones of themselves when they run, introducing a computational overhead. The computer must keep track of unfinished recursive calls and their partial calculations, requiring more memory. And extra CPU cycles are spent to switch from a recursive call to the next and back.

This potential problem can be visualized in recursion trees:
a diagram showing how the algorithm spawns more calls as it
delves deeper in calculations.as we seen recursion trees for calculating Fibonacci numbers and checking palindrome words.

If performance must be maximized, we can avoid this overhead
by rewriting recursive algorithms in a purely iterative form. Doing
so is always possible. It's a trade: the iterative code generally runs
faster but it's also more complex and harder to understand.

Key insight: Many iterative algorithms are just optimized recursive algorithms with an explicit stack.

| Feature	 | Recursion	 | Iteration |
| --- | --- | --- |
| Code Length	 | Typically shorter and more elegant.	 | Often longer and more 'manual.' |
| Memory	 | Uses the Call Stack (higher memory overhead).	 | Uses a fixed amount of memory. |
| Performance	 | Can be slower due to function call overhead.	 | Generally faster. |
| Best For	 | Trees, Graphs, and complex branching.	 | Simple linear traversals or counters. |


Recursion vs Iteration

| Aspect      | Recursion             | Iteration                |
| ----------- | --------------------- | ------------------------ |
| Mechanism   | Function calls        | Loops                    |
| Memory      | Uses call stack       | Usually constant         |
| Readability | Often cleaner         | Sometimes more efficient |
| Best For    | Trees, divide-conquer | Simple repetition        |
| Risk        | Stack overflow        | Infinite loops           |

## Recursion and correctness proofs

Recursion aligns perfectly with:

* Mathematical induction
* Invariants on subproblems

To prove a recursive algorithm correct:

* Base case is correct
* Assume recursive calls are correct
* Show the combine step is correct

This is why recursion dominates algorithm textbooks.

## Costs and limitations of recursion

Recursion is powerful but not free:

* Function call overhead
* Stack memory usage
* Risk of stack overflow
* Repeated computation (if no memoization)

Algorithm strategies like Dynamic Programming exist largely to fix naive recursion.


## Advantages of Recursion

### Simplicity

Many problems become shorter and clearer.

### Natural Modeling

Excellent for:

* trees
* nested structures
* mathematical definitions

## Disadvantages of Recursion

### Call Stack Overhead

Every recursive call consumes memory.

### Possible Stack Overflow

Too many recursive calls can exhaust stack memory.

### Sometimes Slower

Function-call overhead may be higher than loops.

Example:

naive Fibonacci recursion is inefficient.

## Mental Model

Recursion is essentially:

```text
Solve problem
→ reduce to smaller version
→ let recursion solve smaller part
→ combine answers
```

The critical requirement is:

```text
each recursive call MUST move toward the base case
```

Otherwise recursion never terminates.

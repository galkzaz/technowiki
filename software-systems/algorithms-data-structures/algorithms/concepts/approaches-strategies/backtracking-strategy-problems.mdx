# 2. Constraint Satisfaction Problems (CSP)

## 2.1 N-Queens Family

### N-Queens

<details>

<summary>**How do you place eight queens on the board such that no queens attack each other?**</summary>

Refernces: https://code.energy/8-queens-problem/

**Problem Statement**

In Chess pieces move on an 8 × 8 board, attacking enemy pieces. The queen is the most powerful piece: it can attack pieces that occupy its row, its column, or its diagonals. 

The N-Queens problem asks whether it is possible to place N queens on an N × N chessboard such that:
- No two queens share the same row
- No two queens share the same column
- No two queens share the same diagonal
    
The objective is to find one or all valid arrangements satisfying these constraints.

Try finding a solution manually: you'll see it's not trivial. Figure shows one of the ways queens can be peacefully positioned.

![The letmost queen attacks other queens. Moving her up, none of the queens attack each other](/docs/assets/software-systems/data-structures-and-algorithms/algorithms/approaches-strategies/n-queen-1.png)

**the brute force way**

As eight queens can be placed in the chessboard in over four billion ways. Solving this problem the brute force way inspecting all these possibilities is sloppy. Imagine the first two queens are placed on the board attacking each other: regardless where the next queens are placed, a solution isn't possible. Yet, a brute force approach would waste time with all these doomed queen placements.

see software-systems/algorithms-data-structures/algorithms/concepts/approaches-strategies/brute-force-strategy-problems#brute-force-strategy-problems-n-queens

Searching only viable queen placements is more efficient. The
first queen can be placed anywhere. Viable placements for the next queens are limited by already placed queens: a queen cannot be
placed in the attacking range of another queen. Placing queens
following this rule, we're likely to get a board where it's impossible
to place an additional queen before all eight queens are placed:

![Placing a queen limits viable places for the next queens](/docs/assets/software-systems/data-structures-and-algorithms/algorithms/approaches-strategies/n-queen-placing-a-queen-limits-viable-places-for-the-next-queens.png)

This can only mean the last queen was placed incorrectly. So we
backtrack: we roll back the previous placement and continue the
search. That's the essence of the backtracking strategy: keep on
placing queens in valid positions. Once we get stuck, roll back
the placement of the last queen and carry on. The process can be
streamlined using recursion:
```
function queens(board)
  if board.has_ͧ_queens
    return board
  for each position in board.unattacked_positions
    board.place_queen(position)
      solution ← queens(board)
    if solution
      return solution
    board.remove_queen(position)
return False
```
If the board isn't already solved, it loops through all viable positions for the next queen. It uses recursion to check if placing a queen in each of these positions gives a solution. Here's how the
process works:

![Backtracking in the 8 Queens Puzzle](/docs/assets/software-systems/data-structures-and-algorithms/algorithms/approaches-strategies/n-queen-backtracking-in-the-n-queens-puzzle.png)

The problem is solved by placing queens row by row, ensuring that each partial placement is valid before proceeding.
At each row:
- Attempt to place a queen in each column
- Check whether the placement conflicts with previously placed queens
- If a conflict occurs, abandon the placement and try the next column
- If no column is valid, backtrack to the previous row

```c
#include <stdio.h>
#include <stdlib.h>

int isSafe(int board[], int row, int col) {
    for (int i = 0; i < row; i++)
        if (board[i] == col ||
            abs(board[i] - col) == row - i)
            return 0;
    return 1;
}

void printBoard(int board[], int n) {
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++)
            printf(board[i] == j ? 'Q ' : '. ');
        printf('\n');
    }
    printf('\n');
}

void solve(int board[], int row, int n) {
    if (row == n) {
        printBoard(board, n);
        return;
    }
    for (int col = 0; col < n; col++) {
        if (isSafe(board, row, col)) {
            board[row] = col;
            solve(board, row + 1, n);
        }
    }
}

int main() {
    int n = 4;
    int board[n];
    solve(board, 0, n);
    return 0;
}
```

```java
public class NQueensBacktracking {

    static boolean isSafe(int[] board, int row, int col) {
        for (int i = 0; i < row; i++)
            if (board[i] == col ||
                Math.abs(board[i] - col) == row - i)
                return false;
        return true;
    }

    static void printBoard(int[] board) {
        int n = board.length;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++)
                System.out.print(board[i] == j ? 'Q ' : '. ');
            System.out.println();
        }
        System.out.println();
    }

    static void solve(int[] board, int row) {
        int n = board.length;
        if (row == n) {
            printBoard(board);
            return;
        }
        for (int col = 0; col < n; col++) {
            if (isSafe(board, row, col)) {
                board[row] = col;
                solve(board, row + 1);
            }
        }
    }

    public static void main(String[] args) {
        int n = 4;
        int[] board = new int[n];
        solve(board, 0);
    }
}
```

```rust
fn is_safe(board: &Vec<usize>, row: usize, col: usize) -> bool {
    for i in 0..row {
        if board[i] == col ||
           (board[i] as i32 - col as i32).abs() == (row as i32 - i as i32)
        {
            return false;
        }
    }
    true
}

fn print_board(board: &Vec<usize>) {
    let n = board.len();
    for i in 0..n {
        for j in 0..n {
            if board[i] == j {
                print!('Q ');
            } else {
                print!('. ');
            }
        }
        println!();
    }
    println!();
}

fn solve(board: &mut Vec<usize>, row: usize) {
    let n = board.len();
    if row == n {
        print_board(board);
        return;
    }
    for col in 0..n {
        if is_safe(board, row, col) {
            board[row] = col;
            solve(board, row + 1);
        }
    }
}

fn main() {
    let n = 4;
    let mut board = vec![0; n];
    solve(&mut board, 0);
}
```

**Key Observations**
- The algorithm explores a decision tree
- Invalid branches are pruned early
- Backtracking avoids testing all 44=256 possibilities
- Only feasible partial solutions are expanded

**Complexity**
- Worst-case time complexity: O(N!)
- Space complexity: O(N) (recursion stack + board state)

**Conceptual Summary**

The N-Queens problem demonstrates how backtracking systematically explores a combinatorial search space by making choices, detecting conflicts early, and undoing decisions when necessary. This makes backtracking a powerful strategy for constraint satisfaction problems.

The iterative strategy consists in using loops (e.g. for, while) to repeat a process until a condition is met. Each step in a loop is called an iteration. It's great for running through an input and applying the same operations on every part of it.

An **iterative algorithm** solves a problem by **repeating a sequence of steps** using loops such as:

* `for`
* `while`
* `do-while`

Instead of calling itself repeatedly like recursion, the algorithm keeps updating variables until a stopping condition is reached.

## Core Idea

The strategy is:

1. Start with an initial state
2. Repeat operations
3. Update the state after each step
4. Stop when a condition becomes false
5. Return the final result

## General Structure

**Pseudocode**

```text
initialize variables

while condition is true
    perform operations
    update variables

return result
```

## Characteristics of Iterative Algorithms

| Characteristic        | Description                             |
| --------------------- | --------------------------------------- |
| Repetition            | Uses loops                              |
| State Update          | Variables change during execution       |
| Termination Condition | Loop stops at a condition               |
| Memory Efficient      | Usually uses less memory than recursion |
| Explicit Control Flow | Programmer manages repetition directly  |

---

## Iteration vs Recursion

| Aspect         | Iteration           | Recursion                      |
| -------------- | ------------------- | ------------------------------ |
| Main Mechanism | Loops               | Function calls                 |
| Memory Usage   | Usually low         | Uses call stack                |
| Speed          | Often faster        | Usually slower                 |
| Risk           | Infinite loop       | Stack overflow                 |
| State Storage  | Variables           | Call stack frames              |
| Best For       | Repeated processing | Naturally recursive structures |

## Step-by-Step Example — Factorial Iteratively

We want to compute:
$$
5! = 5 \times 4 \times 3 \times 2 \times 1
$$

**Mathematical Formula**
$$
n! = \prod_{i=1}^{n} i
$$

**Iterative Strategy**

Instead of recursively computing:

```text
5 × factorial(4)
```

we repeatedly multiply numbers in a loop.

---

### Pseudocode

```text
function factorial(n)

    result ← 1

    for i ← 1 to n
        result ← result × i

    return result
```

---

### Step-by-Step Execution Trace

For `n = 5`

| Iteration | i | result before | Operation | result after |
| --------- | - | ------------- | --------- | ------------ |
| Start     | — | 1             | —         | 1            |
| 1         | 1 | 1             | 1 × 1     | 1            |
| 2         | 2 | 1             | 1 × 2     | 2            |
| 3         | 3 | 2             | 2 × 3     | 6            |
| 4         | 4 | 6             | 6 × 4     | 24           |
| 5         | 5 | 24            | 24 × 5    | 120          |

**Final answer: 120**
---


## Important Concepts in Iterative Strategy

### 1. Initialization

Starting values must be set correctly.

Example:

```text
result ← 1
```

---

### 2. Loop Condition

Determines when iteration stops.

Example:

```text
i <= n
```

---

### 3. State Update

Variables must change every iteration.

Example:

```text
i ← i + 1
```

Without updates → infinite loop.

---

### 4. Accumulator Variable

A variable that stores intermediate results.

Examples:

```text
sum
count
result
max
min
```

## Example — Linear Search

Find `8` in:

```text
[4, 1, 8, 2]
```

---

### Pseudocode

```text
function linear_search(A, target)

    for i ← 0 to length(A)-1

        if A[i] = target
            return i

    return NOT_FOUND
```

---

### Execution Trace

| Iteration | i | A[i] | Compare with 8 | Result   |
| --------- | - | ---- | -------------- | -------- |
| 1         | 0 | 4    | 4 ≠ 8          | continue |
| 2         | 1 | 1    | 1 ≠ 8          | continue |
| 3         | 2 | 8    | 8 = 8          | found    |

## Advantages of Iterative Strategy

| Advantage               | Explanation               |
| ----------------------- | ------------------------- |
| Efficient Memory Usage  | No recursive call stack   |
| Fast Execution          | Lower overhead            |
| Simple Runtime Behavior | Easier to trace execution |
| Good for Large Inputs   | Avoids stack overflow     |


## Disadvantages

| Disadvantage                          | Explanation                           |
| ------------------------------------- | ------------------------------------- |
| Can Be Less Elegant                   | Some problems are naturally recursive |
| Manual State Management               | Programmer handles updates explicitly |
| Complex Loops Can Become Hard to Read | Nested loops may reduce clarity       |

## When to Use Iteration

Iteration is preferred when:

* The problem involves repeated processing
* Performance is important
* Large inputs are expected
* Recursion depth may become large
* State changes can be expressed clearly with loops

## Role of Iterative Algorithm Strategy in Algorithm Design

In **algorithm design**, the iterative strategy is one of the most fundamental ways to construct algorithms.

It provides a method for solving problems through:

* repeated execution,
* controlled state updates,
* and loop-based progression.

Iteration is not just a programming technique — it is a **core algorithmic design strategy** used in almost every area of computer science.

**What Is an Algorithm Design Strategy?**

An algorithm design strategy is a **general approach or methodology** for solving problems.

Examples include:

| Strategy            | Main Idea                                  |
| ------------------- | ------------------------------------------ |
| Iteration           | Repeat operations using loops              |
| Recursion           | Solve smaller versions of the same problem |
| Divide and Conquer  | Split problem into subproblems             |
| Dynamic Programming | Store/reuse computed results               |
| Greedy Strategy     | Make locally optimal choices               |
| Backtracking        | Explore and undo choices                   |

Iteration is often the **foundation** upon which other strategies are implemented.

The iterative strategy plays several important roles.

### 1. Repeated Processing of Data

Many problems require processing elements one-by-one.

Iteration provides controlled repetition.

Example:

* traversing arrays
* scanning lists
* processing files
* counting values

** Example**

```text id="k0b9w6"
for each element in array
    process element
```

### 2. State Transformation Over Time

Iterative algorithms gradually transform the program state until the solution emerges.

The algorithm maintains:

* current state,
* partial solution,
* progress indicators.

**Example — Factorial**

State changes every iteration:

```text id="wktv2s"
result = result × i
```

**Mathematical Growth**

$n! = \prod_{i=1}^{n} i$

### 3. Efficient Alternative to Recursion

Iteration is frequently used to replace recursion because it:

* avoids call-stack overhead,
* improves memory efficiency,
* reduces risk of stack overflow.

**Recursive vs Iterative Thinking**

Recursive:

```text id="q0a6f0"
factorial(n) = n × factorial(n-1)
```

Iterative:

```text id="fy1o86"
repeat multiplication in a loop
```

### 4. Foundation for Traversal Algorithms

Most traversal algorithms rely on iteration.

Examples:

| Structure    | Iterative Traversal   |
| ------------ | --------------------- |
| Arrays       | Sequential loops      |
| Linked Lists | Pointer iteration     |
| Trees        | Stack-based traversal |
| Graphs       | BFS/DFS loops         |

**Example — Array Traversal**

```text id="1svf4x"
for i ← 0 to n-1
    visit A[i]
```

### 5. Building Block for More Advanced Strategies

Many advanced strategies internally depend on iteration.

| Strategy              | How Iteration Is Used      |
| --------------------- | -------------------------- |
| Dynamic Programming   | Filling tables iteratively |
| Greedy Algorithms     | Repeated local decisions   |
| Graph Algorithms      | Iterative exploration      |
| Numerical Algorithms  | Repeated approximation     |
| Simulation Algorithms | Time-step iteration        |

** Example — Dynamic Programming**

Fibonacci iterative DP:

```text id="xjlwm8"
for i ← 2 to n
    dp[i] = dp[i-1] + dp[i-2]
```

Fibonacci Relation
$$
F_n = F_{n-1} + F_{n-2}
$$

### 6. Controlling Time Complexity

Iteration directly influences algorithm complexity.

**Single Loop**

```text id="8otz0r"
for i ← 1 to n
```

Complexity: $O(n)$

**Nested Loops**

```text id="n2ch5e"
for i ← 1 to n
    for j ← 1 to n
```

Complexity: $O(n^2)$

Iteration helps designers reason about:

* runtime growth,
* scalability,
* performance trade-offs.

### 7. Incremental Problem Solving

Iteration often solves problems incrementally.

Each iteration:

* improves the partial solution,
* moves closer to completion,
* maintains progress.

**Example — Linear Search**

```text id="im9n6q"
check next element
```

until:

* target found,
* or data exhausted.

### 8. Enables Streaming and Online Algorithms

Iteration is essential when data arrives continuously.

Examples:

* network packets,
* sensor streams,
* event processing,
* reactive systems.

The algorithm processes data incrementally instead of waiting for all input.

### 9. Supports Deterministic Execution Flow

Iterative algorithms usually have predictable execution flow:

```text id="tghj1g"
initialize
→ repeat
→ update
→ terminate
```

This makes them:

* easier to debug,
* easier to optimize,
* easier to analyze formally.

### 10. Hardware-Friendly Execution

Iteration aligns naturally with hardware execution models.

Processors optimize loops using:

* caching,
* pipelining,
* branch prediction,
* vectorization.

This often makes iterative algorithms highly performant.

| Role                    | Importance                          |
| ----------------------- | ----------------------------------- |
| Repetition Mechanism    | Core execution model                |
| State Evolution         | Gradual solution building           |
| Traversal Tool          | Processing collections/structures   |
| Efficiency Tool         | Lower memory overhead               |
| Complexity Control      | Direct runtime analysis             |
| Foundation Strategy     | Supports many advanced algorithms   |
| Incremental Computation | Enables streaming/online processing |

## Relationship Between Iteration and Other Design Strategies

| Strategy            | Relationship with Iteration                            |

## Conceptual Role of Iteration

Iteration represents:

> controlled repetition with evolving state

It is the primary mechanism for:

* progression,
* accumulation,
* traversal,
* convergence,
* and repeated refinement.

**Typical Problems Solved with Iterative Algorithm Strategy**

The **iterative strategy** is especially suitable for problems that involve:

* repeated operations,
* sequential processing,
* gradual state updates,
* or continuous refinement.

It is one of the most widely used strategies because many computational problems naturally consist of repeating steps until a goal is reached.

### Main Categories of Problems Solved Iteratively

| Problem Category        | Why Iteration Fits            |
| ----------------------- | ----------------------------- |
| Traversal Problems      | Visit elements one-by-one     |
| Accumulation Problems   | Repeatedly combine values     |
| Searching Problems      | Check items until found       |
| Counting Problems       | Maintain counters             |
| Simulation Problems     | Repeated state changes        |
| Numerical Approximation | Gradual convergence           |
| Dynamic Programming     | Build solutions incrementally |
| Graph Traversal         | Explore nodes iteratively     |
| Stream Processing       | Handle continuous input       |

### 1. Traversal Problems

Traversal means visiting every element in a structure.

Iteration is ideal because loops naturally move through collections sequentially.

**Typical Structures**

* arrays
* linked lists
* matrices
* files
* strings

**Example — Array Traversal**

```text id="m4ts2p"
for i ← 0 to n-1
    process A[i]
```

**Typical Tasks**

* printing elements
* transforming data
* validation
* aggregation

### 2. Accumulation Problems

These problems build a result gradually.

An accumulator variable stores intermediate results.

**Example — Sum of Numbers**

$$
1 + 2 + 3 + 4 + 5
$$

** Formula**

\sum_{i=1}^{n} i

** Iterative Solution**

```text id="1vhmtq"
sum ← 0

for i ← 1 to n
    sum ← sum + i
```

** Common Accumulation Problems**

| Problem | Accumulator |
| ------- | ----------- |
| Sum     | total       |
| Product | result      |
| Average | sum/count   |
| Maximum | max         |
| Minimum | min         |

### 3. Searching Problems

Iteration repeatedly checks elements until:

* target found,
* or search space exhausted.

**Example — Linear Search**

```text id="imym40"
for each element x in A
    if x = target
        return FOUND
```

**Typical Searching Problems**

* finding values
* locating duplicates
* membership testing
* filtering data

### 4. Counting Problems

Many algorithms repeatedly count occurrences or events.

**Example — Count Even Numbers**

```text id="oj7m9c"
count ← 0

for each x in A
    if x mod 2 = 0
        count ← count + 1
```

**Common Counting Tasks**

* frequency counting
* word counting
* event counting
* occurrence statistics

### 5. Repetitive Mathematical Computation

Mathematical algorithms often require repeated updates.

**Example — Factorial**

n! = \prod_{i=1}^{n} i

** Iterative Algorithm**

```text id="m5ujzd"
result ← 1

for i ← 1 to n
    result ← result × i
```

**Other Mathematical Problems**

| Problem           | Iterative Nature              |
| ----------------- | ----------------------------- |
| Power computation | repeated multiplication       |
| Fibonacci         | repeated state updates        |
| GCD               | repeated remainder operations |
| Matrix operations | nested loops                  |

**Example — Fibonacci Iteratively**

```text id="7n2x18"
a ← 0
b ← 1

repeat n times
    next ← a + b
    a ← b
    b ← next
```

**Fibonacci Relation**
$$
F_n = F_{n-1} + F_{n-2}
$$
### 6. Simulation Problems

Simulations repeatedly update system state over time.

Iteration models:

* time progression,
* movement,
* interactions.

**Examples**

* traffic simulation
* physics simulation
* game loops
* weather models
* CPU scheduling

** General Pattern**

```text id="ej24tv"
while simulation_running
    update_state
    process_events
    advance_time
```

### 7. Dynamic Programming Problems

Dynamic programming often uses iterative table filling.

Each iteration computes a larger subproblem using smaller solutions.

**Example — Fibonacci DP**

```text id="prwh36"
dp[0] ← 0
dp[1] ← 1

for i ← 2 to n
    dp[i] ← dp[i-1] + dp[i-2]
```

**Typical DP Problems**

| Problem                    | Iterative Table Construction |
| -------------------------- | ---------------------------- |
| Fibonacci                  | sequential states            |
| Knapsack                   | table filling                |
| Longest Common Subsequence | matrix updates               |
| Coin Change                | repeated minimization        |

### 8. Sorting Algorithms

Many sorting algorithms are fundamentally iterative.

**Examples**

| Algorithm      | Iterative Mechanism        |
| -------------- | -------------------------- |
| Bubble Sort    | repeated swapping          |
| Selection Sort | repeated minimum selection |
| Insertion Sort | repeated insertion         |
| Heap Sort      | repeated heap adjustment   |

**Example — Bubble Sort**

```text id="j9n7lq"
repeat
    swap adjacent out-of-order elements
until no swaps occur
```

### 9. Graph Traversal Problems

Graphs are often explored iteratively.

**Example — Breadth-First Search (BFS)**

```text id="z0tm6u"
while queue not empty
    node ← dequeue
    visit node
```

**Typical Graph Problems**

* shortest paths
* connectivity
* network traversal
* dependency resolution

### 10. Stream and Online Processing

When data arrives continuously, iteration processes items incrementally.

**Examples**

* log processing
* event streams
* sensor systems
* reactive systems
* packet processing

**Pattern**

```text id="67q5fx"
while data available
    process next item
```

### 11. Numerical Approximation Problems

Some algorithms repeatedly improve an approximation.

**Example — Newton’s Method**

{/* $$
x_{n+1} = x_n - \frac{f(x_n)}{f'(x_n)}
$$ */}

** Iterative Refinement**
{/* $$
x_{n+1}=x_n-\frac{f(x_n)}{f'(x_n)}
$$ */}
** General Pattern**

```text id="v8x4jv"
repeat
    improve approximation
until error small enough
```

### 12. State Machine Problems

Iteration is natural for systems with repeated state transitions.

**Examples**

* parsers
* protocol handlers
* workflow engines
* operating systems

**Pattern**

```text id="x2v8ee"
while system active
    transition to next state
```

**Common Characteristics of Problems Suitable for Iteration**

Iteration works best when the problem has:

| Characteristic        | Meaning              |
| --------------------- | -------------------- |
| Repetition            | Same steps repeated  |
| Sequential Progress   | Clear next step      |
| State Updates         | Variables evolve     |
| Termination Condition | Known stopping rule  |
| Incremental Solution  | Partial results grow |

### Problems Less Suitable for Pure Iteration

Some problems are more naturally recursive:

| Problem Type       | Why Recursion Fits Better |
| ------------------ | ------------------------- |
| Tree recursion     | hierarchical structure    |
| Divide and conquer | recursive decomposition   |
| Backtracking       | branching exploration     |

Even then, many recursive solutions can still be converted into iterative ones using:

* stacks,
* queues,
* explicit state management.

### High-Level View

Most iterative problems follow this model:

```text id="8p9i9f"
initialize state

while not finished
    process current step
    update state

return result
```

### Final Perspective

The iterative strategy is most effective for problems where the solution can be obtained through:

```text id="0p1prv"
repeat → update → progress → terminate
```

This makes iteration one of the most universal and practical strategies in algorithm design.

**Backtracking** is a systematic way to explore the search space of possible solutions while pruning choices that cannot lead to a valid or optimal solution.

**Backtracking** is an algorithmic strategy for systematically exploring the solution space of a problem by incrementally constructing candidates and abandoning those that violate problem constraints. It is primarily used for problems in which solutions must satisfy a set of conditions, and the search space is combinatorial in nature.

**Backtracking** is an algorithmic strategy that enhances exhaustive search by pruning infeasible solutions early. It relies heavily on recursion and depth-first search, and it is particularly effective for problems involving constraints and combinatorial structures.

Backtracking is an algorithmic strategy used to solve problems by:

1. Building a solution step-by-step
2. Checking whether the current partial solution is still valid
3. Abandoning (“backtracking from”) paths that cannot lead to a valid solution
4. Trying alternative choices

It is essentially:

* **Depth-First Search (DFS)** over a decision tree
* With **pruning** of invalid or useless paths

At its core, **backtracking** is controlled **brute force**. It explores all possible solutions by making choices and then backtracking when a choice leads to an invalid or suboptimal solution.

**Backtracking** works best in problems where the solution is a sequence of choices and making a choice restrains subsequent choices.
It identifies as soon as possible the choices you've made cannot give you the solution you want, so you can sooner step back and try something else. Fail early, fail often.

At each step, the algorithm makes a tentative decision, extends a partial solution, and checks whether the current state remains feasible. If a partial solution cannot lead to a valid complete solution, the algorithm reverses (or backtracks) to a previous decision point and explores alternative choices.

## Core Idea

Backtracking incrementally builds a solution step by step:
1. Choose a candidate option
2. Check if the partial solution is still valid
3. If valid → continue
4. If invalid → undo the choice (backtrack) and try another option

At every step:

1. Choose an option
2. Add it to the current state
3. Recurse
4. Undo the choice (backtrack)
5. Try the next option

## Mental Model

Imagine solving a maze:

* Walk forward
* If you hit a dead end:

  * go back
  * try another path

That “go back and try again” behavior is backtracking.

## Generic Structure

```text
backtrack(state):

    if solution found:
        save/output solution
        return

    for every possible choice:
        if choice is valid:

            make choice

            backtrack(new_state)

            undo choice
```

```python
def backtrack(current, n):

    if len(current) == n:
        print("".join(current))
        return

    for ch in ['0', '1']:

        ### choose
        current.append(ch)

        ### explore
        backtrack(current, n)

        ### undo
        current.pop()

```

### What Makes This Backtracking?

These two operations:

```python

current.pop()
```

Without `pop()`:

* choices remain permanently
* recursion state becomes corrupted
* other branches cannot be explored properly

The undo operation is the defining feature of backtracking.

## Role of Backtracking in Algorithm Design
The primary role of backtracking in algorithm design is to reduce the effective search space of exhaustive search methods. Unlike brute force algorithms, which generate and test all possible candidate solutions, backtracking eliminates infeasible candidates as early as possible. This pruning significantly improves practical performance, even though the worst-case time complexity may remain exponential.

Backtracking's role is to make exhaustive search practical by eliminating impossible choices as early as possible.

Backtracking is especially useful when:
- The problem has strong constraints that can be checked incrementally.
- The number of valid solutions is small compared to the total number of possibilities.
- A complete enumeration of feasible solutions is required.

Many problems have:
- Huge combinational spaces
- Strong constraints
- Few valid solutions

Backtracking allows algorithms to:
- Avoid exploring impossible paths
- Enforce constraints early
- Find solutions without checking every combination

So its role is: Reduce exponential search by early rejection

This makes it fundamentally different from:
- Pure brute force → explores all possibilities blindly
- Greedy → commits permanently to local choices
- Dynamic Programming → stores and reuses subproblem results

Backtracking explores only feasible paths.

- DP answers **how many / how optimal**.
- Backtracking answers **is there a valid one / list them all**.

**Backtracking Is Not Always Enough** as it's:
- Still exponential in the worst case
- Does not reuse results
- May revisit equivalent states

That's why:
- Memoization + backtracking → DP
- Heuristics + backtracking → CSP solvers

## Relationship to Brute Force Algorithms
Backtracking can be viewed as an optimized form of brute force search. Both approaches explore the solution space exhaustively; however, brute force evaluates all candidates without discrimination, while backtracking abandons partial solutions that violate constraints before they are fully constructed.

Thus, backtracking improves brute force by incorporating early feasibility checks, preventing unnecessary exploration of invalid branches of the search tree.

| Aspect             | Brute Force       | Backtracking              |
| ------------------ | ----------------- | ------------------------- |
| Explores           | All possibilities(Tries everything) | Only feasible ones(Tries selectively)        |
| Pruning            | No pruning               | Prunes invalid paths                       |
| Typical structure  | Nested loops      | Recursion + undo          |
| Efficiency         | Worst possible(Often slower )    | Often dramatically better(Usually much faster) |
| Use of constraints | Late              | Early                     |

Backtracking is brute force with intelligence.

**Example of Pruning**

Suppose target sum = 10.

Current partial sum = 15.

No need to continue exploring that branch.

So we stop immediately.

That is pruning.

## Backtracking Template

```python
def backtrack(path, choices):

    if goal_reached(path):
        result.append(path.copy())
        return

    for choice in choices:

        if not valid(choice, path):
            continue

        ## make choice
        path.append(choice)

        ## recurse
        backtrack(path, choices)

        ## undo choice
        path.pop()
```

## Example — Permutations

```python
def permute(nums):

    result = []
    used = [False] * len(nums)

    def backtrack(path):

        if len(path) == len(nums):
            result.append(path.copy())
            return

        for i in range(len(nums)):

            if used[i]:
                continue

            used[i] = True
            path.append(nums[i])

            backtrack(path)

            path.pop()
            used[i] = False

    backtrack([])

    return result
```

## Role of Recursion in Backtracking
Backtracking algorithms are most naturally expressed using recursion, where each recursive call represents a decision at a particular level of the solution construction process. The recursion stack implicitly stores the sequence of choices made so far.

When a recursive call returns, the algorithm automatically restores the previous state, allowing alternative decisions to be explored. This recursive structure aligns closely with a depth-first traversal of a conceptual search tree.

Backtracking almost always uses recursion because:
- Each recursive call represents a decision level
- The call stack naturally stores:
  * Current partial solution
  * Previous states
- Returning from recursion = undoing a choice

Conceptually:
- Recursion = decision tree traversal
- Backtracking = DFS with pruning

## Position Among Algorithmic Strategies
Backtracking occupies a distinct position among algorithmic strategies:
- Brute force explores all possibilities without pruning.
- Backtracking explores only feasible portions of the search space.
- Dynamic programming avoids repeated computation by storing and reusing subproblem results.

While backtracking focuses on feasibility and constraint satisfaction, dynamic programming is primarily concerned with optimality and overlapping subproblems.

Backtracking sits between brute force and dynamic programming:
```
Brute Force
     ↓ (add pruning)
Backtracking
     ↓ (add memoization)
Dynamic Programming
```
- Backtracking focuses on validity constraints
- DP focuses on optimality and overlapping subproblems

They solve different problem classes.

## Applications of Backtracking
Backtracking is commonly applied to:
- Constraint satisfaction problems (e.g., N-Queens, Sudoku, graph coloring)
- Combinatorial generation problems (e.g., permutations, combinations, subsets(with constraints))
- Search problems (e.g., maze traversal, word search)
- Decision problems where the existence of a solution must be determined i.e Is there any valid solution?

## Limitations of Backtracking
Despite its advantages, backtracking does not guarantee polynomial-time performance. In the worst case, the algorithm may still explore an exponential number of states. Additionally, backtracking does not inherently avoid recomputation of equivalent subproblems, which limits its efficiency compared to dynamic programming in problems with overlapping substructures.


## DFS Algorithm

DFS maintains information about which vertices have been discovered and uses recursion or a stack to determine which vertex to explore next.

A basic implementation needs:

| Data                         | Purpose                                                   |
| ---------------------------- | --------------------------------------------------------- |
| `visited[]` or `color[]`     | Tracks the discovery state of each vertex.                |
| `parent[]`                   | Records which vertex discovered each vertex.              |
| Call stack or explicit stack | Remembers where to continue after exploring a branch.     |
| `discoveryTime[]`            | Optionally records when each vertex is first discovered.  |
| `finishTime[]`               | Optionally records when each vertex finishes exploration. |

The time arrays are useful for advanced algorithms, but they are not required for a basic traversal.

DFS can be implemented in three common ways:

1. Iterative DFS — uses an explicit stack.
2. Recursive DFS — uses the programming language's call stack.
3. Three-color DFS — tracks each vertex as white, gray, or black to represent its exploration state.

### Iterative DFS (using a stack)

The algorithm uses a LIFO stack to explore vertices. It marks a vertex as visited when it is pushed onto the stack, preventing duplicate pushes.

### Pseudocode1
```
ITERATIVE-DFS(G, source):

    create an empty stack S
    create visited[0 ... V-1], initialized to FALSE

    visited[source] = TRUE
    PUSH(S, source)

    while S is not empty:

        u = POP(S)
        VISIT(u)

        for each vertex v adjacent to u:

            if visited[v] == FALSE:

                visited[v] = TRUE
                PUSH(S, v)
```

How it works:

- `PUSH` adds a vertex to the top of the stack.
- `POP` removes the most recently added vertex.
- Marking vertices when pushed prevents the same vertex from being added multiple times.

The exact traversal order depends on the order in which adjacent vertices are pushed. Unlike recursive DFS, iterative DFS may produce a different traversal order depending on stack handling.

### Pseudocode2
The following is an iterative Depth-First Search (DFS) implementation using a stack and a set to find a node containing a specific key.

```
function DFS(start_node, key):
    next_nodes ← Stack.new()
    seen_nodes ← Set.new()

    next_nodes.push(start_node)
    seen_nodes.add(start_node)

    while not next_nodes.empty():

        node ← next_nodes.pop()

        if node.key = key:
            return node

        for n in node.connected_nodes:
            if n not in seen_nodes:
                next_nodes.push(n)
                seen_nodes.add(n)

    return NULL
```
This algorithm searches a graph starting from `start_node` until it finds a node whose key matches the requested `key`.

It uses two data structures:

| Data structure       | Purpose                                                                               |
| -------------------- | ------------------------------------------------------------------------------------- |
| Stack (`next_nodes`) | Stores nodes waiting to be explored.                                                  |
| Set (`seen_nodes`)   | Tracks nodes that have already been discovered to avoid visiting them more than once. |


1. Step 1: Initialize the stack and set

```
next_nodes ← Stack.new()
seen_nodes ← Set.new()
```

- `next_nodes`: A stack containing nodes waiting to be processed.
- `seen_nodes`: A set containing nodes that have already been discovered.

Initially, both are empty.

1. Step 2: Add the starting node

```
next_nodes.push(start_node)
seen_nodes.add(start_node)
```

We add the starting node to both structures.

Why add it to `seen_nodes` immediately?

To prevent it from being added again when another node has an edge pointing back to it.

1. Step 3: Continue while the stack is not empty

```
while not next_nodes.empty():
```

As long as there are unexplored nodes waiting in the stack, continue searching.

If the stack becomes empty, all reachable nodes have been explored without finding the requested key.

1. Step 4: Retrieve the next node

```
node ← next_nodes.pop()
```

Remove and retrieve the top node from the stack.

Remember that a stack follows the LIFO (Last In, First Out) principle.

This means the most recently added node is explored first.

This behavior is what gives DFS its depth-first characteristic.

1. Step 5: Check whether the node matches the key

```
if node.key = key:
    return node
```

Compare the current node's key with the target key.

- If they match, return the node immediately.
- Otherwise, continue exploring its neighbors.

1. Step 6: Explore connected nodes

```
for n in node.connected_nodes:
```

Iterate through all nodes directly connected to the current node.

For each neighbor:

```
if n not in seen_nodes:
    next_nodes.push(n)
    seen_nodes.add(n)
```

We perform two operations:

1. Check whether the neighbor has already been discovered.
2. If not, add it to the stack and mark it as discovered.

Important: We mark nodes as discovered when pushing them onto the stack, not when popping them. This prevents the same node from being pushed multiple times through different paths.

1. Step 7: Return NULL

```
return NULL
```

If the stack becomes empty, the algorithm has explored every node reachable from the starting node without finding the target.

Therefore, it returns `NULL`.

**Practical Example: DFS Traversal**

Consider the following graph:

```
        A
       / \
      B   C
     / \   \
    D   E   F
       /
      G
```

Suppose we execute:

```
DFS(A, G)
```

We want to find the node whose key is `G`.

Assume neighbors are processed in the order shown in the graph (left to right).

**Execution walkthrough**

The stack is displayed from bottom to top, with the top on the right.

| Step | Popped node | Newly pushed nodes | Stack (bottom → top) |
| ---- | ----------- | ------------------ | -------------------- |
| 0    | —           | A                  | `[A]`                |
| 1    | A           | B, C               | `[B, C]`             |
| 2    | C           | F                  | `[B, F]`             |
| 3    | F           | —                  | `[B]`                |
| 4    | B           | D, E               | `[D, E]`             |
| 5    | E           | G                  | `[D, G]`             |
| 6    | G           | —                  | `[D]`                |

At step 6:

```
if G.key = G:
    return G
```

Target found

The algorithm returns node `G`.

Notice that DFS explores the branch through `C` before returning to explore the branch through `B`. This happens because `C` was pushed last and therefore popped first.

#### How iterative DFS works

DFS explores one branch as deeply as possible before returning to explore another branch.

Consider this undirected graph:

```
        0
       / \
      1   2
     / \
    3   4
```

Its adjacency lists, assuming edges are inserted in the order shown, are:

```
0: 1, 2
1: 0, 3, 4
2: 0
3: 1
4: 1
```

A stack follows LIFO (Last In, First Out):

```
PUSH(stack, v)   // Add v to the top
POP(stack)       // Remove the top vertex
```

The algorithm works as follows:

1. Push the starting vertex onto the stack.
2. Pop a vertex.
3. If it has already been visited, skip it.
4. Otherwise, mark it visited and process it.
5. Push its unvisited neighbors onto the stack.
6. Repeat until the stack is empty.

One important implementation detail: this version marks vertices as visited when they are popped, so duplicate entries may temporarily appear on the stack. We check `visited[]` after popping to avoid processing a vertex more than once.

### Recursive DFS

Recursive DFS relies on function calls instead of an explicitly managed stack.

```
RECURSIVE-DFS(G, source):

    create visited[0 ... V-1], initialized to FALSE

    DFS-VISIT(G, source, visited)


DFS-VISIT(G, u, visited):

    visited[u] = TRUE
    VISIT(u)

    for each vertex v adjacent to u:

        if visited[v] == FALSE:

            DFS-VISIT(G, v, visited)
```

How it works:

1. Mark the current vertex as visited.
2. Process the vertex.
3. Recursively explore each unvisited neighbor.
4. Return to the previous call when all neighbors have been explored.

The function call stack automatically handles backtracking.

To traverse a disconnected graph, use an outer loop:

```
DFS-ALL(G):

    create visited[0 ... V-1], initialized to FALSE

    for each vertex u in G:

        if visited[u] == FALSE:

            DFS-VISIT(G, u, visited)
```

#### 5. Recursive DFS and Backtracking

Backtracking is the process of returning to an earlier point when the current path cannot be extended through any undiscovered neighbor.

In recursive DFS, this happens automatically when a function call returns.

##### 5.1 Example

Consider:

```
        A
       / \
      B   C
     / \
    D   E
```

Assume neighbors are examined from left to right.

The traversal unfolds as follows:

```
1. Visit A
   |
   +-- Visit B
       |
       +-- Visit D
       |   |
       |   +-- D has no undiscovered neighbors
       |       Return to B
       |
       +-- Visit E
           |
           +-- E has no undiscovered neighbors
               Return to B
               Return to A
   |
   +-- Visit C
       |
       +-- C has no undiscovered neighbors
           Return to A
```

The traversal order is:

```
A -> B -> D -> E -> C
```

The backtracking sequence is:

```
D -> B -> E -> B -> A -> C -> A
```

The second sequence describes the returns between recursive calls rather than the discovery order.

##### 5.2 How recursion remembers its progress

Each recursive call retains its local execution state, including which neighbor it is currently examining.

When `dfsVisit(D)` returns, the caller `dfsVisit(B)` resumes from the point immediately after the call to `dfsVisit(D)`.

This is why recursion makes DFS concise.

##### 5.3 Recursive DFS versus iterative DFS

| Feature         | Recursive DFS               | Iterative DFS                 |
| --------------- | --------------------------- | ----------------------------- |
| Storage         | Call stack                  | Explicit stack                |
| Backtracking    | Automatic                   | Managed by the algorithm      |
| Code            | Often simpler               | More control over memory      |
| Deep graphs     | May overflow the call stack | Avoids recursion-depth limits |
| Traversal order | Depends on neighbor order   | Depends on push/pop policy    |

A subtle implementation detail: an iterative DFS that simply pushes all neighbors and marks them visited immediately may produce a different DFS tree from the recursive version. To reproduce recursive DFS precisely, the implementation must preserve the order in which neighbors are examined and the point at which each vertex finishes.

### Three-Color DFS

The three-color method tracks the progress of every vertex. It is especially useful for cycle detection, edge classification, and graph algorithms that depend on finishing times.

| Color | Meaning                                                            |
| ----- | ------------------------------------------------------------------ |
| WHITE | The vertex has not been discovered.                                |
| GRAY  | The vertex has been discovered and is still being explored.        |
| BLACK | The vertex and all its adjacent vertices have been fully explored. |

#### Pseudocode
```
DFS(graph):

    mark all vertices WHITE
    initialize all parents to NONE

    for each vertex u:
        if color[u] == WHITE:
            dfsVisit(u)


dfsVisit(u):

    color[u] = GRAY
    process(u)

    for each neighbor v of u:

        if color[v] == WHITE:
            parent[v] = u
            dfsVisit(v)

    color[u] = BLACK
```

This version traverses the entire graph, including disconnected components.

If you want to search only the vertices reachable from a source, call `dfsVisit(source)` directly after initialization rather than looping over all vertices.

```
THREE-COLOR-DFS(G):

    for each vertex u in G:

        color[u] = WHITE
        parent[u] = NIL

    time = 0

    for each vertex u in G:

        if color[u] == WHITE:

            DFS-VISIT(G, u)


DFS-VISIT(G, u):

    color[u] = GRAY

    time = time + 1
    discovery[u] = time

    VISIT(u)

    for each vertex v adjacent to u:

        if color[v] == WHITE:

            parent[v] = u
            DFS-VISIT(G, v)

        else if color[v] == GRAY:

            REPORT-BACK-EDGE(u, v)

    color[u] = BLACK

    time = time + 1
    finish[u] = time
```

#### Example of color transitions

```
WHITE  -- discover -->  GRAY  -- finish -->  BLACK
```

Consider this directed graph:

```
    0 ----> 1
    ^       |
    |       v
    +-------2
```

If DFS follows `0 → 1 → 2`, then the edge `2 → 0` points to a gray vertex. This is a back edge, indicating a directed cycle.

Important: this back-edge rule applies directly to directed graphs. For undirected graphs, you must ignore the edge back to the current vertex's parent when checking for cycles.

#### 3.2 Step 1: Initialize the graph state

Initially, all vertices are undiscovered.

```
A = WHITE
B = WHITE
C = WHITE
D = WHITE
E = WHITE
F = WHITE
```

The parent of each vertex is initially `NONE`.

```
parent[A] = NONE
parent[B] = NONE
parent[C] = NONE
parent[D] = NONE
parent[E] = NONE
parent[F] = NONE
```

#### 3.3 Step 2: Discover a vertex

When DFS visits `A`, it changes its color from white to gray.

```
A = GRAY
```

Gray means the vertex has been discovered and its exploration is currently active.

DFS then examines `A`'s neighbors.

If `B` is the first undiscovered neighbor, DFS records:

```
parent[B] = A
```

and recursively visits `B`.

#### 3.4 Step 3: Continue deeper

Suppose DFS follows the path:

```
A -> B -> D
```

The recursive calls look like this:

```
dfsVisit(A)
    dfsVisit(B)
        dfsVisit(D)
```

If `D` has no white neighbors, its call finishes:

```
D = BLACK
```

Execution returns to `B`, where DFS continues examining any remaining neighbors.

#### 3.5 Step 4: Backtrack

After all of `B`'s neighbors have been examined, `B` becomes black and the algorithm returns to `A`.

The process continues until every reachable vertex has finished.

```
WHITE -> GRAY -> BLACK
```

A vertex becomes black only after all its relevant adjacency entries have been examined.

#### 4. Visited Nodes and Three-Color States

A Boolean visited array is sufficient for basic DFS traversal. However, the three-color model gives a clearer understanding of DFS and is especially useful for cycle detection.

##### 4.1 White: undiscovered

A white vertex has not yet been visited.

```
color[v] = WHITE
```

DFS may discover it by following an edge from another vertex.

##### 4.2 Gray: discovered and active

A gray vertex has been discovered, but its recursive call has not finished.

```
color[v] = GRAY
```

The vertex is active in the current DFS call stack.

For example:

```
dfsVisit(A)
    dfsVisit(B)
        dfsVisit(D)
```

While exploring `D`, the active vertices are:

```
A = GRAY
B = GRAY
D = GRAY
```

##### 4.3 Black: finished

A black vertex has completed its exploration.

```
color[v] = BLACK
```

Once all of a vertex's neighbors have been examined, DFS marks it black and returns to its caller.

##### 4.4 A complete state walkthrough

Consider:

```
    A
   / \
  B   C
 /
D
```

Assuming DFS explores `B` before `C`:

| Event      | A   | B   | C   | D   |
| ---------- | --- | --- | --- | --- |
| Initially  | W   | W   | W   | W   |
| Discover A | G   | W   | W   | W   |
| Discover B | G   | G   | W   | W   |
| Discover D | G   | G   | W   | G   |
| Finish D   | G   | G   | W   | B   |
| Finish B   | G   | B   | W   | B   |
| Discover C | G   | B   | G   | B   |
| Finish C   | G   | B   | B   | B   |
| Finish A   | B   | B   | B   | B   |

`W`, `G`, and `B` mean white, gray, and black, respectively.

##### 4.5 Why is gray especially important?

Suppose DFS examines an edge to a gray vertex. That vertex is still active on the recursion stack.

In a directed graph, such an edge is a back edge, and it indicates a directed cycle.

An edge to a black vertex does not have the same meaning: the target may already be completely explored without creating a cycle.

This is one reason the three-color model is more informative than a single Boolean visited flag.

### Comparison

| Feature                          | Iterative DFS             | Recursive DFS             | Three-color DFS             |
| -------------------------------- | ------------------------- | ------------------------- | --------------------------- |
| Main mechanism                   | Explicit stack            | Call stack                | Recursion plus color states |
| Tracks visited vertices          | Boolean array or set      | Boolean array or set      | WHITE, GRAY, BLACK          |
| Backtracking                     | Explicit stack operations | Automatic                 | Automatic                   |
| Discovery/finish times           | Requires extra logic      | Requires extra logic      | Included                    |
| Directed cycle detection         | Additional logic required | Additional logic required | Detect gray back edges      |
| Time complexity (adjacency list) | $O(V+E)$              | $O(V+E)$              | $O(V+E)$                |
| Auxiliary space                  | $O(V)$                | $O(V)$                | $O(V)$                  |

Key takeaway: Use iterative DFS when you want explicit control over the stack, recursive DFS for a straightforward traversal, and three-color DFS when you also need to understand the state and timing of each vertex—for example, to detect directed cycles or perform topological sorting.

{/* # Depth-First Search (DFS) Algorithm */}

**Depth-First Search (DFS)** is a graph traversal algorithm that explores one path as deeply as possible before backtracking to explore other paths.

Unlike **Breadth-First Search (BFS)**, which uses a queue to explore vertices level by level, DFS uses a stack or recursion to follow one branch before returning to previously discovered vertices.

DFS is particularly useful for graph traversal, cycle detection, connected components, topological sorting, and analyzing graph structure.

## DFS Concept

Consider this undirected graph:

```
        A
       / \
      B   C
     / \   \
    D   E   F
```

Suppose we start DFS at vertex `A` and examine neighbors from left to right.

One possible traversal is:

```
A -> B -> D -> E -> C -> F
```

DFS begins at `A`, follows the branch through `B`, continues to `D`, and then backtracks when `D` has no undiscovered neighbors. It then explores `E`, returns to `A`, and explores the branch through `C`.

The exact order depends on how neighbors are ordered and whether the implementation is recursive or iterative.

### How does DFS explore a graph?

Searching a graph via Depth First Search (DFS), we keep following
edges, going deeper and deeper into the graph. When we reach
a node that has no edges to any new nodes, we go back to the
previous node and continue the process. We use a Stack to keep
track of the exploration trail, pushing a node when we explore it,
and popping a node when we need to go back. The backtracking
strategy (sec. 3.4) explores solutions this way.

Imagine exploring a maze:

1. Start at the entrance.
2. Choose an unexplored passage.
3. Continue along that passage while new passages are available.
4. When you reach a dead end, return to the previous junction.
5. Choose another unexplored passage.
6. Continue until all reachable passages have been explored.

This is the basic idea of DFS.

```
Start at A

        A
       / \
      B   C
     / \   \
    D   E   F

Explore: A -> B -> D
                       |
                    backtrack
                       |
Explore: A -> B -> E
                       |
                    backtrack
                       |
Explore: A -> C -> F
```

Backtracking is not an error or a restart. It is an essential part of the algorithm.

### DFS versus BFS

#### Depth-First Search

Follow a branch deeply before exploring another.

```
A -> B -> D -> backtrack
          -> E -> backtrack
    -> C -> F
```

- Uses a stack or recursive calls.
- Explores deeply before backtracking.
- Useful for structural analysis and cycle detection.
  
#### Breadth-First Search
Explore nearby vertices before moving farther away.

```
Level 0: A
Level 1: B, C
Level 2: D, E, F
```

- Uses a queue.
- Explores level by level.
- Finds shortest paths by edge count in unweighted graphs.

DFS does not generally find shortest paths. Its purpose is to explore systematically according to depth-first order.

### What can DFS accomplish?

DFS can help answer questions such as:

- Which vertices are reachable from a starting vertex?
- Does a graph contain a cycle?
- Which vertices belong to each connected component?
- Is a directed graph acyclic?
- What is a valid topological ordering of a directed acyclic graph?
- Which vertices are ancestors or descendants in a traversal tree?
- How is a graph structured in terms of discovery and finishing times?

Some advanced problems, such as strongly connected components and articulation points, use DFS together with additional information and algorithms.

## Stack-Based Search

The stack is one of the fundamental data structures used by DFS.

A stack follows the LIFO principle: Last In, First Out.

- `push(v)`: add vertex `v` to the top of the stack.
- `pop()`: remove the top vertex.
- `isEmpty()`: check whether the stack is empty.

The most recently added vertex is explored first, encouraging DFS to continue deeper along the current branch.

### Why does DFS use a stack?

Consider this graph:

```
        A
       / \
      B   C
     / \
    D   E
```

Suppose we start at `A` and want to explore `B` before `C`.

Initially:

```
Stack: [A]
```

Pop `A` and push its neighbors so that `B` will be popped first:

```
Stack: [C, B]    <- B is on top
```

Pop `B` and push `D` and `E`, so that `D` is explored first:

```
Stack: [C, E, D]    <- D is on top
```

Pop `D`. If it has no undiscovered neighbors:

```
Stack: [C, E]
```

The algorithm then explores `E` before returning to `C`.

This is how a stack reproduces depth-first exploration.

## Recursive DFS
Recursive DFS also uses a stack.

DFS does not require an explicitly created stack. A recursive implementation relies on the programming language's call stack.

For example:
```
        A
       / \
      B   C
     / \
    D   E
```

```
dfs(A)
    dfs(B)
        dfs(D)
        return
        dfs(E)
        return
    return
    dfs(C)
        dfs(F)
        return
    return
```

Each recursive call remembers where execution should resume after the deeper call finishes.

The call stack therefore naturally supports DFS's backtracking behavior.

## Parent Relationships and the DFS Forest

When DFS discovers a white vertex `v` from vertex `u`, it records:

```
parent[v] = u
```

These parent links form a DFS tree for the component being explored.

For the previous example:

```
        A
       / \
      B   C
     / \
    D   E
```

The parent relationships are:

```
parent[A] = NONE
parent[B] = A
parent[C] = A
parent[D] = B
parent[E] = B
```

The corresponding tree records how the traversal discovered each vertex.

### Graph edges versus DFS tree edges

A graph may contain edges that do not become parent relationships.

For example:

```
    A ----- B
    | \     |
    |  \    |
    C ----- D
```

If DFS discovers `D` through `B`, the edge from `A` to `D` may not be a tree edge.

The original graph retains all its edges, while the DFS tree contains only the edges that first discovered vertices.

### DFS tree and DFS forest

If every vertex is reachable from the starting vertex, the traversal produces one DFS tree.

If the graph is disconnected, a full traversal can produce several trees:

```
DFS forest:

    A           X
   / \         /
  B   C       Y
      |
      D
```

Each tree root has no parent. The full collection is called a DFS forest.

### Can DFS reconstruct paths?

Yes. Starting from a target, follow the parent links backward and reverse the result.

For example:

```
parent[D] = B
parent[B] = A
parent[A] = NONE
```

The path is:

```
A -> B -> D
```

However, unlike BFS, DFS does not guarantee that this path has the minimum number of edges.

## Discovery and Finishing Times

DFS can record two timestamps for each vertex:

- Discovery time $d[u]$: when DFS first discovers vertex `u`.
- Finishing time $f[u]$: when DFS has examined all relevant neighbors of `u`.

These times are useful for understanding graph structure and implementing advanced algorithms.

### Example

Consider:

```
    A
   / \
  B   C
 /
D
```

Assuming `B` is explored before `C`, one possible timestamp sequence is:

| Event      | Time |
| ---------- | ---- |
| Discover A | 1    |
| Discover B | 2    |
| Discover D | 3    |
| Finish D   | 4    |
| Finish B   | 5    |
| Discover C | 6    |
| Finish C   | 7    |
| Finish A   | 8    |

Thus:

| Vertex | Discovery $d[u]$ | Finish $f[u]$ |
| ------ | -------------------- | ----------------- |
| A      | 1                    | 8                 |
| B      | 2                    | 5                 |
| D      | 3                    | 4                 |
| C      | 6                    | 7                 |

The discovery and finishing times satisfy:

$$
d[u] < f[u]
$$

For every descendant of `u` in the DFS tree, its discovery and finishing times lie between those of `u`:

$$
d[u] < d[v] < f[v] < f[u]
$$

This is a useful property for reasoning about ancestor-descendant relationships.

### Why do timestamps matter?

Discovery and finishing times are used in:

- Directed-cycle detection.
- Topological sorting.
- Strongly connected components.
- Graph edge classification.
- Algorithms for articulation points and bridges.

For a directed acyclic graph, vertices ordered by decreasing finishing time form a valid topological ordering.

## DFS Complexity

Let:

- $V$ = number of vertices.
- $E$ = number of edges.

### Time complexity

Using an adjacency list, a complete DFS traversal takes:

$$
\boxed{O(V+E)}
$$

Why?

- Each vertex is discovered once.
- Each vertex finishes once.
- Each adjacency-list entry is examined a constant number of times.
- Each tree edge causes at most one recursive descent.

For an undirected graph, each edge typically appears in two adjacency lists. For a directed graph, each edge typically appears once.

If DFS starts at a single source and explores only reachable vertices, the more precise bound is $O(V_r+E_r)$, where $V_r$ and $E_r$ describe the reachable subgraph.

### Space complexity

DFS uses:

$$
\boxed{O(V)}
$$

auxiliary space in the worst case.

This includes:

- The visited or color array.
- The parent array.
- Optional discovery and finishing time arrays.
- The recursion stack or explicit stack.

The recursion depth can reach $V$ in a graph where DFS follows a long chain:

```
A -> B -> C -> D -> E -> ...
```

For very deep graphs, iterative DFS can avoid exhausting the programming language's call stack.

### Adjacency list versus adjacency matrix

| Graph representation | DFS time     | Explanation                                         |
| -------------------- | ------------ | --------------------------------------------------- |
| Adjacency list       | $O(V+E)$ | Examines existing edges                             |
| Adjacency matrix     | $O(V^2)$ | Scans all possible neighbors of each reached vertex |

Adjacency lists are generally a good choice for sparse graphs. An adjacency matrix may be appropriate for dense graphs or when constant-time edge-existence checks are important.

## DFS on Directed and Undirected Graphs

DFS works on both graph types, but edge directions affect what it can reach and what its traversal reveals.

### Undirected graphs

An undirected edge can be traversed in either direction.

```
A ----- B
```

Starting at `A`, DFS can discover `B`; starting at `B`, DFS can discover `A`.

DFS can find connected components by exploring every vertex reachable from a source.

For undirected graphs, cycle detection must account for the edge back to the parent. Otherwise, the ordinary edge connecting a child to its parent could be incorrectly reported as a cycle.

### 9.2 Directed graphs

A directed edge has a specific direction.

```
A ----> B ----> C
```

Starting at `A`, DFS can reach `B` and `C`.

Starting at `C`, it cannot necessarily reach `A`.

In directed graphs, DFS is especially useful for:

- Detecting directed cycles.
- Determining whether a directed acyclic graph exists.
- Producing a topological ordering.
- Supporting strongly connected component algorithms.

### 9.3 DFS on disconnected graphs

Calling DFS once explores only the source's reachable vertices.

To explore every vertex, use an outer loop:

```
for each vertex u:
    if color[u] == WHITE:
        dfsVisit(u)
```

Each time a new white vertex is found, DFS starts another tree in the forest.

The full traversal still takes $O(V+E)$ time with adjacency lists.

## 10. Cycle Detection

One important application of DFS is determining whether a graph contains a cycle.

The exact technique depends on whether the graph is directed or undirected.

### 10.1 Detecting cycles in a directed graph

Use the three-color model:

- White: undiscovered.
- Gray: currently active in the DFS call stack.
- Black: finished.

When DFS examines an edge $u \rightarrow v$:

- If `v` is white, recursively explore it.
- If `v` is gray, a directed cycle exists.
- If `v` is black, this edge alone does not establish a cycle.

Example:

```
A ----> B ----> C
        ^       |
        |_______|
```

The path reaches `C`, which has an edge back to active vertex `B`.

Because `B` is gray when the edge `C -> B` is examined, the graph contains a directed cycle:

```
B -> C -> B
```

### 10.2 Detecting cycles in an undirected graph

For an undirected graph, a vertex's parent is expected to appear among its neighbors.

Consider:

```
A ----- B
 \     /
   \ /
    C
```

If DFS traverses `A -> B -> C`, then `C` encounters `A`, which is already visited.

That indicates a cycle because `A` is not the parent of `C`.

A common rule is:

```
for each neighbor v of u:

    if not visited[v]:
        parent[v] = u
        dfs(v)

    else if v != parent[u]:
        cycle exists
```

This simplified rule assumes a conventional undirected adjacency-list representation and requires appropriate handling of self-loops and parallel edges. For multigraphs, edge IDs can be needed to distinguish the actual parent edge from another edge to the parent vertex.

## 11. Applications of DFS

DFS is particularly useful when the structure of the graph matters, rather than simply finding the closest vertices.

Cycle detection

Determine whether dependencies contain a circular relationship, such as modules that depend on each other.

Topological sorting

Order the vertices of a directed acyclic graph so that every prerequisite appears before the task that depends on it. DFS finishing times can be used to produce this ordering.

Connected components

Find groups of mutually reachable vertices in an undirected graph by running DFS from each undiscovered vertex.

Maze and state-space exploration

Follow a possible sequence of moves, then backtrack when a path cannot be extended. This is a natural fit for recursive problem solving.

Advanced graph analysis

DFS is a foundation for finding strongly connected components, bridges, articulation points, and other structural properties.

### DFS and topological sorting

For a directed acyclic graph (DAG), one DFS-based method is:

1. Run DFS.
2. Append each vertex to a list when it finishes.
3. Reverse that list.

The resulting order is a valid topological ordering, provided the graph has no directed cycle.

For example:

```
A -> C
B -> C
C -> D
```

A valid topological ordering is:

```
A, B, C, D
```

or:

```
B, A, C, D
```

Both are valid because `A` and `B` must precede `C`, and `C` must precede `D`.

## 12. Common Mistakes and Edge Cases

| Mistake                                    | Why it matters                                                 | Correct approach                                              |
| ------------------------------------------ | -------------------------------------------------------------- | ------------------------------------------------------------- |
| Forgetting visited tracking                | Cycles can cause repeated exploration or infinite recursion    | Mark vertices when discovered                                 |
| Confusing gray with black                  | An active vertex and a finished vertex have different meanings | Use three colors for algorithms that need this distinction    |
| Assuming DFS finds shortest paths          | Depth-first order does not minimize the number of edges        | Use BFS for unweighted shortest paths                         |
| Ignoring disconnected components           | A single DFS may not visit the entire graph                    | Add an outer loop over all vertices                           |
| Using recursion on a very deep graph       | The call stack can overflow                                    | Consider iterative DFS                                        |
| Assuming a unique traversal order          | Neighbor ordering changes the traversal                        | Specify neighbor ordering if deterministic output is required |
| Treating every visited neighbor as a cycle | In undirected graphs, the parent edge is expected              | Ignore the parent edge during cycle detection                 |

### Important edge cases to test

- An empty graph or invalid starting vertex.
- A single isolated vertex.
- A long chain of vertices.
- A graph with cycles.
- A disconnected graph.
- A self-loop.
- Parallel edges.
- A directed graph with a cycle.
- A directed acyclic graph.
- A graph with multiple possible DFS trees.

For cycle detection in particular, distinguish between the requirements for directed graphs and undirected graphs. The same visited check cannot be used interchangeably without considering edge direction and traversal state.

## 13. A Complete DFS Implementation in Java

The following implementation uses an adjacency list and recursive DFS. It records visited state and parent relationships, and includes a test graph in `main`.

```
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class DFSExample {

    static void dfs(
            List<List<Integer>> graph,
            int u,
            boolean[] visited,
            int[] parent) {

        // Mark the current vertex as discovered.
        visited[u] = true;
        System.out.println("Visit: " + u);

        // Explore every adjacent vertex.
        for (int v : graph.get(u)) {

            if (!visited[v]) {

                // Record how v was discovered.
                parent[v] = u;

                // Explore v before continuing with u.
                dfs(graph, v, visited, parent);
            }
        }

        // All neighbors have been examined.
        System.out.println("Finish: " + u);
    }

    public static void main(String[] args) {

        int n = 6;

        List<List<Integer>> graph = new ArrayList<>();

        for (int i = 0; i < n; i++) {
            graph.add(new ArrayList<>());
        }

        // Build an undirected graph.
        addEdge(graph, 0, 1);
        addEdge(graph, 0, 2);
        addEdge(graph, 1, 3);
        addEdge(graph, 1, 4);
        addEdge(graph, 2, 5);

        boolean[] visited = new boolean[n];
        int[] parent = new int[n];

        Arrays.fill(parent, -1);

        int source = 0;

        dfs(graph, source, visited, parent);

        System.out.println("\nParent relationships:");

        for (int v = 0; v < n; v++) {
            System.out.println(
                    "parent[" + v + "] = " + parent[v]);
        }
    }

    static void addEdge(
            List<List<Integer>> graph,
            int u,
            int v) {

        graph.get(u).add(v);
        graph.get(v).add(u);
    }
}
```

### 13.1 Test graph

```
        0
       / \
      1   2
     / \   \
    3   4   5
```

Because neighbors are examined in insertion order, DFS visits:

```
0 -> 1 -> 3 -> 4 -> 2 -> 5
```

The output includes both discovery and finishing events:

```
Visit: 0
Visit: 1
Visit: 3
Finish: 3
Visit: 4
Finish: 4
Finish: 1
Visit: 2
Visit: 5
Finish: 5
Finish: 2
Finish: 0
```

Notice that the finishing order differs from the discovery order. This is important for understanding DFS timestamps and topological sorting.

The parent relationships are:

```
parent[0] = -1
parent[1] = 0
parent[2] = 0
parent[3] = 1
parent[4] = 1
parent[5] = 2
```

The value `-1` indicates that the starting vertex has no parent.

Implementation note: This example runs DFS only from vertex `0`. To traverse every vertex in a disconnected graph, loop over all vertices and call `dfs` for each vertex that has not yet been visited. Validate the source vertex before starting the traversal in a reusable implementation.

## 14. BFS vs. DFS

Now that we have examined both algorithms, let's compare their behavior directly.

| Property                            | BFS                             | DFS                                   |
| ----------------------------------- | ------------------------------- | ------------------------------------- |
| Full name                           | Breadth-First Search            | Depth-First Search                    |
| Exploration strategy                | Level by level                  | Deep along a branch, then backtrack   |
| Main data structure                 | Queue                           | Stack or recursion                    |
| Vertex selection                    | Oldest waiting vertex           | Most recently entered vertex          |
| Visited tracking                    | Prevents duplicate discovery    | Prevents repeated exploration         |
| Parent relationships                | BFS tree                        | DFS tree                              |
| Shortest paths in unweighted graphs | Guaranteed                      | Not guaranteed                        |
| Cycle detection                     | Possible with appropriate state | Especially useful with color states   |
| Topological sorting                 | Not the usual approach          | Naturally supports a DFS-based method |
| Time with adjacency lists           | $O(V+E)$                    | $O(V+E)$                          |
| Auxiliary space                     | $O(V)$                      | $O(V)$ worst case                 |

### When should you use DFS instead of BFS?

Choose DFS when you need to:

- Explore an entire branch before exploring alternatives.
- Detect cycles using active recursion-stack information.
- Topologically sort a directed acyclic graph.
- Analyze graph structure using discovery and finishing times.
- Implement recursive backtracking.

Choose BFS when you need to:

- Find a shortest path measured in number of edges.
- Compute minimum hop counts from a source.
- Explore vertices in increasing order of distance.
- Find all vertices within a specified number of steps.

Both algorithms can determine reachability and find connected components in undirected graphs.

## 15. Final Mental Model

Think of DFS as a sequence of recursive decisions:

```
             DFS
              |
       Discover a vertex
              |
       Mark it GRAY
              |
       Examine neighbors
              |
       Undiscovered neighbor?
              |
             Yes
              |
       Record its parent
              |
       Explore it deeply
              |
       No more new neighbors
              |
       Mark vertex BLACK
              |
       Backtrack to caller
```

The key concepts fit together as follows:

- Visited state prevents repeated exploration and distinguishes active vertices from finished ones when using three colors.
- Stack or recursion drives depth-first exploration and preserves the information needed to backtrack.
- Parent relationships record the DFS tree and allow path reconstruction.
- Discovery and finishing times provide additional information for structural algorithms.
- Backtracking lets DFS explore alternative branches after finishing the current one.

The central principle is: DFS keeps exploring an available path until it cannot go any deeper, then returns to the most recent unfinished vertex and continues from there.

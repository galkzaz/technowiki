If going deep in the graph isn’t a good approach, you can try
Breadth First Search (BFS). 

Breadth-First Search (BFS) is a graph traversal algorithm that explores vertices level by level, starting from a given source vertex.

Breadth-First Search (BFS) is a graph traversal and search algorithm that explores a graph outward from a starting vertex, visiting vertices in order of their distance from the source.

Instead of following one path as far as possible, BFS explores nearby vertices first, then vertices farther away.

The main idea is simple: visit the starting vertex first, then all its immediate neighbors, then the neighbors of those vertices, and continue outward until no more reachable vertices remain.

Breadth-First Search takes a different approach from Depth-First Search when
searching a graph. Breadth-First Search systematically visits all vertices in the
graph G = (V, E) that are k edges away from the source vertex s before visiting any
vertex that is k + 1 edges away. This process repeats until no more vertices are
reachable from s. Breadth-First Search does not visit vertices in G that are not
reachable from s. The algorithm works for undirected as well as directed graphs.

For example, imagine searching for a friend in a social network:

- First, examine your direct friends.
- Next, examine friends of those friends.
- Then, examine people three connections away.
- Continue until you find the person or run out of reachable vertices.

This is the central idea behind BFS: explore the graph level by level.

**BFS uses a queue to determine which vertex to explore next**. This makes it especially useful for finding shortest paths in unweighted graphs.

## BFS Concept

Consider this undirected graph:

```
        A
       / \
      B   C
     / \   \
    D   E   F
```

Suppose we start BFS at vertex `A`.

BFS explores the graph in layers, where each layer represents vertices at the same minimum number of edges from the starting vertex.

```
Level 0:           A

Level 1:         B   C

Level 2:       D   E   F
```

The traversal order, assuming neighbors are examined from left to right, is:

```
A -> B -> C -> D -> E -> F
```

Notice that BFS visits both `B` and `C` before visiting `D`, `E`, or `F`.

This is the defining behavior of BFS: explore all vertices at distance $d$ before exploring vertices at distance $d+1$.

Here, distance means the minimum number of edges from the source.

### Why is BFS called breadth-first?

Imagine standing at `A` and exploring a network of connected locations.

- First, inspect every location one step away.
- Next, inspect every location two steps away.
- Then inspect every location three steps away.
- Continue until all reachable locations have been explored.

The search spreads outward in breadth rather than following one branch deeply.

Compare that with Depth-First Search (DFS):

- BFS — breadth first: Explores neighboring vertices before moving to more distant vertices. Uses a queue.

- DFS — depth first: Follows a branch as deeply as possible before backtracking. Uses a stack or recursion.

### What problem does BFS solve?

BFS can answer questions such as:

- Which vertices are reachable from a starting vertex?
- What is the minimum number of edges from the source to each reachable vertex?
- What is a shortest path between two vertices in an unweighted graph?
- Which vertices belong to the same connected component in an undirected graph?
- How many steps away is a particular state in a puzzle or maze?

BFS is not just a way to visit vertices. Its ordering provides useful distance information.

BFS is more than a way to visit every vertex. Its level-by-level behavior makes it useful for several problems.

| Problem                              | How BFS helps                                                            |
| ------------------------------------ | ------------------------------------------------------------------------ |
| Reachability                         | Determines which vertices can be reached from a source                   |
| Shortest path in an unweighted graph | Finds a path with the fewest edges                                       |
| Minimum number of moves              | Finds the minimum moves in a maze or board when each move has equal cost |
| Connected components                 | Finds groups of mutually reachable vertices in an undirected graph       |
| Degrees of separation                | Finds the minimum number of links between people in a network            |
| Bipartite graph checking             | Can color vertices by alternating BFS levels and detect conflicts        |

The key limitation is that ordinary BFS minimizes the number of edges, not the sum of arbitrary edge weights. If edges have different costs, Dijkstra's algorithm or another suitable shortest-path algorithm may be needed.

## 4. BFS versus DFS

BFS and Depth-First Search (DFS) are both graph traversal algorithms, but they explore graphs differently.

| Property                           | BFS                                      | DFS                                                   |
| ---------------------------------- | ---------------------------------------- | ----------------------------------------------------- |
| Exploration strategy               | Level by level                           | Follows a branch deeply, then backtracks              |
| Typical mechanism                  | Queue (FIFO)                             | Stack (LIFO) or recursion                             |
| Shortest path in unweighted graphs | Yes                                      | Not guaranteed                                        |
| Common uses                        | Minimum-edge paths, levels, reachability | Cycle detection, topological sorting, graph structure |
| Time with adjacency lists          | $O(V+E)$                             | $O(V+E)$                                          |

Both algorithms can traverse a graph, but their exploration order gives them different strengths.

## Queue-Based Search

The queue is the central data structure in BFS.

A queue follows the FIFO principle: First In, First Out.

- `enqueue(v)`: add vertex `v` to the back of the queue.
- `dequeue()`: remove the vertex at the front of the queue.
- `isEmpty()`: check whether the queue contains any vertices.

The earliest discovered vertex that is still waiting to be explored is always processed first.

### Why does BFS need a queue?

Suppose the graph is:

```
        A
       / \
      B   C
     / \   \
    D   E   F
```

Initially, the queue contains only `A`.

```
Queue: [A]
```

Remove `A` and discover `B` and `C`:

```
Queue: [B, C]
```

Remove `B` and discover `D` and `E`:

```
Queue: [C, D, E]
```

Remove `C` and discover `F`:

```
Queue: [D, E, F]
```

The queue ensures that `C` is processed before `D` and `E`, even though `D` and `E` were discovered while processing `B`.

This preserves the level-by-level exploration order.

### BFS queue walkthrough

Suppose the graph is:

```
        A
       / \
      B   C
     / \   \
    D   E   F
```

The following table shows the queue after each vertex has been processed. Assume neighbors are examined in alphabetical order.

| Step | Vertex processed | Queue afterward |
| ---- | ---------------- | --------------- |
| 0    | —                | `[A]`           |
| 1    | `A`              | `[B, C]`        |
| 2    | `B`              | `[C, D, E]`     |
| 3    | `C`              | `[D, E, F]`     |
| 4    | `D`              | `[E, F]`        |
| 5    | `E`              | `[F]`           |
| 6    | `F`              | `[]`            |

When the queue becomes empty, BFS has finished exploring every vertex reachable from `A`.

Key principle: BFS discovers vertices in nondecreasing order of their distance from the source. The FIFO queue is what makes this possible.

## When should you use BFS?

Choose BFS when the problem naturally asks about distance measured in steps or edges.

Examples:

- Find the minimum number of flights when every flight counts as one step.
- Find the fewest moves to reach a destination in a maze.
- Find all people within two connections of a user.
- Determine whether a destination is reachable from a source.
- Explore every vertex in an unweighted graph in increasing distance order.

Consider a flight network where each airport is a vertex and each direct flight is an edge. BFS can find a route with the fewest flights, assuming each flight counts equally. It does not necessarily find the cheapest or fastest itinerary.

The main takeaway is simple: BFS explores outward from a source, one distance level at a time. That behavior—not the queue implementation itself—is the defining idea of the algorithm.


## Shortest Paths in Unweighted Graphs

One of BFS's most important properties is that it finds shortest paths in unweighted graphs.

An unweighted graph treats every edge as having equal cost. Equivalently, we can consider each edge to have cost one.

The length of a path is then the number of edges it contains.

### Example

Consider this graph:

```
       A
      / \
     B   C
    /     \
   D ----- E
          /
         F
```

Suppose we want the shortest path from `A` to `F`.

One possible path is:

```
A -> C -> E -> F
```

It has three edges.

A different route, if one exists, might have more edges. BFS discovers vertices in increasing order of distance, so the first discovery of `F` gives a path with the minimum number of edges.

### How distances are calculated

Initialize the source distance to zero:

```
distance[A] = 0
```

For every newly discovered neighbor `v` of a vertex `u`:

```
distance[v] = distance[u] + 1
```

For example:

```
distance[A] = 0
distance[B] = 1
distance[C] = 1
distance[D] = 2
distance[E] = 2
distance[F] = 3
```

The distance array describes the minimum number of edges from the source to every reachable vertex.

For unreachable vertices, the distance remains infinity (or a sentinel value such as `-1`, depending on the implementation).

### Reconstructing a shortest path

Consider this graph:

```
       A
      / \
     B   C
    /     \
   D ----- E
          /
         F
```         
Suppose the target is `F`.

Follow the parent links backward:

```
parent[F] = E
parent[E] = C
parent[C] = A
```

This gives:

```
F -> E -> C -> A
```

Reverse it:

```
A -> C -> E -> F
```

That is a shortest path.

### Why does BFS guarantee a shortest path?

The guarantee follows from the order in which BFS explores vertices.

1. The source has distance zero.
2. All vertices one edge away are discovered before vertices two edges away are processed.
3. All vertices at distance two are discovered before vertices at distance three are processed.
4. This continues for each successive level.

Therefore, when a vertex is first discovered, its distance is the minimum number of edges needed to reach it.

This guarantee depends on the graph being unweighted, or every edge having the same cost. For arbitrary edge weights, BFS does not generally find a minimum-cost path.

### Can BFS find all shortest paths?

Yes, with a small modification.

Instead of storing only one parent per vertex, store a collection of parents that achieve the same minimum distance:

```
if v is undiscovered:
    distance[v] = distance[u] + 1
    parents[v] = [u]
    enqueue(v)

else if distance[v] == distance[u] + 1:
    add u to parents[v]
```

This records all predecessor vertices that lead to a shortest path. The number of shortest paths can be very large, so reconstructing every path may require substantial time and memory.

## BFS Complexity

BFS complexity depends on the graph representation and the number of vertices and edges.

Let:

- $V$ = number of vertices.
- $E$ = number of edges.

### Time complexity

With an adjacency list, BFS takes:

$$
\boxed{O(V+E)}
$$

Why?

- Initializing the visited, parent, and distance arrays takes $O(V)$.
- Each reachable vertex is enqueued and dequeued at most once.
- Each adjacency-list entry is examined at most once.

For an undirected graph, each edge normally appears in two adjacency lists. For a directed graph, each edge normally appears once.

Thus, the total work is proportional to the number of vertices plus the number of edges.

For a search starting from a single source, a more precise bound is $O(V_r+E_r)$, where $V_r$ and $E_r$ describe the reachable portion of the graph.

### Space complexity

The auxiliary space is:

$$
\boxed{O(V)}
$$

This includes:

- The visited array.
- The parent array.
- The distance array, if used.
- The queue.

Each vertex can enter the queue only once in a standard BFS implementation.

### Adjacency list versus adjacency matrix

| Representation   | BFS time     | Why                                                 |
| ---------------- | ------------ | --------------------------------------------------- |
| Adjacency list   | $O(V+E)$ | Examines existing edges                             |
| Adjacency matrix | $O(V^2)$ | Scans all possible neighbors of each reached vertex |

For sparse graphs, adjacency lists are usually more efficient. For dense graphs, an adjacency matrix may be reasonable.

## BFS on Directed and Undirected Graphs

BFS works with both directed and undirected graphs. The main difference is which edges can be followed.

### Undirected graph

```
A ----- B
```

If `A` is connected to `B`, traversal can move in either direction.

Starting at `A`, BFS can discover `B`. Starting at `B`, it can discover `A`.

### Directed graph

```
A ----> B
```

Starting at `A`, BFS can reach `B`.

Starting at `B`, BFS cannot necessarily reach `A`.

BFS follows outgoing edges only. This is important when analyzing dependency graphs, directed networks, and state transitions.

### BFS and connected components

For an undirected graph, BFS can identify all vertices in the same connected component as the source.

To find every connected component:

```
for each vertex v:
    if not visited[v]:
        BFS(v)
        componentCount++
```

The same approach does not directly find strongly connected components in a directed graph. That problem requires additional algorithms, such as Kosaraju's or Tarjan's algorithm.

## Applications of BFS

BFS is useful whenever the order of exploration by distance or number of steps matters.

- Shortest routes

Find the minimum number of connections between two locations, such as the fewest flights when every flight connection counts equally.

- Social networks

Find people within one, two, or three connection steps of a user.

- Maze solving

Model each open cell as a vertex and each legal move as an edge. BFS finds a shortest route when every move has equal cost.

- Network reachability

Discover reachable machines, services, or network nodes and compute their minimum hop counts.

- Puzzle solving

Explore states such as board configurations in a puzzle. BFS finds the solution requiring the fewest moves when all moves have equal cost.

Other uses include finding vertices within a distance limit, checking whether a graph is bipartite, and calculating shortest distances from a source to every reachable vertex.

## Common Mistakes and Edge Cases

### Mistake 1: Using BFS for arbitrary weighted shortest paths

Consider:

```
A ----(10)---- B
 \             /
  (1)        (1)
    \       /
        C
```

The direct path from `A` to `B` costs 10, while the path through `C` costs 2.

BFS optimizes the number of edges, not the total weight. It may choose the one-edge route even though it is more expensive.

Use Dijkstra's algorithm for nonnegative edge weights, or Bellman–Ford when negative edge weights are allowed under its assumptions.

### Mistake 2: Forgetting to mark vertices as discovered

In cyclic graphs, vertices may repeatedly enter the queue. Mark each vertex when it is discovered.

### Mistake 3: Confusing discovery order with processing order

A vertex can be discovered and added to the queue long before it is processed.

```
Queue: [B, C, D]

Discovered: B, C, D
Processed:  A
```

Discovery means the algorithm knows about the vertex. Processing means the algorithm has removed it from the queue and examined its neighbors.

### Mistake 4: Assuming the traversal order is unique

Neighbor ordering affects the order among vertices at the same distance.

For example:

```
    A
   / \
  B   C
```

Both of these are valid BFS orders:

```
A -> B -> C
A -> C -> B
```

Both preserve BFS's shortest-path guarantee.

### Edge cases to test

- Empty graph or invalid source vertex.
- One isolated vertex.
- A graph containing cycles.
- A graph with parallel edges.
- A graph containing self-loops.
- A disconnected graph.
- A source equal to the target.
- An unreachable target.
- A graph with several shortest paths of equal length.

For production implementations, also validate vertex IDs and handle memory allocation or collection-size constraints appropriately.


## Summary

The entire BFS algorithm can be understood through five rules:

1. Start: Mark the source as discovered and enqueue it.
2. Select: Remove the oldest vertex from the queue.
3. Explore: Examine each of its neighbors.
4. Discover: For each undiscovered neighbor, record its parent and distance, mark it visited, and enqueue it.
5. Finish: Continue until the queue is empty or the required target has been reached.

```
             BFS
              |
       Start at source
              |
       Mark as visited
              |
       Add to queue
              |
       Queue empty? ------ Yes ---> Finish
              |
              No
              |
       Remove front vertex
              |
       Examine neighbors
              |
       Unvisited neighbor?
              |
       Mark + record parent
       + compute distance
              |
       Add to queue
              |
           Repeat
```

The essential connection between BFS's concepts is:

- The queue determines the exploration order.
- The visited set prevents repeated discovery.
- The parent array records the discovery tree.
- The distance array records minimum edge counts.
- The adjacency representation determines how neighbors are examined and affects complexity.

Together, these make BFS a fundamental algorithm for graph traversal, reachability, and shortest paths in unweighted graphs.

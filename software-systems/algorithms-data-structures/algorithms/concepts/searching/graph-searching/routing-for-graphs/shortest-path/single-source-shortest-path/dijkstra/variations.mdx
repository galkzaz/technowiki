## Finding the Most Reliable Path

an interesting application of Dijkstra's algorithm: finding the path with the highest probability of successfully delivering a message through a network.

This is slightly different from the usual shortest-path problem.

Instead of minimizing the total distance or cost, we want to maximize the probability that the entire path succeeds.

We may seek the most reliable path to send a message from one point to another
through a network where we know the probability that any leg of a transmission
delivers the message correctly. The probability of any path (i.e., a sequence of legs)
delivering a message correctly is the product of all the probabilities along the path.
Using the same technique that makes multiplication possible on a slide rule, we can
replace the probability on each edge with the negative value of the logarithm of the
probability. The shortest path in this new graph corresponds to the most reliable
path in the original graph.

### 1. Understanding the problem

Imagine sending a message through a network.

Each communication link has a probability of successfully delivering the message.

For example:

```
       0.9           0.8
  A ----------> B ----------> D
   \
    \ 0.7
     \
      v
       C -------------------> D
                0.95
```

There are two possible paths from A to D:

Path 1:

```
A → B → D

Probability = 0.9 × 0.8
            = 0.72
```

Path 2:

```
A → C → D

Probability = 0.7 × 0.95
            = 0.665
```

Therefore, Path 1 is more reliable because:

\\[ 0.72 > 0.665 \\]

Our objective is to find the path with the maximum product of edge probabilities.

### 2. Why can't we directly use Dijkstra's algorithm?

The traditional Dijkstra algorithm minimizes the sum of edge weights.

For example:

\\[ \text{Path cost}=w_1+w_2+\cdots+w_k \\]

But in our reliability problem, the path probability is calculated by multiplication:

\\[ P(\text{path})=p_1\times p_2\times\cdots\times p_k \\]

Dijkstra's algorithm is designed to minimize additive costs, not maximize multiplicative probabilities.

We need to transform the problem.

### 3. Transform multiplication into addition using logarithms

The key mathematical property is:

\\[ \log(a\times b)=\log(a)+\log(b) \\]

This means we can convert multiplication into addition.

For each edge, instead of using its original probability \\(p\\), we assign a new weight:

\\[ \boxed{w=-\log(p)} \\]

Why use the negative logarithm?

Because probabilities are between 0 and 1:

\\[ 0 < p \leq 1 \\]

Therefore:

\\[ \log(p)\leq 0 \\]

And consequently:

\\[ -\log(p)\geq 0 \\]

This is important because Dijkstra's algorithm requires nonnegative edge weights.

**The transformation**

Original graph: maximize the product of probabilities.

\\[ \max \prod\_{i=1}^{k}p_i \\]

Transformed graph: minimize the sum of negative logarithms.

\\[ \min \sum\_{i=1}^{k}-\log(p_i) \\]

Equivalent optimization problems

### 4. Practical example

Let's transform the previous graph.

Original edge probabilities:

| Edge  | Probability |
| ----- | ----------- |
| A → B | 0.9         |
| B → D | 0.8         |
| A → C | 0.7         |
| C → D | 0.95        |

We will use the natural logarithm, \\(\ln\\), for the transformation.

\\[ w=-\ln(p) \\]

Calculate the new edge weights:

| Edge  | Probability \\(p\\) | Transformed weight \\(-\ln(p)\\) |
| ----- | ------------------- | -------------------------------- |
| A → B | 0.9                 | 0.10536                          |
| B → D | 0.8                 | 0.22314                          |
| A → C | 0.7                 | 0.35667                          |
| C → D | 0.95                | 0.05129                          |

The transformed graph becomes:

```
       0.10536        0.22314
  A ------------> B ------------> D
   \
    \ 0.35667
     \
      v
       C -----------------------> D
                 0.05129
```

Now we can apply ordinary Dijkstra's algorithm because all transformed weights are nonnegative.

### 5. Step-by-step comparison of the paths

Path 1: A → B → D

Original probability:

\\[ P_1=0.9\times0.8=0.72 \\]

Transformed cost:

\\[ W_1=-\ln(0.9)-\ln(0.8) \\]

\\[ W_1=0.10536+0.22314=0.32850 \\]

Path 2: A → C → D

Original probability:

\\[ P_2=0.7\times0.95=0.665 \\]

Transformed cost:

\\[ W_2=-\ln(0.7)-\ln(0.95) \\]

\\[ W_2=0.35667+0.05129=0.40796 \\]

Compare the results:

| Path      | Original reliability | Transformed cost |
| --------- | -------------------- | ---------------- |
| A → B → D | 0.72                 | 0.32850          |
| A → C → D | 0.665                | 0.40796          |

The path with the highest reliability has the lowest transformed cost.

Therefore, Dijkstra selects:

Most reliable path

\\[ \boxed{A\rightarrow B\rightarrow D} \\]

Its reliability is 72%.

### 6. Why does this transformation work mathematically?

Suppose a path contains \\(k\\) edges, with probabilities:

\\[ p_1,p_2,\ldots,p_k \\]

The original path reliability is:

\\[ P=\prod\_{i=1}^{k}p_i \\]

Our objective is:

\\[ \max P \\]

Apply the negative logarithm:

\\[ -\ln(P)=-\ln\left(\prod\_{i=1}^{k}p_i\right) \\]

Using the logarithm multiplication property:

\\[ -\ln(P)=\sum\_{i=1}^{k}-\ln(p_i) \\]

Since the negative logarithm is a strictly decreasing function, maximizing \\(P\\) is equivalent to minimizing \\(-\ln(P)\\).

Thus:

\\[ \boxed{ \max \prod\_{i=1}^{k}p_i \quad\Longleftrightarrow\quad \min \sum\_{i=1}^{k}-\ln(p_i) } \\]

This is exactly the additive optimization problem solved by Dijkstra's algorithm.

### 7. Algorithm implementation approach

You do not need to create a completely new shortest-path algorithm.

You can reuse any standard Dijkstra implementation:

1. Read the graph and its edge probabilities.
2. Transform each probability into a weight using `-Math.log(p)` in Java.
3. Run Dijkstra on the transformed graph.
4. Reconstruct the path using the predecessor array.
5. Convert the transformed shortest distance back into a probability.

The final probability is:

\\[ \boxed{P=e^{-\text{dist}[v]}} \\]

For example, if the transformed shortest distance is 0.32850:

\\[ P=e^{-0.32850}\approx0.72 \\]

### 8. Important edge cases

| Probability | Transformed weight | Meaning                            |
| ----------- | ------------------ | ---------------------------------- |
| 1.0         | 0                  | Completely reliable edge           |
| 0.9         | 0.10536            | Highly reliable                    |
| 0.5         | 0.69315            | 50% success probability            |
| 0.1         | 2.30259            | Low reliability                    |
| 0           | \\(+\infty\\)      | Impossible successful transmission |

A probability of zero requires special handling because \\(\log(0)\\) is undefined. Such an edge can be treated as unavailable for finding a positive-probability path.

Also, the multiplication model assumes that the edge-success events are independent (or that the probabilities are conditional probabilities correctly accounting for previous events).

### 9. Summary

| Traditional Dijkstra     | Reliability variation                               |
| ------------------------ | --------------------------------------------------- |
| Minimize path cost       | Maximize path reliability                           |
| Edge weight = cost       | Edge weight = probability                           |
| Add edge weights         | Multiply probabilities                              |
| `dist[v]` = minimum cost | `dist[v]` = minimum transformed cost                |
| Relaxation uses addition | Transform probabilities, then use ordinary addition |
| Select minimum distance  | Select minimum transformed distance                 |

The key insight: Dijkstra's algorithm can solve more than ordinary distance problems. By transforming a multiplicative optimization problem into an additive one using logarithms, we can reuse the same algorithm to find the most reliable path through a network.

### Implementation

### Java

The implementation below uses:

- An adjacency list to represent the directed graph.
- Java's `PriorityQueue` as a min-priority queue.
- Lazy deletion instead of decrease-key.
- A predecessor array to reconstruct the most reliable path.
- `double` for probabilities and transformed distances.


```Java

import java.util.*;

public class MostReliablePath {

    private static final double INF = Double.POSITIVE_INFINITY;

    // Represents a directed edge.
    // probability is the probability of successful transmission.
    static class Edge {
        int destination;
        double probability;
        double weight;

        Edge(int destination, double probability) {
            this.destination = destination;
            this.probability = probability;

            // Transform probability into a nonnegative weight.
            this.weight = -Math.log(probability);
        }
    }

    // Represents a vertex and its current distance.
    static class VertexDistance {
        int vertex;
        double distance;

        VertexDistance(int vertex, double distance) {
            this.vertex = vertex;
            this.distance = distance;
        }
    }

    // Stores the result of the algorithm.
    static class Result {
        double[] distance;
        int[] predecessor;

        Result(double[] distance, int[] predecessor) {
            this.distance = distance;
            this.predecessor = predecessor;
        }
    }

    // Directed weighted graph.
    static class Graph {
        int V;
        List<Edge>[] adjacencyList;

        @SuppressWarnings("unchecked")
        Graph(int V) {
            this.V = V;
            adjacencyList = new ArrayList[V];

            for (int i = 0; i < V; i++) {
                adjacencyList[i] = new ArrayList<>();
            }
        }

        void addEdge(int source, int destination, double probability) {

            if (source < 0 || source >= V ||
                destination < 0 || destination >= V) {
                throw new IllegalArgumentException("Invalid vertex");
            }

            if (Double.isNaN(probability) ||
                probability <= 0.0 || probability > 1.0) {
                throw new IllegalArgumentException(
                    "Probability must be in the range (0, 1]"
                );
            }

            adjacencyList[source].add(
                new Edge(destination, probability)
            );
        }
    }

    // Dijkstra's algorithm on transformed edge weights.
    static Result dijkstra(Graph graph, int source) {

        int V = graph.V;

        double[] distance = new double[V];
        int[] predecessor = new int[V];
        boolean[] visited = new boolean[V];

        Arrays.fill(distance, INF);
        Arrays.fill(predecessor, -1);

        distance[source] = 0.0;

        PriorityQueue<VertexDistance> pq =
            new PriorityQueue<>(
                Comparator.comparingDouble(v -> v.distance)
            );

        pq.offer(new VertexDistance(source, 0.0));

        while (!pq.isEmpty()) {

            VertexDistance current = pq.poll();

            int u = current.vertex;

            // Skip outdated priority-queue entries.
            if (current.distance != distance[u]) {
                continue;
            }

            if (visited[u]) {
                continue;
            }

            visited[u] = true;

            // Relax outgoing edges.
            for (Edge edge : graph.adjacencyList[u]) {

                int v = edge.destination;

                if (visited[v]) {
                    continue;
                }

                double candidate =
                    distance[u] + edge.weight;

                if (candidate < distance[v]) {

                    distance[v] = candidate;
                    predecessor[v] = u;

                    pq.offer(
                        new VertexDistance(v, candidate)
                    );
                }
            }
        }

        return new Result(distance, predecessor);
    }

    // Reconstruct the path from source to destination.
    static List<Integer> getPath(
            int destination,
            int[] predecessor) {

        List<Integer> path = new ArrayList<>();

        int current = destination;

        while (current != -1) {
            path.add(current);
            current = predecessor[current];
        }

        Collections.reverse(path);

        return path;
    }

    // Convert transformed distance back into probability.
    static double getReliability(double transformedDistance) {

        if (transformedDistance == INF) {
            return 0.0;
        }

        return Math.exp(-transformedDistance);
    }

    // Display the most reliable paths from the source.
    static void printResults(
            int source,
            Result result) {

        System.out.println("Source vertex: " + source);
        System.out.println();

        System.out.printf(
            "%-12s %-20s %-20s%n",
            "Destination",
            "Reliability",
            "Path"
        );

        for (int v = 0; v < result.distance.length; v++) {

            if (result.distance[v] == INF) {
                System.out.printf(
                    "%-12d %-20s %s%n",
                    v,
                    "0.0",
                    "Unreachable"
                );
                continue;
            }

            double reliability =
                getReliability(result.distance[v]);

            List<Integer> path =
                getPath(v, result.predecessor);

            System.out.printf(
                "%-12d %-20.5f %s%n",
                v,
                reliability,
                path
            );
        }
    }

    // Main test function.
    public static void main(String[] args) {

        /*
         * Example graph:
         *
         * A --0.9--> B --0.8--> D
         *  \
         *   \ 0.7
         *    \
         *     v
         *      C --0.95--> D
         */

        int A = 0;
        int B = 1;
        int C = 2;
        int D = 3;

        Graph graph = new Graph(4);

        graph.addEdge(A, B, 0.9);
        graph.addEdge(B, D, 0.8);

        graph.addEdge(A, C, 0.7);
        graph.addEdge(C, D, 0.95);

        // Find the most reliable paths starting from A.
        Result result = dijkstra(graph, A);

        printResults(A, result);

        // Explicitly verify the two paths to D.
        System.out.println("\nComparison of paths to D:");

        double path1 = 0.9 * 0.8;
        double path2 = 0.7 * 0.95;

        System.out.printf(
            "A -> B -> D: %.5f%n", path1
        );

        System.out.printf(
            "A -> C -> D: %.5f%n", path2
        );

        System.out.printf(
            "Most reliable path: %s%n",
            getPath(D, result.predecessor)
        );

        System.out.printf(
            "Maximum reliability: %.5f%n",
            getReliability(result.distance[D])
        );
    }
}

```

#### 3. Understanding the important code sections

A. Transforming probabilities

```
this.weight = -Math.log(probability);
```

For example:

```
Probability = 0.9

Transformed weight = -ln(0.9)
                   = 0.10536
```

We use `Math.log()` because it calculates the natural logarithm.

B. Relaxation

```
double candidate = distance[u] + edge.weight;

if (candidate < distance[v]) {
    distance[v] = candidate;
    predecessor[v] = u;
}
```

Notice that the relaxation operation is exactly the same as ordinary Dijkstra. We only changed the edge weights before running the algorithm.

C. Recovering the original probability

```
return Math.exp(-transformedDistance);
```

Because:

\\[ w=-\ln(P) \\]

We recover the original probability using:

\\[ P=e^{-w} \\]

For the path A → B → D:

\\[ P=e^{-0.32850}\approx0.72 \\]

D. Reconstructing the path

The predecessor array for the example is:

```
pred[] = [-1, 0, 0, 1]
```

For destination D (vertex 3):

```
3 ← 1 ← 0
```

Reverse the sequence:

```
0 → 1 → 3
```

#### 4. Complexity analysis

Let \\(V\\) be the number of vertices and \\(E\\) the number of directed edges.

| Operation                    | Complexity       |
| ---------------------------- | ---------------- |
| Graph initialization         | O(V)             |
| Transform edge probabilities | O(E)             |
| Priority queue operations    | O((V + E) log E) |
| Path reconstruction          | O(V) per path    |

Overall:

\\[ \boxed{O(V+E\log E)} \\]

For a simple graph, this is commonly expressed as:

\\[ \boxed{O((V+E)\log V)} \\]

Space complexity:

\\[ \boxed{O(V+E)} \\]

#### 5. Important implementation notes

- This implementation assumes independent edge-success events, or probabilities that correctly represent conditional success.
- Probabilities must be in the range \\(0 < p \leq 1\\).
- A probability of zero is treated as an unavailable edge because its negative logarithm is infinite.
- A probability of one produces a weight of zero, which is valid for Dijkstra.
- The graph is directed. If communication is possible in both directions, add both directed edges.
- For applications requiring high numerical precision across very long paths, retaining transformed distances is preferable to repeatedly multiplying probabilities.

Key takeaway: We did not implement a new shortest-path algorithm. We transformed a maximum-product path problem into a minimum-sum path problem and reused the standard Dijkstra implementation.

## Common Implementations of Dijkstra’s Algorithm

Dijkstra's algorithm has several common implementations. They all use the same greedy strategy, but differ in graph representation and how they select the unvisited vertex with the smallest tentative distance.

Dijkstra’s algorithm is commonly implemented using a min-priority queue (binary heap). However, for dense graphs, a simpler implementation that uses an adjacency matrix and linear search to find the next vertex can be more efficient.

### 1. Main implementations

| ## | Implementation                 | Graph representation     | Minimum selection mechanism               | Time complexity        |
| - | ------------------------------ | ------------------------ | ----------------------------------------- | ---------------------- |
| 1 | Linear scan                    | Adjacency matrix         | Linear search                             | \\(O(V^2)\\)           |
| 2 | Linear scan                    | Adjacency list           | Linear search                             | \\(O(V^2+E)\\)         |
| 3 | Binary heap with decrease-key  | Adjacency list           | Indexed binary min-heap                   | \\(O((V+E)\log V)\\)   |
| 4 | Binary heap with lazy deletion | Adjacency list           | Standard binary min-heap / priority queue | \\(O((V+E)\log V)\\)\* |
| 5 | Fibonacci heap                 | Adjacency list           | Fibonacci min-heap                        | \\(O(E+V\log V)\\)     |
| 6 | Array-based priority queue     | Adjacency matrix or list | Unsorted array                            | \\(O(V^2+E)\\)         |

\*For lazy deletion, a more precise bound is \\(O((V+E)\log E)\\); for ordinary simple graphs, this is commonly expressed as \\(O((V+E)\log V)\\).

### 2. How they differ

#### 1. Linear scan + adjacency matrix

- Stores the graph in a \\(V \times V\\) matrix.
- Scans all vertices to find the minimum tentative distance.
- Scans a complete matrix row to examine neighbors.
- Best suited to: dense graphs and relatively small graphs.

\\[ O(V^2) \\]

#### 2. Linear scan + adjacency list

- Stores only existing edges in adjacency lists.
- Still scans all vertices to find the minimum tentative distance.
- Examines only actual outgoing edges.
- Best suited to: simple implementations where a heap is unnecessary.

\\[ O(V^2+E) \\]

#### 3. Indexed binary min-heap + decrease-key

- Uses an adjacency list.
- Maintains one heap entry per discovered, unfinalized vertex.
- Uses a `position[]` array to locate vertices inside the heap.
- Updates an existing priority using `decreaseKey()`.
- Best suited to: sparse graphs and implementations requiring explicit heap control.

\\[ O((V+E)\log V) \\]

#### 4. Binary heap + lazy deletion

- Uses an adjacency list and a standard priority queue.
- When a shorter path is found, inserts a new entry instead of updating an existing one.
- Old entries remain in the heap and are skipped when extracted.
- Best suited to: practical implementations using built-in priority queues, such as Java's `PriorityQueue`.

\\[ O((V+E)\log V) \\]

#### 5. Fibonacci heap

- Uses an adjacency list.
- Supports very efficient amortized decrease-key operations.
- Extract-min is more expensive than decrease-key, but the overall theoretical complexity is improved.
- Best suited to: theoretical analysis and specialized applications with many decrease-key operations.

\\[ O(E+V\log V) \\]

#### 6. Unsorted array as a priority queue

- Stores candidate vertices in an unsorted array.
- Finds the minimum by scanning the array.
- Priority updates are direct array updates.
- Best suited to: simple implementations; asymptotically similar to linear scan.

\\[ O(V^2+E) \\]

## Understanding the Dijkstra Invariant: Sets S and V − S
{/*
This paragraph describes an important concept behind Dijkstra's algorithm: how the algorithm progressively determines which shortest-path distances are guaranteed to be correct. */}

The key idea is that Dijkstra divides the graph's vertices into two conceptual sets:

- `S`: Vertices whose shortest distances from the source have been finalized.
- `V` − S: Vertices whose shortest distances have not yet been finalized.

Let's break this down using our graph.

### Understanding the two sets

As Dijkstra’s Algorithm executes, `dist[v]` represents the maximum length of the
shortest path found from the source `s` to `v` using only vertices visited within the set `S`.

Suppose we have:

$$
V = \\{0,1,2,3,4,5\\}
$$

We start from source vertex 0.

Initially, no vertex has been finalized:

$$
S = \varnothing
$$

Therefore:

$$
V-S = \\{0,1,2,3,4,5\\}
$$

As Dijkstra executes, vertices move from `V-S` into `S`.

For example:

```
Initially:

S   = { }

V-S = {0, 1, 2, 3, 4, 5}
```

After processing vertex 0:

```
S   = {0}

V-S = {1, 2, 3, 4, 5}
```

After processing vertex 1:

```
S   = {0, 1}

V-S = {2, 3, 4, 5}
```

After processing vertex 2:

```
S   = {0, 1, 2}

V-S = {3, 4, 5}
```

This continues until all reachable vertices have been finalized.

## 2. What does `dist[v]` represent?

For each v ∈ S, dist[v] is correct.

This is the most important property.

It means:

- If a vertex belongs to `S`, its shortest distance from the source is known and will never need to change.
- If a vertex belongs to `V-S`, its distance is still tentative. A shorter path might be discovered later.

Let's distinguish them.

| Vertex category    | Meaning of `dist[v]`                         |
| ------------------ | -------------------------------------------- |
| $v \in S$      | Final shortest distance from source          |
| $v \in V-S$    | Best distance discovered so far; may improve |
| Unreachable vertex | Distance remains infinity                    |

### Example: Vertex 3

Initially, vertex 3 has a direct path from vertex 0:

```
0 --------18--------> 3
```

Therefore:

```
dist[3] = 18
```

At this point, 18 is only a tentative distance.

Later, Dijkstra processes vertex 2 and discovers:

```
0 ----8----> 2 ----9----> 3
```

The new distance is:

$$
8+9=17
$$

Since:

$$
17<18
$$

We update:

```
dist[3] = 17
```

This demonstrates why we cannot consider a vertex's distance final before it is extracted as the minimum from the priority queue.

### What does the paragraph mean by "using only vertices visited within S"?

This describes the mathematical invariant maintained by Dijkstra.

For a vertex $v$ that has not yet been finalized, `dist[v]` represents the minimum path length discovered so far among paths whose intermediate vertices have already been finalized in $S$.

More formally:

$$
dist[v] = \min\_{\substack{P:s\leadsto v\\\ \text{internal vertices of }P\in S}} w(P)
$$

Here:

- $P$ is a path from source $s$ to vertex $v$.
- $w(P)$ is the sum of the edge weights along that path.
- Internal vertices are the vertices between the source and destination.

For example, after processing vertex 0:

```
S = {0}
```

We know these paths:

```
0 → 1 = 6
0 → 2 = 8
0 → 3 = 18
```

But we haven't yet processed vertices 1, 2, 3, 4, or 5.

Their distances are tentative.

Once vertex 2 enters `S`, we can use it as an intermediate vertex to discover a better path to vertex 3:

```
0 → 2 → 3 = 8 + 9 = 17
```

The distance improves from 18 to 17.

### Complete walkthrough of S and V − S

Let's connect the sets to our actual Dijkstra execution.

Source vertex: 0

| Iteration | Extracted vertex | S (finalized)   | V − S (remaining) |
| --------- | ---------------- | --------------- | ----------------- |
| Initial   | —                | `{}`            | `{0,1,2,3,4,5}`   |
| 1         | 0                | `{0}`           | `{1,2,3,4,5}`     |
| 2         | 1                | `{0,1}`         | `{2,3,4,5}`       |
| 3         | 2                | `{0,1,2}`       | `{3,4,5}`         |
| 4         | 4                | `{0,1,2,4}`     | `{3,5}`           |
| 5         | 3                | `{0,1,2,3,4}`   | `{5}`             |
| 6         | 5                | `{0,1,2,3,4,5}` | `{}`              |

Notice that vertices 3 and 4 both have distance 17. We chose vertex 4 first, but vertex 3 could have been chosen first as well.

The final result is unaffected.

### Why doesn't our Java implementation explicitly maintain S?

Dijkstra's Algorithm does not need to create and maintain the set S.

This means we don't necessarily need a separate mathematical set or collection.

In our Version 3 Java implementation, we use:

```
boolean[] visited;
```

This array represents membership in `S`.

For example:

```
result.visited[u] = true;
```

When we extract the minimum-distance vertex, we mark it as visited.

Our arrays effectively represent:

```
visited[v] == true  → v belongs to S

visited[v] == false → v has not been finalized
```

We also use:

```
IndexedMinHeap heap;
```

The heap manages vertices waiting to be processed.

There is one implementation detail worth noting: our Version 3 inserts only discovered vertices into the heap. Therefore, an unreachable vertex never enters the heap and remains unvisited. In the classical pseudocode from your previous question, all vertices are initially inserted, including those with infinite distances.

Both approaches are valid.

### When does Dijkstra terminate?

Dijkstra's Algorithm terminates when all vertices are either visited or are shown to not be reachable from the source vertex s.

There are two possible situations.

Situation A: All vertices are reachable.

Every vertex eventually gets extracted from the priority queue and added to `S`.

```
S   = {0, 1, 2, 3, 4, 5}
V-S = {}
```

Situation B: Some vertices are unreachable.

Consider this graph:

```
    0 ----4----> 1

    2 ----3----> 3
```

Starting from vertex 0:

```
S = {0, 1}

V-S = {2, 3}
```

Vertices 2 and 3 cannot be reached from 0.

In our Version 3 implementation, the priority queue becomes empty after processing 0 and 1. We terminate without ever inserting 2 or 3.

In the all-vertices-initialized approach, the remaining vertices have infinite distances. We can stop when the minimum extracted distance is infinity.

```
int u = heap.extractMin();

if (result.distance[u] == INF) {
    break;
}
```

This avoids unnecessary processing.

### Important correction: "maximum length" versus "minimum length"

For an unfinalized vertex, `dist[v]` represents the minimum length among the paths discovered so far, subject to the finalized-vertex constraint.

In other words, it is the best-known distance, not the maximum distance.

### Summary of the invariant

| Concept                        | Explanation                                                                   |
| ------------------------------ | ----------------------------------------------------------------------------- |
| $V$                        | All vertices in the graph                                                     |
| $S$                        | Vertices whose shortest distances are finalized                               |
| $V-S$                      | Vertices whose shortest distances are not finalized                           |
| `dist[v]` when $v \in S$   | Guaranteed shortest distance                                                  |
| `dist[v]` when $v \in V-S$ | Tentative shortest distance                                                   |
| `visited[v]`                   | Indicates whether vertex belongs to S                                         |
| Priority queue                 | Selects the unfinalized vertex with the smallest tentative distance           |
| Termination                    | All reachable vertices are finalized; unreachable vertices remain at infinity |

The central idea to remember:

Dijkstra progressively moves vertices from `V-S` into `S`. Each time it extracts the vertex with the smallest tentative distance, that distance becomes final (provided all edge weights are nonnegative). This is the greedy property that makes Dijkstra's algorithm correct.

## Overview

**Shortest Path Algorithms** are a family of graph algorithms used to find the most efficient path between vertices in a graph.

The goal is to determine a path that minimizes some measure of cost, such as:

- Distance between locations.
- Travel time between cities.
- Network latency between computers.
- Financial cost of transportation.
- Number of connections or transitions.

Finding the shortest path between nodes is the most famous graph
problem. GPS navigation systems will search a graph of streets and
crossroads to compute your itinerary. Some even use traffic data
to increase the weight of edges representing jammed streets.

These algorithms operate on graphs, where vertices represent entities and edges represent connections between them.

When edges have weights, the shortest path is generally the path with the minimum total edge weight, not necessarily the path containing the fewest edges.

For example, consider this weighted graph:

```
              4
         A -------- B
         |          |
       10|          |2
         |          |
         C -------- D
              3
```

Suppose we want to find the shortest path from A to D.

There are two possible paths:

| Path      | Total Cost  |
| --------- | ----------- |
| A → B → D | 4 + 2 = 6   |
| A → C → D | 10 + 3 = 13 |

The shortest path is:

```
A → B → D

Total cost = 6
```

The algorithm must examine the graph and determine which path has the minimum total cost.

## Core Concepts

Before studying individual shortest path algorithms, it is important to understand several fundamental concepts.

### 2.1 Graph

A graph consists of:

- Vertices (V): Represent entities or locations.
- Edges (E): Represent connections between vertices.
- Weights: Represent the cost associated with traversing an edge.

Shortest path algorithms can operate on directed or undirected graphs.

### 2.2 Path

A path is a sequence of vertices connected by edges.

For example:

```
A → B → D → E
```

This path connects A to E through B and D.

### 2.3 Path Cost

The path cost is the sum of the weights of all edges along a path.

For a path:

```
A --4--> B --2--> D --5--> E
```

The total path cost is:

$$
Cost(A,E) = 4 + 2 + 5 = 11
$$

### 2.4 Shortest Path

A shortest path between two vertices is a path whose total cost is minimum among all possible paths connecting those vertices.

An important distinction:

- Shortest path does not necessarily mean the path with the fewest edges.
- It means the path with the minimum total weight.

When all edges have equal weights, minimizing total cost is equivalent to minimizing the number of edges.

### 2.5 Weighted vs. Unweighted Graphs

| Graph Type | Edge Representation            | Shortest Path Criterion |
| ---------- | ------------------------------ | ----------------------- |
| Unweighted | Edges have no explicit weights | Minimum number of edges |
| Weighted   | Edges have numerical weights   | Minimum total weight    |

For unweighted graphs, BFS is sufficient to find shortest paths.

For weighted graphs, the appropriate algorithm depends on the properties of the edge weights.

### 2.6 Relaxation

Relaxation is one of the most important operations in shortest path algorithms.

It means attempting to improve the currently known shortest distance to a vertex by discovering a potentially cheaper path through another vertex.

Suppose:

```
A --4--> B --3--> C
```

Initially, assume:

```
dist[A] = 0
dist[B] = ∞
dist[C] = ∞
```

After processing A:

```
dist[B] = 4
```

Then, processing B gives:

```
dist[C] = 4 + 3 = 7
```

The general relaxation formula for an edge $u \rightarrow v$ with weight $w(u,v)$ is:

$$
dist[v] = \min(dist[v], dist[u] + w(u,v))
$$

The algorithm updates `dist[v]` only when the newly discovered path is cheaper.

Relaxation is fundamental to Dijkstra, Bellman-Ford, and DAG shortest path algorithms.

## Types of Shortest Path Problems

Shortest path problems are classified according to what we want to calculate.

### 3.1 Single-Pair Shortest Path

Find the shortest path between two specific vertices.

```
Source: A
Target: E

Find shortest path A → E
```

Example: Finding the shortest driving route between two cities.

### 3.2 Single-Source Shortest Path (SSSP)

Find the shortest paths from one source vertex to every other reachable vertex.

```
              A (source)
             / \
            /   \
           B     C
          / \   / \
         D   E F   G

Find shortest paths:
A → B
A → C
A → D
A → E
A → F
A → G
```

Instead of calculating just one path, the algorithm calculates the shortest distance from A to all other vertices.

Common algorithms:

- Breadth-First Search (BFS) for unweighted graphs.
- Dijkstra's Algorithm for non-negative edge weights.
- Bellman-Ford for graphs that may contain negative edge weights.
- DAG Shortest Path for directed acyclic graphs.

### 3.3 All-Pairs Shortest Path (APSP)

Find the shortest paths between every pair of vertices.

For a graph containing vertices A, B, C, and D, calculate:

```
A → B    A → C    A → D
B → A    B → C    B → D
C → A    C → B    C → D
D → A    D → B    D → C
```

Common algorithm:

\- Floyd-Warshall Algorithm.

This problem is useful when we need shortest path information for many different source-target combinations.

## Shortest Path Algorithms

Different algorithms are suitable for different graph characteristics.

### 4.1 Breadth-First Search (BFS)

**Unweighted graphs**

BFS finds shortest paths in terms of the minimum number of edges.

It explores the graph level by level using a queue.

Example:

```
        A
       / \
      B   C
     /     \
    D       E
```

Starting from A:

```
Level 0: A
Level 1: B, C
Level 2: D, E
```

The shortest path from A to E is:

```
A → C → E

Distance = 2 edges
```

Time complexity with an adjacency list: $O(V+E)$

### 4.2 Dijkstra's Algorithm

**Non-negative edge weights**

To find short paths, BFS and DFS strategies are usable but bad. One famous and very effective way of finding the shortest path is the Djkistra Algorithm. 

Dijkstra's algorithm finds the shortest paths from a source vertex to all reachable vertices in a weighted graph, provided all edge weights are non-negative.

It uses a greedy strategy:

1. Start from the source vertex.
2. Maintain the currently known shortest distances.
3. Select the unprocessed vertex with the smallest tentative distance.
4. Relax its outgoing edges.
5. Repeat until all reachable vertices have been processed.

As BFS uses an auxiliary Queue to keep
track of nodes to explore, the Djkistra Algorithm uses a Priority
Queue. When new nodes are explored, their connections are added
to the Priority Queue. A node’s priority is the weight of the edges
that take it to the starting node. This way, the next node to explore
is always the closest to where we started.

A priority queue (usually implemented using a min-heap) makes selecting the next vertex efficient.

Typical complexity with an adjacency list and binary min-heap: $O((V+E)\log V)$

### 4.3 Bellman-Ford Algorithm

**Supports negative weights**

Bellman-Ford solves the Single-Source Shortest Path problem even when some edges have negative weights.

Unlike Dijkstra, it can also detect reachable negative-weight cycles.

A negative-weight cycle is a cycle whose total weight is negative.

Example:

```
A --2--> B
^       |
|       |
-5      1
|       |
+-------+
```

Traversing this cycle repeatedly decreases the total path cost indefinitely.

Therefore, a finite shortest path does not exist for vertices reachable from such a cycle.

Time complexity: $O(VE)$

### 4.4 Shortest Path in Directed Acyclic Graphs (DAGs)

**Directed acyclic graphs**

For a directed acyclic graph, shortest paths can be calculated efficiently using topological sorting followed by edge relaxation.

General approach:

1. Perform topological sorting.
2. Initialize the source distance to zero.
3. Process vertices in topological order.
4. Relax outgoing edges.

Time complexity: $O(V+E)$

An interesting advantage is that this algorithm can handle negative edge weights because the graph contains no directed cycles.

### 4.5 Floyd-Warshall Algorithm

**All-pairs shortest paths**

Floyd-Warshall calculates shortest paths between every pair of vertices.

It uses dynamic programming to determine whether passing through an intermediate vertex produces a shorter path.

The central recurrence is:

$$
dist[i][j] = \min(dist[i][j], dist[i][k] + dist[k][j])
$$

Where:

- $i$: Starting vertex.
- $j$: Destination vertex.
- $k$: Intermediate vertex.

Time complexity:

$$
O(V^3)
$$

Space complexity:

$$
O(V^2)
$$

It supports negative edge weights but not negative-weight cycles when meaningful finite shortest paths are required.

## 5. Algorithm Comparison

| Algorithm         | Problem | Edge Weights          | Time Complexity        |
| ----------------- | ------- | --------------------- | ---------------------- |
| BFS               | SSSP    | Equal / unweighted    | $O(V+E)$           |
| Dijkstra          | SSSP    | Non-negative          | $O((V+E)\log V)$\* |
| Bellman-Ford      | SSSP    | Positive and negative | $O(VE)$            |
| DAG Shortest Path | SSSP    | Positive and negative | $O(V+E)$           |
| Floyd-Warshall    | APSP    | Positive and negative | $O(V^3)$           |

\*Dijkstra complexity assumes an adjacency list and binary min-heap with lazy priority-queue updates. Other implementations have different complexities.

## 6. Choosing the Appropriate Algorithm

The choice depends primarily on the graph structure, edge weights, and problem requirements.

```
                 Shortest Path Problem
                          |
                What do we need?
                          |
              +-----------+-----------+
              |                       |
          Single Source           All Pairs
              |                       |
       What are the weights?    Floyd-Warshall
              |
       +------+----------------+
       |      |                |
   Equal    Non-negative    Negative
   weights  weights         weights
       |      |                |
      BFS  Dijkstra       Bellman-Ford
                              |
                    Is the graph a DAG?
                              |
                         DAG Shortest
                             Path
```

A more practical selection guide:

| Situation                              | Recommended Algorithm |
| -------------------------------------- | --------------------- |
| Unweighted graph                       | BFS                   |
| Weighted graph with non-negative edges | Dijkstra              |
| Negative edge weights                  | Bellman-Ford          |
| Directed acyclic graph                 | DAG Shortest Path     |
| Shortest paths between all pairs       | Floyd-Warshall        |

Note that a DAG with negative edges can use DAG shortest paths instead of Bellman-Ford. This is generally more efficient.

## 7. Data Structures Used

Shortest path algorithms rely on several fundamental data structures.

| Data Structure             | Purpose                                               | Algorithms                |
| -------------------------- | ----------------------------------------------------- | ------------------------- |
| Adjacency List             | Represent graph connections                           | All                       |
| Adjacency Matrix           | Represent graph connections and weights               | Especially Floyd-Warshall |
| Queue                      | Process vertices level by level                       | BFS                       |
| Priority Queue (Min-Heap)  | Select vertex with minimum tentative distance         | Dijkstra                  |
| Array / Distance Map       | Store shortest known distances                        | All                       |
| Parent / Predecessor Array | Reconstruct shortest paths                            | All                       |
| Stack                      | Support topological processing or iterative traversal | DAG algorithms            |

### Understanding the distance and predecessor arrays

Consider a graph:

```
       4         2
  A ------ B ------ D
   \               /
    \             /
     \----- C ---/
          3
```

Suppose the algorithm starts from A and determines:

```
dist[A] = 0
dist[B] = 4
dist[C] = 3
dist[D] = 6
```

The predecessor array might contain:

| Vertex | Distance | Predecessor |
| ------ | -------- | ----------- |
| A      | 0        | -1          |
| B      | 4        | A           |
| C      | 3        | A           |
| D      | 6        | B           |

The predecessor array allows us to reconstruct the actual shortest path.

For D:

```
D ← B ← A
```

Reverse the sequence:

```
A → B → D
```

Total cost = 6.

## 8. Real-World Applications

Shortest path algorithms are used in many areas of computer science and engineering.

| Application         | Graph Representation             | Objective                           |
| ------------------- | -------------------------------- | ----------------------------------- |
| GPS Navigation      | Cities and roads                 | Minimize distance or travel time    |
| Network Routing     | Routers and network links        | Minimize routing cost               |
| Social Networks     | Users and relationships          | Find shortest connection chains     |
| Airline Networks    | Airports and flights             | Minimize travel cost or connections |
| Robotics            | Locations and possible movements | Find an efficient movement path     |
| Game Development    | Map positions and transitions    | Find paths for game characters      |
| Distributed Systems | Nodes and communication links    | Find efficient communication routes |

One important distinction: the shortest path algorithm minimizes the weight you provide. If you want to minimize travel time, edge weights must represent travel time rather than physical distance.

## 9. Common Challenges and Pitfalls

When implementing shortest path algorithms, pay attention to the following:

1. Unreachable vertices: Some vertices might not be reachable from the source. Their distance remains infinity.
2. Negative edge weights: Standard Dijkstra cannot correctly handle negative edge weights.
3. Negative cycles: A reachable negative-weight cycle makes finite shortest paths undefined for affected vertices.
4. Path reconstruction: Calculating distances is not enough when the application needs the actual route.
5. Integer overflow: Adding large distances can overflow integer types.
6. Disconnected graphs: An algorithm must correctly handle vertices outside the source's reachable component.
7. Multiple shortest paths: Different paths can have the same minimum cost.
8. Graph representation: An adjacency list is usually preferable for sparse graphs, while an adjacency matrix can be useful for dense graphs and APSP algorithms.

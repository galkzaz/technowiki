## Overview

Shortest Path is a fundamental problem in graph theory and graph algorithms. It involves finding a path between vertices in a graph such that the total cost of traversing that path is minimized.

The cost can represent different things depending on the problem:

- Physical distance between locations.
- Travel time between cities.
- Network latency between computers.
- Financial cost of transportation.
- Number of edges or connections traversed.

Shortest path algorithms are designed to solve this problem efficiently, even when a graph contains thousands or millions of vertices and edges.

Before studying algorithms such as BFS, Dijkstra, and Bellman-Ford, we need to understand the fundamental concepts they share.

## Graph Model

A graph is commonly represented as:

$$
G = (V,E)
$$

Where:

- $V$: Set of vertices (nodes).
- $E$: Set of edges (connections).

For weighted graphs, we associate a weight with every edge:

$$
w(u,v)
$$

This represents the cost of moving from vertex $u$ to vertex $v$.

Consider the following weighted directed graph:

```
                  4
             A -------> B
             |          |
           10|          |3
             |          |
             v          v
             C -------> D
                  2
```

Its vertices are: $ V = {A,B,C,D}$

Its edges and weights are:

$$ E = { (A,B,4), (A,C,10), (B,D,3), (C,D,2) } $$

The graph is directed, meaning we can traverse an edge only in its specified direction.

For example:

- A → B has a cost of 4.
- B → D has a cost of 3.
- A → C has a cost of 10.
- C → D has a cost of 2.

The objective is to determine the minimum-cost path between vertices.

## Path and Path Cost

### 3.1 What Is a Path?

A path is a sequence of vertices where each consecutive pair is connected by an edge.

For example:

```
A → B → D
```

This is a path from A to D because:

- An edge connects A to B.
- An edge connects B to D.

Another possible path is:

```
A → C → D
```

Both paths connect the same source and destination.

### 3.2 Path Length vs. Path Cost

These two concepts are related but different.

Path length can refer to the number of edges traversed.

Path cost is the sum of the weights of the traversed edges.

Consider:

```
A --2--> B --3--> D
 \
  \--8--> C --1--> D
```

We have two possible paths:

| Path      | Number of Edges | Total Cost |
| --------- | --------------- | ---------- |
| A → B → D | 2               | 5          |
| A → C → D | 2               | 9          |

Both paths have the same length in terms of edge count, but different costs.

Now consider:

```
A --2--> B --2--> D
 \
  \--1--> C --1--> E --1--> D
```

| Path          | Number of Edges | Total Cost |
| ------------- | --------------- | ---------- |
| A → B → D     | 2               | 4          |
| A → C → E → D | 3               | 3          |

The second path contains more edges but has a lower total cost.

This distinction is important because shortest path algorithms generally minimize total weight, not the number of edges.

### 3.3 Mathematical Definition of Path Cost

Suppose a path is:

$$
P = (v_0,v_1,\ldots,v_k)
$$

Its cost is:

$$
Cost(P)=\sum\_{i=0}^{k-1}w(v_i,v\_{i+1})
$$

For example:

```
A --4--> B --3--> C --2--> D
```

The path cost is:

$$
Cost(A,D)=4+3+2=9
$$

## 4. Shortest Path Definition

A shortest path between two vertices is a path with the minimum total cost among all possible paths connecting those vertices.

Let:

- $s$: Source vertex.
- $v$: Destination vertex.
- $P(s,v)$: Set of all paths from $s$ to $v$.

Then the shortest path distance is:

$$
\boxed{ \delta(s,v)=\min\_{P\in P(s,v)} Cost(P) }
$$

Here, $\delta(s,v)$ represents the minimum possible cost from $s$ to $v$.

If no path exists between the vertices:

$$
\delta(s,v)=\infty
$$

Consider:

```
                  4
             A -------> B
             |          |
           10|          |3
             |          |
             v          v
             C -------> D
                  2
```

We want the shortest path from A to D.

Possible paths:

Path 1:

```
A → B → D
```

$$
Cost(P_1)=4+3=7
$$

Path 2:

```
A → C → D
```

$$
Cost(P_2)=10+2=12
$$

Therefore:

$$
\delta(A,D)=\min(7,12)=7
$$

The shortest path is:

```
A → B → D
```

with a total cost of 7.

## 5. Weighted vs. Unweighted Graphs

Shortest path algorithms depend heavily on whether the graph has weights.

### 5.1 Unweighted Graphs

An unweighted graph does not explicitly assign different costs to edges.

We can treat every edge as having weight 1.

```
       A
      / \
     B   C
    /     \
   D       E
```

Suppose we want the shortest path from A to E.

```
A → C → E
```

The distance is:

$$
Distance(A,E)=2
$$

Since every edge has equal cost, minimizing total cost is equivalent to minimizing the number of edges.

Algorithm: Breadth-First Search (BFS).

Time complexity:

$$
O(V+E)
$$

### 5.2 Weighted Graphs

In a weighted graph, edges have numerical weights representing different costs.

```
       2
  A -------- B
   \         |
    \ 5      | 3
     \       |
      C -----D
         1
```

The shortest path is determined by the sum of the edge weights.

For example:

```
A → B → D
Cost = 2 + 3 = 5

A → C → D
Cost = 5 + 1 = 6
```

The shortest path is A → B → D.

Algorithm: Dijkstra's Algorithm is appropriate when all edge weights are non-negative.

### 5.3 Comparison

| Property          | Unweighted Graph        | Weighted Graph       |
| ----------------- | ----------------------- | -------------------- |
| Edge weights      | Implicitly equal        | Explicit values      |
| Path optimization | Minimum number of edges | Minimum total weight |
| Typical algorithm | BFS                     | Dijkstra             |
| Negative weights  | Not applicable          | Possible             |
| Priority queue    | Not needed for BFS      | Used by Dijkstra     |

## 6. Types of Edge Weights

Understanding edge weights is essential because different algorithms support different weight conditions.

### 6.1 Positive Weights

All edges have weights greater than zero.

```
A --4--> B
B --3--> C
A --8--> C
```

Most shortest path algorithms can handle positive weights.

### 6.2 Zero-Weight Edges

Some edges have a weight of zero.

```
A --0--> B
B --3--> C
A --5--> C
```

Zero-weight edges are valid in Dijkstra's algorithm.

The path:

```
A → B → C
Cost = 0 + 3 = 3
```

is shorter than the direct path with cost 5.

### 6.3 Negative Weights

An edge can have a negative weight.

```
A --4--> B
B --(-3)--> C
A --5--> C
```

The path:

```
A → B → C
Cost = 4 - 3 = 1
```

is cheaper than the direct path with cost 5.

Negative weights introduce complications for greedy algorithms such as Dijkstra.

Important: Dijkstra's algorithm does not guarantee correct results when negative-weight edges are present. Bellman-Ford can handle negative weights, provided there is no reachable negative-weight cycle affecting the shortest path.

### 6.4 Negative-Weight Cycles

A cycle is a path that starts and ends at the same vertex.

A negative-weight cycle is a cycle whose total weight is negative.

Consider:

```
       2
  A -------> B
  ^          |
  |          | -5
  |          |
  +----------+
```

The cycle is:

```
A → B → A
```

Its total cost is:

$$
2+(-5)=-3
$$

Traversing this cycle repeatedly decreases the total path cost:

```
First traversal:  -3
Second traversal: -6
Third traversal:  -9
Fourth traversal: -12
```

Therefore, there is no finite minimum path cost for destinations reachable after repeatedly traversing this cycle.

This is why Bellman-Ford includes negative-cycle detection.

A negative cycle does not necessarily affect every vertex in the graph. Only vertices reachable from that cycle have their shortest distances made undefined.

## 7. Shortest Path Problem Classifications

Shortest path problems are classified according to the number of source and destination vertices involved.

### 7.1 Single-Pair Shortest Path

Find the shortest path between two specified vertices.

```
        A
       / \
      B   C
     /     \
    D       E

Source: A
Target: E
```

The objective is to find:

```
A → ... → E
```

Typical applications:

- GPS navigation between two locations.
- Finding the cheapest route between two airports.
- Finding a path between two network devices.

### 7.2 Single-Source Shortest Path (SSSP)

Find the shortest paths from one source vertex to all other reachable vertices.

```
             A (Source)
            / \
           B   C
          / \   \
         D   E   F
```

The objective is to calculate:

```
A → B
A → C
A → D
A → E
A → F
```

The result is a collection of shortest distances and corresponding paths.

Algorithms:

- BFS.
- Dijkstra.
- Bellman-Ford.
- DAG Shortest Path.

### 7.3 Single-Destination Shortest Path

Find the shortest paths from every vertex to one specified destination.

```
             A
            / \
           B   C
          / \   \
         D   E   F
                 |
                 G (Destination)
```

The objective is to find the shortest path from every vertex to G.

For directed graphs, one useful technique is to reverse all graph edges and run a Single-Source Shortest Path algorithm starting at G.

### 7.4 All-Pairs Shortest Path (APSP)

Find the shortest paths between every pair of vertices.

For example:

```
A → B
A → C
A → D

B → A
B → C
B → D

C → A
C → B
C → D

D → A
D → B
D → C
```

The result can be represented as a distance matrix.

For a graph with four vertices:

| From / To | A | B | C | D |
| --------- | - | - | - | - |
| A         | 0 | 4 | 7 | 9 |
| B         | ∞ | 0 | 3 | 5 |
| C         | ∞ | ∞ | 0 | 2 |
| D         | ∞ | ∞ | ∞ | 0 |

These values are illustrative.

Common algorithm:

\- Floyd-Warshall.

## Edge Relaxation

{/* Fundamental operation */}

Relaxation is the central operation used by many shortest path algorithms.

It means checking whether a newly discovered path to a vertex is cheaper than the currently known path.

Instead of immediately assuming that the first discovered path is optimal, we continuously improve our distance estimates.

### Distance Array

Shortest path algorithms typically maintain a distance array.

For each vertex $v$:

$$
dist[v]
$$

represents the currently known shortest distance from the source to that vertex.

Initially, for a source vertex $s$:

$$
dist[s]=0
$$

For every other vertex:

$$
dist[v]=\infty
$$

Example:

```
Graph:

A --4--> B --3--> C
 \
  \--10----------> C
```

Starting from A:

```
dist[A] = 0
dist[B] = ∞
dist[C] = ∞
```

### Relaxation Formula

For an edge from $u$ to $v$ with weight $w(u,v)$:

$$
\boxed{ dist[v] = \min(dist[v],dist[u]+w(u,v)) }
$$

This formula compares:

1. The existing known distance to v.
2. The newly discovered distance through u.

If the new distance is smaller, we update it.

### Step-by-Step Relaxation

Consider:

```
        4          3
   A ------> B ------> C
    \
     \
      \ 10
       \
        -------> C
```

Source vertex:

```
s = A
```

Initial state

| Vertex | Distance | Predecessor |
| ------ | -------- | ----------- |
| A      | 0        | -1          |
| B      | ∞        | -1          |
| C      | ∞        | -1          |

Step 1: Relax edge A → B

Edge weight:

$$
w(A,B)=4
$$

Calculate:

$$
dist[B]=\min(\infty,0+4)=4
$$

Updated state:

| Vertex | Distance | Predecessor |
| ------ | -------- | ----------- |
| A      | 0        | -1          |
| B      | 4        | A           |
| C      | ∞        | -1          |

Step 2: Relax edge A → C

Edge weight:

$$
w(A,C)=10
$$

Calculate:

$$
dist[C]=\min(\infty,0+10)=10
$$

Updated state:

| Vertex | Distance | Predecessor |
| ------ | -------- | ----------- |
| A      | 0        | -1          |
| B      | 4        | A           |
| C      | 10       | A           |

Step 3: Relax edge B → C

Edge weight:

$$
w(B,C)=3
$$

Calculate:

$$
dist[C]=\min(10,4+3)=7
$$

Since 7 is smaller than 10, update the distance and predecessor.

Final state:

| Vertex | Distance | Predecessor |
| ------ | -------- | ----------- |
| A      | 0        | -1          |
| B      | 4        | A           |
| C      | 7        | B           |

The shortest path is:

```
A → B → C

Total cost = 7
```

Notice that the initially discovered path A → C had a cost of 10. Relaxation improved it to 7 through B.

### 8.4 When Does Relaxation Occur?

Different algorithms organize relaxation differently.

| Algorithm         | Relaxation Strategy                                                                      |
| ----------------- | ---------------------------------------------------------------------------------------- |
| BFS               | Process outgoing edges level by level; first discovery gives the minimum number of edges |
| Dijkstra          | Relax outgoing edges of the vertex with the smallest tentative distance                  |
| Bellman-Ford      | Repeatedly relax all edges                                                               |
| DAG Shortest Path | Relax outgoing edges in topological order                                                |
| Floyd-Warshall    | Consider intermediate vertices using dynamic programming                                 |

This is one of the most important connections between shortest path algorithms: they share the relaxation operation but differ in the order and conditions under which they apply it.

## 9. Distance and Predecessor Arrays

To calculate shortest paths, we generally need more than just the distance values.

We maintain two important structures.

### 9.1 Distance Array

Stores the currently known minimum cost from the source to each vertex.

```
dist[A] = 0
dist[B] = 4
dist[C] = 7
dist[D] = ∞
```

### 9.2 Predecessor Array

Stores the previous vertex along the currently known shortest path.

For example:

```
pred[A] = -1
pred[B] = A
pred[C] = B
pred[D] = -1
```

The predecessor of C is B because the best known path to C goes through B.

### 9.3 Path Reconstruction

Suppose we want to reconstruct the shortest path from A to C.

Start at the destination C and follow its predecessors:

```
C ← B ← A
```

Reverse the sequence:

```
A → B → C
```

Pseudocode:

```
reconstructPath(pred, target):

    path = empty list
    current = target

    while current != -1:
        path.add(current)
        current = pred[current]

    reverse(path)

    return path
```

In a complete implementation, we should also check whether the target is reachable before returning a path. Otherwise, an unreachable target would incorrectly produce a path containing only itself.

### 9.4 Why Keep Both Arrays?

| Structure         | Answers                        |
| ----------------- | ------------------------------ |
| Distance array    | What is the minimum cost?      |
| Predecessor array | Which path produces that cost? |

For example:

```
dist[D] = 12
```

tells us that the shortest distance to D is 12.

But it does not tell us whether the path is:

```
A → B → D
```

or:

```
A → C → E → D
```

The predecessor array provides the information needed to reconstruct the route.

## Important Shortest Path Properties

### Optimal Substructure

A shortest path contains shortest paths within its subpaths.

Suppose the shortest path from A to D is:

```
A → B → C → D
```

Then the subpath:

```
B → C → D
```

must also be a shortest path from B to D.

Otherwise, if a cheaper path from B to D existed, replacing the original subpath would produce a cheaper path from A to D, contradicting the assumption that the original path was shortest.

This property is important in shortest path algorithms and dynamic programming.

### Subpath Optimality

More formally, if:

$$
P=(v_0,v_1,\ldots,v_k)
$$

is a shortest path from $v_0$ to $v_k$, then every contiguous subpath:

$$
(v_i,\ldots,v_j)
$$

is a shortest path between $v_i$ and $v_j$, assuming the shortest path distances are well-defined.

### Multiple Shortest Paths

A graph can contain multiple paths with exactly the same minimum cost.

```
        2
   A ------> B
   |          |
  3|          |3
   |          |
   v          v
   C ------> D
        2
```

Possible paths from A to D:

```
A → B → D = 2 + 3 = 5

A → C → D = 3 + 2 = 5
```

Both are shortest paths.

An algorithm that maintains only one predecessor per vertex may return either path.

If an application needs all shortest paths, additional predecessor information must be maintained.

### Unreachable Vertices

Not every vertex is necessarily reachable from a given source.

```
A ---- B ---- C

D ---- E
```

Starting from A:

```
dist[A] = 0
dist[B] = 1
dist[C] = 2
dist[D] = ∞
dist[E] = ∞
```

The vertices D and E are unreachable from A.

The algorithm must preserve their distances as infinity.

### Shortest Paths in Directed vs. Undirected Graphs

In an undirected graph, an edge can be traversed in both directions.

```
A ----- B
```

This represents:

```
A → B
B → A
```

In a directed graph, an edge has a specific direction:

```
A -----> B
```

This does not imply that B can reach A.

Consequently, shortest path calculations can produce different results depending on graph direction.

## Shortest Path Algorithms at a Glance

Now that the fundamentals are clear, we can connect them to the algorithms that solve different variations of the problem.

| Algorithm         | Problem | Weight Restrictions                          | Main Technique                   |

| Dijkstra          | SSSP    | Non-negative weights                         | Greedy + priority queue          |

| DAG Shortest Path | SSSP    | Negative weights allowed                     | Topological sorting + relaxation |

## Common Mistakes and Misconceptions

| Misconception                               | Correct Understanding                                               |
| ------------------------------------------- | ------------------------------------------------------------------- |
| Shortest path always means fewest edges     | It generally means minimum total edge weight                        |
| BFS works for every weighted graph          | BFS finds minimum-cost paths only when all edges have equal weights |
| Dijkstra supports negative weights          | Dijkstra requires non-negative edge weights                         |
| The first discovered path is always optimal | A later relaxation may discover a cheaper path                      |
| Every vertex is reachable from the source   | Some vertices may be unreachable                                    |
| Shortest path is always unique              | Multiple paths can have the same minimum cost                       |
| Distance array gives the actual route       | A predecessor structure is needed to reconstruct the route          |
| Negative edges always mean negative cycles  | Negative edges and negative cycles are different concepts           |

## Hash-Based Search Applications

This section answers a different question:

> **Where is Hash-Based Search useful in real software?**

The important characteristic is that we have a collection of objects and frequently need to determine whether a particular **key** exists or retrieve information associated with that key.

---

### Membership Testing

One common application is simply asking:

> Does this element exist?

For example, suppose we maintain a set of usernames:

```text
{"alice", "bob", "charlie", "david"}
```

When a user attempts to register:

```text
username = "alice"
```

we need to determine whether `"alice"` already exists.

A hash-based structure can perform this lookup efficiently:

```text
"alice"
   │
   ▼
 hash("alice")
   │
   ▼
 H[h]
   │
   ▼
 found?
```

This is the basic **existence query**.

---

## Associative Lookup

Hashing is also useful when we want to retrieve a value associated with a key.

For example:

```text
Student ID → Student
```

```text
1001 → Alice
1002 → Bob
1003 → Charlie
```

Searching for:

```text
1002
```

gives:

```text
1002
 │
 ▼
hash(1002)
 │
 ▼
H[h]
 │
 ▼
Bob
```

This is called **associative lookup**.

This is one of the most important applications of hash tables.

---

## Dictionaries / Maps

A dictionary or map is essentially a very common application of hash-based lookup.

For example:

```text
username → email
```

```text
"alice" → "alice@example.com"
"bob"   → "bob@example.com"
```

A lookup:

```text
map["alice"]
```

uses the key `"alice"` to locate the associated value.

Conceptually:

```text
       key
        │
        ▼
   hash function
        │
        ▼
    hash table
        │
        ▼
     value
```

This is the underlying idea behind structures such as:

* Java `HashMap`
* C++ `unordered_map`
* Python `dict`

The implementation details belong in your **Hash Tables** section, while the application here is simply the use of hashing for fast lookup.

---

## Symbol Tables

Hash-based lookup is widely useful for mapping names to information.

For example, a compiler might maintain:

```text
variable name → information about variable
```

such as:

```text
"count" → integer
"price" → double
"name"  → string
```

When the compiler encounters:

```text
count
```

it needs to quickly determine what `count` represents.

A hash-based lookup can provide that mapping efficiently.

---

## Caches

Hash-based lookup is also useful in caches.

Suppose a system stores:

```text
URL → cached response
```

For example:

```text
"/users/42" → cached user data
"/products/17" → cached product data
```

When a request arrives:

```text
GET /users/42
```

the system can use the URL or another key to quickly determine whether the result is already cached.

Conceptually:

```text
request key
     │
     ▼
   hash
     │
     ▼
 cache table
     │
 ┌───┴────┐
 │        │
hit      miss
 │        │
 ▼        ▼
return   retrieve
cache    from source
```

This is particularly useful when lookups happen very frequently.

---

## Duplicate Detection

Hash-based searching can also be used to detect duplicates.

Suppose:

```text
C = [42, 17, 42, 31, 17]
```

As we process the elements, we can maintain a set of previously seen values:

```text
42 → not seen → insert
17 → not seen → insert
42 → already seen → duplicate
31 → not seen → insert
17 → already seen → duplicate
```

The hash structure allows membership testing to be performed efficiently.

---

## Database and System Lookups

Hash-based lookup can also appear in systems that repeatedly need to locate objects using identifiers.

Examples include:

```text
ID → object
session ID → session
user ID → user
product ID → product
file name → metadata
IP address → information
```

The common pattern is always:

```text
key
 │
 ▼
hash
 │
 ▼
location
 │
 ▼
associated object/value
```

---

## Why These Applications Use Hashing

All of these applications have a common requirement:

> **Given a key, quickly determine whether it exists and/or retrieve the information associated with it.**

For example:

| Application         | Key             | Lookup result        |
| ------------------- | --------------- | -------------------- |
| Username database   | username        | user record          |
| Student system      | student ID      | student              |
| Dictionary          | word            | definition           |
| Cache               | URL/request key | cached result        |
| Symbol table        | variable name   | variable information |
| Duplicate detection | element         | exists/not exists    |
| Session storage     | session ID      | session data         |

So the general pattern is:

```text
             Hash-Based Lookup
                    │
          ┌─────────┼─────────┐
          │         │         │
       Exists?    Find?    Retrieve?
          │         │         │
          └─────────┼─────────┘
                    ▼
                  hash
                    │
                    ▼
                hash table
```

## Putting the Entire Topic Together

The complete structure can be viewed as:

```text
                 Hash-Based Search
                        │
                        ▼
                  Hash Function
                        │
                        ▼
                  Hash Table
                        │
              ┌─────────┴─────────┐
              │                   │
       Direct Addressing    Collision Handling
                                  │
                         ┌────────┴────────┐
                         │                 │
                    Chaining       Open Addressing
                                         │
                              ┌──────────┼──────────┐
                              │          │          │
                           Linear    Quadratic   Double
                           Probing    Probing    Hashing
```

And the complexity picture is:

| Operation | Expected | Worst Case |
| --------- | -------: | ---------: |
| Search    | **O(1)** |   **O(n)** |
| Insert    | **O(1)** |   **O(n)** |
| Delete    | **O(1)** |   **O(n)** |

The central idea to remember is:

> **Hash-based searching trades some memory and additional collision-handling complexity for very fast expected lookup.**

The key relationship is:

```text
Key
 │
 ▼
Hash Function
 │
 ▼
Initial Table Position
 │
 ├── Empty ──────────► Found/Insert
 │
 └── Occupied
        │
        ▼
   Collision Handling
        │
        ├── Chaining
        │
        └── Probing
              ├── Linear
              ├── Quadratic
              └── Double Hashing
```

This also explains why **hash-based searching is fundamentally different from binary search**: binary search exploits an **ordered structure**, while hashing exploits a **mapping from keys to locations**.

{/* This paragraph introduces open addressing, which is the major alternative to the separate chaining approach you've been studying. */}

One popular variation of Hash-Based Search modifies the handling of collisions by
restricting each bin to contain a single element. Instead of creating a linked list to
hold all elements that hash to some bin in the hash table, it uses the open addressing
technique to store colliding items in some other empty bin in the hash table H. 

With open addressing, the hash table reduces storage overhead by eliminating all linked lists.

**open addressing**, is a major alternative to the **separate chaining**. The key difference is:

> **Separate chaining puts multiple elements inside the same bin using a linked list. Open addressing allows only one element per bin and finds another empty bin when a collision occurs.**

With open addressing, each table position contains at most **one element**.

So instead of:

```text
H[3] → A → E → F
```

we have:

```text
H[3] = A
H[4] = E
H[5] = F
```

The elements that collide are moved to other empty positions in the **same array**.

Conceptually:

```text
Separate Chaining

H[3] → A → E → F
       linked list
```

versus:

```text
Open Addressing

H[3] = A
H[4] = E
H[5] = F
```

No linked lists are needed.

To insert an element using open addressing, compute the desired bin `hk = hash(e`) that should contain `e`. If `H[hk]` is empty, assign `H[hk] = e` just as in the standard algorithm. Otherwise probe through `H` using a probing strategy and place `e` in the first discovered empty bin:

Suppose we have:

```text
H = [ _ ][ _ ][ A ][ _ ][ _ ]
```

and we want to insert `B`.

Suppose:

$$
hash(B)=2
$$

The desired bin is:

```text
H[2]
```

But:

```text
H[2] = A
```

so we have a collision.

With separate chaining:

```text
H[2] → A → B
```

With open addressing:

```text
H[2] = A
```

is occupied, so we **probe** for another position.

For example:

```text
H[3] = empty
```

so:

```text
H[3] = B
```

Now:

```text
H
 ↓
[ _ ][ _ ][ A ][ B ][ _ ]
```

---

**Why this matters for search**

Insertion and search must use the **same probing strategy**.

Suppose we inserted:

```text
25 → H[5]
35 → H[6]  (because H[5] was occupied)
45 → H[7]
```

To search for `45`, we cannot simply check `H[5]` and say "not found."

We must reproduce the same probe sequence:

```text
search(45)

hash(45) = 5
     ↓
H[5] = 25  → not 45
     ↓
H[6] = 35  → not 45
     ↓
H[7] = 45  → FOUND
```

So open addressing changes **both insertion and searching**.

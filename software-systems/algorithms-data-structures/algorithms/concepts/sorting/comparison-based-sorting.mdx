## Transposition Sorting
Transposition Sorting (often called Transposition Sort or Odd-Even Transposition Sort) is a simple comparison-based sorting algorithm that works by repeatedly swapping adjacent elements if they are out of order. Conceptually, it's very close to Bubble Sort, but it is structured in phases that make it especially suitable for parallel systems.

Early sorting algorithms found elements(adjacent or not adjacent) in the collection A that were out of place
and moved them into their proper position by transposing (or swapping) elements
in A. Selection Sort and (the infamous) Bubble Sort belong to this sorting family.
But these algorithms are outperformed by Insertion Sort.

this sorting algorithms is simple sorting algorithms that builds the final sorted array one item at a time.
It is much less efficient on large lists than more advanced algorithms such as quicksort, heapsort, or merge sort.

An algorithm falls under Transposition Sorting if it:
- Sorts by pairwise swaps (transpositions)
- Typically swaps adjacent elements
- Gradually removes inversions
- Is comparison-based
- Is usually in-place
Formally, each operation is a transposition:
(ai,aj)→(aj,ai)

Some books  is using "transposition sorting" in a broader, older sense than many modern textbooks.
Let's reconcile the book's statement with the stricter definition.
- Broad (Exchange-based) Definition (Used by Algorithms in a Nutshell): Any sorting algorithm that works by repeatedly swapping (transposing) pairs of elements belongs to the transposition sorting family.
Under this definition:
  - The swap does not need to be adjacent
  - Any pairwise exchange counts as a transposition

  like 
  - Selection Sort
  - Bubble Sort
- Narrow (Adjacent-transposition) Definition(Used in parallel algorithms & sorting networks): A transposition sort swaps only adjacent elements, typically in structured phases.
Under this definition:
- Bubble Sort 
- Odd-Even Transposition Sort 
- Selection Sort → ✘ (non-adjacent swaps)

## Core Idea
The algorithm sorts a list by performing a sequence of transposition phases:
- Odd phase: compare and swap elements at indices
  * (1,2), (3,4), (5,6), …
- Even phase: compare and swap elements at indices
  * (0,1), (2,3), (4,5), …

These two phases alternate until the list is sorted.

Each phase performs independent comparisons, which means they can be executed in parallel.

## Step-by-Step Explanation
Consider the array:
```
     0, 1, 2 ,3, 4
A = [5, 3, 4, 1, 2]
```
1. **Phase 1**: Even phase
  * Compare (0,1), (2,3)
    ```
    (5,3) → swap → [3,5,4,1,2]
    (4,1) → swap → [3,5,1,4,2]
    ```
2. **Phase 2**: Odd phase
  * Compare (1,2), (3,4)
    ```
    (5,1) → swap → [3,1,5,4,2]
    (4,2) → swap → [3,1,5,2,4]
    ```
3. **Phase 3**: Even phase
  * Compare (0,1), (2,3)
    ```
    (3,1) → swap → [1,3,5,2,4]
    (5,2) → swap → [1,3,2,5,4]
    ```
4. **Phase 4**: Odd phase
  * Compare (1,2), (3,4)
    ```
    (3,2) → swap → [1,2,3,5,4]
    (5,4) → swap → [1,2,3,4,5]
    ```
After enough phases (at most n), the array becomes sorted.

## Pseudocode
```Pseudocode
procedure TranspositionSort(A[0..n-1])
    repeat n times
        // Even phase
        for i = 0 to n-2 step 2 do
            if A[i] > A[i+1] then
                swap(A[i], A[i+1])

        // Odd phase
        for i = 1 to n-2 step 2 do
            if A[i] > A[i+1] then
                swap(A[i], A[i+1])
```
## Why It Works
- Each phase moves elements one position closer to their correct place.
- Repeating the odd and even phases ensures that every adjacent inversion is eventually removed.
- After at most n phases, all elements are guaranteed to be in sorted order.
This can be proven by observing that the largest element moves right by at least one position per full iteration (odd + even).

## Selection Sort
One common sorting strategy is to select the largest value from the range A[0, n) and swap its location with the rightmost element A[n – 1]. This process is repeated, subsequently, on each successive smaller range A[0, n – 1) until A is sorted.

Selection sort repeatedly selects the smallest remaining element and places it in its correct position.
It divides the array into:
- A sorted prefix
- An unsorted suffix

At each step, it grows the sorted prefix by one element.

Selection Sort is an example of a Greedy approach [see](software-systems/algorithms-data-structures/algorithms/approaches-strategies/greedy-strategy.mdx#selection-sort).

Given array A[0…n−1]:
For each position i=0 to n−2:
    1. Find the minimum element in A[i…n−1]
    2. Swap it with A[i]

### Input/Output
Describes the expected format of input data to the algorithm and the resulting values computed.
### Context
Although inefficient for large data, it is useful when:
- Memory is extremely limited
- Swap cost is expensive
- Data size is small
- Teaching algorithm fundamentals

It is often used in embedded systems where writes are costly.

Practical Use Cases Where It Might Be Acceptable
- Very small arrays (n < 20) — overhead of more complex algorithms may outweigh quadratic cost.
- Teaching and algorithmic exercises — simple to explain and implement.
- Embedded systems with tiny memory and fixed-size arrays.

Selection sort is mostly academic:
1. Quadratic comparisons → slow for n > 1000.
2. Not adaptive → no benefit for sorted or nearly sorted data.
3. Stability is not guaranteed → requires extra logic.
4. Poor memory/cache performance → bad for real-world datasets or disk-based sorting.

In production, algorithms like merge sort, quicksort, heap sort, and Timsort are preferred.

### Example Walkthrough
Sort: [5,2,4,6,1,3] 
1. **Pass 1 (i = 0)**
    * Find minimum in entire array → 1
    * Swap with first element: [**1**,2,4,6,**5**,3] 
1. **Pass 2 (i = 1)**
    * Find minimum in: [**2**,4,6,5,3] 
    * Minimum = 2
    * Already in place → no change. [**1**,**2**,4,6,**5**,3] 
1. **Pass 3 (i = 2)**
    * Minimum in: [4,6,5,**3**] 
    * Minimum = 3
    * Swap: [1,2,**3**,6,5,**4**] 
1. Continue…
1. **Final result**: [1,2,3,4,5,6]

### Analogy
Imagine sorting exam papers by score:
- Scan all papers
- Pick lowest score
- Put it in first position
- Repeat for remaining stack

You repeatedly select the smallest remaining item.

### Correctness
correctness using the loop invariant method:

At the start of iteration i:
$$
A[0....i−1]
$$
contains the i smallest elements of the array in sorted order.

1. **Initialization**

Before the first iteration (i=0):
- The subarray A[0⋯−1] is empty.
- An empty set is trivially sorted.
- It contains the 0 smallest elements.

The invariant holds before the first iteration.

2. **Maintenance**

Assume the invariant holds at the start of iteration i.

So: $A[0…i−1]$ contains the  contains the i smallest elements in sorted order.

During iteration i:
- The algorithm finds the minimum element in A[i…n−1].
- That minimum must be the (i+1)-th smallest element overall.
- It swaps this element into position i.

Thus after the swap: $A[0…i]$ contains the i+1 smallest elements in sorted order.

Therefore, the invariant holds at the next iteration.

3. **Termination**

The loop runs for i=0 to n−2.

When it terminates: i=n−1 

By the invariant: $A[0…n−2]$

contains the n−1 smallest elements in sorted order.

The final remaining element: A[n−1]  must be the largest element.

Thus the entire array: $A[0…n−1]$ is sorted.

Termination proves correctness.

By:
- Initialization
- Maintenance
- Termination

Selection sort correctly sorts the array. Selection sort is correct.

**Additional Correctness Insight**

Why the minimum chosen is correct
- At iteration i: All elements before i are already the smallest ones.
- Thus, the smallest element remaining must belong at position i.

Selection sort never disturbs the sorted prefix.

Selection sort is correct because:
- Each step places exactly one element in its final position.
- The sorted portion grows monotonically.
- No later operation disturbs earlier sorted elements.

**Alternative Proof (Exchange Argument)**

Suppose after completion, the array is not sorted.

Then there exist indices i\<j such that:
$$
A[i]>A[j] 
$$
But at iteration i, the algorithm selects the smallest element from $A[i…n−1]$.

Therefore, no smaller element than $A[i]$ can appear later.

Contradiction.

Hence the array must be sorted.

### Solution
#### C Language
##### Basic Implementation

```c
/* Swap two integers */
void swap(int *a, int *b) {
  int temp = *a;
  *a = *b;
  *b = temp;
}

/* Selection Sort */
void selectionSort(int arr[], int n) {
  for (int i = 0; i < n - 1; i++) {
    int min_index = i;

    /* Find index of smallest element */
    for (int j = i + 1; j < n; j++) {
      if (arr[j] < arr[min_index]) {
        min_index = j;
      }
    }

    /* Swap only if needed */
    if (min_index != i) {
      swap(&arr[i], &arr[min_index]);
    }
  }
}
```
the condition
```
if (min_index != i)
```
avoids unnecessary self-swaps.

##### Pointer-Based Implementation
```c
void selectionSort(int *arr[], int n) {
  for (int i = 0; i < n - 1; i++) {
    int min_index = i;

    /* Find pointer to smallest value */
    for (int j = i + 1; j < n; j++) {
      if (*arr[j] < *arr[min_index]) {
        min_index = j;
      }
    }

    /* Swap pointers (not values) */
    if (min_index != i) {
      int *temp = arr[i];
      arr[i] = arr[min_index];
      arr[min_index] = temp;
    }
  }
}
```
- values[] stores actual integers.
- ptrs[] stores pointers to those integers.
- Sorting rearranges pointers only.
- The original values[] array remains unchanged in memory.

Before sort:
```
values:  [5][2][4][6][1][3]
ptrs:     ↑  ↑  ↑  ↑  ↑  ↑
          p0 p1 p2 p3 p4 p5
```
After sort:
```
values:  [5][2][4][6][1][3]
ptrs:     ↑  ↑  ↑  ↑  ↑  ↑

```
Data unchanged, only pointer order changed.

**Why Use Pointer-Based Sorting?**

Efficient for large records, If each element is a large struct:
```c
struct Student {
    char name[100];
    int id;
    double gpa;
};
```
Swapping entire structs is expensive.
Instead:
- Keep data in place
- Sort an array of `struct Student *`
- Swap only pointers (8 bytes)

Much faster and cache-friendly.

##### Selection Sort with a comparison function
this is how large records are actually sorted in high-performance systems.
Instead of moving full records (which may be hundreds of bytes), we:
1. Keep the original data array untouched.
2. Create an array of pointers to elements.
3. Sort the pointer array using a comparator.
4. Optionally apply the permutation later.

This reduces data movement from O(n⋅record_size) to O(n⋅pointer_size).
```c
/* Generic pointer-based selection sort */
void selectionSortPtr(void *arr[], size_t n,
                      int (*cmp)(const void *, const void *)) {

  for (size_t i = 0; i < n - 1; i++) {
    size_t min_index = i;

    for (size_t j = i + 1; j < n; j++) {
      if (cmp(arr[j], arr[min_index]) < 0) {
        min_index = j;
      }
    }

    if (min_index != i) {
      void *temp = arr[i];
      arr[i] = arr[min_index];
      arr[min_index] = temp;
    }
  }
}

/* Comparator for integers */
int cmp_int(const void *a, const void *b) {
  int x = *(const int *)a;
  int y = *(const int *)b;

  if (x < y)
    return -1;
  if (x > y)
    return 1;
  return 0;
}
```
Original values array:
```
5 2 4 6 1 3
```
Sorted order via pointers:
```
1 2 3 4 5 6
```

After sorting:
- values[] is still: [5 2 4 6 1 3]
- Only ptrs[] is reordered.
So:
```
ptrs[0] → &values[4] (1)
ptrs[1] → &values[1] (2)
ptrs[2] → &values[5] (3)
...
```
If integers were replaced by large records (e.g., 256-byte structs):
- Value-based sort moves 256 bytes per swap
- Pointer-based sort moves only 8 bytes per swap

Huge cache and performance improvement.

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct {
  char name[100];
  int id;
  double salary;
} Employee;

int cmp_salary(const void *a, const void *b) {
  const Employee *e1 = a;
  const Employee *e2 = b;

  if (e1->salary < e2->salary)
    return -1;
  if (e1->salary > e2->salary)
    return 1;
  return 0;
}

/* Generic selection sort for pointer arrays */
void selectionSortPtr(void *arr[], size_t n,
                      int (*cmp)(const void *, const void *)) {

  for (size_t i = 0; i < n - 1; i++) {
    size_t min_index = i;

    for (size_t j = i + 1; j < n; j++) {
      if (cmp(arr[j], arr[min_index]) < 0) {
        min_index = j;
      }
    }

    if (min_index != i) {
      void *temp = arr[i];
      arr[i] = arr[min_index];
      arr[min_index] = temp;
    }
  }
}
int main() {
  Employee employees[] = {
      {"Alice", 1, 70000}, {"Bob", 2, 50000}, {"Carol", 3, 90000}};

  size_t n = sizeof(employees) / sizeof(employees[0]);

  /* Create pointer array */
  Employee *ptrs[n];
  for (size_t i = 0; i < n; i++) {
    ptrs[i] = &employees[i];
  }

  /* Sort pointer array */
  selectionSortPtr((void **)ptrs, n, cmp_salary);

  /* Print sorted order */
  for (size_t i = 0; i < n; i++) {
    printf("%s %.2f\n", ptrs[i]->name, ptrs[i]->salary);
  }

  return 0;
}
```

##### Generic Selection Sort (Value-Based) using memcpy
**Sorting Intgeres**
```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* Generic selection sort */
void selectionSort(void *base, size_t n, size_t size,
                   int (*cmp)(const void *, const void *)) {

  char *arr = (char *)base; // byte-level access

  for (size_t i = 0; i < n - 1; i++) {
    size_t min_index = i;

    for (size_t j = i + 1; j < n; j++) {
      void *elem_j = arr + j * size;
      void *elem_min = arr + min_index * size;

      if (cmp(elem_j, elem_min) < 0) {
        min_index = j;
      }
    }

    if (min_index != i) {
      char temp[size]; // VLA (C99)
      memcpy(temp, arr + i * size, size);
      memcpy(arr + i * size, arr + min_index * size, size);
      memcpy(arr + min_index * size, temp, size);
    }
  }
}
int cmp_int(const void *a, const void *b) {
  int x = *(const int *)a;
  int y = *(const int *)b;

  if (x < y)
    return -1;
  if (x > y)
    return 1;
  return 0;
}

int main() {
  int arr[] = {5, 2, 4, 6, 1, 3};
  size_t n = sizeof(arr) / sizeof(arr[0]);

  selectionSort(arr, n, sizeof(int), cmp_int);

  for (size_t i = 0; i < n; i++)
    printf("%d ", arr[i]);
  printf("\n");

  return 0;
}
```

- n → number of elements
- size → size of each element
- cmp → comparator function

##### Generic Selection Sort (Value-Based) using memmove
Classic selection sort:
    1. Find minimum in unsorted region.
    2. Swap it with position i.

That’s a two-element swap, not a block shift.

There is no contiguous block being moved.

So memmove gives no advantage.

We Can Make Selection Sort Stable Using memmove
Instead of swapping:
    1. Find minimum element at position min_index.
    2. Store that element in a temporary buffer.
    3. Shift all elements from i to min_index - 1 one step right.
    4. Insert the minimum at position i.

That preserves stability.
This does use memmove.


```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* Stable Selection Sort using memmove */
void stableSelectionSort(void *base, size_t n, size_t size,
                         int (*cmp)(const void *, const void *)) {

    char *arr = (char *)base;

    for (size_t i = 0; i < n - 1; i++) {

        size_t min_index = i;

        /* Find minimum */
        for (size_t j = i + 1; j < n; j++) {
            if (cmp(arr + j * size, arr + min_index * size) < 0) {
                min_index = j;
            }
        }

        /* If minimum not already in place */
        if (min_index != i) {

            char min_value[size];

            /* Save minimum element */
            memcpy(min_value, arr + min_index * size, size);

            /* Shift block right by one */
            memmove(arr + (i + 1) * size,
                    arr + i * size,
                    (min_index - i) * size);

            /* Insert minimum at correct position */
            memcpy(arr + i * size, min_value, size);
        }
    }
}

int cmp_int(const void *a, const void *b) {
  int x = *(const int *)a;
  int y = *(const int *)b;

  if (x < y)
    return -1;
  if (x > y)
    return 1;
  return 0;
}

int main() {
  int arr[] = {5, 2, 4, 6, 1, 3};
  size_t n = sizeof(arr) / sizeof(arr[0]);

  stableSelectionSort(arr, n, sizeof(int), cmp_int);

  for (size_t i = 0; i < n; i++)
    printf("%d ", arr[i]);
  printf("\n");

  return 0;
}

```

##### Performance comparison (pointer vs value)
We compare:
    1. Value-based selection sort (swap full records)
    2. Pointer-based selection sort (swap only pointers)

🔷 1️⃣ What Actually Changes?
Value-Based Sort
Swapping two elements of size S bytes:
 per swapCost per swap=O(S) 
Total swaps ≤ n−1
Total data movement:
O(nS) 
Comparisons:
Θ(n2) 

Pointer-Based Sort
Swapping two pointers (size P, usually 8 bytes):
 per swapCost per swap=O(P) 
Total data movement:
O(nP) 
Comparisons still:
Θ(n2) 

🔷 2️⃣ When Does It Matter?
Let:
- S=256 bytes (large struct)
- P=8 bytes (64-bit pointer)
Then:
PS​=32 
Pointer sort moves 32× less data per swap.

🔷 3️⃣ Cache Behavior
Value-Based
Each swap:
- Reads full record
- Writes full record
- Causes cache line pollution
If record > cache line (64B typical), multiple cache lines touched.

Pointer-Based
Swaps only 8-byte pointers.
Data array remains untouched.
Better:
- Cache locality
- TLB usage
- Memory bandwidth

🔷 4️⃣ But There Is a Trade-Off
Pointer-based sorting introduces:
Indirection
When comparing:
cmp(arr[j], arr[min_index])
We dereference:
pointer → record

```C
#include <stdio.h>

/* Stable selection sort for integer arrays */
void stableSelectionSortInt(int arr[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int min_index = i;

        /* Find minimum in the unsorted part */
        for (int j = i + 1; j < n; j++) {
            if (arr[j] < arr[min_index]) {
                min_index = j;
            }
        }

        /* Shift elements instead of swapping */
        if (min_index != i) {
            int min_value = arr[min_index];

            /* Move all elements between i and min_index one step to the right */
            for (int k = min_index; k > i; k--) {
                arr[k] = arr[k - 1];
            }

            /* Place the minimum element at position i */
            arr[i] = min_value;
        }
    }
}
int main() {
    int arr[] = {5, 2, 4, 2, 6, 1, 3};
    int n = sizeof(arr) / sizeof(arr[0]);

    stableSelectionSortInt(arr, n);

    printf("Stable selection sorted array:\n");
    for (int i = 0; i < n; i++) {
        printf("%d ", arr[i]);
    }
    printf("\n");

    return 0;
}

```
1. **Stability**: Shifting elements preserves order of duplicates.
2. **Time Complexity**:
    ◦ Comparisons: Θ(n²)
    ◦ Moves: O(n²)
3. **Space Complexity**: O(1) extra (just min_value).
4. **Use Case**: Small integer arrays where stability matters.

```C
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* Stable selection sort using memmove */
void stableSelectionSort(void *base, size_t n, size_t size,
                         int (*cmp)(const void *, const void *)) {

  char *arr = (char *)base;

  for (size_t i = 0; i < n - 1; i++) {
    size_t min_index = i;

    /* Find minimum element in unsorted part */
    for (size_t j = i + 1; j < n; j++) {
      if (cmp(arr + j * size, arr + min_index * size) < 0) {
        min_index = j;
      }
    }

    if (min_index != i) {
      char temp[size];

      /* Copy the minimum element */
      memcpy(temp, arr + min_index * size, size);

      /* Shift elements between i and min_index one step right safely */
      memmove(arr + (i + 1) * size, arr + i * size, (min_index - i) * size);

      /* Insert minimum element at correct position */
      memcpy(arr + i * size, temp, size);
    }
  }
}

int cmp_int(const void *a, const void *b) {
  int x = *(const int *)a;
  int y = *(const int *)b;
  if (x < y)
    return -1;
  if (x > y)
    return 1;
  return 0;
}

int main() {
  int arr[] = {5, 2, 4, 2, 6, 1, 3};
  size_t n = sizeof(arr) / sizeof(arr[0]);

  stableSelectionSort(arr, n, sizeof(int), cmp_int);

  printf("Stable selection sorted array:\n");
  for (size_t i = 0; i < n; i++)
    printf("%d ", arr[i]);
  printf("\n");

  return 0;
}

```
Key Notes
1. Why memmove?
    ◦ Elements from i to min_index - 1 are shifted overlapping memory.
    ◦ memcpy would be undefined behavior in this case.
2. **Stability**:
    ◦ Only elements greater than the minimum are shifted.
    ◦ Equal elements remain in their relative positions.
3. **Space**:
    ◦ Temporary buffer temp[size] used per iteration.
4. **Time Complexity**:
    ◦ Comparisons: Θ(n²)
    ◦ Moves: Θ(n² × size)

### Analysis
Selection Sort is the slowest of all the sorting algorithms described in this chapter;
it requires quadratic time even in the best case (i.e., when the array is already sorted). 

It repeatedly performs almost the same task without learning anything from
one iteration to the next. Selecting the largest element, max, in A takes n – 1 comparisons, and selecting the second largest element, second, takes n – 2 comparison—not much progress! Many of these comparisons are wasted, because if an element
is smaller than second, it can’t possibly be the largest element and therefore has no
impact on the computation for max.
#### Time Complexity 
For each i, we compare with all remaining elements.

Total comparisons:
$$
(n−1)+(n−2)+⋯+1 \\
= \frac{n(n−1)}{2} \\
=\theta(n^2) 
$$
- Best case: $\theta(n^2)$
- Average case: $\theta(n^2)$
- Worst case: $\theta(n^2)$

Unlike insertion sort, best case is still quadratic.

Number of Swaps

At most: n−1 

This is important. Selection sort minimizes swaps compared to insertion sort.

#### Space Complexity
Space Complexity is O(1)

In-place sorting.

Selection sort is NOT stable.

#### External-Memory Analysis
Why External-Memory Analysis Matters

When data doesn’t fit in RAM:
- Records are stored on secondary storage (HDD, SSD).
- Access cost is dominated by I/O operations, not CPU instructions.
- Moving a record on disk is much more expensive than in-memory swaps.
- Sorting algorithms must be analyzed in I/O complexity.

**External-Memory Model**

We use the Aggarwal-Vitter I/O model:
- N = number of elements to sort
- B = number of elements per disk block (block size)
- M = number of elements that fit in RAM
- I/O operation: transfer of one block of B elements from disk to RAM or vice versa
Goal: minimize total I/O operations.

Stable selection sort (memmove-based) requires:
1. Find minimum in unsorted portion (read blocks sequentially).
2. Shift all elements from position i to min_index-1 one block right.

**I/O Analysis**
- Each iteration reads the unsorted portion → sequential block scans:
    $$
    I/Os per iteration ≈\frac{N−i}{B}
    $$
- Worst case (sum over all iterations):
    $$
    Total I/Os=\sum_{i=0}^{N-1} \frac{N−i}{B} = \theta{frac{N^2}{B}}
    $$
- Shifting elements with memmove → may touch multiple blocks per move.

Observation: Also impractical for large disk-resident datasets.

**Implications**
1. I/O dominates CPU cost when N≫M (dataset larger than RAM).
2. Algorithms that repeatedly access or shift elements one by one are very inefficient on disk.
3. Both insertion and stable selection sort are fine for small datasets or in-memory, but not for external memory.

**Takeaways**
1. Insertion/Selection sorts are "in-memory only" — never choose them for large external datasets.
2. **I/O cost dominates**: total I/Os scale as Θ(N²/B) for these simple algorithms.
3. Stable sorting for disk → usually done via external merge sort.
4. **Trick question: "Can you sort a 1 TB dataset using insertion sort on disk?" → Answer**: Practically impossible.

### Usage In Production
Selection sort is rarely used in production systems, and the reasons are rooted in its algorithmic inefficiency, lack of adaptability, and memory access patterns. Let’s break it down clearly.

**Time Complexity Issues**
| Case    | Number of Comparisons | Number of Swaps / Moves |
| ------- | --------------------- | ----------------------- |
| Best    | Θ(n²)                 | Θ(n)                    |
| Average | Θ(n²)                 | Θ(n)                    |
| Worst   | Θ(n²)                 | Θ(n)                    |
Observations:
- Comparisons are always O(n²), even if the array is already sorted.
- Swaps are fewer than in bubble sort (Θ(n)), but the quadratic comparison cost dominates.
- For large datasets, this is extremely inefficient compared to O(n log n) algorithms like Merge Sort, Quick Sort, or Heap Sort.

**Lack of Adaptivity**
- Selection sort does not adapt to partially sorted data.
- Even if the array is already sorted, it still performs Θ(n²) comparisons.
- This makes it non-adaptive — inefficient in real-world scenarios where data may already be partially sorted.

**Stability Issues**
- Classic selection sort is not stable (swaps equal elements and can reorder duplicates).
- In production, stability is often required — for example:
        ◦ Sorting database records by a secondary key after primary key sort.
        ◦ Maintaining user input order for UI lists.
- Making selection sort stable requires extra shifting or memory (memmove), which increases data movement cost.

**Poor Cache and Memory Performance**
- Selection sort performs many random accesses in the array:
        ◦ Scanning the unsorted portion to find the minimum.
        ◦ Swapping the min element.
- These non-sequential memory accesses make it cache-unfriendly, particularly for large records or external-memory scenarios.

**External-Memory / Disk-Based Sorting**
- When sorting large datasets stored on disk:
        ◦ Each iteration reads blocks sequentially to find the minimum.
        ◦ Shifting elements for stability involves overlapping block movement (memmove), which is I/O expensive.
- Result: Θ(n²/B) I/O operations — completely impractical for modern big-data workloads.

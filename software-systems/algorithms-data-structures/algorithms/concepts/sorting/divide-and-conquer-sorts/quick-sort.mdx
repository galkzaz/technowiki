**Quicksort** is a **divide-and-conquer sorting algorithm**. It works by choosing an element called a **pivot**, rearranging the array so that elements smaller than the pivot go to one side and larger elements go to the other, and then recursively sorting the two sides.

The key idea is:

> **Partition around a pivot, then recursively sort the two partitions.**

The Quicksort algorithm selects an element in the collection (sometimes randomly, sometimes the leftmost, sometimes the middle one) to partition an array into two subarrays. Thus, Quicksort has two steps. First, the array is partitioned and then each subarray is recursively sorted

Here’s how Quicksort sorts a pile of cards:
1. If the pile has fewer than four cards, put them in the right order and you’re done. Else, continue to step 2.
2. Choose at random any card from the pile to be the pivot.
3. Cards larger than the pivot go to a new pile to the right; cards smaller than the pivot go to a new pile to the left.
4. Start this procedure for each of the two piles you just created.
5. Join the left pile, pivot and right pile to get a sorted pile.

![A sample Quicksort run](/docs/assets/software-systems/data-structures-and-algorithms/algorithms/sorting/divide-and-conquer-sorts/quick-sort/quicksort-sorts-a-pile-of-cards.png)

## The Big Picture

Suppose we have:

```text
[8, 3, 1, 7, 0, 10, 2]
```

Choose `7` as the pivot.

After partitioning:

```text
[3, 1, 0, 2]  7  [8, 10]
     smaller       larger
```

Now Quicksort recursively sorts:

```text
[3, 1, 0, 2]
```

and

```text
[8, 10]
```

Eventually:

```text
[0, 1, 2, 3, 7, 8, 10]
```

## Quicksort Structure

Conceptually:

```text
QUICKSORT(A, low, high)

    if low < high

        pivotIndex = PARTITION(A, low, high)

        QUICKSORT(A, low, pivotIndex - 1)

        QUICKSORT(A, pivotIndex + 1, high)
```

There are therefore two important operations:

```text
Quicksort
   │
   ├── Partition
   │     └── put pivot in correct position
   │
   ├── Recursively sort left side
   │
   └── Recursively sort right side
```

## The Partition Operation

Partitioning is the heart of Quicksort.

Consider:

```text
[8, 3, 1, 7, 0, 10, 2]
```

We'll use the **last element** as the pivot:

```text
pivot = 2
```

We want:

```text
elements < 2 | 2 | elements > 2
```

After partitioning, we could get:

```text
[1, 0]  2  [8, 3, 7, 10]
```

The important thing is that **2 is now in its final sorted position**.

It doesn't matter that the two sides aren't sorted yet.


## Lomuto Partition Scheme

One common implementation uses the **Lomuto partition scheme**.

For:

```text
[8, 3, 1, 7, 0, 10, 2]
```

we choose:

```text
pivot = 2
```

Maintain an index `i` representing the boundary between elements smaller than the pivot and the rest.

Initially:

```text
i = low - 1
```

So:

```text
i = -1
```

Then scan the array from left to right.

1. Element `8`

```text
8 > 2
```

Do nothing.

```text
[8, 3, 1, 7, 0, 10, 2]
 ^
```

2. Element `3`

```text
3 > 2
```

Do nothing.

3. Element `1`

```text
1 < 2
```

Increment `i` and swap.

```text
[1, 3, 8, 7, 0, 10, 2]
```

4. Element `7`

```text
7 > 2
```

Do nothing.

5. Element `0`

```text
0 < 2
```

Increment `i` and swap:

```text
[1, 0, 8, 7, 3, 10, 2]
```

6. Element `10`

```text
10 > 2
```

Do nothing.

Finally, put the pivot immediately after the smaller elements:

```text
[1, 0, 2, 7, 3, 10, 8]
       ^
     pivot
```

Now `2` is in its final position.

---

7. Recursive Calls

We now have:

```text
[1, 0]  2  [7, 3, 10, 8]
```

Quicksort recursively processes:

```text
[1, 0]
```

and:

```text
[7, 3, 10, 8]
```

For the left side:

```text
[1, 0]
```

Choose:

```text
pivot = 0
```

Partition:

```text
[0, 1]
```

For the right side:

```text
[7, 3, 10, 8]
```

Choose:

```text
pivot = 8
```

Partition:

```text
[7, 3]  8  [10]
```

Then:

```text
[7, 3]
```

becomes:

```text
[3, 7]
```

Final result:

```text
[0, 1, 2, 3, 7, 8, 10]
```

**Recursion Tree**

The process can be visualized as:

```text
                    [8,3,1,7,0,10,2]
                            |
                         pivot=2
                            |
              ┌─────────────┴─────────────┐
              ↓                           ↓
          [1,0]                       [7,3,10,8]
            |                              |
         pivot=0                         pivot=8
            |                              |
          [0,1]                    ┌───────┴───────┐
                                   ↓               ↓
                                 [3,7]            [10]
                                   |
                                 [3,7]

Result:

[0,1,2,3,7,8,10]
```

The recursion tree is the reason Quicksort is a **divide-and-conquer** algorithm.

## Why Does It Work?

The crucial property is:

> After partitioning, the pivot is in its final sorted position.

Suppose:

```text
[smaller elements] pivot [larger elements]
```

Because every element on the left is smaller than the pivot, and every element on the right is larger, the pivot doesn't need to move again.

We only need to solve two smaller problems:

```text
sort(left)
sort(right)
```

Eventually each subarray contains zero or one element.

A zero- or one-element array is already sorted.

## Base Case

The recursive algorithm stops when:

```text
low >= high
```

Why? Because:

```text
one element → already sorted
zero elements → already sorted
```

For example:

```text
[5]
```

doesn't need sorting.

## Implementation
**C Implementation**

```c
#include <stdio.h>

void swap(int *a, int *b)
{
    int temp = *a;
    *a = *b;
    *b = temp;
}

int partition(int arr[], int low, int high)
{
    int pivot = arr[high];

    int i = low - 1;

    for (int j = low; j < high; j++)
    {
        if (arr[j] < pivot)
        {
            i++;
            swap(&arr[i], &arr[j]);
        }
    }

    // Put pivot in its final position
    swap(&arr[i + 1], &arr[high]);

    return i + 1;
}

void quicksort(int arr[], int low, int high)
{
    if (low < high)
    {
        int pivotIndex = partition(arr, low, high);

        quicksort(arr, low, pivotIndex - 1);
        quicksort(arr, pivotIndex + 1, high);
    }
}

void printArray(int arr[], int n)
{
    for (int i = 0; i < n; i++)
        printf("%d ", arr[i]);

    printf("\n");
}

int main()
{
    int arr[] = {8, 3, 1, 7, 0, 10, 2};

    int n = sizeof(arr) / sizeof(arr[0]);

    printf("Before sorting:\n");
    printArray(arr, n);

    quicksort(arr, 0, n - 1);

    printf("After sorting:\n");
    printArray(arr, n);

    return 0;
}
```

Output:

```text
Before sorting:
8 3 1 7 0 10 2

After sorting:
0 1 2 3 7 8 10
```

**Java Implementation**

```java
public class QuickSort {

    static int partition(int[] arr, int low, int high) {

        int pivot = arr[high];

        int i = low - 1;

        for (int j = low; j < high; j++) {

            if (arr[j] < pivot) {
                i++;

                int temp = arr[i];
                arr[i] = arr[j];
                arr[j] = temp;
            }
        }

        // Put pivot in final position
        int temp = arr[i + 1];
        arr[i + 1] = arr[high];
        arr[high] = temp;

        return i + 1;
    }

    static void quicksort(int[] arr, int low, int high) {

        if (low < high) {

            int pivotIndex = partition(arr, low, high);

            quicksort(arr, low, pivotIndex - 1);
            quicksort(arr, pivotIndex + 1, high);
        }
    }

    public static void main(String[] args) {

        int[] arr = {8, 3, 1, 7, 0, 10, 2};

        quicksort(arr, 0, arr.length - 1);

        for (int x : arr) {
            System.out.print(x + " ");
        }

        System.out.println();
    }
}
```

## Context
Quicksort exhibits worst-case quadratic behavior if the partitioning at each recursive step only divides a collection of n elements into an “empty” and “large” set,
where one of these sets has no elements and the other has n − 1 (note that the pivot element provides the last of the n elements, so no element is lost)

## Time Complexity

The performance depends heavily on **how the pivot divides the array**.

#### Best case

Suppose every partition divides the array approximately in half:

```text
             n
           /   \
        n/2     n/2
        / \     / \
      n/4 n/4 n/4 n/4
```

The recursion depth is approximately:

```text
log₂ n
```

At every level, partitioning processes approximately `n` elements.

Therefore:

```text
T(n) = 2T(n/2) + O(n)
```

giving:

```text
O(n log n)
```

---

#### Average case

With reasonably balanced partitions on average:

```text
O(n log n)
```

This is why Quicksort is generally considered a very efficient comparison-based sorting algorithm.

---

#### Worst case

Suppose the pivot is always the smallest or largest element:

```text
n
|
n-1
|
n-2
|
n-3
|
...
|
1
```

Then:

```text
T(n) = T(n - 1) + O(n)
```

which gives:

```text
O(n²)
```

For example, if we always choose the **last element** as the pivot:

```text
[1, 2, 3, 4, 5, 6, 7]
```

the pivot is always the largest element.

The partitions become:

```text
[] | 1 | [2,3,4,5,6,7]

[] | 2 | [3,4,5,6,7]

[] | 3 | [4,5,6,7]

...
```

That's a very unbalanced recursion tree.

## Space Complexity

Quicksort is interesting because it can sort **in-place**.

It doesn't require another array proportional to `n`.

However, recursion requires stack space.

#### Balanced recursion

```text
O(log n)
```

#### Worst-case recursion

```text
O(n)
```

So:

| Case    |         Time | Auxiliary Stack |
| ------- | -----------: | --------------: |
| Best    | `O(n log n)` |      `O(log n)` |
| Average | `O(n log n)` |      `O(log n)` |
| Worst   |      `O(n²)` |          `O(n)` |


## Pivot Selection

Pivot selection is extremely important.

Figure shows Quicksort in action. Each of the black squares represents a pivot selection. The first pivot selected is “2,” which turns out to be a poor choice since it produces two subarrays of size 1 and size 14. During the next recursive invocation of Quicksort on the right subarray, “12” is selected to be the pivot (shown in the fourth row down), which produces two subarrays of size 9 and 4, respectively. Already you can see the benefit of using partition since the last four elements in the array are, in fact, the largest four elements, although they are still unordered. Because of the random nature of the pivot selection, different behaviors are possible. 

![Sample Quicksort execution](/docs/assets/software-systems/data-structures-and-algorithms/algorithms/sorting/divide-and-conquer-sorts/quick-sort/pivot-selection1.png)
In a different execution, shown in Figure 4-8, the first selected pivot nicely sub‐
divides the problem into two more or less comparable tasks
![Sample Quicksort execution](/docs/assets/software-systems/data-structures-and-algorithms/algorithms/sorting/divide-and-conquer-sorts/quick-sort/pivot-selection2.png)

Selecting the pivot element from a subarray A[left, left + n) must be an efficient operation; it shouldn’t require checking all n elements of the subarray.

Often one chooses median-of-three; Sedgewick reports that this approach returns an improvement of 5%, but note that some arrangements of data will force even this alternative into subpar performance (Musser, 1997). A median-of-five pivot selection has also been used. Performing further computation to identify the proper pivot rarely provides beneficial results because of the extra computational costs

Common strategies include:

#### First element

```text
pivot = arr[low]
```

Simple, but can perform badly on already sorted data.

#### Last element

```text
pivot = arr[high]
```

Very simple and commonly used for teaching.

#### Random pivot

Choose a random element:

```text
pivot = arr[random_index]
```

This reduces the likelihood of consistently encountering pathological input.

#### Median-of-three

Choose the median of:

```text
first
middle
last
```

For example:

```text
[2, 9, 5, 1, 7, 8, 3]
 ^        ^        ^
first   middle    last
```

Values:

```text
2, 1, 3
```

Median:

```text
2
```

Use that as the pivot.

## Analysis
Surprisingly, using a random element as pivot enables Quicksort to provide an
average-case performance that usually outperforms other sorting algorithms. In
addition, there are numerous enhancements and optimizations researched for
Quicksort that have achieved the most efficiency out of any sorting algorithm.
In the ideal case, partition divides the original array in half and Quicksort exhibits O(n log n) performance. In practice, Quicksort is effective with a randomly
selected pivot.

In the worst case, the largest or smallest item is picked as the pivot. When this happens, Quicksort makes a pass over all elements in the array (in linear time) to sort just a single item in the array. If this process is repeated n − 1 times, it will result in
O(n2) worst-case behavior.

## Variations
Quicksort is the sorting method of choice on most systems. On Unix-based sys‐
tems, there is a built-in library function called qsort. Often, the operating system
uses optimized versions of the default Quicksort algorithm. Two of the commonly
cited sources for optimizations are by Sedgewick (1978) and Bentley and McIlroy (1993). It is instructive that some versions of the Linux operating system implement
qsort using Heap Sort.
Various optimizations include:
• Create a stack that stores the subtasks to be processed to eliminate recursion
• Choose the pivot based on median-of-three strategy
• Set the minimum partition size below which to use Insertion Sort instead
which varies by implementation and machine architecture; in JDK 1.8, the
threshold value is set to 7
• When processing the two subproblems, minimize the total size of the recursive
stack by solving the smaller subproblem first 

However, none of these optimizations will eliminate the O(n2) worst-case behavior
of Quicksort. The only way to ensure an O(n log n) worst-case performance is to
use a partition function that can guarantee it finds a “reasonable approximation” to
the actual median of that set. The Blum-Floyd-Pratt-Rivest-Tarjan (BFPRT) partition algorithm (Blum et al., 1973) is a provably linear time algorithm, but it has only theoretical value.

### Picking a pivot
Selecting the pivot element from a subarray A[left, left + n) must be an efficient
operation; it shouldn’t require checking all n elements of the subarray. Some alternatives are:
• Select first or last: A[left] or A[left + n − 1]
• Select random element in A[left, left + n − 1]
• Select median-of-k: the middle value of k elements taken from A[left, left + n −
1]
Often one chooses median-of-three; Sedgewick reports that this approach returns
an improvement of 5%, but note that some arrangements of data will force even this
alternative into subpar performance (Musser, 1997). A median-of-five pivot selection has also been used. Performing further computation to identify the proper
pivot rarely provides beneficial results because of the extra computational costs.

### Processing subarrays
Quicksort yields two recursive invocations of Quicksort on smaller subarrays.
While processing one, the activation record of the other is pushed onto the execution stack. If the larger subarray is processed first, it is possible to have a linear
number of activation records on the stack at the same time (although modern compilers may eliminate this observed overhead). To minimize the possible depth of the
stack, process the smaller subarray first. If the depth of the recursion is a foreseeable
issue, then perhaps Quicksort is not appropriate for your application.
### Processing the partition
In the partition method, elements less than or equal to the selected pivot are inserted toward the front of the subarray. This approach might skew the size of the subarrays for the recursive step if the selected pivot has many duplicate elements in the array. One way to reduce the imbalance is to place elements equal to the pivot alternatively in the first and second subarrays.

### Using simpler insertion sort technique for small subarrays
On small arrays, Insertion Sort is faster than Quicksort, but even when used on
large arrays, Quicksort ultimately decomposes the problem to require numerous
small subarrays to be sorted. One commonly used technique to improve the recursive performance of Quicksort is to invoke Quicksort for large subarrays only, and
use Insertion Sort for small ones, as shown in next code.
Sedgewick (1978) suggests that a combination of median-of-three and using Insertion Sort for small subarrays offers a speedup of 20%–25% over pure Quicksort.

```c
#include <stdio.h>
#include <stdlib.h>

/* small threshold for switching to insertion sort */
static const int minSize = 10;

/* forward declarations for helpers used by do_qsort */
int selectPivotIndex(void **ar, int left, int right);
void insertion(void **ar, int (*cmp)(const void *, const void *), int left, int right);

/**
 * In linear time, group the subarray ar[left, right] around a pivot
 * element pivot=ar[pivotIndex] by storing pivot into its proper
 * location, store, within the subarray (whose location is returned
 * by this function) and ensuring all ar[left,store) <= pivot and
 * all ar[store+1,right] > pivot.
 */
int partition(void **ar, int (*cmp)(const void *, const void *),
              int left, int right, int pivotIndex)
{
    int idx, store;
    void *pivot = ar[pivotIndex];
    /* move pivot to the end of the array */
    void *tmp = ar[right];
    ar[right] = ar[pivotIndex];
    ar[pivotIndex] = tmp;
    /* all values <= pivot are moved to front of array and pivot inserted
     * just after them. */
    store = left;
    for (idx = left; idx < right; idx++)
    {
        if (cmp(ar[idx], pivot) <= 0)
        {
            tmp = ar[idx];
            ar[idx] = ar[store];
            ar[store] = tmp;
            store++;
        }
    }
    tmp = ar[right];
    ar[right] = ar[store];
    ar[store] = tmp;
    return store;
}
/**
 * Sort array ar[left,right] using Quicksort method.
 * The comparison function, cmp, is needed to properly compare elements.
 */
void do_qsort(void **ar, int (*cmp)(const void *, const void *),
              int left, int right)
{
    int pivotIndex;
    if (right <= left)
    {
        return;
    }
    /* partition */
    pivotIndex = selectPivotIndex(ar, left, right);
    pivotIndex = partition(ar, cmp, left, right, pivotIndex);
    if (pivotIndex - 1 - left <= minSize)
    {
        insertion(ar, cmp, left, pivotIndex - 1);
    }
    else
    {
        do_qsort(ar, cmp, left, pivotIndex - 1);
    }
    if (right - pivotIndex - 1 <= minSize)
    {
        insertion(ar, cmp, pivotIndex + 1, right);
    }
    else
    {
        do_qsort(ar, cmp, pivotIndex + 1, right);
    }
}
/** Qsort straight */
void sortPointers(void **vals, int total_elems,
                  int (*cmp)(const void *, const void *))
{
    do_qsort(vals, cmp, 0, total_elems - 1);
}

/* ------------------- Test / helper code ------------------- */

int cmp_int(const void *a, const void *b)
{
    int ia = *(const int *)a;
    int ib = *(const int *)b;
    return (ia > ib) - (ia < ib);
}

int selectPivotIndex(void **ar, int left, int right)
{
    /* simple middle pivot */
    (void)ar;
    return left + (right - left) / 2;
}

void insertion(void **ar, int (*cmp)(const void *, const void *), int left, int right)
{
    int i, j;
    for (i = left + 1; i <= right; i++)
    {
        void *key = ar[i];
        j = i - 1;
        while (j >= left && cmp(ar[j], key) > 0)
        {
            ar[j + 1] = ar[j];
            j--;
        }
        ar[j + 1] = key;
    }
}

int main(void)
{
    int data[] = {33, 10, 55, 71, 29, 3, 18, 42, 90, 1, 67, 8, 24};
    int n = sizeof(data) / sizeof(data[0]);
    void **vals = malloc(n * sizeof(void *));
    if (!vals)
        return 1;
    for (int i = 0; i < n; i++)
        vals[i] = &data[i];

    printf("Before:\n");
    for (int i = 0; i < n; i++)
        printf("%d ", *(int *)vals[i]);
    printf("\n");

    sortPointers(vals, n, cmp_int);

    printf("After:\n");
    for (int i = 0; i < n; i++)
        printf("%d ", *(int *)vals[i]);
    printf("\n");

    free(vals);
    return 0;
}
```
### IntroSort(Introspective Sort)
Switching to Insertion Sort for small subarrays is a local decision that is made based upon the size of the subarray. Musser (1997) introduced a Quicksort variation called IntroSort, which monitors the recursive depth of Quicksort to ensure efficient processing. If the depth of the Quicksort recursion exceeds log (n) levels, then IntroSort switches to Heap Sort. 

Designed by David Musser, IntroSort is a hybrid algorithm that dynamically switches between three different sorting techniques to achieve optimal performance and a guaranteed worst-case time complexity of \(O(N \log N)\):QuickSort: It begins with QuickSort using a median-of-three pivot selection for high-speed execution.HeapSort: If the recursion depth exceeds a threshold (typically \(2 \times \log_2 N\)), it switches to HeapSort to prevent the \(O(N^2)\) worst-case performance of QuickSort.Insertion Sort: If a partition size falls below a specific threshold (16 elements in the SGI implementation), it stops recursing and finishes with a final Insertion Sort pass, which is highly efficient for small datasets.This design proved so successful that major modern standard C++ library implementations—including GNU libstdc++ and LLVM libc++—adopted IntroSort variants as their default engine for std::sort
## Quicksort vs Merge Sort

Both are divide-and-conquer algorithms, but they divide the problem differently.

#### Merge Sort

First divide:

```text
        [8 3 1 7 0 10 2]
             /      \
        [8 3 1]    [7 0 10 2]
```

Then sort and **merge**.

```text
divide → recursively sort → merge
```

#### Quicksort

First **partition around a pivot**:

```text
[1 0]  2  [7 3 10 8]
```

Then recursively sort the partitions.

```text
partition → recursively sort
```

Comparison:

| Property       | Quicksort            | Merge Sort            |
| -------------- | -------------------- | --------------------- |
| Paradigm       | Divide & conquer     | Divide & conquer      |
| Main operation | Partition            | Merge                 |
| Average time   | `O(n log n)`         | `O(n log n)`          |
| Worst time     | `O(n²)`              | `O(n log n)`          |
| Extra array    | Usually no           | Usually yes           |
| In-place       | Yes, common variants | Usually no for arrays |
| Stable         | Usually no           | Yes                   |
| Cache locality | Generally good       | Good                  |
| Recursion      | Yes                  | Yes                   |


## The Most Important Concept

Don't memorize Quicksort as a sequence of swaps.

Understand this invariant:

```text
                pivot
                  ↓
[ elements < pivot ][ pivot ][ elements > pivot ]
```

After partitioning:

```text
                 ✓
                 pivot
                  ↓
[ smaller ][ pivot ][ larger ]
```

The pivot is **finished**.

Then:

```text
Quicksort(smaller)
Quicksort(larger)
```

That's the entire algorithm.

## Quicksort in the Divide-and-Conquer Hierarchy

Since you're studying algorithms systematically, place Quicksort here:

```text
Algorithms
│
├── Searching
│
├── Sorting
│   │
│   ├── Simple Sorting
│   │   ├── Bubble Sort
│   │   ├── Selection Sort
│   │   └── Insertion Sort
│   │
│   ├── Divide and Conquer
│   │   ├── Merge Sort
│   │   └── Quicksort
│   │
│   └── Non-comparison Sorting
│       ├── Counting Sort
│       ├── Radix Sort
│       └── Bucket Sort
│
└── Algorithmic Paradigms
    ├── Brute Force
    ├── Divide and Conquer
    ├── Greedy
    ├── Dynamic Programming
    └── Backtracking
```

The key distinction is:

```text
Merge Sort:
    divide first
    merge later

Quicksort:
    partition first
    recursively sort later
```

And the **partition operation** is the concept you should master before moving on to Quicksort optimizations such as **Hoare partitioning, randomized Quicksort, 3-way partitioning, and tail-recursion optimization**.

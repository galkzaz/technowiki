
## 8. Radix Sort

Radix Sort takes a different approach.

Instead of sorting numbers based on their entire values, it sorts them **digit by digit**.

Consider:

```text
[170, 45, 75, 90, 802, 24, 2, 66]
```

We can process:

```text
ones digit
tens digit
```

For example:

```text
170 → 0
45  → 5
75  → 5
90  → 0
802 → 2
24  → 4
2   → 2
66  → 6
```

After sorting by the ones digit, we continue with the tens digit, then hundreds digit.

---

## 9. LSD Radix Sort

The most common version is **LSD Radix Sort**:

**Least Significant Digit first.**

For:

```text
329
457
657
839
436
720
355
```

we process:

```text
ones
↓
tens
↓
hundreds
```

The crucial requirement is that each digit-level sorting operation is **stable**.

Usually Counting Sort is used as the internal sorting algorithm.

So:

```text
Radix Sort
    ↓
Counting Sort
    ↓
digit by digit
```

---

## 10. Why Stability Matters in Radix Sort

Suppose we have:

```text
21
31
12
```

After sorting by the ones digit:

```text
21
31
12
```

Both `21` and `31` have the same ones digit.

Their relative order must be preserved.

Then we sort by the tens digit.

Because the previous ordering is preserved among equal digits, the final result becomes:

```text
12
21
31
```

This is why LSD Radix Sort requires a **stable** sorting algorithm for each digit.

---

## 11. Radix Sort Complexity

Let:

* \(n\) = number of elements
* \(d\) = number of digits
* \(k\) = number of possible digit values

For decimal numbers:

$$
k=10
$$

Using Counting Sort for each digit:

$$
O(d(n+k))
$$

If \(k=10\):

$$
O(dn)
$$

If the number of digits \(d\) is fixed, this can behave like:

$$
O(n)
$$

This is how Radix Sort can beat the \(O(n\log n)\) comparison-sorting bound.

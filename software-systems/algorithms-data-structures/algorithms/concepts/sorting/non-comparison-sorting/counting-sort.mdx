
## 4. Counting Sort

Counting Sort is usually the easiest non-comparison sorting algorithm to understand.

Suppose we have:

```text
[4, 2, 2, 8, 3, 3, 1]
```

The values range from:

```text
1 ... 8
```

We create a count array:

```text
Value:  0 1 2 3 4 5 6 7 8
Count:  0 1 2 2 1 0 0 0 1
```

This tells us:

```text
1 appears 1 time
2 appears 2 times
3 appears 2 times
4 appears 1 time
8 appears 1 time
```

Then reconstruct:

```text
[1, 2, 2, 3, 3, 4, 8]
```

---

### Counting Sort algorithm

Conceptually:

```text
find minimum and maximum

create count array

for each element:
    count[element]++

for each possible value:
    output it count[value] times
```

For example:

```text
Input:

[4, 2, 2, 8, 3, 3, 1]

Count:

1 → 1
2 → 2
3 → 2
4 → 1
8 → 1

Output:

[1, 2, 2, 3, 3, 4, 8]
```

---

## 5. Counting Sort Complexity

Suppose:

$$
n = \text{"number of elements"}
$$

and:

$$
k = \text{"range of values"}
$$

Then:

$$
T(n)=O(n+k)
$$

Space:

$$
O(k)
$$

This can be extremely efficient when \(k\) is small.

For example:

```text
n = 1,000,000
values = 0 ... 100
```

Then:

$$
O(n+k)
=
O(1,000,000+101)
$$

which is essentially:

$$
O(n)
$$

---

## 6. The Problem with Counting Sort

Consider:

```text
[1, 999,999, 500,000]
```

The range is:

```text
1 ... 999999
```

We would need a huge count array.

Even though:

```text
n = 3
```

we might need:

```text
k ≈ 1,000,000
```

Therefore:

$$
O(n+k)
$$

could be much worse than \(O(n\log n)\).

So Counting Sort works particularly well when:

```text
k is not much larger than n
```

## 7. Counting Sort with Negative Numbers

Counting Sort can also handle negative integers.

For:

```text
[-3, -1, -3, 2, 0]
```

we can shift the values.

Minimum:

```text
-3
```

Map:

```text
-3 → 0
-2 → 1
-1 → 2
 0 → 3
 1 → 4
 2 → 5
```

The transformation is:

$$
index = value - min
$$

So:

```text
-3 → -3 - (-3) = 0
-1 → -1 - (-3) = 2
 2 →  2 - (-3) = 5
```

This allows the same counting technique.

An **array** is the simplest and most fundamental data structure used to store a collection of elements of the same type in contiguous memory locations.

Formally: **Array**: A linear data structure that stores elements in contiguous memory and allows direct access using an index.

Example:
```
Index:   0   1   2   3   4
Array:  [5] [2] [4] [6] [1]
```
- Each element has an index (position).
- The index usually starts from 0 in most programming languages (C, C++, Python, Java).

The **Array** is the simplest way to store a bunch of items in computer memory. It consists in allocating a sequential space in the computer memory, and writing your items sequentially in that space, marking the end of the sequence with a special `NULL` token.

Each object in an array occupies the same amount of space in memory. 

Imagine an array starting at memory address `s`, where each item occupy `b` bytes. The `nth` item in the array can be obtained fetching `b` bytes starting from memory position `s + (b × n)`.

```
Memory Contents
+-----+-----+-----+-----+-----+-----+-----+-----+
|     |     |  A  |  B  |  C  |  D  | Null|     |
+-----+-----+-----+-----+-----+-----+-----+-----+
-------------------------------------------------
+-----+-----+-----+-----+-----+-----+-----+-----+
|  11 |  12 |  13 |  14 |  15 |  16 |  17 |     |
+-----+-----+-----+-----+-----+-----+-----+-----+
Memory Addresses
```
This lets us access any item from an array instantly. 

Example in memory:

Memory Address
```
1000 → 5
1004 → 2
1008 → 4
1012 → 6
1016 → 1
```
If each integer = 4 bytes, then
```
Address of A[i] = Base Address + (i × size_of_element)
```
Example:
```
A[3] = 1000 + (3 × 4)
     = 1012
```
This is why array access is extremely fast.

So An **array** is a contiguous block of memory storing elements of the same type that allows **constant-time indexed access**, making it the **fundamental building block of many data structures and algorithms**.
## Key Characteristics of Arrays
| Property               | Explanation                         |
| ---------------------- | ----------------------------------- |
| **Linear structure**   | Elements are arranged sequentially  |
| **Contiguous memory**  | Stored in adjacent memory locations |
| **Fixed size**         | Size usually determined at creation |
| **Index-based access** | Elements accessed using index       |
| **Homogeneous**        | Same data type                      |

## Array as an Abstract Data Type
Conceptually an array is:
```
A : Index → Value
```
Example:
```
A(0) = 5
A(1) = 2
A(2) = 4
```
Operations:
| Operation  | Meaning            |
| ---------- | ------------------ |
| create     | allocate array     |
| read(i)    | get element        |
| write(i,x) | set element        |
| length     | number of elements |

## Arrays and Data Structures
Arrays are the foundation of many other data structures and algorithms.

Many Data Structures Use Arrays Internally. Arrays are used because of:
- fast access
- compact memory
- good cache performance

| Data Structure      | How Array is Used    |
| ------------------- | -------------------- |
| Stack               | top index in array   |
| Queue               | circular array       |
| Heap                | tree stored in array |
| Hash Table          | bucket array         |
| Dynamic Programming | DP table             |

They provide:
1. **Fast Random Access**

Accessing any element takes constant time.

Time Complexity: O(1)

Example:
```
A[1000]
```
The system directly computes the address.

2. **Efficient Memory Layout**

Because arrays are contiguous, they:
- use memory efficiently
- benefit from CPU cache locality(CPU cache locality refers to the principle that programs tend to reuse data/instructions recently accessed (temporal locality) or access data located near each other in memory (spatial locality).)

This makes arrays very fast in practice.

3. **Building Block for Other Data Structures**

The Array is especially useful for implementing the Stack, but can also used to implement Lists and Queues. Arrays are simple to code and have the advantage of instant access time.

Many structures are implemented using arrays.
| Data Structure | How Array is Used                  |
| -------------- | ---------------------------------- |
| Stack          | Array-based stack                  |
| Queue          | Circular array queue               |
| Heap           | Binary heap stored in array        |
| Hash table     | Array of buckets                   |
| Matrix         | 2D array                           |
| Dynamic Array  | Resizable array (like Python list) |

**Example: Binary Heap representation:**
```
Index:   0   1   2   3   4   5
Heap:   [1] [3] [2] [7] [6] [4]
```
Tree structure stored inside an array.

Tree relationships:
- parent = (i-1)/2
- left = 2i + 1
- right = 2i + 2

This works only because of arrays.

## Advantages of Arrays
| Advantage               | Reason               |
| ----------------------- | -------------------- |
| Very fast access        | O(1) indexing        |
| Cache friendly          | contiguous memory    |
| Simple structure        | easy implementation  |
| Efficient for iteration | sequential traversal |

## Disadvantages of Arrays
Arrays are simple to code and have the advantage of instant access time. But they also have disadvantages.
1. It can be impractical to allocate large amounts of sequential space in the memory. 
2. If you need to grow an array, there might not be enough free space adjacent to it in the memory. 
3. **Removing an item in the middle is problematic**: you have to push all subsequent items one step back, or mark the removed item’s memory space as "dead". Neither option is desirable. 
4. Similarly, adding an item causes you to push all subsequent items one step forward.

| Limitation          | Explanation         |
| ------------------- | ------------------- |
| Fixed size          | Cannot grow easily  |
| Expensive insertion | Requires shifting   |
| Expensive deletion  | Requires shifting   |
| Homogeneous         | Same data type only |

These limitations led to other structures like:
- linked lists
- dynamic arrays
- trees

```c
#include <stdio.h>

void printArray(int arr[], int size) {
    for (int i = 0; i < size; i++) {
        printf("%d ", arr[i]);
    }
    printf("\n");
}

int main() {
    int arr[6] = {5, 2, 4, 6, 1, 0};
    int size = 5;
    int index = 2;
    int value = 10;

    // Shift elements to the right
    for (int i = size; i > index; i--) {
        arr[i] = arr[i - 1];
    }

    // Insert new element
    arr[index] = value;
    size++;

    printf("After insertion: ");
    printArray(arr, size);  // Output: 5 2 10 4 6 1

    return 0;
}
```

```c
    for (int i = 0; i < size; i++) {
```

```c
#include <stdio.h>

int linearSearch(int arr[], int size, int target) {
    for (int i = 0; i < size; i++) {
        if (arr[i] == target) {
            return i;
        }
    }
    return -1;  // Not found
}

int main() {
    int arr[5] = {5, 2, 4, 6, 1};

    int index = linearSearch(arr, 5, 4);

    if (index != -1) {
        printf("Element found at index: %d\n", index);  // Output: 2
    } else {
        printf("Element not found\n");
    }

    return 0;
}
```

**Traversal Operation**

<Tabs>
  <TabItem value="c" label="C" default>
```c
#include <stdio.h>

int main() {
    int arr[5] = {5, 2, 4, 6, 1};

    // Forward traversal
    printf("Forward: ");
    for (int i = 0; i < 5; i++) {
        printf("%d ", arr[i]);
    }
    printf("\n");  // Output: 5 2 4 6 1

    // Backward traversal
    printf("Backward: ");
    for (int i = 4; i >= 0; i--) {
        printf("%d ", arr[i]);
    }
    printf("\n");  // Output: 1 6 4 2 5

    return 0;
```

## Memory Layout & Address Calculation
Think of an array as:
Numbered boxes in a row
```
  0   1   2   3   4
┌───┬───┬───┬───┬───┐
│ 5 │ 2 │ 4 │ 6 │ 1 │
└───┴───┴───┴───┴───┘
```
Each box can be accessed instantly using its number.

The most important theoretical property of arrays is: **Contiguous memory storage**

Example:

Array:
```
A = [5,2,4,6,1]
```
Memory layout:
```
Address      Value
1000         5
1004         2
1008         4
1012         6
1016         1
```
If element size = 4 bytes.

**Address Calculation Formula**

To access any element quickly, computers use:
```
Address(A[i]) = Base + (i × element_size)
```
Example
```
Base = 1000
element_size = 4
i = 3
```
```
Address = 1000 + (3 × 4)
        = 1012
```
This is why: Array Access = O(1)

## CPU Cache Performance

Example: Memory
```

```
If CPU reads first element: `5`

It automatically loads:
```
5 2 4 6
```
So iteration becomes very fast. This property is called: **Spatial Locality**
## Array In Programming Languages
In C, an array is simply a contiguous block of memory containing elements of the same type.

Example:
```
int A[5] = {5,2,4,6,1};
```
Memory representation:
```
Address      Value
1000         5
1004         2
1008         4
1012         6
1016         1
```
If an int occupies 4 bytes, the elements are stored back-to-back.

So internally:
```
A = address of first element
```
**Array Name Is Essentially a Pointer**

In C, the array name behaves like **a pointer to the first element**.

Example:
```c
int A[5];
```
Internally:
```
A → &A[0]
```
So:
```
A == &A[0]
```
Both refer to the base address.

Example:
```c
printf("%p\n", A);
printf("%p\n", &A[0]);
```
These print the same address.

**How Indexing Works Internally**

When you write:
```c
A[i]
```
The compiler converts it to:
```
*(A + i)
```
Which means:
1. Take base address
2. Move i elements forward
3. Dereference the pointer

More precisely:
```
Address = Base + (i × sizeof(type))
```
Example:
- Base = 1000
- i = 3
- sizeof(int) = 4
- Address = 1000 + (3 × 4)
          = 1012

Then C reads the value stored at 1012.

In C:
```
Array = Pointer + Contiguous Memory
```
So arrays are essentially:
```
memory block + indexing arithmetic
```
This simplicity is why C is considered close to hardware.

Internally, C manages arrays by:
1. Allocating contiguous memory
2. Treating the array name as a pointer to the first element
3. Translating indexing A[i] into pointer arithmetic
4. Computing addresses using
    ```
    Base + (index × element_size)
    ```

This design gives very fast memory access and efficient low-level control.

Arrays in C exist in two layers:

Language Level
```c
A[i]
```
A convenient syntax.

Machine Level
```
*(base + offset)
```
Pure memory access.

### Internal Representation

In C, arrays are mostly a language-level abstraction that the compiler translates directly into memory layout and assembly instructions, rather than being implemented by a runtime library or data structure.

In many languages, arrays are runtime objects.
Example:
- Python list → implemented in CPython
- Java array → managed by JVM
- C++ vector → implemented in the STL library

But in C:
```c
int A[5];
```
This is not a runtime object.
It simply means:
```
Reserve 5 × sizeof(int) bytes of memory
```
So the compiler just allocates memory.

What the Compiler Actually Generates

Example:
```c
int A[5];
A[2] = 10;
```
The compiler translates this roughly into assembly like:
```
load base address of A
compute offset = 2 × 4
store 10 at (base + offset)
```
Conceptually:
```
mov rax, A        ; base address
mov rbx, 2
imul rbx, 4       ; multiply by element size
add rax, rbx      ; compute address
mov [rax], 10     ; store value
```
There is no array object, only address arithmetic.

**What the Compiler Handles**

The compiler is responsible for:

1. **Memory Allocation**

Example:
```c
int A[5];
```
Compiler reserves: 20 bytes

2. **Index Translation**

Example:
```c
A[i]
```
becomes:
```
*(A + i)
```
And then:
```
Base + i × sizeof(type)
```

3. **Type Checking**

The compiler ensures:
```
A[3] = 5;
```
matches the element type.

**What the CPU Actually Sees**

```
stores
arithmetic

```

```
1016 → 1
```
Accessing `A[3]` simply means: read memory at address 1012.

- dynamic resizing
- garbage collection
- metadata storage

C does none of this. Array access becomes pure pointer arithmetic.

The Only "Implementation" Is Memory Layout, So, C defines only how arrays must be laid out in memory:

Rule: Elements must be contiguous

Meaning: A[i+1] immediately follows A[i]

Everything else is just arithmetic.

Example

Conceptual translation:

### Compiler basic array operations
In RISC-V (and most CPUs): Arrays do not exist at hardware level

The CPU only understands:
- load
- store
- add
- shift
- branch

Array indexing is compiled into these primitive instructions.
Below is a conceptual view of how basic array operations in C translate into RISC-V assembly.

Assumptions:
- Architecture: RISC-V RV64
- int size = 4 bytes
- Array base address stored in register
- Registers follow RISC-V ABI:
    * a0–a7 → function arguments
    * t0–t6 → temporaries
    * s0–s11 → saved registers

1. **Declaring an Array**

C Code
```
int A[5];
```
If this is a global array, the compiler places it in the data section.

RISC-V Assembly
```nasm
.data
A: .space 20
```
Explanation:
```
5 elements × 4 bytes = 20 bytes
```
So memory becomes:
```
A:
1000 → A[0]
1004 → A[1]
1008 → A[2]
1012 → A[3]
1016 → A[4]
```

2. **Access Operation (Read)**

C Code
```c
x = A[2];
```
Address Calculation
```
Address = base + (index × element_size)
        = A + (2 × 4)
        = A + 8
```
RISC-V Assembly
```nasm
la   t0, A       # load address of array A
lw   t1, 8(t0)   # load word at A + 8  → A[2]
mv   a0, t1      # store result in x (example)
```
Explanation:
- la  → load address
- lw  → load 32-bit word

So:
```
lw t1, 8(t0)
```
means:
```
t1 = *(t0 + 8)
```

3. **Write Operation (Update)**

C Code
```
A[3] = 10;
```
Address Calculation
```
A + (3 × 4) = A + 12
```
RISC-V Assembly
```nasm
la   t0, A
li   t1, 10
sw   t1, 12(t0)
```
Explanation:
- sw = store word

So:
```
*(A + 12) = 10
```
4. **Access With Variable Index**

C Code
```c
x = A[i];
```
Now the offset must be computed at runtime.

Address Formula
```
A + (i × 4)
```
RISC-V Assembly
```nasm
la   t0, A        # base address
slli t1, a1, 2    # t1 = i * 4
add  t2, t0, t1   # address = A + offset
lw   t3, 0(t2)    # load A[i]
```
Explanation:
- slli = shift left logical immediate
- `i * 4 = i << 2`

This is a very common compiler optimization.

5. **Write With Variable Index**

C Code
```c
A[i] = x;
```
RISC-V Assembly
```nasm
la   t0, A
slli t1, a1, 2
add  t2, t0, t1
sw   a2, 0(t2)
```
Explanation:
```
*(A + i*4) = x
```
6. **Array Traversal (Loop)**

C Code
```c
for(int i=0;i<5;i++)
    sum += A[i];
```
Typical RISC-V Assembly
```nasm
la   t0, A        # base address
li   t1, 0        # i = 0
li   t2, 0        # sum = 0

loop:
    slli t3, t1, 2
    add  t4, t0, t3
    lw   t5, 0(t4)
    add  t2, t2, t5

    addi t1, t1, 1
    blt  t1, 5, loop
```
Explanation:
- i * 4 → offset
- base + offset → address
- load element
- add to sum

7. **Pointer Version (Compiler Optimization)**

Compilers often avoid index multiplication by using pointer increments.

Equivalent C Code
```c
int *p = A;
for(int i=0;i<5;i++)
    sum += *p++;
```
RISC-V Assembly
```nasm
la   t0, A
li   t2, 0

loop:
    lw   t3, 0(t0)
    add  t2, t2, t3
    addi t0, t0, 4
    blt  t0, A+20, loop
```
This is more efficient.

No multiplication required.

8. **2D Array Access**

C Code
```c
int B[3][4];
x = B[2][1];
```
Row-major address formula:
```
Address = base + ((row * columns) + column) * size
= B + ((2*4)+1)*4
= B + (9*4)
= B + 36
```
RISC-V
```nasm
la   t0, B
lw   t1, 36(t0)
```

**Summary of Array Operations → RISC-V**
| Operation      | C Code   | RISC-V Concept    |
| -------------- | -------- | ----------------- |
| Read element   | `x=A[i]` | load word         |
| Write element  | `A[i]=x` | store word        |
| Address calc   | `A+i`    | base + offset     |
| Index multiply | `i*4`    | shift left        |
| Traversal      | loop     | pointer increment |

To reach index 500000 you must traverse.

**Array transformations** are techniques that convert an array into another form (derived array) so that certain operations become faster or easier.

Instead of working directly on the original array, we preprocess or transform it into a structure that supports efficient queries or updates.

General idea:
```
Original Array  →  Transformed Array  →  Fast Operations
```
Example: `A = [3,1,4,2,5]`

Transform it into a prefix sum array: `P = [3,4,8,10,15]`

Now range sums become `O(1)` instead of `O(n)`.

Array transformations are the **bridge between simple arrays and advanced data structures**.
```
Array
  ↓
Prefix / Difference
  ↓
Fenwick Tree
  ↓
Segment Tree
```
Most advanced structures are smart transformations of arrays.

{/*Why Array Transformations Are Important*/}
Many algorithm problems involve:
- Range queries
- Range updates
- Subarray computations
- Frequency counting

Without transformation: each query = O(n)

With transformation: each query = O(1) or O(log n)

This idea is called: **Preprocessing for faster queries**

The Most Important Array Transformations
| Transformation         | Purpose                      | Query Time  |
| ---------------------- | ---------------------------- | ----------- |
| Prefix Sum             | Fast range sums              | O(1)        |
| Suffix Sum             | Right-side cumulative values | O(1)        |
| Difference Array       | Fast range updates           | O(1) update |
| Prefix Product         | Product calculations         | O(1)        |
| Coordinate Compression | Reduce value range           | O(log n)    |
| Sparse Table           | Static range queries         | O(1)        |
| Fenwick Tree (BIT)     | Dynamic prefix sums          | O(log n)    |
| Segment Tree           | General range queries        | O(log n)    |

Conceptual Hierarchy of Array Transformations
```
Basic Arrays
     │
     ├── Prefix / Suffix Arrays
     │
     ├── Difference Arrays
     │
     ├── Sparse Table
     │
     ├── Fenwick Tree
     │
     └── Segment Tree
```
Each step increases power and flexibility.

Intuition Behind Array Transformations: Instead of computing something repeatedly, we: Precompute once, Then answer queries instantly.

Example:

Without transformation:
```
100000 queries
Each takes O(n)
```
Total: O(n * q)

With transformation:
```
Preprocess O(n)
Query O(1)
```
Total: O(n + q)

Huge improvement.

So, **Array transformations convert an array into a derived structure that enables faster queries, updates, or computations**.

## Prefix Sum Transformation
Idea: Transform array so each position stores **sum of all previous elements**.

Original array: A = [3,1,4,2,5]

Prefix array: P = [3,4,8,10,15]

Definition:
```
P[i] = A[0] + A[1] + ... + A[i]
```
**Range Sum Query**

Compute: sum(i,j)

Formula:
```
sum(i,j) = P[j] - P[i-1]
```
Example:
$$
sum(2,4) \\
= 4 + 2 + 5 \\
= 11
$$

Using prefix:
$$
P[4] - P[1] = 15 - 4 = 11
$$

Complexity:
- Preprocessing: O(n)
- Query: O(1)
## Suffix Sum Transformation
Opposite of prefix sum.

Definition:
$$
S[i] = A[i] + A[i+1] + ... + A[n-1]
$$
Example: A = [3,1,4,2,5]

Suffix array:
$$
S = [15,12,11,7,5]
$$
Uses:
- right-side computations
- suffix algorithms
- dynamic programming

## Difference Array Transformation
Used for **fast range updates**.

Problem: Add `+3` to every element in range `[2,5]`.

Normal method:
```
for i in 2..5:
   A[i] += 3
```
Cost: O(n)

Difference array idea:
$$
D[i] = A[i] - A[i-1]
$$
Example: A = [5,5,5,5,5]

Difference array: D = [5,0,0,0,0]

Update range [2,5]:
```
D[2] += 3
D[6] -= 3
```
Then compute prefix sum to recover array.

Complexity:
- Update = O(1)
- Rebuild = O(n)

Used in:
- range update problems
- competitive programming
- simulation algorithms

## Prefix Product Transformation
Used for **multiplication problems**.

Example: A = [1,2,3,4]

Prefix product: P = [1,2,6,24]

Suffix product: S = [24,24,12,4]

Used for the classic problem: Product of array except self

Result:
$$
result[i] = prefix[i-1] * suffix[i+1]
$$
## Coordinate Compression
Used when array values are **very large**.

Example: A = [1000000, 5000000, 2000000]

Compress values: [1,3,2]

Steps:
1. Sort unique values
2. Replace with ranks

Used in:
- segment trees
- fenwick trees
- geometric algorithms

## Sparse Table Transformation
Used for **static range queries** like:
- minimum
- maximum
- gcd

Example array: A = [5,2,4,7,1,3,6]

Sparse table precomputes answers for ranges of size: $2^k$

Example:
```
[0..1]
[0..3]
[0..7]
```
Query complexity: O(1)

Preprocessing: O(n log n)

Used in:
- range minimum query (RMQ)
- LCA algorithms

## Fenwick Tree (Binary Indexed Tree)
A dynamic extension of prefix sums.

Supports:
```
update(index,value)
prefix_sum(index)
```
Complexity: O(log n)

Used when:
- array values change
- frequent updates + queries

## Segment Tree
General range query structure.

Supports:
- sum
- minimum
- maximum
- gcd
- custom operations

Example tree structure:
```
            sum(0..7)
           /        \
      sum(0..3)    sum(4..7)
      /     \       /     \
  sum(0..1) sum(2..3) ...
```
Complexity:
- Query = O(log n)
- Update = O(log n)

## Relation between Array algorithm patterns and array transformations
Array algorithm patterns and array transformations are related but serve different roles in algorithm design. The difference can be summarized like this:
| Concept                      | Purpose                                                                             |
| ---------------------------- | ----------------------------------------------------------------------------------- |
| **Array Algorithm Patterns** | Techniques for **solving problems by scanning or manipulating arrays**              |
| **Array Transformations**    | Techniques for **preprocessing arrays into another form to make operations faster** |

So:
- Array Patterns → How to process arrays
- Array Transformations → How to reshape arrays

The relationship looks like this:
```
Array
   │
   ├── Array Algorithm Patterns
   │      (two pointers, sliding window, etc.)
   │
   └── Array Transformations
          (prefix sum, difference array, etc.)
```
But in practice they interact.

Many algorithm patterns use transformations internally.

Example: Range Sum Problem

Pattern: Prefix Sum

But prefix sum is also a transformation.

**Comparison Table**
| Feature   | Array Patterns           | Array Transformations    |
| --------- | ------------------------ | ------------------------ |
| Purpose   | Solve algorithm problems | Preprocess arrays        |
| Focus     | Algorithm strategy       | Data representation      |
| When used | During problem solving   | Before queries/updates   |
| Example   | Sliding window           | Prefix sum               |
| Type      | Algorithmic technique    | Data structure technique |

Imagine arrays as data in a spreadsheet.

Patterns are like:
- Scanning rows
- Comparing cells
- Moving pointers

Transformations are like:
- Adding summary columns
- Precomputing totals
- Building indexes

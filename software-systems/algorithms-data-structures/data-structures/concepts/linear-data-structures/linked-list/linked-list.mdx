A **Linked List** is one of the fundamental linear data structures used in algorithms and system programming. It is especially important in low-level programming (like C) and appears frequently in algorithm design and memory management.

With Linked Lists, items are stored in a chain of cells that don't need to be at sequential memory addresses. Memory for each cell is allocated as needed. Each cell has a pointer indicating the address of the next cell in the chain. A cell with an empty pointer marks
the end of the chain.

A **Linked List** is a collection of nodes where each node contains:
1. **Data** – the actual value stored
2. **Pointer (link)** – reference to the next node in the list

Unlike an array, elements are not stored in contiguous memory.

**Conceptual View**
```
[Data | Next] → [Data | Next] → [Data | Next] → NULL
```
Example list:
```
10 → 20 → 30 → 40 → NULL
```
Each element points to the next element.

**Structure of a Node**

Often the list itself is defined as:

Singly Linked List
```
STRUCT LinkedList
    head
END STRUCT
```
Doubly Linked List
```
STRUCT DoublyLinkedList
    head
    tail
END STRUCT
```
Example node in memory for Singly Linked List:
```
Address   Data   Next
1000      10     2000
2000      20     3000
3000      30     NULL
```
Traversal follows the next pointers.

Linked lists can be used to implement Stacks, Lists, and Queues. There’s no problem growing the list: each cell can be kept at any part of the memory. We can create lists as big as the amount of free memory we have. It’s also easy to insert items in the middle or delete any item by changing the cell pointers:

## Arrays vs Linked Lists
<!--Why Linked Lists Exist-->
Feature-rich programming languages often come with built-in implementations for List, Queue, Stack and other ADTs. These implementations often resort to a default data structure. Some of these implementations can even switch data structures automatically during runtime, based on how data is being accessed.

When performance isn't an issue, we can rely on these generic ADT implementations and not worry about data structures. But when performance must be optimal, or when working with a lower level language that doesn't have such features, you must decide which data structures to use. Analyze the operations your data must undergo, and choose an implementation that uses an appropriate data structure. 

Linked Lists are preferable to Arrays when:
- You need insertions/deletions in the list to be extremely fast,
- You don't need random, unordered access to the data,
- You insert or delete items in the middle of a list,
- You can't evaluate the exact size of the list (it needs to grow or shrink throughout the execution).

Arrays are preferable over Linked Lists when:
- You frequently need random, unordered access to the data,
- You need extreme performance to access the items,
- The number of items doesn't change during execution, so you can easily allocate contiguous space of computer memory.

| Problem          | Array                   | Linked List         |
| ---------------- | ----------------------- | ------------------- |
| Memory layout    | Contiguous              | Non-contiguous      |
| Insert in middle | O(n) shift              | O(1) pointer change |
| Delete element   | O(n) shift              | O(1) pointer change |
| Random access    | O(1)                    | O(n)                |
| Memory size      | Fixed / resizing costly | Dynamic             |

## Core Operations
### Traversal
Visit each node sequentially.
```
Head → Node → Node → Node → NULL
```
Pseudocode
```
PROCEDURE Traverse(head)

    current ← head

    WHILE current ≠ NULL
        PRINT current.data
        current ← current.next
    END WHILE

END PROCEDURE
```
Code:
```c
void traverse(struct Node* head) {
    struct Node* temp = head;
    while (temp != NULL) {
        printf("%d ", temp->data);
        temp = temp->next;
    }
}
```
Time Complexity: O(n)

### Insertion
Three main insertion types.

1. **Insert at Beginning**

    Pseudocode
    ```
    PROCEDURE InsertFront(head, value)
    
        newNode ← CREATE NODE
        newNode.data ← value
    
        newNode.next ← head
        head ← newNode
    
    END PROCEDURE
    ```
    Before
    ```
    20 → 30 → 40
    ```
    After inserting 10
    ```
    10 → 20 → 30 → 40
    ```
    Steps:
    1. Create node
    2. Set newNode->next = head
    3. Update head
    ```c
    newNode->next = head;
    head = newNode;
    ```
    Time Complexity: O(1)

2. **Insert at End**
    
    Pseudocode
    ```
    PROCEDURE InsertEnd(head, value)
    
        newNode ← CREATE NODE
        newNode.data ← value
        newNode.next ← NULL
    
        current ← head
    
        WHILE current.next ≠ NULL
            current ← current.next
        END WHILE
    
        current.next ← newNode
    
    END PROCEDURE
    ```
    Before
    ```
    10 → 20 → 30 → NULL
    ```
    After inserting 40
    ```
    10 → 20 → 30 → 40 → NULL
    ```
    Requires traversal.
    ```c
    struct Node* temp = head;
    while (temp->next != NULL) {
        temp = temp->next;
    }
    temp->next = newNode;
    ```
    Time Complexity: O(n)

3. **Insert in Middle**
        
    Before
    ```
    10 → 20 → 40
    ```
    Insert 30 after 20
    ```
    10 → 20 → 30 → 40
    ```
    Adjust two pointers.
    ```c
    struct Node* temp = head;
    while (temp->data != 20) {
        temp = temp->next;
    }
    newNode->next = temp->next;
    temp->next = newNode;
    ```
    Time Complexity: O(n)
4. Insert After a Node

    Pseudocode
    ```
    PROCEDURE InsertAfter(node, value)

    newNode ← CREATE NODE
    newNode.data ← value

    newNode.next ← node.next
    node.next ← newNode

    END PROCEDURE
    ```
    Example

    Before
    ```
    10 → 20 → 40
    ```
    Insert 30 after 20
    ```
    10 → 20 → 30 → 40
    ```
### Deletion
Pseudocode
```
PROCEDURE DeleteNode(head, value)

    current ← head
    previous ← NULL

    WHILE current ≠ NULL AND current.data ≠ value
        previous ← current
        current ← current.next
    END WHILE

    IF current = NULL
        RETURN
    END IF

    IF previous = NULL
        head ← current.next
    ELSE
        previous.next ← current.next
    END IF

END PROCEDURE
```
Example:
```
10 → 20 → 30 → 40
```
Delete 30
```
10 → 20 → 40
```
Steps:
1. Find previous node
2. Change pointer
    ```c
    prev->next = target->next;
    ```
    
Time Complexity: O(n)

| Insert at head  | O(1) |

## Types of Linked Lists
1. **Singly Linked List**

Each node points to next node only.
```
10 → 20 → 30 → NULL
```

2. **Doubly Linked List**

Nodes contain two pointers.
```
NULL ← 10 ⇄ 20 ⇄ 30 → NULL
```
Structure
```c
struct Node {
    int data;
    struct Node* prev;
    struct Node* next;
};
```
Advantages:
- Traversal both directions
- Easier deletion

3. **Circular Linked List**

Last node points back to first node.
```
10 → 20 → 30
 ↑         ↓
 └─────────┘
```
No NULL pointer.

Used in:
- Round-robin scheduling
- Cyclic buffers

## Linked List Algorithm Patterns
Most linked list algorithms rely on only three fundamental ideas:
1. Traversal
2. Pointer manipulation
3. Two-pointer techniques

Mastering these allows solving almost every linked list problem.

### Traversal Pattern
**Origin**: From arrays, generalized for linked lists.

**Purpose**: Visit every node sequentially.

**Code Pattern**:
```c
Node* current = head;
while(current != NULL) {
    // process current->data
    current = current->next;
}
```
- **Complexity**: O(n)
- **Use Cases**: Printing, searching, counting, modifying all nodes.
- **Variant**: Recursive traversal (stack-based).

### Fast & Slow Pointers (Tortoise & Hare)
**Origin**: Unique to linked lists due to pointer structure.

**Purpose**: Detect cycles, find middle, solve two-pointer problems in O(n).

Pseudocode
```
PROCEDURE FindMiddle(head)

    slow ← head
    fast ← head

    WHILE fast ≠ NULL AND fast.next ≠ NULL

        slow ← slow.next
        fast ← fast.next.next

    END WHILE

    RETURN slow

END PROCEDURE
```
**Pattern**:
```c
Node *slow = head, *fast = head;
while(fast && fast->next) {
    slow = slow->next;
    fast = fast->next->next;
}
```
**Use Cases**:
- Detect cycle (Floyd’s Cycle Detection)
- Find middle node
- Check palindrome in linked list

**Complexity**: O(n), space O(1)

### Reverse Linked List Pattern
**Purpose**: Reverse the order of nodes.

Pseudocode
```
PROCEDURE ReverseList(head)

    prev ← NULL
    current ← head

    WHILE current ≠ NULL

        next ← current.next
        current.next ← prev

        prev ← current
        current ← next

    END WHILE

    head ← prev

END PROCEDURE
```
Complexity: O(n)

**Code Pattern (Iterative)**:
```c
Node* prev = NULL;
Node* current = head;
Node* next;
while(current != NULL) {
    next = current->next;
    current->next = prev;
    prev = current;
    current = next;
}
head = prev;
```
**Recursive Variant**: Uses stack implicitly.

**Cross-Origin**: Conceptually similar to array reversal, but pointer manipulation replaces index arithmetic.

**Use Cases**:
- Undo operations
- Stack emulation
- Algorithms requiring reversed traversal

### Search Algorithm
Pseudocode
```
PROCEDURE Search(head, key)

    current ← head

    WHILE current ≠ NULL
        IF current.data = key
            RETURN current
        END IF

        current ← current.next
    END WHILE

    RETURN NULL

END PROCEDURE
```
Complexity: O(n)
### Merge Two Sorted Lists
**Purpose**: Merge two sorted linked lists into a single sorted list.

Pseudocode
```
PROCEDURE MergeLists(list1, list2)

    dummy ← new Node
    tail ← dummy

    WHILE list1 ≠ NULL AND list2 ≠ NULL

        IF list1.data < list2.data
            tail.next ← list1
            list1 ← list1.next
        ELSE
            tail.next ← list2
            list2 ← list2.next
        END IF

        tail ← tail.next

    END WHILE

    IF list1 ≠ NULL
        tail.next ← list1
    ELSE
        tail.next ← list2
    END IF

    RETURN dummy.next

END PROCEDURE
```
**Pattern**: Similar to merge in merge sort on arrays, but uses pointers.
```c
Node* merge(Node* l1, Node* l2) {
    Node dummy;
    Node* tail = &dummy;
    while(l1 && l2) {
        if(l1->data < l2->data) { tail->next = l1; l1 = l1->next; }
        else { tail->next = l2; l2 = l2->next; }
        tail = tail->next;
    }
    tail->next = l1 ? l1 : l2;
    return dummy.next;
}
```
**Complexity**: O(n + m), n = length of first list, m = length of second list.

**Use Cases**: Merge sort for linked lists, combining ordered streams.

### Cycle Detection Pattern(Floyd's algorithm)
**Purpose**: Detect if a linked list has a cycle.

Pseudocode
```
PROCEDURE DetectCycle(head)

    slow ← head
    fast ← head

    WHILE fast ≠ NULL AND fast.next ≠ NULL

        slow ← slow.next
        fast ← fast.next.next

        IF slow = fast
            RETURN TRUE
        END IF

    END WHILE

    RETURN FALSE

END PROCEDURE
```
Complexity:
- Time: O(n)
- Space: O(1)
**Pattern**: Fast & slow pointer (Floyd's algorithm).
```c
Node* slow = head;
Node* fast = head;
while(fast && fast->next) {
    slow = slow->next;
    fast = fast->next->next;
    if(slow == fast) return true; // cycle detected
}
return false;
```
**Cross-Origin**: Unique to pointer-based structures, arrays don't naturally form cycles.

**Use Cases**: Memory leak detection, graph-like structures, system-level programming.

### Two-Pointer Intersection Pattern
**Purpose**: Find intersection node of two linked lists.

The Two-Pointer Intersection Pattern is used to find the node where two singly linked lists intersect (share the same memory node).

Important: Intersection means same memory address, not same value.

Example:
```
List A: 1 → 2 → 3 → 4 → 5
                     ↑
List B:       9 → 8 ┘
```
Both lists share nodes 4 → 5.

**Idea of the Two-Pointer Intersection Pattern**

Two pointers traverse both lists.

When a pointer reaches the end of its list, it jumps to the head of the other list.

Eventually both pointers traverse equal total distance and meet at the intersection.

Total distance traveled:
```
pointerA = lengthA + lengthB
pointerB = lengthB + lengthA
```
So they meet at the intersection node.

**Pattern**: Traverse both lists, adjust starting points to equalize remaining lengths.

```c
#include <stdio.h>
#include <stdlib.h>

struct Node {
    int data;
    struct Node* next;
};

struct Node* getIntersection(struct Node* headA, struct Node* headB) {

    struct Node* pA = headA;
    struct Node* pB = headB;

    while (pA != pB) {

        if (pA == NULL)
            pA = headB;
        else
            pA = pA->next;

        if (pB == NULL)
            pB = headA;
        else
            pB = pB->next;
    }

    return pA;
}

struct Node* newNode(int data) {
    struct Node* n = malloc(sizeof(struct Node));
    n->data = data;
    n->next = NULL;
    return n;
}

int main() {

    struct Node* common = newNode(4);
    common->next = newNode(5);

    struct Node* headA = newNode(1);
    headA->next = newNode(2);
    headA->next->next = newNode(3);
    headA->next->next->next = common;

    struct Node* headB = newNode(9);
    headB->next = newNode(8);
    headB->next->next = common;

    struct Node* intersection = getIntersection(headA, headB);

    if (intersection)
        printf("Intersection at node with value: %d\n", intersection->data);
    else
        printf("No intersection\n");
}
```

**Step-by-Step Walkthrough**

Lists:
```
A: 1 → 2 → 3 → 4 → 5
B: 9 → 8 → 4 → 5
```
Traversal:
```
pA path:
1 → 2 → 3 → 4 → 5 → NULL → 9 → 8 → 4

pB path:
9 → 8 → 4 → 5 → NULL → 1 → 2 → 3 → 4
```
They meet at: `node 4`

This Pattern Works Because both pointers traverse:
```
LengthA + LengthB
```
So the distance difference between lists disappears.

This is why the pointers synchronize at the intersection.

**Complexity**: 
| Metric           | Value    |
| ---------------- | -------- |
| Time Complexity  | O(n + m) |
| Space Complexity | O(1)     |

Where:
- n = length of list A
- m = length of list B

**Cross-Origin**: Conceptually similar to array two-pointer technique, but pointer manipulation is critical here.

This pattern appears in:
- Linked List intersection problems
- Graph path convergence
- Memory structure sharing
- Kernel structures
- Persistent data structures

### Delete Node Pattern
**Purpose**: Remove a node from the list efficiently.

**Pattern**:
```c
if(node_to_delete->next != NULL) {
    Node* temp = node_to_delete->next;
    node_to_delete->data = temp->data;
    node_to_delete->next = temp->next;
    free(temp);
}
```
**Special case**: Deleting head node or tail node.

**Cross-Origin**: Deletion concept exists in arrays (shift elements), but in linked lists it's pointer reassignment, O(1) if node known.

### Palindrome Check Pattern
- Purpose: Check if linked list is a palindrome.
- Pattern:
        1. Use fast & slow pointers to find middle.
        2. Reverse second half of the list.
        3. Compare first half with reversed second half.
- Cross-Origin: Similar to array palindrome check, but traversal is pointer-based.

### Odd-Even Reordering Pattern
- Purpose: Group nodes by odd/even positions.
- Pattern: Two pointers (odd and even) traverse alternately and relink nodes.
- Use Cases: Linked list reordering, queue optimizations.

2.10 Flatten & Expand Nested Linked Lists
- Purpose: Flatten multi-level linked lists into single-level.
- Pattern: Recursive traversal and pointer adjustment.
- Cross-Origin: Recursive tree traversal inspires this pattern.

- Linked lists allow dynamic memory management but lose random access.

## Linked List Memory Model in C
In C, a linked list is dynamic; nodes are created at runtime using malloc (or similar). Each node contains data and pointer(s).
1. **Singly Linked List Node**
    ```c
    struct Node {
        int data;          // 4 bytes (on 32-bit) or 8 bytes (64-bit)
        struct Node* next; // 4 bytes (32-bit) or 8 bytes (64-bit)
    };
    ```
    - Heap allocation: `malloc(sizeof(Node))` places the node in heap memory.
    - Pointer to next connects nodes, forming a chain.
    - Head pointer keeps track of the first node.

2. **Doubly Linked List Node**
    ```c
    struct Node {
        int data;
        struct Node* prev;
        struct Node* next;
    };
    ```
    - Extra prev pointer doubles memory cost per node.
    - Enables bidirectional traversal.
    - Still dynamic in heap.

3. **Memory Layout Example (Singly Linked List)**

    Suppose we insert 10 → 20 → 30:
    | Address | Data | Next |
    | ------- | ---- | ---- |
    | 1000    | 10   | 5000 |
    | 5000    | 20   | 7000 |
    | 7000    | 30   | NULL |
    
    - Nodes are non-contiguous, unlike arrays.
    - Traversal follows the next pointer.

4. **Linked List in Assembly**

    Suppose node structure:
    ```c
    struct Node {
        int data;
        struct Node* next;
    };
    ```
    Allocation in C:
    ```c
    struct Node* n = malloc(sizeof(struct Node));
    n->data = 42;
    n->next = NULL;
    ```
    In Assembly (simplified pseudo):
    ```nasm
    # a0 = argument to malloc = 16 bytes (8 for data + 8 for pointer)
    li a0, 16
    call malloc        # returns pointer in a0
    mv t0, a0          # store allocated address in t0 (n)
    
    li t1, 42          # data value
    sw t1, 0(t0)       # store data at offset 0
    sd x0, 8(t0)       # store next = NULL (x0 = 0)
    ```
    Explanation:
    - sw = store word (4 bytes for data)
    - sd = store doubleword (8 bytes for 64-bit pointer)
    - Nodes are heap allocated, scattered in memory.

    Traversal in assembly:
    ```c
    Node* curr = head;
    while(curr != NULL) {
        printf("%d\n", curr->data);
        curr = curr->next;
    }
    ```
    ```nasm
    mv t0, s0       # t0 = head
    loop:
        beq t0, x0, end   # if curr == NULL, exit
        lw t1, 0(t0)      # t1 = curr->data
        # (print t1 or process)
        ld t0, 8(t0)      # curr = curr->next
        j loop
    end:
    ```
    - lw = load word (data)
    - ld = load doubleword (pointer)

Takeaway:
- Linked lists are heap-based.
- Each pointer is just an address in memory.
- CPU follows these addresses; this is why access is O(n) — no index math like arrays.

## Singly Linked List
A **Singly Linked List (SLL)** is the simplest and most fundamental form of linked list used in data structures. It is widely used in system programming, kernels, memory allocators, and many algorithms because of its dynamic size and efficient insert/delete operations.

A **Singly Linked List** is a linear data structure consisting of **nodes**, where each node contains:
1. **Data**
2. **Pointer to the next node**

Each node points **only to the next node**, hence the name **singly**.


**Structure**:
```
[Data | Next] → [Data | Next] → [Data | Next] → NULL
```
Example:
```
10 → 20 → 30 → 40 → NULL
```
- 10 is the head node
- 40 is the last node
- NULL marks the end of the list

The list is accessed using a head pointer.
```
head → 10 → 20 → 30 → 40 → NULL
```
If `head = NULL`, then the list is empty.

A **Singly Linked List** is essentially a chain of heap objects connected by pointers.

Arrays use: index arithmetic

Linked lists use: pointer traversal

**Node Structure** 

A Singly Linked List node stores:
- the data
- a pointer/reference to the next node

Pseudocode
```
STRUCT Node
    data
    next
END STRUCT
```
Explanation:
| Field  | Meaning                    |
| ------ | -------------------------- |
| `data` | value stored in the node   |
| `next` | reference to the next node |

Example List
```
head → [10 | • ] → [20 | • ] → [30 | • ] → NULL
```
Expanded form:
```
Node1:
    data = 10
    next → Node2

Node2:
    data = 20
    next → Node3

Node3:
    data = 30
    next → NULL
```
Traversal direction:
```
head → node → node → node → NULL
```
### Memory Model

Unlike arrays, linked list nodes are not stored contiguously.

Example memory layout:
| Address | Data | Next   |
| ------- | ---- | ------ |
| 0x1000  | 10   | 0x2000 |
| 0x2000  | 20   | 0x3500 |
| 0x3500  | 30   | 0x5000 |
| 0x5000  | 40   | NULL   |

Logical structure:
```
10 → 20 → 30 → 40 → NULL
```
Physical memory:
```
0x1000 → 0x2000 → 0x3500 → 0x5000
```
Nodes may be scattered anywhere in heap memory.

### Basic Operations on Singly Linked List
The core operations are:
1. Traversal
2. Insertion
3. Deletion
4. Searching

### Time Complexity Summary
| Operation      | Complexity |
| -------------- | ---------- |
| Traversal      | O(n)       |
| Search         | O(n)       |
| Insert at head | O(1)       |
| Insert at end  | O(n)       |
| Delete         | O(n)       |

### Advantages and Disadvantages
**Advantages of Singly Linked List**
- Dynamic size
- Efficient insertion/deletion
- No memory shifting
- Good for unknown data sizes

The Linked List also has its drawbacks: 
1. we can’t instantly retrieve the nth item. For that, we have to start searching at the first cell, use it to get the address of the second cell, then get the second cell, use its pointer to the next cell and so on, until we get to the nth cell.
2. Also, if we’re only given the address of a single cell, it’s not easy to
remove it or move backwards. With no other information, we can’t
know the address of the previous cell in the chain.

**Disadvantages of Singly Linked List**
- No random access
- Extra memory for pointers
- Poor cache locality

Singly linked lists appear in many systems:
- Hash tables (separate chaining)
- Graph adjacency lists
- Memory allocators
- Stacks and queues
- Kernel process lists

**Node Structure in C**

**Creating a Node**

Nodes are usually created using dynamic memory allocation.
```c
struct Node* createNode(int value) {

    struct Node* newNode = malloc(sizeof(struct Node));

    newNode->data = value;
    newNode->next = NULL;

    return newNode;
}
```
```c
#include <stdio.h>
#include <stdlib.h>

// Define the node structure
struct Node {
    int data;
    struct Node* next;
};

// Create a new node with given data
struct Node* create_node(int data) {
    struct Node* new_node = (struct Node*)malloc(sizeof(struct Node));
    new_node->data = data;
    new_node->next = NULL;
    return new_node;
}

// Insert a node at the beginning of the list
struct Node* insert_at_head(struct Node* head, int data) {
    struct Node* new_node = create_node(data);
    new_node->next = head;
    return new_node;
}

// Insert a node at the end of the list
struct Node* insert_at_tail(struct Node* head, int data) {
    struct Node* new_node = create_node(data);

    // If list is empty
    if (head == NULL) {
        return new_node;
    }

    // Traverse to the last node
    struct Node* temp = head;
    while (temp->next != NULL) {
        temp = temp->next;
    }

    // Link the last node to new node
    temp->next = new_node;
```

## Doubly Linked List
The **Double Linked List** is the Linked List with an extra: cells have
two pointers: one to the cell that came before it, and other to the
cell that comes after.

A **Doubly Linked List (DLL)** is an extension of the **Singly Linked List** where each node keeps two pointers: one to the next node and one to the previous node. This allows traversal in both directions and makes some operations easier.

A **Doubly Linked List** is a linear data structure where each node contains:
1. Data
2. Pointer to the next node
3. Pointer to the previous node

**Structure**:
```
NULL ← [prev | data | next] ⇄ [prev | data | next] ⇄ [prev | data | next] → NULL
```
Example:
```
NULL ← 10 ⇄ 20 ⇄ 30 ⇄ 40 → NULL
```
Key points:
- `10` is the `head`
- `40` is the `tail`
- `prev of head` = NULL
- `next of tail` = NULL

**Node Structure**

A Doubly Linked List node stores:
- the data
- a pointer to the previous node
- a pointer to the next node

**Pseudocode**
```
STRUCT Node
    data
    prev
    next
END STRUCT
```
Explanation:
| Field  | Meaning                    |
| ------ | -------------------------- |
| `data` | value stored               |
| `prev` | reference to previous node |
| `next` | reference to next node     |

**Head and Tail Pointers**

Often two pointers are used:
```
head → first node
tail → last node
```
Example:
```
head                tail
 ↓                   ↓
NULL ← 10 ⇄ 20 ⇄ 30 ⇄ 40 → NULL
```
Advantages:
- Fast insertion at both ends
- Easy backward traversal

Example List
```
NULL ← [ • |10| • ] ⇄ [ • |20| • ] ⇄ [ • |30| • ] → NULL
```
Expanded form:
```
Node1:
prev → NULL
data = 10
next → Node2

Node2:
prev → Node1
data = 20
next → Node3

Node3:
prev → Node2
data = 30
next → NULL
```
Traversal directions:
```
Forward  : head → node → node → node → NULL
Backward : tail → node → node → node → NULL
```
**Comparison of Node Structures with Singly Linked List**
| Feature   | Singly Linked List | Doubly Linked List |
| --------- | ------------------ | ------------------ |
| Pointers  | 1 (`next`)         | 2 (`prev`, `next`) |
| Traversal | One direction      | Two directions     |
| Memory    | Less               | More               |
| Deletion  | Need previous node | Direct             |

### Memory Layout
Nodes are not contiguous in memory.
Example memory:
Address	Prev	Data	Next
0x1000	NULL	10	0x2500
0x2500	0x1000	20	0x4000
0x4000	0x2500	30	0x6000
0x6000	0x4000	40	NULL
Logical structure:
NULL ← 10 ⇄ 20 ⇄ 30 ⇄ 40 → NULL
Because every node stores two pointers, memory usage is higher than singly linked lists.

### Time Complexity
| Operation      | Complexity               |
| -------------- | ------------------------ |
| Traversal      | O(n)                     |
| Search         | O(n)                     |
| Insert at head | O(1)                     |
| Insert at tail | O(1) (with tail pointer) |
| Delete node    | O(1)                     |

### Advantages and Disadvantages
It has the same benefits as the Linked List: no big chunk of memory preallocation is required, because memory space for new cells can be allocated on demand. And the extra pointers let us walk the chain of cells forwards and backwards. And if we’re only given the address of a single cell, we’re able to delete it.

Still, there’s no way to access the nth item instantly. Also, storing two pointers in each cell directly translates to more code complexity and more required memory to store our data.

**Advantages**
- Traverse forward and backward
- Easier deletion (no need to find previous node)
- Efficient operations at both ends

**Disadvantages**
- More memory usage (extra pointer)
- More pointer updates during insert/delete
- Slightly slower due to pointer overhead

### Real-World Uses
Doubly linked lists are widely used in systems:
- LRU Cache
- Undo/Redo systems
- Browser navigation (back/forward)
- Memory allocators
- Operating system process lists

```c
#include <stdio.h>
#include <stdlib.h>

// Define the doubly linked list node structure
struct Node {
    int data;
    struct Node* prev;  // Pointer to previous node
    struct Node* next;  // Pointer to next node
};

// Create a new node with given data
struct Node* create_node(int data) {
    struct Node* new_node = (struct Node*)malloc(sizeof(struct Node));
    new_node->data = data;
    new_node->prev = NULL;
    new_node->next = NULL;
    return new_node;
}

// Insert a node at the beginning of the list
struct Node* insert_at_head(struct Node* head, int data) {
    struct Node* new_node = create_node(data);

    // If list is empty
    if (head == NULL) {
        return new_node;
    }

    // Link new node to head
    new_node->next = head;
    head->prev = new_node;

    return new_node;
}

// Insert a node at the end of the list
struct Node* insert_at_tail(struct Node* head, int data) {
    struct Node* new_node = create_node(data);

    // If list is empty
    if (head == NULL) {
        return new_node;
    }

    // Traverse to the last node
    struct Node* temp = head;
    while (temp->next != NULL) {
        temp = temp->next;
    }

    // Link the last node to new node
    temp->next = new_node;
    new_node->prev = temp;

    return head;
}

// Insert a node at a specific position (1-indexed)
struct Node* insert_at_position(struct Node* head, int data, int position) {
    struct Node* new_node = create_node(data);

    // If position is 1, insert at head
    if (position == 1) {
        return insert_at_head(head, data);
    }

    // Traverse to the position
    struct Node* temp = head;
    int count = 1;

    while (temp != NULL && count < position - 1) {
        temp = temp->next;
        count++;
    }

    // Position out of range
    if (temp == NULL) {
        printf("Position out of range\n");
        free(new_node);
        return head;
    }

    // Insert the node
    new_node->next = temp->next;
    new_node->prev = temp;

    if (temp->next != NULL) {
        temp->next->prev = new_node;
    }

    temp->next = new_node;

    return head;
}

// Delete a node with given data
struct Node* delete_node(struct Node* head, int data) {
    // If list is empty
    if (head == NULL) {
        return NULL;
    }

    // Traverse to find the node
    struct Node* current = head;

    while (current != NULL && current->data != data) {
        current = current->next;
    }

    // Node not found
    if (current == NULL) {
        return head;
    }

    // If the node to delete is head
    if (current == head) {
        head = current->next;
        if (head != NULL) {
            head->prev = NULL;
        }
        free(current);
        return head;
    }

    // Unlink the node from both sides
    if (current->prev != NULL) {
        current->prev->next = current->next;
    }

    if (current->next != NULL) {
        current->next->prev = current->prev;
    }

    free(current);
    return head;
}

// Display the list in forward direction
void display_forward(struct Node* head) {
    printf("Forward: ");
    struct Node* temp = head;
    while (temp != NULL) {
        printf("%d ⇄ ", temp->data);
        temp = temp->next;
    }
    printf("NULL\n");
}

// Display the list in backward direction
void display_backward(struct Node* head) {
    // Find the last node first
    struct Node* temp = head;
    if (temp == NULL) {
        printf("Backward: NULL\n");
        return;
    }

    while (temp->next != NULL) {
        temp = temp->next;
    }

    printf("Backward: ");
    while (temp != NULL) {
        printf("%d ⇄ ", temp->data);
        temp = temp->prev;
    }
    printf("NULL\n");
}

// Search for a node with given data
int search(struct Node* head, int data) {
    struct Node* temp = head;
    while (temp != NULL) {
        if (temp->data == data) {
            return 1; // Found
        }
        temp = temp->next;
    }
    return 0; // Not found
}

// Get the size of the list
int get_size(struct Node* head) {
    int count = 0;
    struct Node* temp = head;
    while (temp != NULL) {
        count++;
        temp = temp->next;
    }
    return count;
}

// Reverse the list
struct Node* reverse_list(struct Node* head) {
    // If list is empty or has only one node
    if (head == NULL || head->next == NULL) {
        return head;
    }

    struct Node* current = head;
    struct Node* temp = NULL;

    // Swap prev and next for all nodes
    while (current != NULL) {
        temp = current->prev;
        current->prev = current->next;
        current->next = temp;
        current = current->prev;
    }

    // Change head
    if (temp != NULL) {
        head = temp->prev;
    }

    return head;
}

// Free all nodes in the list
void free_list(struct Node* head) {
    struct Node* temp;
    while (head != NULL) {
        temp = head;
        head = head->next;
        free(temp);
    }
}

int main() {

    printf("=== Doubly Linked List Operations ===\n\n");

    // Insert elements at head

    head = insert_at_head(head, 20);
    head = insert_at_head(head, 10);

    // Insert at position

    // Search for elements

    free_list(head);
```

- `create_node()`: Allocates memory for a new node and initializes both prev and next pointers
- `insert_at_head()`: Creates node and updates prev pointer of old head
- `insert_at_tail()`: Traverses to end and maintains bidirectional links
- `insert_at_position()`: Inserts node at specific position with proper prev/next updates

- Doubly linked lists use more memory per node (two pointers instead of one)
- Bidirectional traversal is now possible
- Deletion is easier than singly linked lists when you have a node pointer

```python
        if temp.next is not None:
            temp.next.prev = new_node

        temp.next = new_node

    def delete_node(self, data):
        """Delete a node with given data - O(n)"""
        # If list is empty
        if self.head is None:
            return

        # Traverse to find the node
        current = self.head

        while current is not None and current.data != data:
            current = current.next

        # Node not found
        if current is None:
            return

        # If the node to delete is head
        if current == self.head:
            self.head = current.next
            if self.head is not None:
                self.head.prev = None
            return

        # Unlink the node from both sides
        if current.prev is not None:
            current.prev.next = current.next

        if current.next is not None:
            current.next.prev = current.prev

    def display_forward(self):
        """Display the list in forward direction - O(n)"""
        output = "Forward: "
        temp = self.head
        while temp is not None:
            output += str(temp.data) + " ⇄ "
            temp = temp.next
        output += "None"
        print(output)

    def display_backward(self):
        """Display the list in backward direction - O(n)"""
        # Find the last node first
        temp = self.head
        if temp is None:
            print("Backward: None")
            return

        while temp.next is not None:
            temp = temp.next

        output = "Backward: "
        while temp is not None:
            output += str(temp.data) + " ⇄ "
            temp = temp.prev
        output += "None"
        print(output)

    def search(self, data):
        """Search for a node with given data - O(n)"""
        temp = self.head
        while temp is not None:
            if temp.data == data:
                return True  # Found
            temp = temp.next
        return False  # Not found

    def get_size(self):
        """Get the size of the list - O(n)"""
        count = 0
        temp = self.head
        while temp is not None:
            count += 1
            temp = temp.next
        return count

    def reverse_list(self):
        """Reverse the list by swapping prev and next pointers - O(n)"""
        # If list is empty or has only one node
        if self.head is None or self.head.next is None:
            return

        current = self.head
        temp = None

        # Swap prev and next for all nodes
        while current is not None:
            temp = current.prev
            current.prev = current.next
            current.next = temp
            current = current.prev

        # Change head
        if temp is not None:
            self.head = temp.prev

    def __str__(self):
        """String representation of the list"""
        result = "["
        temp = self.head
        while temp is not None:
            result += str(temp.data)
            if temp.next is not None:
                result += ", "
            temp = temp.next
        result += "]"
        return result
```

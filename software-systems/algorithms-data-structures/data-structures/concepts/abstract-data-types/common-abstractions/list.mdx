When storing a bunch of items, you sometimes need more flexibility. For instance, you could want to freely reorder the items; or to access, insert and remove items at any position. In these cases, the List is handy. 

The List is one of the most used ADTs. For instance, if you need to store links to the most frequently accessed files in a system, a list is ideal: you can sort the links for display purposes, and remove links as will as the corresponding files become less frequently accessed.

A List is a collection in which elements are maintained in a sequence. Each element has a position (index), and the same element can appear multiple times.

A List Abstract Data Type (ADT) is a linear collection of elements in which each element occupies a specific position in a sequence.

A List allows us to store, access, insert, delete, search, and modify elements while maintaining their positional order.

Lists are among the fundamental abstract data types because they provide the foundation for several important data structures and are widely used in programming languages.

Examples include:

- A shopping list containing products.
- A playlist containing songs.
- A sequence of system log entries.
- A list of students enrolled in a course.
- A sequence of tasks waiting to be processed.

Before examining implementations, it is important to distinguish three concepts:

| Concept             | Meaning                                                   | Example                                                    |
| ------------------- | --------------------------------------------------------- | ---------------------------------------------------------- |
| List ADT            | Abstract definition of the behavior and operations        | Ordered collection with positional access                  |
| List interface      | Programming-language contract describing those operations | Java `List`, C++ sequence-container interfaces/conventions |
| List implementation | Concrete data structure used to implement the ADT         | Dynamic array, linked list                                 |

The List ADT describes what a List does, while its implementation determines how it works and how efficiently it performs operations.

A list is a fundamental data structure in the Java programming language. They give us the ability to
easily create, store, and manipulate an ordered collection of elements. This data structure uses the
`java.util.list` interface and extends the `java.util.Collection` interface. In Java, the `List` interface represents this abstraction, while `ArrayList`, `LinkedList`, and `Vector` are different implementations.


## 1. Characteristics of the List ADT

A conventional List ADT has the following characteristics:

1. Linear organization: Elements are arranged in a sequence.
2. Positional ordering: Every element has a position relative to other elements.
3. Duplicates: Multiple elements may contain the same value.
4. Dynamic membership: Elements can be inserted and removed.
5. Element access: Elements can be accessed using their positions.
6. Traversal: Elements can be visited sequentially.

Consider the following List:

```
Index:    0       1       2       3       4
        +-------+-------+-------+-------+-------+
List:   |  10   |  20   |  30   |  20   |  50   |
        +-------+-------+-------+-------+-------+
```

Notice:

- The elements have a defined sequence.
- The value `20` appears twice.
- Each element has a position.
- We can insert, remove, or replace elements.

The List ADT does not require any particular memory organization. It can be implemented using an array, linked nodes, or other structures.

## 2. Operations of the List ADT

The List ADT defines a collection of fundamental operations.

These operations describe what users of the data structure can do without needing to know its internal implementation.

Commonly defined operations in a List ADT include:
- `insert(n, e)`: insert the item `e` at position `n`,
- `remove(n)`: remove the item at position `n`,
- `get(n)`: get the item at position n,
- `sort()`: sort the items in the list,
- `slice(start, end)`: return a sub-list slice starting at the position start up until the position end,
- `reverse()`: reverse the order of the list.

### 2.1. Creation and Initialization

Create an empty List or initialize it with existing elements.

```
create()
create(elements)
```

Example:

```
List = [10, 20, 30, 40]
```

### 2.2. Insertion

Add elements to the List.

Common insertion operations:

| Operation                | Description                    | Example              |
| ------------------------ | ------------------------------ | -------------------- |
| `add(element)`           | Add an element at the end      | Add 50               |
| `insert(index, element)` | Insert at a specified position | Insert 15 at index 1 |
| `prepend(element)`       | Insert at the beginning        | Add 5                |
| `append(element)`        | Add at the end                 | Add 50               |

Example:

```
Original:
[10, 20, 30, 40]

Insert 15 at index 1:

[10, 15, 20, 30, 40]
```

Elements after the insertion position move one position to the right.

### 2.3. Deletion

Remove elements from the List.

| Operation         | Description                                |
| ----------------- | ------------------------------------------ |
| `remove(index)`   | Remove the element at a specified position |
| `remove(element)` | Remove an element matching a value         |
| `removeFirst()`   | Remove the first element                   |
| `removeLast()`    | Remove the last element                    |
| `clear()`         | Remove all elements                        |

Example:

```
Original:
[10, 20, 30, 40]

Remove element at index 1:

[10, 30, 40]
```

An important distinction: removing by value and removing by position are different operations.

For example, if the List contains duplicate values, removing by value may remove only the first matching occurrence, depending on the API.

### 2.4. Access and Retrieval

Retrieve an element without removing it.

| Operation    | Description                       |
| ------------ | --------------------------------- |
| `get(index)` | Retrieve an element at a position |
| `getFirst()` | Retrieve the first element        |
| `getLast()`  | Retrieve the last element         |

Example:

```
List = [10, 20, 30, 40]

get(2) = 30
get(0) = 10
```

### 2.5. Updating and Replacement

Replace the value at a specific position.

```
Original:
[10, 20, 30, 40]

set(2, 99):

[10, 20, 99, 40]
```

The position remains unchanged; only the stored value is replaced.

### 2.6. Searching

Find the position of an element.

| Operation              | Description                     |
| ---------------------- | ------------------------------- |
| `contains(element)`    | Check whether an element exists |
| `indexOf(element)`     | Find the first occurrence       |
| `lastIndexOf(element)` | Find the last occurrence        |

Example:

```
List = [10, 20, 30, 20, 40]

indexOf(20)     = 1
lastIndexOf(20) = 3
contains(50)   = false
```

### 2.7. Traversal and Iteration

Visit elements sequentially.

```
List = [10, 20, 30, 40]

Traversal:

10 -> 20 -> 30 -> 40
```

Common traversal mechanisms include:

- Iterators.
- Traditional loops.
- Enhanced for loops.
- Functional iteration methods such as `forEach`.

### 2.8. Size and State Operations

These operations provide information about the List.

| Operation    | Description                             |
| ------------ | --------------------------------------- |
| `size()`     | Return the number of elements           |
| `isEmpty()`  | Check whether the List is empty         |
| `capacity()` | Return allocated capacity, when exposed |
| `clear()`    | Remove all elements                     |

Notice that `size` and `capacity` are different concepts.

For a dynamic array:

```
+----+----+----+----+----+----+
| 10 | 20 | 30 |    |    |    |
+----+----+----+----+----+----+
       Size = 3
       Capacity = 6
```

The List contains three elements but has room for six without requiring another allocation.

Not every List implementation exposes capacity.

### 2.9. Other Useful Operations

More advanced List APIs may provide:

- Sorting.
- Reversing.
- Slicing or extracting a sublist.
- Concatenating two lists.
- Replacing elements based on a condition.
- Filtering elements.
- Removing duplicates.

These are useful extensions, although not all are fundamental List ADT operations.

## 3. Advantages of the List ADT

The List ADT provides several advantages that make it useful in software applications.

| Advantage                | Explanation                                            |
| ------------------------ | ------------------------------------------------------ |
| Ordered elements         | Maintains the positional sequence of elements          |
| Dynamic membership       | Supports adding and removing elements                  |
| Positional access        | Allows accessing elements by index                     |
| Duplicate elements       | Allows repeated values                                 |
| Easy traversal           | Supports sequential iteration                          |
| Flexible implementations | Can be implemented using different data structures     |
| Abstraction              | Hides implementation details behind a common interface |
| Reusability              | Provides a general-purpose collection abstraction      |

We create lists in our programs because we want to leverage
one or more of its advantages.

Let's examine some particularly important advantages.

### 3.1. Separation of abstraction and implementation

The List ADT allows application code to depend on the List abstraction instead of a particular storage mechanism.

For example, in Java:

```
List<String> names = new ArrayList<>();
```

We can replace the implementation:

```
List<String> names = new LinkedList<>();
```

Both implementations support the List contract, although their performance characteristics differ.

This provides flexibility and reduces coupling between application logic and data structure implementation.


### 1. Ordered Elements

A List maintains the order of its elements. When we insert new elements, their positions follow the insertion rules of the List.

Consider a system that maintains application log entries.

```
List<String> logs = new ArrayList<>();

logs.add("Application started");
logs.add("User logged in");
logs.add("Order created");
logs.add("Application stopped");
```

The list maintains the sequence:

```
Index       Element
-----       ----------------------
  0         Application started
  1         User logged in
  2         Order created
  3         Application stopped
```

We can retrieve the elements in their original sequence.

```
for (String log : logs) {
    System.out.println(log);
}
```

Output:

```
Application started
User logged in
Order created
Application stopped
```

Why is this useful?

Consider these applications:

- System logs: Maintain the sequence of recorded events.
- Transaction history: Maintain the order of transactions.
- Shopping lists: Maintain the order in which products were added.
- Workflow processing: Maintain a sequence of steps.
- Message processing: Maintain the order of messages.

Important distinction: A List preserves positional order, not necessarily sorted order.

For example:

```
List<Integer> numbers =
    new ArrayList<>(List.of(30, 10, 50, 20));
```

The List maintains:

```
[30, 10, 50, 20]
```

It does not automatically sort the elements.

If you insert an element at a particular index, subsequent elements shift to accommodate it.

```
numbers.add(1, 99);
```

Result:

```
[30, 99, 10, 50, 20]
```

### 2. Automatic Resizing

Lists can dynamically accommodate changes in their number of elements.

Unlike a traditional fixed-size array, an `ArrayList` can grow when additional elements are inserted.

Consider a traditional Java array:

```
int[] numbers = new int[3];

numbers[0] = 10;
numbers[1] = 20;
numbers[2] = 30;
```

Its length is fixed at three.

You cannot directly add another element beyond its allocated capacity.

With `ArrayList`:

```
List<Integer> numbers = new ArrayList<>();

numbers.add(10);
numbers.add(20);
numbers.add(30);
numbers.add(40);
numbers.add(50);
```

The collection automatically manages its internal capacity.

Conceptually:

```
Initially:
+----+----+----+
| 10 | 20 | 30 |
+----+----+----+
Capacity = 3

After adding more elements:
+----+----+----+----+----+----+
| 10 | 20 | 30 | 40 | 50 |    |
+----+----+----+----+----+----+
Capacity = 6 (illustrative)
```

The actual `ArrayList` implementation may allocate a larger backing array and copy existing references when capacity is exhausted.

Why is this useful?

- We don't need to predict the number of elements in advance.
- We don't manually allocate a larger array.
- We can add and remove elements dynamically.
- Collection size can change during application execution.

Important: Automatic resizing is an advantage of dynamically resizable List implementations such as `ArrayList`, not a universal characteristic of every List implementation.

For example, `LinkedList` grows by allocating additional nodes rather than resizing a backing array.

### 3. Positional Data Access

A List allows us to access elements using their indexes.

This is also called indexed or positional access.

Consider:

```
List<String> fruits = new ArrayList<>();

fruits.add("Apple");
fruits.add("Banana");
fruits.add("Orange");
fruits.add("Mango");
```

The elements have positions:

```
Index:    0         1          2          3
       +---------+----------+----------+---------+
       | Apple   | Banana   | Orange   | Mango   |
       +---------+----------+----------+---------+
```

We can retrieve a specific element:

```
String fruit = fruits.get(2);

System.out.println(fruit);
```

Output:

```
Orange
```

We can also update an element:

```
fruits.set(1, "Pineapple");
```

Result:

```
[Apple, Pineapple, Orange, Mango]
```

Why is this useful?

- Accessing a particular position in a collection.
- Implementing pagination and indexed navigation.
- Retrieving elements from a sequence.
- Updating elements without searching by value.

However, there is an important implementation difference:

| Implementation | `get(index)` complexity |
| -------------- | ----------------------- |
| ArrayList      | $O(1)$              |
| LinkedList     | $O(n)$              |
| Vector         | $O(1)$              |

Why?

`ArrayList` stores references in an array, so it can calculate the memory position directly.

`LinkedList` must traverse nodes until it reaches the requested position.

Therefore, although positional access is part of the List abstraction, its performance depends on the underlying implementation.

### 4. Duplicate Elements

Unlike a `Set`, a List allows duplicate elements.

For example:

```
List<String> products = new ArrayList<>();

products.add("Laptop");
products.add("Mouse");
products.add("Keyboard");
products.add("Mouse");
```

Result:

```
Index     Element
-----     --------
  0       Laptop
  1       Mouse
  2       Keyboard
  3       Mouse
```

Both occurrences of `"Mouse"` are retained.

This is important because sometimes repeated values represent different occurrences of the same information.

Practical examples:

- Shopping cart: A product may appear multiple times as separate entries.
- Transaction history: Multiple transactions may involve the same account.
- Event logs: The same event may occur repeatedly.
- Exam answers: Multiple questions may have identical answers.
- Message history: The same message content may be submitted more than once.

Compare List and Set:

| Characteristic     | List                       | Set                       |
| ------------------ | -------------------------- | ------------------------- |
| Duplicates         | Allowed                    | Not allowed               |
| Positional indexes | Supported                  | Not supported             |
| Ordering           | Maintains positional order | Depends on implementation |
| Access by index    | Supported                  | Not supported             |

For example:

```
List<String> list =
    new ArrayList<>(List.of("A", "B", "A"));
```

Result:

```
[A, B, A]
```

Whereas:

```
Set<String> set =
    new HashSet<>(List.of("A", "B", "A"));
```

Result contains only:

```
[A, B]
```

### 5. Iterability

A List provides convenient ways to traverse its elements.

This means we can visit each element and perform operations on it.

Java provides several ways to iterate over a List.

1\. Traditional for loop

```
List<String> fruits =
    List.of("Apple", "Banana", "Orange");

for (int i = 0; i < fruits.size(); i++) {
    System.out.println(fruits.get(i));
}
```

This is useful when we need the element index.

2\. Enhanced for loop

```
for (String fruit : fruits) {
    System.out.println(fruit);
}
```

This is useful when we only need to access elements sequentially.

3\. forEach method

```
fruits.forEach(fruit ->
    System.out.println(fruit)
);
```

4\. Iterator

```
Iterator<String> iterator = fruits.iterator();

while (iterator.hasNext()) {
    String fruit = iterator.next();
    System.out.println(fruit);
}
```

An Iterator is particularly useful when traversing a collection and conditionally removing elements using `iterator.remove()`.

Why is this useful?

Iteration is essential for:

- Processing collection elements.
- Filtering data.
- Transforming data.
- Searching for specific values.
- Generating reports.
- Applying business rules to collections.

For example:

```
List<Integer> numbers =
    List.of(10, 20, 30, 40, 50);

int sum = 0;

for (int number : numbers) {
    sum += number;
}

System.out.println(sum);
```

Output:

```
150
```

Note that iterability is not exclusive to Lists. Java collections generally support iteration through the `Iterable` interface.

This is one of the most important advantages of the List ADT.

Java separates the abstract behavior of a List from its underlying implementation.

The `List` interface defines what operations a List supports, while concrete classes determine how those operations are implemented.

The three implementations mentioned in the paragraph are:

- `ArrayList`
- `LinkedList`
- `Vector`

| Characteristic            | ArrayList            | LinkedList                               | Vector               |
| ------------------------- | -------------------- | ---------------------------------------- | -------------------- |
| Internal structure        | Dynamic array        | Doubly linked nodes                      | Dynamic array        |
| Random access             | $O(1)$           | $O(n)$                               | $O(1)$           |

ArrayList

Best suited for:

- Frequent indexed access.
- Frequent iteration.
- General-purpose collection storage.
- Situations where insertion at the end is common.

LinkedList

- Deque operations at both ends.
- Insertion/removal when the relevant node or iterator position is already available.

- Individual methods are synchronized.
- Often replaced by `ArrayList` in single-threaded use.

There is an important architectural benefit here.

You can program against the `List` interface instead of depending on a specific implementation:

```
List<String> names = new ArrayList<>();
```

Later, if your requirements change:

```
List<String> names = new LinkedList<>();
```

The rest of your code can continue using the List contract without depending on implementation-specific methods.

This is an example of programming to an interface rather than an implementation.

## 4. Limitations of the List ADT

Although Lists are flexible, they are not suitable for every situation.

The limitations depend partly on the underlying implementation.

### 4.1. Searching can be expensive

A conventional List does not automatically provide efficient key-based lookup.

For example:

```
List = [10, 20, 30, 40, 50]
```

To find `40`, we may need to examine several elements sequentially.

$$
T(n) = O(n)
$$

If frequent lookup by key is required, a HashMap may be more appropriate.

### 4.2. Insertion and deletion can be expensive

In an array-backed List, inserting an element in the middle requires shifting subsequent elements.

```
Before:
[10, 20, 30, 40, 50]

Insert 99 at index 2:

[10, 20, 99, 30, 40, 50]
```

The elements `30`, `40`, and `50` must be shifted.

This requires $O(n)$ time in the general case.

Linked lists avoid shifting elements, but finding the insertion position may still require $O(n)$ traversal.

### 4.3. Memory overhead

Different implementations have different memory costs.

- Dynamic arrays may reserve unused capacity.
- Linked lists allocate separate nodes.
- Doubly linked lists maintain two references per node.
- Some specialized lists maintain additional metadata.

Therefore, the choice of implementation affects memory efficiency.

### 4.4. No automatic uniqueness guarantee

Lists allow duplicates.

If the application requires unique elements, additional checking is needed or a Set should be used.

For example:

```
List<String> usernames = new ArrayList<>();

usernames.add("admin");
usernames.add("admin");
```

Both entries are accepted.

### 4.5. No automatic sorting

A List maintains positional order, but it does not necessarily maintain sorted order.

For example:

```
[50, 10, 40, 20, 30]
```

If sorted ordering is required, we must explicitly sort the List or choose an appropriate ordered structure.

### 4.6. Thread safety is not guaranteed

Many List implementations are not thread-safe.

For example, Java's `ArrayList` does not provide synchronization for concurrent modifications.

If multiple threads modify a shared List, synchronization or a concurrent collection may be necessary.

## 6. Data Structures Based on the List ADT

The List ADT can be implemented using several different underlying data structures.

The most important implementations are:

### 6.1. Array-Based List

An array-based List stores elements in an array and maintains the number of occupied positions.

```
Index:  0    1    2    3    4
      +----+----+----+----+----+
      | 10 | 20 | 30 | 40 | 50 |
      +----+----+----+----+----+
```

Characteristics:

- Direct indexed access.
- Efficient traversal.
- Good memory locality.
- Insertion and deletion in the middle require shifting elements.

Examples:

- Java `ArrayList`.
- C++ `std::vector`.
- Python `list`.
- Rust `Vec<T>`.
- JavaScript `Array`.

A dynamic array is particularly useful when indexed access and sequential traversal are frequent.

### 6.2. Singly Linked List

A singly linked list consists of nodes, where each node stores data and a reference to the next node.

```
Head
 |
 v
+------+------+
|  10  | Next |----+
+------+------+    |
                   v
              +------+------+
              |  20  | Next |----+
              +------+------+    |
                                  v
                             +------+------+
                             |  30  | null|
                             +------+------+
```

Characteristics:

- Each node points to the next node.
- No direct indexed access.
- Efficient insertion and deletion at the head.
- Efficient insertion after a known node.
- Requires traversal to locate an element.

Typical applications:

- Simple dynamic sequences.
- Stack implementation.
- Some graph representations.
- Specialized memory-management structures.

### 6.3. Doubly Linked List

A doubly linked list maintains references to both the previous and next nodes.

```
null <- [10] <-> [20] <-> [30] -> null
```

Each node contains:

```
+----------+-------+----------+
| Previous | Data  | Next     |
+----------+-------+----------+
```

Characteristics:

- Traversal in both directions.
- Efficient insertion and deletion when the node is already known.
- Efficient operations at both ends when head and tail references are maintained.
- More memory overhead than a singly linked list.

Typical applications:

- Deques.
- LRU cache implementations.
- Browser navigation history.
- Bidirectional traversal.

### 6.4. Circular Linked List

A circular linked list connects the final node back to the first node.

Singly circular linked list:

```
       +-----------------------+
       |                       |
       v                       |
Head -> [10] -> [20] -> [30] ---+
```

Doubly circular linked list:

```
       +-----------------------------+
       |                             |
       v                             |
      [10] <-> [20] <-> [30] --------+
       ^                             |
       +-----------------------------+
```

Characteristics:

- No conventional null termination at the circular boundary.
- Traversal can continue cyclically.
- Useful for repeated round-robin processing.

Typical applications:

- Round-robin scheduling.
- Multiplayer turn management.
- Cyclic resource allocation.
- Repeating playlists.

### 6.5. Specialized List Structures

There are also more specialized structures that extend or optimize list-like behavior.

| Structure            | Description                                             | Typical use                                        |
| -------------------- | ------------------------------------------------------- | -------------------------------------------------- |
| Unrolled Linked List | Each node stores multiple elements                      | Reduce node overhead and improve locality          |
| Skip List            | Linked levels provide shortcuts for searching           | Ordered maps and sets                              |
| Gap Buffer           | Maintains a movable gap in an array                     | Text editors                                       |
| XOR Linked List      | Encodes neighboring node references using XOR           | Memory-constrained specialized implementations     |
| Cursor List          | Uses array indexes instead of pointers to connect nodes | Environments without convenient dynamic allocation |

An important distinction: these are specialized sequence or linked structures, not necessarily implementations of exactly the same List ADT contract.

## 7. Comparison of List-Based Data Structures

This table compares the principal List implementations.

### 7.1. Structural and operational comparison

Assume $n$ is the number of elements.

| Operation                | Dynamic Array        | Singly Linked List | Doubly Linked List | Circular Linked List |
| ------------------------ | -------------------- | ------------------ | ------------------ | -------------------- |
| Access by index          | $O(1)$           | $O(n)$         | $O(n)$         | $O(n)$           |
| Search by value          | $O(n)$           | $O(n)$         | $O(n)$         | $O(n)$           |
| Insert at beginning      | $O(n)$           | $O(1)$         | $O(1)$         | $O(1)$\*         |
| Insert at end            | $O(1)$ amortized | $O(n)$\*       | $O(1)$\*       | $O(1)$\*         |
| Insert at known position | $O(n)$           | $O(1)$\*\*     | $O(1)$\*\*     | $O(1)$\*\*       |
| Delete at beginning      | $O(n)$           | $O(1)$         | $O(1)$         | $O(1)$\*         |
| Delete at end            | $O(1)$           | $O(n)$\*       | $O(1)$\*       | $O(n)$\*         |
| Traversal                | $O(n)$           | $O(n)$         | $O(n)$         | $O(n)$           |

\* Assumes appropriate head/tail references and correct pointer maintenance. A singly linked list with only a head reference has $O(n)$ append and tail deletion. A circular singly linked list with a tail reference can perform several end operations in $O(1)$. \*\*Assumes the relevant node or insertion position has already been located; locating it by index takes $O(n)$.

### 7.2. Memory and implementation comparison

| Structure            | Memory organization                          | Memory overhead               | Main advantage                              | Main limitation                         |
| -------------------- | -------------------------------------------- | ----------------------------- | ------------------------------------------- | --------------------------------------- |
| Dynamic Array        | Contiguous array of references/elements      | Unused capacity               | Fast indexed access                         | Shifting on insertion/deletion          |
| Singly Linked List   | Separate nodes with next references          | One link per node             | Efficient head operations                   | Forward-only traversal                  |
| Doubly Linked List   | Separate nodes with previous/next references | Two links per node            | Bidirectional traversal                     | Additional memory                       |
| Circular Linked List | Nodes connected in a cycle                   | One or two links per node     | Cyclic traversal                            | More careful termination logic          |
| Unrolled Linked List | Blocks of elements linked together           | Block and link overhead       | Better locality than node-per-element lists | More complex insertion/deletion         |
| Skip List            | Multiple linked levels                       | Additional forward references | Expected $O(\log n)$ search             | Extra memory and probabilistic behavior |

## 8. List ADT in Different Programming Languages

The List ADT is language-independent, but programming languages expose it through different interfaces, classes, standard-library containers, and built-in types.

Some languages provide a dedicated List interface, while others use dynamic arrays as their primary list abstraction.

Let's examine the six languages you mentioned.

### 8.1. C

C does not provide a standard built-in List ADT or a standard collection library comparable to Java's Collections Framework.

Lists are generally implemented manually using arrays or dynamically allocated nodes.

| Structure            | C representation             | Description                 |
| -------------------- | ---------------------------- | --------------------------- |
| Dynamic Array        | `malloc()` / `realloc()`     | Dynamically allocated array |
| Singly Linked List   | `struct Node *next`          | Node-based forward list     |
| Doubly Linked List   | `struct Node *prev`, `*next` | Bidirectional linked list   |
| Circular Linked List | Circular node references     | Last node points to first   |

Example of a singly linked list:

```
typedef struct Node {
    int data;
    struct Node *next;
} Node;
```

Creating nodes:

```
Node *first = malloc(sizeof(Node));
Node *second = malloc(sizeof(Node));

first->data = 10;
first->next = second;

second->data = 20;
second->next = NULL;
```

Representation:

```
first
  |
  v
+------+------+
|  10  |   o--+----+
+------+------+    |
                   v
              +------+------+
              |  20  | NULL |
              +------+------+
```

Thread safety: C does not automatically provide thread-safe linked lists or dynamic arrays. Synchronization must be implemented using facilities such as POSIX mutexes or C11 synchronization primitives.

### 8.2. C++

C++ provides several standard-library sequence containers.

The most important are:

| Structure          | C++ type               | Internal implementation |
| ------------------ | ---------------------- | ----------------------- |
| Dynamic Array      | `std::vector<T>`       | Dynamic array           |
| Doubly Linked List | `std::list<T>`         | Doubly linked list      |
| Singly Linked List | `std::forward_list<T>` | Singly linked list      |
| Double-ended Queue | `std::deque<T>`        | Segmented dynamic array |

Example:

```
#include <vector>
#include <list>
#include <forward_list>

std::vector<int> numbers = {10, 20, 30};

std::list<int> linkedNumbers = {10, 20, 30};

std::forward_list<int> forwardNumbers = {10, 20, 30};
```

Notice that C++ uses different container names rather than one universal `List` interface.

A particularly important distinction:

- `std::vector` is usually the default choice for general-purpose sequences.
- `std::list` is useful when frequent insertion and deletion at known positions justify node-based storage.
- `std::forward_list` provides a more memory-efficient singly linked alternative.

Thread safety: Standard containers do not provide general synchronization for concurrent modifications. Some concurrent reads are permitted under the C++ library's thread-safety guarantees, but concurrent structural modification requires appropriate synchronization.

### 8.3. Java

Java provides a formal `List<E>` interface in the Collections Framework.

The main implementations include:

| Structure                  | Java class                | Internal implementation |
| -------------------------- | ------------------------- | ----------------------- |
| Dynamic Array              | `ArrayList<E>`            | Dynamic array           |
| Doubly Linked List         | `LinkedList<E>`           | Doubly linked list      |
| Synchronized Dynamic Array | `Vector<E>`               | Dynamic array           |
| Copy-on-Write List         | `CopyOnWriteArrayList<E>` | Copy-on-write array     |

Example:

```
List<Integer> numbers = new ArrayList<>();

numbers.add(10);
numbers.add(20);
numbers.add(30);

System.out.println(numbers.get(1));
```

Output:

```
20
```

Java's List interface is particularly useful because application code can depend on the abstraction:

```
List<Integer> numbers = new ArrayList<>();
```

rather than depending directly on a concrete implementation.

Thread safety:

- `ArrayList`: Not thread-safe.
- `LinkedList`: Not thread-safe.
- `Vector`: Synchronizes individual methods.
- `CopyOnWriteArrayList`: Supports concurrent access using copy-on-write semantics.
- `Collections.synchronizedList()`: Provides a synchronized wrapper.

### 8.4. JavaScript

JavaScript provides the built-in `Array` object as its primary dynamic sequence structure.

```
const numbers = [10, 20, 30];

numbers.push(40);
numbers.unshift(5);

console.log(numbers[2]);
```

JavaScript arrays support:

| Operation                 | Method                     |
| ------------------------- | -------------------------- |
| Append                    | `push()`                   |
| Remove last               | `pop()`                    |
| Insert at beginning       | `unshift()`                |
| Remove first              | `shift()`                  |
| Insert/remove at position | `splice()`                 |
| Search                    | `indexOf()` / `includes()` |
| Iterate                   | `forEach()`                |
| Extract a portion         | `slice()`                  |
| Sort                      | `sort()`                   |

JavaScript does not provide a standard built-in linked-list class.

Linked lists can be implemented manually using objects:

```
class Node {
    constructor(data) {
        this.data = data;
        this.next = null;
    }
}
```

Thread safety:

JavaScript typically executes application code on an event-loop thread within an execution agent. Web Workers and Node.js worker threads introduce concurrent execution.

Ordinary arrays are not automatically synchronized. Shared memory between workers requires mechanisms such as `SharedArrayBuffer` and `Atomics`, rather than treating a normal array as a synchronized collection.

### 8.5. Rust

Rust provides `Vec<T>` as its primary dynamic-array collection.

It also provides `LinkedList<T>` in its standard library.

| Structure          | Rust type       | Internal implementation   |
| ------------------ | --------------- | ------------------------- |
| Dynamic Array      | `Vec<T>`        | Growable contiguous array |
| Doubly Linked List | `LinkedList<T>` | Doubly linked list        |
| Double-ended Queue | `VecDeque<T>`   | Growable ring buffer      |

Example:

```
fn main() {
    let mut numbers: Vec<i32> = Vec::new();

    numbers.push(10);
    numbers.push(20);
    numbers.push(30);

    println!("{}", numbers[1]);
}
```

Output:

```
20
```

Rust also provides `VecDeque<T>`:

```
use std::collections::VecDeque;

fn main() {
    let mut numbers = VecDeque::new();

    numbers.push_back(10);
    numbers.push_back(20);
    numbers.push_front(5);

    println!("{:?}", numbers);
}
```

Output:

```
[5, 10, 20]
```

An interesting Rust design decision is that `Vec<T>` is preferred for most general-purpose sequence operations, while `LinkedList<T>` is intended for situations where its particular node-based behavior is useful.

Thread safety:

Rust uses ownership, borrowing, and type-system guarantees to prevent data races.

- `Vec<T>` and `LinkedList<T>` are not internally synchronized.
- They can be shared across threads when their element types satisfy the appropriate `Send` and `Sync` requirements.
- `Mutex<T>` can protect mutable shared collections.
- `RwLock<T>` supports synchronized readers and writers.

For example:

```
use std::sync::Mutex;

let numbers = Mutex::new(vec![10, 20, 30]);
```

### 8.6. Python

Python provides `list` as its primary dynamic sequence type.

It also provides `collections.deque`, a double-ended queue.

| Structure          | Python type           | Internal implementation   |
| ------------------ | --------------------- | ------------------------- |
| Dynamic Array      | `list`                | Dynamic array             |
| Double-ended Queue | `collections.deque`   | Linked blocks of elements |
| Singly Linked List | Manual implementation | User-defined nodes        |
| Doubly Linked List | Manual implementation | User-defined nodes        |

Example:

```
numbers = [10, 20, 30]numbers.append(40)numbers.insert(1, 15)print(numbers[2])
```

Output:

```
20
```

Python's `list` supports:

- Indexed access.
- Dynamic resizing.
- Duplicate elements.
- Iteration.
- Insertion and deletion.
- Slicing.

For efficient operations at both ends:

```
from collections import dequenumbers = deque([10, 20, 30])numbers.appendleft(5)numbers.append(40)print(numbers)
```

Output:

```
deque([5, 10, 20, 30, 40])
```

Thread safety:

Python's thread-safety guarantees depend on the implementation and operation.

In conventional CPython builds, the GIL provides some protection around interpreter execution, but it does not make arbitrary compound operations on a shared List atomic or logically thread-safe.

For synchronized producer-consumer processing, Python provides `queue.Queue`.

### 9.2. Operations performance

The following table compares typical implementations rather than individual language-specific micro-optimizations.

| Operation            | Dynamic Array        | Singly Linked List | Doubly Linked List | Circular Linked List |
| -------------------- | -------------------- | ------------------ | ------------------ | -------------------- |
| Access by index      | $O(1)$           | $O(n)$         | $O(n)$         | $O(n)$           |
| Search               | $O(n)$           | $O(n)$         | $O(n)$         | $O(n)$           |
| Append               | $O(1)$ amortized | $O(1)$\*       | $O(1)$\*       | $O(1)$\*         |
| Prepend              | $O(n)$           | $O(1)$         | $O(1)$         | $O(1)$\*         |
| Insert at known node | $O(n)$           | $O(1)$         | $O(1)$         | $O(1)$           |
| Remove known node    | $O(n)$           | $O(1)$\*\*     | $O(1)$         | $O(1)$\*\*       |
| Remove last          | $O(1)$           | $O(n)$\*       | $O(1)$\*       | $O(n)$\*         |

\* Assumes the implementation maintains the appropriate tail reference.\
\*\* Singly linked deletion requires access to the predecessor, except for special cases such as deleting the head.

These are structural complexities. Actual performance also depends on memory allocation, cache locality, runtime implementation, and element type.

### 9.3. Thread-safety comparison

| Language   | Default List implementation | Thread-safety characteristics                                                      | Common synchronization mechanism                  |
| ---------- | --------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------- |
| C          | Manual arrays/lists         | No automatic synchronization                                                       | POSIX mutexes, C11 synchronization                |
| C++        | `std::vector`, `std::list`  | No general synchronization for concurrent modifications                            | `std::mutex`, `std::shared_mutex`                 |
| Java       | `Vector`,`ArrayList`, `LinkedList`   | `ArrayList`, `LinkedList` Not thread-safe, `Vector` thread-safe                                                                   | `synchronizedList`, concurrent collections, locks |
| JavaScript | `Array`                     | No automatic synchronization; workers have separate execution contexts             | `SharedArrayBuffer`, `Atomics`                    |
| Rust       | `Vec<T>`, `LinkedList<T>`   | Ownership and type-system safety; no automatic synchronization for shared mutation | `Mutex`, `RwLock`                                 |
| Python     | `list`                      | No general guarantee of thread-safe compound operations                            | `threading.Lock`, `queue.Queue`                   |

An important distinction: thread safety and memory safety are not the same thing.

While LinkedList and ArrayList are not thread-safe by default, they can be made
thread-safe by explicitly synchronizing access. This should prevent concurrent access-related
data corruption, but it will likely lead to lower performance regarding your application.

Rust, for example, prevents data races through its ownership and type systems, but that does not mean every shared data structure automatically provides synchronized access.

- A deque is a specialized sequence abstraction, not exactly the same contract as a general List.
- A skip list is an ordered linked structure with multiple levels; it is not simply an ordinary List implementation.
- Concurrent variants exist for some of these structures, but synchronization must be evaluated separately.

## 11. When Should You Use Each Structure?

A useful way to remember the differences is to start with the application's access pattern.

When choosing between `LinkedList`, `ArrayList`, and `Vector` list types, we should consider
the requirements based on our use case. For example, if our use case includes frequent adds
and deletes, then `LinkedList` might be the best option. Alternatively, if we have infrequent
adds and deletes, but heavy reads, then `ArrayList` is likely our best option. Finally, if we are
most concerned about thread safety, `Vector` might be our best option.

**Choosing a List-based structure**

- **Frequent indexed access?**

    Use a **Dynamic Array**.

    Examples: `ArrayList`, `std::vector`, `Vec<T>`, Python `list`.

- **Frequent insertion/removal at the beginning?**

    Consider a **Linked List or Deque**.

    Examples: `LinkedList`, `std::deque`, `VecDeque<T>`.

- **Frequent operations at both ends?**

    Use a *Deque*.

    Examples: Java `ArrayDeque`, Python `collections.deque`.

- **Cyclic processing?**

    Consider a **Circular Linked List**.

    Examples: round-robin scheduling and cyclic resource allocation.

- **Ordered searching and insertion?**

    Consider a **Skip List**.

    Examples: ordered indexes and specialized concurrent collections.

The Stack or Queue should be preferred when the flexibility of List isn’t needed. Using a simpler ADT ensures data is handled in a strict and robust way (FIFO or LIFO). It also makes the code easier to understand: knowing a variable is a Stack helps to see how data flows in and out.

One additional practical recommendation: for general-purpose application development, dynamic arrays are usually the first choice. Linked lists should be selected when their particular insertion, deletion, or traversal characteristics provide a genuine advantage.

## 12. Important Conceptual Distinction: List, Stack, Queue, and Deque

Since you are building your DSA knowledge progressively, it is important to understand the relationship between these abstract data types.

They are related, but they define different behaviors.

| ADT            | Access principle  | Insertion                       | Removal                 |
| -------------- | ----------------- | ------------------------------- | ----------------------- |
| List           | Positional access | At different positions          | At different positions  |
| Stack          | LIFO              | Top                             | Top                     |
| Queue          | FIFO              | Rear                            | Front                   |
| Deque          | Both ends         | Front or rear                   | Front or rear           |
| Priority Queue | Priority-based    | According to priority structure | Highest/lowest priority |

For example:

```
LIST
[10, 20, 30, 40]
Can access and modify elements by position.


STACK
       TOP
        |
        v
       [40]
       [30]
       [20]
       [10]

Last In, First Out.


QUEUE

FRONT                  REAR
  |                      |
  v                      v
[10] -> [20] -> [30] -> [40]

First In, First Out.
```

These ADTs can share underlying implementations.

For example:

- A Stack can be implemented using an array or linked list.
- A Queue can be implemented using a circular array or linked list.
- A Deque can be implemented using a doubly linked list or circular dynamic array.

However, sharing an implementation does not make these ADTs equivalent.

### 14. Final Takeaways

There are five concepts you should retain from this chapter:

1. List ADT: Defines a linear collection with positional ordering, duplicate elements, and operations for accessing and manipulating elements.
2. Implementations: Dynamic arrays, singly linked lists, doubly linked lists, and circular linked lists provide different ways to implement list-like behavior.
3. Performance: The same List operation can have different time and space complexities depending on the implementation.
4. Programming languages: The List ADT is language-independent, but each language exposes it through different abstractions and concrete types.
5. Selection: Choose the implementation according to access patterns, insertion/deletion frequency, memory overhead, concurrency requirements, and performance guarantees.

My suggested learning sequence: Study the List ADT first, then array-based Lists, followed by linked lists (singly, doubly, and circular). After that, study the language-specific implementations, followed by Stack, Queue, and Deque. This creates a natural progression from abstract behavior to concrete implementation and then to specialized ADTs.

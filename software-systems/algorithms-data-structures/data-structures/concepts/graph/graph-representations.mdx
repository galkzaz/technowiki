

One of the most important aspects of the graph data structure is **how we store it in memory**.

A graph representation is a way to store a graph's vertices and edges in memory so that a program can perform operations such as adding edges, checking connections, finding neighbors, and traversing the graph.

Recall that a graph is defined as:

```math
G=(V,E)
```

- $V$: the set of vertices (nodes).
- $E$: the set of edges (connections).

There are several ways to represent a graph in a program. The most common are:

1. Edge List
2. Adjacency Matrix
3. Adjacency List
4. Incidence Matrix

Consider this undirected graph:

```
       A -------- B
       |          |
       |          |
       C -------- D -------- E
```

Its vertices are:

```math
V=\\{A,B,C,D,E\\} 
```

Its edges are:

```math
E=\\{\\{A,B\\},\\{A,C\\},\\{B,D\\},\\{C,D\\},\\{D,E\\}\\} 
```

There are five vertices and five edges.

The neighbors of each vertex are:

| Vertex | Neighbors | Degree |
| ------ | --------- | ------ |
| A      | B, C      | 2      |
| B      | A, D      | 2      |
| C      | A, D      | 2      |
| D      | B, C, E   | 3      |
| E      | D         | 1      |

Every representation below stores this same graph, but organizes the information differently.

## 1. Edge List

An edge list stores the graph as a collection of edges. Each edge records the vertices it connects.

```
Vertices:
A, B, C, D, E

Edges:
(A, B)
(A, C)
(B, D)
(C, D)
(D, E)
```

For an undirected graph, `(A, B)` represents the same connection as `(B, A)`. We store the edge once.

### Python implementation

```python
vertices = ["A", "B", "C", "D", "E"]

edges = [
    ("A", "B"),
    ("A", "C"),
    ("B", "D"),
    ("C", "D"),
    ("D", "E"),
]

print(edges)
```

### How it works

To add an edge between `A` and `D`, append another pair:

```
edges.append(("A", "D"))
```

To check whether `A` and `B` are connected, search the edge list for either ordering of the pair in an undirected graph.

### Advantages and disadvantages

- Advantages: Simple, compact, and easy to process all edges.
- Disadvantages: Checking whether a specific edge exists requires searching the list, typically $O(E)$.
- Best suited for: Algorithms that primarily process edges, such as Kruskal's minimum spanning tree algorithm.

### Adjacency Matrix
An adjacency matrix uses a two-dimensional array to represent which vertices are connected by edges.

Each row represents a vertex, and each column represents a vertex. The cell at row $i$ column $j$ tells us whether an edge exists between those vertices.

For an unweighted graph:

- `1` means an edge exists.
- `0` means no edge exists.

### Example

Using the vertex order `A, B, C, D, E`, our graph becomes:

```
      A  B  C  D  E
    +---------------
 A  | 0  1  1  0  0
 B  | 1  0  0  1  0
 C  | 1  0  0  1  0
 D  | 0  1  1  0  1
 E  | 0  0  0  1  0
```

For example:

- `matrix[A][B] = 1` because A connects to B.
- `matrix[A][D] = 0` because A does not directly connect to D.
- `matrix[D][E] = 1` because D connects to E.

Notice that the matrix is symmetric because the graph is undirected:

```math
M[i][j]=M[j][i] 
```

### Python implementation

```python
vertices = ["A", "B", "C", "D", "E"]

index = {v: i for i, v in enumerate(vertices)}
n = len(vertices)

matrix = [[0] * n for _ in range(n)]

edges = [
    ("A", "B"),
    ("A", "C"),
    ("B", "D"),
    ("C", "D"),
    ("D", "E"),
]

for u, v in edges:
    i, j = index[u], index[v]
    matrix[i][j] = 1
    matrix[j][i] = 1  # Undirected edge

# Check whether A and B are adjacent.
print(matrix[index["A"]][index["B"]])  # 1

# Check whether A and D are adjacent.
print(matrix[index["A"]][index["D"]])  # 0
```

### Weighted graphs

For a weighted graph, the matrix stores edge weights instead of just `1`.

```
       A    B    C
A      0    5    2
B      5    0    7
C      2    7    0
```

Here, the weight of the edge between A and B is 5.

If the graph has negative weights or permits an actual edge weight of zero, use a separate indicator or an appropriate representation to distinguish an existing edge from a missing edge.

### Advantages and disadvantages

- Advantages: Checking whether an edge exists takes $O(1)$ time. The representation is straightforward and works well for dense graphs.
- Disadvantages: Requires $O(V^2)$ space, even when few edges exist. Finding all neighbors of a vertex takes $O(V)$ time.
- Best suited for: Dense graphs and algorithms that frequently check whether specific edges exist.

#### Adjacency Matrix Complexity

For `V` vertices:

| Operation                 | Complexity |
| ------------------------- | ---------: |
| Check whether edge exists |     `O(1)` |
| Add edge                  |     `O(1)` |
| Remove edge               |     `O(1)` |
| Find neighbors            |     `O(V)` |
| Space                     |    `O(V²)` |

The major disadvantage is:

> It uses `O(V²)` memory even when the graph has relatively few edges.


## Adjacency List

An adjacency list stores each vertex together with a list of its neighboring vertices.

Instead of storing every possible connection, it stores only the edges that actually exist.

### Example

For our graph:

```
A: B, C
B: A, D
C: A, D
D: B, C, E
E: D
```

This is usually the most useful representation for graph algorithms.

Conceptually:

```text
Vertex     Neighbors

A          B → C
B          A → D
C          A → D
D          B → C→ E
E          D
```

Each line represents one vertex and its neighbors.

For example:

```
D: B, C, E
```

This means D has three neighbors: B, C, and E.

### Python implementation

```python
graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A", "D"],
    "D": ["B", "C", "E"],
    "E": ["D"],
}

# Find the neighbors of D.
print(graph["D"])  # ['B', 'C', 'E']

# Check whether A and B are adjacent.
print("B" in graph["A"])  # True
```

For an undirected graph, every edge is stored in both endpoints' neighbor lists. For example, B appears in A's list, and A appears in B's list.

### Adding an edge

```python
def add_edge(graph, u, v):
    graph.setdefault(u, [])
    graph.setdefault(v, [])

    graph[u].append(v)
    graph[v].append(u)  # Undirected graph
```

Calling `add_edge(graph, "A", "D")` adds the new connection in both directions.

This simple implementation does not prevent duplicate edges. If the graph is intended to be simple, you should check whether the edge already exists before adding it.

### Java example: Adjacency list

Since adjacency lists are widely used for graph algorithms, here is a simple Java implementation.

```
import java.util.*;

public class GraphExample {

    private final Map<String, List<String>> adjacency =
        new LinkedHashMap<>();

    public void addVertex(String vertex) {
        adjacency.putIfAbsent(vertex, new ArrayList<>());
    }

    public void addEdge(String u, String v) {
        addVertex(u);
        addVertex(v);

        adjacency.get(u).add(v);
        adjacency.get(v).add(u);
    }

    public void printGraph() {
        adjacency.forEach((vertex, neighbors) ->
            System.out.println(vertex + ": " + neighbors)
        );
    }

    public static void main(String[] args) {
        GraphExample graph = new GraphExample();

        graph.addEdge("A", "B");
        graph.addEdge("A", "C");
        graph.addEdge("B", "D");
        graph.addEdge("C", "D");
        graph.addEdge("D", "E");

        graph.printGraph();
    }
}
```

Output:

```
A: [B, C]
B: [A, D]
C: [A, D]
D: [B, C, E]
E: [D]
```

This implementation represents an undirected graph. For a directed graph, `addEdge` would add `v` to `u`'s adjacency list without adding `u` to `v`'s list.

### undirected graph vs directed graph
{/* This paragraph explains why an undirected graph stores each edge twice in an adjacency list, and why that extra storage is useful. */}

**undirected graph stores each edge twice in an adjacency list**

Consider an undirected graph:

```
A ----- B
|
|
C
```

It contains two edges:

- $A-B$
- $A-C$

Because the graph is undirected, the connection $A-B$ can be traversed from either endpoint.

An adjacency list represents this as:

```
A -> B -> C -> NULL
B -> A -> NULL
C -> A -> NULL
```

Notice that the edge between `A` and `B` appears in two places:

```
A's list: A -> B
B's list: B -> A
```

These are two adjacency-list entries representing one logical undirected edge.

uppose the graph instead contains these directed edges:

```
A ----> B
|
v
C
```

The edges are $A \to B$ and $A \to C$.

Its adjacency list is:

```
A -> B -> C -> NULL
B -> NULL
C -> NULL
```

Each directed edge appears only in the list belonging to its source vertex.

| Graph      | Logical edges | Adjacency-list entries |
| ---------- | ------------- | ---------------------- |
| Undirected | 2             | 4                      |
| Directed   | 2             | 2                      |

For an undirected graph, each edge contributes two entries, one for each endpoint. For a directed graph, each edge contributes one entry.

More generally, if $E$ is the number of edges:

- Undirected graph: $2E$ adjacency entries.
- Directed graph: $E$ adjacency entries.

This assumes no self-loops and the usual adjacency-list representation.

---

**Why is the extra storage worthwhile?**

The advantage is that finding all neighbors of a vertex takes time proportional to its actual number of neighbors.

Consider:

```
    A ----- B
    |
    C ----- D
```

Suppose we want to find all neighbors of `A`.

With an adjacency list:

```
A -> B -> C -> NULL
```

We examine only `B` and `C`.

The time complexity is:

$$
O(\deg(A))
$$

Here, $\deg(A)$ is the number of neighbors of `A`.

With an adjacency matrix, we would have to scan the entire row for `A`, which takes $O(V)$ time.

This difference matters for large, sparse graphs, where most vertices have relatively few neighbors.

The key takeaway: An undirected edge is stored twice in a conventional adjacency list to make neighbor traversal efficient from either endpoint. The extra storage is $O(E)$, so the overall space complexity remains $O(V+E)$.

### Advantages and disadvantages

- Advantages: Uses $O(V+E)$ space and efficiently visits a vertex's neighbors.
- Disadvantages: Checking whether a specific edge exists requires searching the relevant neighbor list, which can take $O(\deg(v))$ time.
- Best suited for: Sparse graphs and graph traversal algorithms such as BFS and DFS.

#### Adjacency List Complexity

For `V` vertices and `E` edges:

| Operation      | Typical complexity |
| -------------- | -----------------: |
| Add edge       |             `O(1)` |
| Remove edge    |     `O(degree(v))` |
| Check edge     |     `O(degree(v))` |
| Find neighbors |     `O(degree(v))` |
| Space          |         `O(V + E)` |

For sparse graphs, adjacency lists are usually much more memory-efficient than adjacency matrices.


## Incidence Matrix

An incidence matrix represents the relationship between vertices and edges.

Unlike an adjacency matrix, whose rows and columns both represent vertices, an incidence matrix has:

- One row for each vertex.
- One column for each edge.

For an undirected graph, an entry is `1` if the vertex is an endpoint of that edge and `0` otherwise.

Let's name the edges:

- $e_1=(A,B)$
- $e_2=(A,C)$
- $e_3=(B,D)$
- $e_4=(C,D)$
- $e_5=(D,E)$

The incidence matrix is:

```
       e1 e2 e3 e4 e5
       AB AC BD CD DE
     +---------------
 A   |  1  1  0  0  0
 B   |  1  0  1  0  0
 C   |  0  1  0  1  0
 D   |  0  0  1  1  1
 E   |  0  0  0  0  1
```

For example, the column for edge $e_3=(B,D)$ contains `1` in rows B and D because those are its endpoints.

For a loop-free undirected graph, each edge column contains exactly two `1`s.

### Advantages and disadvantages

- Advantages: Makes the relationship between vertices and individual edges explicit; useful in mathematical graph theory and some network optimization problems.
- Disadvantages: Requires $O(VE)$ space for the standard matrix representation, which can be inefficient for large graphs.
- Best suited for: Mathematical analysis and problems where edge-to-vertex relationships are central.

For directed graphs, incidence matrices commonly use `-1` for the source and `+1` for the destination, although the sign convention may vary.


## Comparing Representations
Let $V$ be the number of vertices, $E$ the number of edges, and $\deg(v)$ the degree of vertex $v$.

| Operation or property          | Edge list    | Adjacency matrix | Adjacency list   | Incidence matrix                                    |
| ------------------------------ | ------------ | ---------------- | ---------------- | --------------------------------------------------- |
| Space                          | $O(V+E)$ | $O(V^2)$     | $O(V+E)$     | $O(VE)$                                         |
| Check a specific edge          | $O(E)$   | $O(1)$       | $O(\deg(v))$ | $O(V)$ to locate endpoints by scanning a column |
| Find all neighbors of a vertex | $O(E)$   | $O(V)$       | $O(\deg(v))$ | $O(VE)$ with a straightforward scan             |
| Iterate over all edges         | $O(E)$   | $O(V^2)$     | $O(V+E)$     | $O(VE)$ to scan the matrix                      |

These are standard worst-case bounds for straightforward implementations. Some operations can be faster with indexing, auxiliary data structures, or different storage layouts.

| Feature                    | Adjacency Matrix | Adjacency List | Edge List |
| -------------------------- | ---------------: | -------------: | --------: |
| Space                      |          `O(V²)` |       `O(V+E)` |    `O(E)` |
| Check edge                 |           `O(1)` |    `O(degree)` |    `O(E)` |
| Find neighbors             |           `O(V)` |    `O(degree)` |    `O(E)` |
| Add edge                   |           `O(1)` |         `O(1)` |    `O(1)` |
| Good for sparse graphs     |                ❌ |              ✅ |         ✅ |
| Good for dense graphs      |                ✅ |              ✅ |        ⚠️ |
| Common in graph algorithms |        Sometimes |    Very common | Sometimes |

### adjacency matrix and adjacency list
Consider this undirected graph with five vertices and four edges:

```
    A ----- B
    |
    C ----- D

    E
```

The edges are `A-B`, `A-C`, `C-D`, and `B-D`—with `E` isolated.

For Adjacency matrix
```
    A  B  C  D  E
A [ 0  1  1  0  0 ]
B [ 1  0  0  1  0 ]
C [ 1  0  0  1  0 ]
D [ 0  1  1  0  0 ]
E [ 0  0  0  0  0 ]
```

Here, `1` means an edge exists and `0` means it doesn't.

An adjacency list stores the neighbors of each vertex, usually using an array of linked lists or dynamic arrays.

For the same graph:

```
A -> B -> C -> NULL
B -> A -> D -> NULL
C -> A -> D -> NULL
D -> B -> C -> NULL
E -> NULL
```
**Checking whether an edge exists**

Suppose we want to know whether `A` is connected to `C`.

**For Adjacency matrix**

```c
if (matrix[A][C] == 1) {
    printf("Edge exists\n");
}
```

We access one array cell directly. Therefore:

$$
\boxed{O(1)}
$$

The lookup time is constant, regardless of how many vertices the graph contains.

**For Adjacency list**

To check whether `A` is connected to `C`, we must search through `A`'s neighbor list:

```
A -> B -> C -> NULL
     |
     +-- first neighbor
```

If we find `C`, the edge exists. Otherwise, we reach the end of the list.

The complexity is:

$$
O(\deg(A))
$$

Here, $\deg(A)$ means the number of neighbors of `A` in this undirected graph.

In the worst case, we examine every neighbor. Unlike an adjacency matrix, this is not necessarily constant time.

**Finding all neighbors of a vertex**

**For Adjacency matrix**

Suppose we want all neighbors of `A`. We must inspect its entire row:

```
A [ 0  1  1  0  0 ]
```

For a graph with $V$ vertices, we may need to inspect all $V$ cells in that row.

Therefore, finding all neighbors using an adjacency matrix takes:

$$
\boxed{O(V)}
$$

Even if `A` has only two neighbors, we still inspect the entire row.

**For Adjacency list**

To find all neighbors of `A`, we traverse its list:

```
A -> B -> C -> NULL
```

We visit only the two actual neighbors, rather than checking every possible vertex.

The complexity is:

$$
O(\deg(A))
$$

This is especially efficient when the graph has relatively few edges.

So With an adjacency matrix, checking whether an edge (vi, vj) exists takes
constant time, but with an adjacency list, it depends on the number of edges in the
list for vi. 

**Space**

Why does an adjacency matrix use more space? An adjacency matrix allocates a cell for every possible pair of vertices. An adjacency list stores only the vertices and their actual edges.

| Property                      | Adjacency matrix | Adjacency list              |
| ----------------------------- | ---------------- | --------------------------- |
| Space complexity              | $O(V^2)$     | $O(V+E)$                |
| Check whether edge exists     | $O(1)$       | $O(\deg(v))$ worst case |
| Find all neighbors of $v$ | $O(V)$       | $O(\deg(v))$            |
| Iterate over all edges        | $O(V^2)$     | $O(V+E)$                |
| Best suited for               | Dense graphs     | Sparse graphs               |

For an undirected graph, the matrix is symmetric: if `A` is connected to `B`, then both `matrix[A][B]` and `matrix[B][A]` are set. Implementations often store both entries.

For an adjacency list, each undirected edge is also commonly stored twice, once for each endpoint.

In contrast, with an adjacency matrix, you need more space and you lose the ability to identify all incident edges to a vertex in time proportional to the number of those edges; instead, you must check all possible edges, which becomes significantly more expensive when the number of vertices becomes large. 

You should use
an adjacency matrix representation when working with dense graphs in which
nearly every possible edge exists(A dense graph has many edges relative to the number of possible edges).

For a simple undirected graph with $V$ vertices, the maximum number of edges is:

$$ 
E\_\{\max}=\frac{V(V-1)}{2}
$$

Consider a graph with 1,000 vertices.

- A sparse graph might have around 2,000 edges.
- A dense graph might have around 400,000 edges.
- A complete graph has 499,500 edges.

An adjacency matrix for 1,000 vertices always allocates:

$$ 
1000 \times 1000 = 1\{,}000\{,}000
$$

cells, even if the graph contains only 2,000 edges.

The matrix can still be a good choice for a dense graph because many of those cells represent real edges, and edge-existence checks remain $O(1)$.

**Why identifying incident edges matters**

An edge is incident to a vertex if that vertex is one of the edge's endpoints.

For example:

```
    A ----- B
    |
    C ----- D
```

The edges incident to `A` are:

```
A-B
A-C
```

With an adjacency list, we can find them by traversing just `A`'s list. With an adjacency matrix, we must scan the whole row to discover which edges exist.

This matters for graph algorithms such as BFS and DFS. These algorithms repeatedly examine each vertex's neighbors.

With an adjacency list, a complete traversal takes:

$$
O(V+E)
$$

With an adjacency matrix, it generally takes:

$$
O(V^2)
$$

The difference can be substantial when a large graph is sparse.

**The practical rule**

- Choose an adjacency matrix when the graph is dense, you frequently check whether specific edges exist, or the graph is small enough that the extra space is insignificant.
- Choose an adjacency list when the graph is sparse, memory matters, or you frequently traverse neighbors using algorithms such as BFS and DFS.

## Graph in Memory

In a programming language, a graph can be represented using an adjacency list.

For example:

```text
A → B, C
B → A, D
C → A, D
D → B, C
```

Conceptually:

```text
Graph
 │
 ├── A ──→ [B, C]
 │
 ├── B ──→ [A, D]
 │
 ├── C ──→ [A, D]
 │
 └── D ──→ [B, C]
```

In practice, we commonly use:

```text
Array/List
    +
Linked Lists / Dynamic Lists
    +
Hash Map
```

depending on how vertices are identified and what operations are needed.

## Which representation should you choose?

Quick decision guide

- Choose an adjacency list for most graph traversal problems.

    Ideal for sparse graphs, BFS, DFS, and general-purpose graph implementations.

- Choose an adjacency matrix when the graph is dense or edge-existence checks must be fast.

    Uses more memory but provides constant-time edge lookup.

- Choose an edge list when you primarily process or sort edges.

    Especially useful for algorithms such as Kruskal's minimum spanning tree algorithm.

- Choose an incidence matrix when the relationship between individual edges and vertices is important.

    More common in mathematical formulations than everyday graph programming.

Key takeaway: Graph representations store the same graph in different ways. An adjacency list is usually the best starting point for learning graph algorithms because it stores only existing edges and works efficiently with sparse graphs.

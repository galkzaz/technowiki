

One of the most important aspects of the graph data structure is **how we store it in memory**.

A graph representation is a way to store a graph's vertices and edges in memory so that a program can perform operations such as adding edges, checking connections, finding neighbors, and traversing the graph.

Recall that a graph is defined as:

```math
G=(V,E)
```

- \\(V\\): the set of vertices (nodes).
- \\(E\\): the set of edges (connections).

There are several ways to represent a graph in a program. The most common are:

1. Edge List
2. Adjacency Matrix
3. Adjacency List
4. Incidence Matrix

Consider this undirected graph:

```
       A -------- B
       |          |
       |          |
       C -------- D -------- E
```

Its vertices are:

\\[ V=\\\{A,B,C,D,E\\} \\]

Its edges are:

\\[ E=\\\{\\\{A,B\\},\\\{A,C\\},\\\{B,D\\},\\\{C,D\\},\\\{D,E\\}\\} \\]

There are five vertices and five edges.

The neighbors of each vertex are:

| Vertex | Neighbors | Degree |
| ------ | --------- | ------ |
| A      | B, C      | 2      |
| B      | A, D      | 2      |
| C      | A, D      | 2      |
| D      | B, C, E   | 3      |
| E      | D         | 1      |

Every representation below stores this same graph, but organizes the information differently.

### Adjacency Matrix
An adjacency matrix uses a 2D array.

Consider:

```text
A ─── B
|     |
|     |
C ─── D
```

We can create:

```text
      A B C D
    +--------
A   | 0 1 1 0
B   | 1 0 0 1
C   | 1 0 0 1
D   | 0 1 1 0
```

`1` means an edge exists.

`0` means an edge does not exist.

For example:

```text
matrix[A][B] = 1
```

because:

```text
A ─── B
```

exists.

---

#### Adjacency Matrix Complexity

For `V` vertices:

| Operation                 | Complexity |
| ------------------------- | ---------: |
| Check whether edge exists |     `O(1)` |
| Add edge                  |     `O(1)` |
| Remove edge               |     `O(1)` |
| Find neighbors            |     `O(V)` |
| Space                     |    `O(V²)` |

The major disadvantage is:

> It uses `O(V²)` memory even when the graph has relatively few edges.

---

### Adjacency List

An adjacency list stores the neighbors of every vertex.

For:

```text
A ─── B
|     |
|     |
C ─── D
```

we can represent it as:

```text
A → B, C
B → A, D
C → A, D
D → B, C
```

This is usually the most useful representation for graph algorithms.

Conceptually:

```text
Vertex     Neighbors

A          B → C
B          A → D
C          A → D
D          B → C
```

---

#### Adjacency List Complexity

For `V` vertices and `E` edges:

| Operation      | Typical complexity |
| -------------- | -----------------: |
| Add edge       |             `O(1)` |
| Remove edge    |     `O(degree(v))` |
| Check edge     |     `O(degree(v))` |
| Find neighbors |     `O(degree(v))` |
| Space          |         `O(V + E)` |

For sparse graphs, adjacency lists are usually much more memory-efficient than adjacency matrices.

---

### Edge List

The simplest representation is an **edge list**.

For:

```text
A ─── B
|     |
C ─── D
```

we could store:

```text
(A, B)
(A, C)
(B, D)
(C, D)
```

For a weighted graph:

```text
(A, B, 5)
(A, C, 2)
(B, D, 7)
(C, D, 3)
```

Edge lists are particularly useful for algorithms such as **Kruskal's algorithm**.

### Sparse vs Dense Graph

This distinction is important.

#### Sparse Graph

A graph is **sparse** when it has relatively few edges.

```text
A ─ B

C ─ D

E
```

For sparse graphs:

```text
E << V²
```

An adjacency list is usually a good representation.

---

#### Dense Graph

A graph is **dense** when it has many edges.

```text
A────B
|\  /|
| \/ |
| /\ |
|/  \|
C────D
```

Here:

```text
E
```

is relatively close to:

$$
V^2
$$

An adjacency matrix can be useful.

---

### Comparing Representations

| Feature                    | Adjacency Matrix | Adjacency List | Edge List |
| -------------------------- | ---------------: | -------------: | --------: |
| Space                      |          `O(V²)` |       `O(V+E)` |    `O(E)` |
| Check edge                 |           `O(1)` |    `O(degree)` |    `O(E)` |
| Find neighbors             |           `O(V)` |    `O(degree)` |    `O(E)` |
| Add edge                   |           `O(1)` |         `O(1)` |    `O(1)` |
| Good for sparse graphs     |                ❌ |              ✅ |         ✅ |
| Good for dense graphs      |                ✅ |              ✅ |        ⚠️ |
| Common in graph algorithms |        Sometimes |    Very common | Sometimes |

## Graph in Memory

In a programming language, a graph can be represented using an adjacency list.

For example:

```text
A → B, C
B → A, D
C → A, D
D → B, C
```

Conceptually:

```text
Graph
 │
 ├── A ──→ [B, C]
 │
 ├── B ──→ [A, D]
 │
 ├── C ──→ [A, D]
 │
 └── D ──→ [B, C]
```

In practice, we commonly use:

```text
Array/List
    +
Linked Lists / Dynamic Lists
    +
Hash Map
```

depending on how vertices are identified and what operations are needed.

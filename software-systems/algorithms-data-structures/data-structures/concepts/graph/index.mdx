A **graph** is a non-linear data structure used to represent **relationships between objects**. It consists of a set of vertices (nodes) and a set of edges connecting pairs of vertices.

The objects are called **vertices (or nodes)**, and the relationships between them are called **edges**.

A simple graph might look like:

```text
        A
       / \
      /   \
     B-----C
     |
     D
```

Here:

* `A, B, C, D` → **vertices**
* `A-B`, `A-C`, `B-C`, `B-D` → **edges**

Graphs are one of the most important data structures because many real-world systems naturally consist of **things + relationships**.

Think about a graph as:

> **Objects + relationships**

For example:

```text
Objects:
A, B, C, D

Relationships:
A connected to B
A connected to C
B connected to D
C connected to D
```

The graph doesn't necessarily describe a hierarchy. Instead, it describes **how things are related**. This is the key difference between graphs and many other data structures.

This is the most flexible data structure there is, and it can be
used to represent almost any type of data. For example, graphs
are ideal for representing a social network, where nodes are people
and edges represent friendships.

Graphs are useful for modeling computer networks, social networks, road maps, dependencies between software components, and communication systems.

### Graph vs Tree

The Graph is similar to the Tree. The difference is that there’s no children or parent nodes, and therefore, no Root Node. Data is freely arranged as nodes and edges, and any node can have multiple incoming and outgoing edges.

A graph is more general than a tree.

A tree looks like:

```text
        A
       / \
      B   C
     / \
    D   E
```

A graph can contain much more complex relationships:

```text
        A
       / \
      B---C
      |\  |
      | \ |
      D---E
```

A tree has strong structural restrictions, while a graph does not.

For example, a graph can contain:

* cycles
* multiple paths between vertices
* disconnected components
* directed edges
* weighted edges
## Terminology
Consider this undirected graph:

```
       A -------- B
       |          |
       |          |
       C -------- D -------- E
```

Its components are:

- Vertices: `A`, `B`, `C`, `D`, `E`
- Edges: `A-B`, `A-C`, `B-D`, `C-D`, `D-E`

We can represent the graph mathematically as:

```math
G = (V,E) 
```

Where:

- `G` is the graph.
- `V` is the set of vertices.
- `E` is the set of edges.

For this example:

$$
V = \{A,B,C,D,E\}
$$

```math
E = {{A,B},{A,C},{B,D},{C,D},{D,E}}
```

Notice that each edge is represented as an unordered pair because the graph is undirected.
### Vertex (Node)
A **vertex** represents an individual object or entity in a graph.

Examples:

- In a social network, a vertex represents a person.
- In a road network, a vertex might represent a city or intersection.
- In a dependency graph, a vertex might represent a software module.

```
       A -------- B
       ^
       |
     Vertex
```

A vertex may contain data, such as an identifier, name, or other attributes

For example, in a social network:

```text
Alice
Bob
Charlie
David
```

Each person can be represented as a vertex:

```text
Alice ─── Bob
  │        │
  │        │
Charlie ─ David
```

---

### Edge (Link)
An **edge** represents a relationship or connection between two vertices.
```
       A -------- B
          Edge
```
The edge between `A` and `B` indicates that the two vertices are connected.

For example:

```text
Alice ─── Bob
```

could mean:
- Alice is friends with Bob, or:
- Alice follows Bob, or:
- Alice can communicate with Bob

The meaning of an edge depends on the application. an edge might represent a road, friendship, network connection, or dependency.

---

### Path

A **path** is a sequence of vertices connected by edges.

```
       A -------- B
                  |
                  |
                  D -------- E
```

One path from `A` to `E` is:

```
A → B → D → E
```

The path uses three edges.

A path is important in problems such as finding routes between cities, determining whether a network connection exists, and navigating a graph using BFS or DFS.

---

### Path length

The length of a path is the number of edges it contains.

For the path:

```
A → B → D → E
```

There are four vertices but only three edges.

Therefore:

$$
\text\{Path length}=3
$$

In a weighted graph, we must distinguish the number of edges from the total weight or cost of the path.

---

### Cycles

A **cycle** is a path that starts and ends at the same vertex, following edges without repeating other vertices in a simple cycle.

```
       A -------- B
       |          |
       |          |
       C -------- D
```

One cycle is:

```
A → B → D → C → A
```

```text
      A
     / \
    B---C
```

We can travel:

```text
A → B → C → A
```

Therefore, the graph contains a cycle.

Cycles are extremely important in graph algorithms.

For example:

* cycle detection(detecting circular references)
* dependency analysis
* deadlock detection
* topological sorting
* circuit design

---

### Adjacent vertices

Two vertices are adjacent if an edge directly connects them.

In the example:

```
       A -------- B
       |
       |
       C
```

- `A` is adjacent to `B`.
- `A` is adjacent to `C`.
- `B` is not adjacent to `C`, because no edge directly connects them.

Important: Adjacency describes a direct connection, not whether two vertices can reach each other through other vertices.

### Incident edge

An edge is incident to a vertex if that vertex is one of the edge's endpoints.

For the edge \\(e=(A,B)\\):

- `e` is incident to `A`.
- `e` is incident to `B`.

This terminology is especially useful when discussing vertex degrees and graph algorithms.

### Neighbors

The neighbors of a vertex are the vertices directly connected to it by edges.

```
       A -------- B
       |
       |
       C
```

The neighbors of `A` are:

$$
N(A)=\{B,C}
$$

In an adjacency-list implementation, we typically store each vertex's neighbors to make graph traversal easier.

### Directed and undirected graph terminology
#### Undirected graph

An undirected graph has edges with no direction.

```
A -------- B
```

The connection can be traversed from `A` to `B` or from `B` to `A`.

Examples include mutual friendships and undirected network connections.

#### Directed graph (digraph)

A directed graph has edges with a specific direction, represented by arrows.

```
A --------> B
```

This represents a directed edge from `A` to `B`.

It does not automatically imply that an edge exists from `B` to `A`.

Examples include one-way roads, follower relationships, and task dependencies.

#### In-degree

The in-degree of a vertex is the number of directed edges entering it.

```
A --------> C <-------- B
```

For vertex `C`:

$$
\deg^\{-}(C)=2
$$

Two edges enter `C`.

#### Out-degree

The out-degree of a vertex is the number of directed edges leaving it.

```
       A
      / \
     v   v
     B   C
```

For vertex `A`:

$$
\deg^\{+}(A)=2
$$

Two edges leave `A`.

For a directed graph, a common convention is to count a self-loop once toward in-degree and once toward out-degree.

### Degree of a vertex

The degree of a vertex in an undirected graph is the number of edges incident to that vertex.

Consider:

```
       A -------- B
       |
       |
       C -------- D
```

- \\(\deg(A)=2\\)
- \\(\deg(B)=1\\)
- \\(\deg(C)=2\\)
- \\(\deg(D)=1\\)

Vertex `A` has degree 2 because it connects to `B` and `C`.

Special cases:

- Isolated vertex: A vertex with degree 0.
- Pendant vertex (leaf): A vertex with degree 1.
- Self-loop: An edge connecting a vertex to itself. In an undirected graph, a self-loop contributes 2 to the vertex's degree under the standard convention.

### Connected vertices and connectivity

In an undirected graph, two vertices are connected if there is a path between them.

A graph is connected if every pair of vertices has a path connecting them.

For example:

```
A -------- B       C -------- D
```

This graph is disconnected because no path connects the pair `{A, B}` to the pair `{C, D}`.

Each maximal connected group of vertices is called a connected component.

Here, there are two connected components:

```
Component 1: A -------- B

Component 2: C -------- D
```

In directed graphs, reachability depends on edge direction, so directed connectivity has additional definitions.

### Weighted and unweighted graphs

#### Weighted graph

A weighted graph assigns a value, called a weight or cost, to each edge.

```
       5
   A ------- B
    \       /
   2 \     / 3
      \   /
        C
```

The edge weights could represent distances, travel times, prices, or connection costs.

For the path `A → C → B`, the total weight is:

\\[ 2+3=5 \\]

Weighted graphs are commonly used in shortest-path algorithms such as Dijkstra's algorithm.

#### Unweighted graph

An unweighted graph does not assign explicit weights to edges.

```
A -------- B
|          |
|          |
C -------- D
```

In many problems, every edge is treated as having equal cost. The shortest path is then the path with the fewest edges.

### Additional graph terminology

| Term            | Meaning                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------- |
| Subgraph        | A graph formed from a subset of another graph's vertices and edges.                                           |
| Simple graph    | A graph with no self-loops and no multiple edges between the same pair of vertices.                           |
| Multigraph      | A graph that allows multiple edges between the same pair of vertices.                                         |
| Self-loop       | An edge connecting a vertex to itself.                                                                        |
| Walk            | A sequence of connected vertices and edges; vertices and edges may repeat.                                    |
| Trail           | A walk that does not repeat edges.                                                                            |
| Simple path     | A path that does not repeat vertices.                                                                         |
| Reachability    | Whether one vertex can be reached from another by following edges.                                            |
| Shortest path   | A path minimizing the number of edges or, in a weighted graph, the total cost.                                |
| Dense graph     | A graph with many edges relative to the maximum possible number.                                              |
| Sparse graph    | A graph with relatively few edges.                                                                            |
| Complete graph  | A simple undirected graph in which every pair of distinct vertices is connected.                              |
| Bipartite graph | A graph whose vertices can be divided into two sets such that every edge connects vertices in different sets. |
| Tree            | A connected, acyclic undirected graph.                                                                        |
| Spanning tree   | A tree containing every vertex of a connected undirected graph, using a subset of its edges.                  |
| DAG             | A directed acyclic graph: a directed graph containing no directed cycles.                                     |

### How the terminology fits together

Consider this graph:

```
       A -------- B
       |          |
       |          |
       C -------- D -------- E
```

We can describe it using graph terminology:

- It has 5 vertices and 5 edges.
- `A` and `B` are adjacent vertices.
- `B` and `D` are neighbors.
- The degree of `D` is 3 because it connects to `B`, `C`, and `E`.
- `A → B → D → E` is a path of length 3.
- `A → B → D → C → A` is a cycle.
- The graph is connected because every vertex can reach every other vertex.
- The graph is undirected because its edges have no arrows.
- The graph is unweighted because no edge costs are specified.

### Why these terms matter in programming

Graph terminology maps directly to common graph algorithms and data structures.

| Concept                       | Where you use it                                   |
| ----------------------------- | -------------------------------------------------- |
| Vertices and edges            | Graph representation                               |
| Neighbors and adjacency       | Adjacency lists and traversal                      |
| Degree, in-degree, out-degree | Network analysis and dependency scheduling         |
| Paths and reachability        | BFS, DFS, routing                                  |
| Cycles                        | Cycle detection and dependency validation          |
| Connected components          | Finding separate networks or groups                |
| Edge weights                  | Shortest-path and minimum-spanning-tree algorithms |
| DAG                           | Topological sorting and build systems              |

For example, an adjacency-list representation of the graph above could be written in Python as:

```Python
graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A", "D"],
    "D": ["B", "C", "E"],
    "E": ["D"]
}

# Neighbors of D
print(graph["D"])
# ['B', 'C', 'E']
```

Each dictionary key represents a vertex, and its list contains its neighbors. Because this graph is undirected, each edge appears in both endpoints' adjacency lists.

The key idea: Vertices represent entities, edges represent relationships, and concepts such as degree, adjacency, paths, and cycles describe the structure of those relationships. Understanding these terms makes graph representations and algorithms much easier to learn.
## Mathematical Definition

A graph is commonly represented as:

$$
G = (V,E)
$$

where:

* `V` = set of vertices
* `E` = set of edges

For example:

```text
A ─── B
|     |
|     |
C ─── D
```

We could define:

$$
V = \{A,B,C,D\}
$$

and:

$$
E = \{(A,B),(A,C),(B,D),(C,D)\}
$$

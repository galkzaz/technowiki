

## Fundamentals
A **graph** is a non-linear data structure used to represent **relationships between objects**.

The objects are called **vertices (or nodes)**, and the relationships between them are called **edges**.

A simple graph might look like:

```text
        A
       / \
      /   \
     B-----C
     |
     D
```

Here:

* `A, B, C, D` → **vertices**
* `A-B`, `A-C`, `B-C`, `B-D` → **edges**

Graphs are one of the most important data structures because many real-world systems naturally consist of **things + relationships**.

Think about a graph as:

> **Objects + relationships**

For example:

```text
Objects:
A, B, C, D

Relationships:
A connected to B
A connected to C
B connected to D
C connected to D
```

The graph doesn't necessarily describe a hierarchy.

Instead, it describes **how things are related**.

This is the key difference between graphs and many other data structures.

---

The Graph is similar to the Tree. The difference is that there’s no children or parent nodes, and therefore, no Root Node. Data is freely arranged as nodes and edges, and any node can have multiple
incoming and outgoing edges.

This is the most flexible data structure there is, and it can be
used to represent almost any type of data. For example, graphs
are ideal for representing a social network, where nodes are people
and edges represent friendships.

## Graph vs Tree

A graph is more general than a tree.

A tree looks like:

```text
        A
       / \
      B   C
     / \
    D   E
```

A graph can contain much more complex relationships:

```text
        A
       / \
      B---C
      |\  |
      | \ |
      D---E
```

A tree has strong structural restrictions, while a graph does not.

For example, a graph can contain:

* cycles
* multiple paths between vertices
* disconnected components
* directed edges
* weighted edges

## Mathematical Definition

A graph is commonly represented as:

$$
G = (V,E)
$$

where:

* `V` = set of vertices
* `E` = set of edges

For example:

```text
A ─── B
|     |
|     |
C ─── D
```

We could define:

$$
V = \{A,B,C,D\}
$$

and:

$$
E = \{(A,B),(A,C),(B,D),(C,D)\}
$$

## Graph Types
### Undirected graphs

In an **undirected graph**, an edge has no direction.

```text
A ─── B
```

means:

```text
A is connected to B
```

and:

```text
B is connected to A
```

Formally:

$$
(A,B) = (B,A)
$$

**Example**

A road between two cities:

```text
Cairo ───────── Giza
```

If the road allows travel in both directions, it can be modeled as an undirected edge.

---

#### Degree of a Vertex

The **degree** of a vertex is the number of edges connected to it in an undirected graph.

Consider:

```text
      B
      |
A ─── C ─── D
      |
      E
```

For `C`:

```text
C → B
C → A
C → D
C → E
```

Therefore:

$$
degree(C)=4
$$

For `A`:

$$
degree(A)=1
$$

---

#### Connected Graph

An undirected graph is **connected** if every vertex can reach every other vertex.

```text
A ─── B
|     |
C ─── D
```

Every vertex can reach every other vertex.

Therefore, it is connected.

---

#### Disconnected Graph

A graph can contain multiple disconnected components.

```text
A ─── B        E ─── F
|              |
C              G
```

There are two separate components:

```text
Component 1:
A ─ B
|
C

Component 2:
E ─ F
|
G
```

There is no path between the two components.

---

### Directed graphs
A **directed graph**, or **digraph**, has edges with directions.

```text
A ───→ B
```

means:

```text
A → B
```

but does not necessarily mean:

```text
B → A
```

Formally:

$$
(A,B) \neq (B,A)
$$

**Example**

A social-media following relationship:

```text
Alice ───→ Bob
```

could mean:

```text
Alice follows Bob
```

Bob does not necessarily follow Alice.

---

#### In-Degree and Out-Degree

For directed graphs, we distinguish between **in-degree** and **out-degree**.

```text
A ───→ B ───→ C
      ↑
      |
      D
```

For `B`:

##### In-degree

Edges coming **into** `B`:

```text
A → B
D → B
```

Therefore:

$$
inDegree(B)=2
$$

##### Out-degree

Edges going **out of** `B`:

```text
B → C
```

Therefore:

$$
outDegree(B)=1
$$

---

### Weighted graphs
An edge can have an associated **weight**.

```text
        10
   A ─────── B
   |         |
  5|         |3
   |         |
   C ─────── D
        7
```

The weights could represent:

* distance
* cost
* time
* bandwidth
* latency
* capacity
* price

For example:

```text
Cairo ── 20 km ── Giza
```

The edge has weight `20`.

Weighted graphs are particularly important for algorithms such as **Dijkstra's algorithm** and **Minimum Spanning Tree** algorithms.

---

### Unweighted graphs

If edges don't have weights, the graph is **unweighted**.

```text
A ─── B
|     |
|     |
C ─── D
```

Often the important information is simply:

> Is there a connection?

rather than:

> What is the cost of the connection?

---

#### Path Length

The **length of a path** in an unweighted graph is usually the number of edges.

```text
A ─ B ─ C ─ D
```

Path:

```text
A → B → C → D
```

Length:

$$
3
$$

In a weighted graph, path length can instead mean the **sum of edge weights**.

```text
A --5-- B --2-- C --7-- D
```

Total cost:

$$
5+2+7=14
$$

For four vertices:

$$
\frac{4(4-1)}{2}=6

edges.

## Graph Representations
One of the most important aspects of the graph data structure is **how we store it in memory**.

The two fundamental representations are:

1. **Adjacency Matrix**
2. **Adjacency List**

There is also:

3. **Edge List**

---

### Adjacency Matrix
An adjacency matrix uses a 2D array.

Consider:

```text
A ─── B
|     |
|     |
C ─── D
```

We can create:

```text
      A B C D
    +--------
A   | 0 1 1 0
B   | 1 0 0 1
C   | 1 0 0 1
D   | 0 1 1 0
```

`1` means an edge exists.

`0` means an edge does not exist.

For example:

```text
matrix[A][B] = 1
```

because:

```text
A ─── B
```

exists.

---

#### Adjacency Matrix Complexity

For `V` vertices:

| Operation                 | Complexity |
| ------------------------- | ---------: |
| Check whether edge exists |     `O(1)` |
| Add edge                  |     `O(1)` |
| Remove edge               |     `O(1)` |
| Find neighbors            |     `O(V)` |
| Space                     |    `O(V²)` |

The major disadvantage is:

> It uses `O(V²)` memory even when the graph has relatively few edges.

---

### Adjacency List

An adjacency list stores the neighbors of every vertex.

For:

```text
A ─── B
|     |
|     |
C ─── D
```

we can represent it as:

```text
A → B, C
B → A, D
C → A, D
D → B, C
```

This is usually the most useful representation for graph algorithms.

Conceptually:

```text
Vertex     Neighbors

A          B → C
B          A → D
C          A → D
D          B → C
```

---

#### Adjacency List Complexity

For `V` vertices and `E` edges:

| Operation      | Typical complexity |
| -------------- | -----------------: |
| Add edge       |             `O(1)` |
| Remove edge    |     `O(degree(v))` |
| Check edge     |     `O(degree(v))` |
| Find neighbors |     `O(degree(v))` |
| Space          |         `O(V + E)` |

For sparse graphs, adjacency lists are usually much more memory-efficient than adjacency matrices.

---

### Edge List

The simplest representation is an **edge list**.

For:

```text
A ─── B
|     |
C ─── D
```

we could store:

```text
(A, B)
(A, C)
(B, D)
(C, D)
```

For a weighted graph:

```text
(A, B, 5)
(A, C, 2)
(B, D, 7)
(C, D, 3)
```

Edge lists are particularly useful for algorithms such as **Kruskal's algorithm**.

### Sparse vs Dense Graph

This distinction is important.

#### Sparse Graph

A graph is **sparse** when it has relatively few edges.

```text

C ─ D

```

For sparse graphs:


A graph is **dense** when it has many edges.

```text

|\  /|
| \/ |
| /\ |

```

Here:

```text
E
```

is relatively close to:

$$

$$

An adjacency matrix can be useful.

### Comparing Representations

| Feature                    | Adjacency Matrix | Adjacency List | Edge List |
| -------------------------- | ---------------: | -------------: | --------: |
| Space                      |          `O(V²)` |       `O(V+E)` |    `O(E)` |
| Check edge                 |           `O(1)` |    `O(degree)` |    `O(E)` |
| Find neighbors             |           `O(V)` |    `O(degree)` |    `O(E)` |
| Add edge                   |           `O(1)` |         `O(1)` |    `O(1)` |
| Good for sparse graphs     |                ❌ |              ✅ |         ✅ |
| Good for dense graphs      |                ✅ |              ✅ |        ⚠️ |
| Common in graph algorithms |        Sometimes |    Very common | Sometimes |

## Graph Traversal Structures
One of the most important operations on graphs is **traversal**.

Traversal means:

> Visit vertices of a graph systematically.

The two fundamental graph traversal algorithms are:

```text
Graph Traversal
│
├── BFS
│   └── Breadth-First Search
│
└── DFS
    └── Depth-First Search
```

---

### Breadth-First Search(BFS)

**BFS** explores the graph level by level.

Consider:

```text
        A
       / \
      B   C
     / \   \
    D   E   F
```

Starting at `A`:

```text
Level 0:
A

Level 1:
B C

Level 2:
D E F
```

Traversal:

```text
A → B → C → D → E → F
```

BFS typically uses a **queue**.

```text
Queue
FIFO
```

BFS is particularly useful for finding the shortest path in an **unweighted graph**.

---

### Depth-First Search(DFS)
DFS explores as deeply as possible before backtracking.

For:

```text
        A
       / \
      B   C
     / \
    D   E
```

one possible DFS traversal is:

```text
A → B → D → E → C
```

DFS can be implemented using:

* recursion
* an explicit stack

```text
Stack
LIFO
```

DFS is useful for:

* cycle detection
* connected components
* topological sorting
* path finding
* graph analysis

## Shortest Paths
Suppose we have:

```text
       4
   A ──── B
   |      |
  2|      |1
   |      |
   C ──── D
       3
```

We may want to find the minimum-cost path from `A` to `D`.

Possible paths:

```text
A → B → D
cost = 4 + 1 = 5
```

and:

```text
A → C → D
cost = 2 + 3 = 5
```

Graph algorithms can systematically find such paths.

Important algorithms include:

* **BFS** — shortest path in unweighted graphs
* **Dijkstra** — shortest paths with non-negative edge weights
* **Bellman-Ford** — supports negative edge weights
* **Floyd-Warshall** — all-pairs shortest paths

### Minimum Spanning Tree Structures
For an undirected weighted graph, a **minimum spanning tree (MST)** connects all vertices with minimum total edge weight and no cycles.

For example:

```text
A ──2── B
|      |
4      1
|      |
C ──3── D
```

An MST chooses enough edges to connect every vertex while minimizing total weight.

Two fundamental algorithms are:

```text
Prim
```

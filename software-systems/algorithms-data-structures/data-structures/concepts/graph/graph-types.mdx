

A graph is a non-linear data structure made of vertices (nodes) and edges (connections). Different graph types describe different properties of those connections, such as whether edges have directions, whether they have weights, and whether the graph contains cycles.

Understanding graph types helps you choose the right representation and algorithm for problems such as shortest-path search, dependency resolution, network routing, and social network analysis.

## Graph classification overview

Graph types are not mutually exclusive. A graph can belong to several categories at once.

For example, a graph can be **directed**, **weighted**, **sparse**, and **acyclic** simultaneously.

**Main classification dimensions**

1. Edge direction 

  Directed graph · Undirected graph

2. Edge values

  Weighted graph · Unweighted graph

3. Structure and connectivity

  Simple graph · Multigraph · Connected graph · Complete graph · Tree · DAG · Bipartite graph

3. Density and geometry

  Sparse graph · Dense graph · Planar graph · Regular graph

## Directed vs. undirected graphs
### Undirected graphs

In an **undirected graph**, an edge has no direction.

```text
A ─── B
```

means:

```text
A is connected to B
```

and:

```text
B is connected to A
```

An undirected graph has edges without a direction. If vertex `A` is connected to vertex `B`, the connection can be traversed in either direction.

```
    A -------- B
    |          |
    |          |
    C -------- D
```

For an undirected edge, `{A, B}` and `{B, A}` represent the same connection.

Formally:

$$
(A,B) = (B,A)
$$

**Example**

A road between two cities:

```text
Cairo ───────── Giza
```

If the road allows travel in both directions, it can be modeled as an undirected edge.

Real-world examples:

- Mutual friendships
- Two-way roads
- Physical network cables
---

#### Degree of a Vertex

The **degree** of a vertex is the number of edges connected to it in an undirected graph.

Consider:

```text
      B
      |
A ─── C ─── D
      |
      E
```

For `C`:

```text
C → B
C → A
C → D
C → E
```

Therefore:

$$
degree(C)=4
$$

For `A`:

$$
degree(A)=1
$$

---

#### Connected Graph

An undirected graph is **connected** if every vertex can reach every other vertex.

```text
A ─── B
|     |
C ─── D
```

Every vertex can reach every other vertex.

Therefore, it is connected.

---

#### Disconnected Graph

A graph can contain multiple disconnected components.

```text
A ─── B        E ─── F
|              |
C              G
```

There are two separate components:

```text
Component 1:
A ─ B
|
C

Component 2:
E ─ F
|
G
```

There is no path between the two components.

---

### Directed graphs
A **directed graph**, or **digraph**, has edges with a specific direction.

```text
A ───→ B
```

means:

```text
A → B
```

but does not necessarily mean:

```text
B → A
```

```
    A -------> B
    ^          |
    |          v
    C <------- D
```

An edge \\(A \rightarrow B\\) does not imply that \\(B \rightarrow A\\) exists.

Formally:

$$
(A,B) \neq (B,A)
$$

**Example**

A social-media following relationship:

```text
Alice ───→ Bob
```

could mean:

```text
Alice follows Bob
```

Bob does not necessarily follow Alice.

Real-world examples:

- One-way roads
- Social media following relationships
- Dependencies between tasks

---

#### In-Degree and Out-Degree

For directed graphs, we distinguish between **in-degree** and **out-degree**.

```text
A ───→ B ───→ C
      ↑
      |
      D
```

For `B`:

##### In-degree

Edges coming **into** `B`:

```text
A → B
D → B
```

Therefore:

$$
inDegree(B)=2
$$

##### Out-degree

Edges going **out of** `B`:

```text
B → C
```

Therefore:

$$
outDegree(B)=1
$$

### Comparison

| Property  | Undirected               | Directed                   |
| --------- | ------------------------ | -------------------------- |
| Edge      | `{A, B}`                 | `(A, B)`                   |
| Direction | None                     | From source to destination |
| Degree    | Number of incident edges | In-degree and out-degree   |
| Traversal | Either direction         | Must follow edge direction |

## Weighted vs. unweighted graphs

### Unweighted graphs

An **unweighted graph** has no explicit values assigned to its edges.

If edges don't have weights, the graph is **unweighted**.

```text
A ─── B
|     |
|     |
C ─── D
```

When looking for a shortest path, each edge is typically treated as having equal cost.

For example, `A → B → D` has two edges.

Often the important information is simply:

> Is there a connection?

rather than:

> What is the cost of the connection?

---

#### Path Length

The **length of a path** in an unweighted graph is usually the number of edges.

```text
A ─ B ─ C ─ D
```

Path:

```text
A → B → C → D
```

Length: $3

In a weighted graph, path length can instead mean the **sum of edge weights**.

```text
A --5-- B --2-- C --7-- D
```

Total cost: $5+2+7=14$

---

### Weighted graphs
An edge can have an associated **weight**.

A **weighted graph** assigns a value to each edge.

```text
        10
   A ─────── B
   |         |
  5|         |3
   |         |
   C ─────── D
        7
```

The weights could represent:

* distance
* cost
* time
* bandwidth
* latency
* capacity
* price
* travel time

For example:

```text
Cairo ── 20 km ── Giza
```

The edge has weight `20`.

**example**

```
          5
    A -------- B
     \         |
    2 \        | 4
       \       |
         C --- D
           1
```

The weights may represent distance, travel time, money, latency, or another cost.

For the route `A → C → D → B`, if the corresponding edges exist with weights 2, 1, and 4, the total cost is: $2+1+4=7$

Weighted graphs are used in:

- Dijkstra's algorithm
- Bellman–Ford algorithm
- Minimum spanning tree algorithms, such as Kruskal's and Prim's

Weighted graphs are particularly important for algorithms such as **Dijkstra's algorithm** and **Minimum Spanning Tree** algorithms.

## Simple graphs and multigraphs

These types describe whether multiple edges or self-loops are allowed.

### Simple graphs
A simple graph has:

- No self-loops.
- At most one edge between any pair of distinct vertices.

```
    A -------- B
    |          |
    |          |
    C -------- D
```

This is a simple undirected graph.

### Multigraphs
A multigraph allows multiple distinct edges between the same pair of vertices.

```
    A ======== B
      ========
```

The two vertices have multiple edges connecting them.

For example, two cities might have several distinct railway connections, each representing a different service or route.

Terminology can vary: some mathematical conventions reserve multigraph for parallel edges and use pseudograph for graphs that also allow self-loops.

A multigraph is useful when two vertices can have multiple distinct edges connecting them. Unlike a simple graph, which allows at most one edge between a pair of vertices, a multigraph can represent several different relationships between the same two entities.

#### Real-world examples
1. **Transportation networks**

Imagine two cities connected by several railway services.
```
           Train A (08:00)
      ┌─────────────────────┐
      │                     │
   [Cairo] ───────────── [Alexandria]
      │                     │
      └─────────────────────┘
           Train B (10:00)
```

Vertices: Cairo and Alexandria.

Parallel edges: Train A and Train B, each representing a different service between the same cities.

Why use a multigraph?

- Each edge can store a departure time, travel duration, ticket price, and train number.
- A route-planning algorithm can compare multiple services between the same locations.
- Removing one service does not remove the other connections.

A simple graph would represent only whether the two cities are connected, losing the distinction between individual services unless extra information were stored elsewhere.

---

2. **Computer networks**

Two servers may have multiple physical or logical connections between them.
```
      Ethernet link
  ┌────────────────────┐
  │                    │
[Server A] ═════════ [Server B]
  │                    │
  └────────────────────┘
        Fiber link
```

Each edge represents a separate network link.

Practical uses:

- Redundancy: If one link fails, another may remain available.
- Network analysis: Compare bandwidth, latency, and reliability across links.
- Failure simulation: Remove one edge and check whether communication is still possible.

For example, the two links could have different bandwidths:

```
Server A ──[1 Gbps Ethernet]── Server B
Server A ──[10 Gbps Fiber]──── Server B
```

A network-routing application can select the link appropriate for its traffic requirements.

---

3. **Social networks**

Two people can have several distinct relationships.

```
         [Alice] ───── [Bob]
              Friends

         [Alice] ───── [Bob]
              Colleagues
```

Both edges connect the same people, but each represents a different relationship.

Examples include:

- Friends and colleagues
- Family members and business partners
- A person following another person and also collaborating with them

This is useful when analyzing networks with multiple relationship types. In practice, a multiplex network or a labeled multigraph may be used, depending on the model.

---

Two bank accounts can exchange money multiple times.

```
             $100 transfer
       ┌─────────────────────┐
       │                     │
  [Account A] ────────── [Account B]
       │                     │
       └─────────────────────┘
             $250 transfer
```

Each edge represents a distinct transaction, not just the existence of a relationship between the accounts.

An edge could store:

```
Transaction {
    transactionId
    sourceAccount
    destinationAccount
    amount
    timestamp
}
```

Applications include fraud detection, transaction auditing, money-flow analysis, and financial investigations.

Important: In a transaction graph, preserving each transaction as a separate edge is valuable because collapsing all edges into one could lose transaction history and timing information.

---

5. Software dependencies and event systems

A software system may have multiple dependency relationships between the same two services.

```
[Order Service] ── REST call ──> [Payment Service]
[Order Service] ── Event       ──> [Payment Service]
```

These edges represent different interactions:

- A synchronous REST request.
- An asynchronous event or message.

A multigraph can help represent communication architecture, message flows, and relationships between services. If the graph only needs to answer whether two services communicate, a simple graph may be sufficient.

#### Implementing a multigraph in Java

Here is a simple adjacency-list implementation. Instead of storing only the neighboring vertex, each edge has its own identity and metadata.

```Java
import java.util.*;

public class MultigraphExample {

    record Edge(
        int id,
        String from,
        String to,
        String label
    ) {}

    static class Multigraph {
        private final Map<String, List<Edge>> adjacency =
            new HashMap<>();

        void addVertex(String vertex) {
            adjacency.putIfAbsent(vertex, new ArrayList<>());
        }

        void addEdge(
            int id, String from, String to, String label
        ) {
            addVertex(from);
            addVertex(to);

            Edge edge = new Edge(id, from, to, label);

            // Store the same edge at both endpoints.
            adjacency.get(from).add(edge);

            if (!from.equals(to)) {
                adjacency.get(to).add(edge);
            }
        }

        List<Edge> getEdges(String vertex) {
            return adjacency.getOrDefault(
                vertex, Collections.emptyList()
            );
        }
    }

    public static void main(String[] args) {
        Multigraph graph = new Multigraph();

        graph.addEdge(1, "Cairo", "Alexandria", "Train A");
        graph.addEdge(2, "Cairo", "Alexandria", "Train B");

        for (Edge edge : graph.getEdges("Cairo")) {
            System.out.println(edge);
        }
    }
}
```

Possible output:

```
Edge[id=1, from=Cairo, to=Alexandria, label=Train A]
Edge[id=2, from=Cairo, to=Alexandria, label=Train B]
```

This implementation demonstrates an undirected multigraph. A production implementation would also need to define how edges are removed, how self-loops are handled, and how edge IDs are kept unique. A directed multigraph would store outgoing edges at their source, with incoming edges tracked separately if needed.

##### When should you use a multigraph?

| Requirement                                              | Multigraph appropriate?          |
| -------------------------------------------------------- | -------------------------------- |
| Multiple train services between two cities               | Yes                              |
| Multiple physical links between servers                  | Yes                              |
| Multiple transactions between accounts                   | Yes                              |
| Different relationship types between people              | Often                            |
| Only need to know whether two vertices are connected     | Usually a simple graph is enough |
| Need to retain each connection's identity and properties | Yes                              |

The key takeaway: Use a multigraph when the relationship between two vertices is not just a single connection, but may consist of multiple distinct connections that matter independently.

### Graph with self-loops

A self-loop is an edge from a vertex back to itself.

```
      .----.
      |    v
      A ---'
```

Self-loops may be useful when modeling state transitions, such as a state machine that remains in the same state after an event.


## Connected and disconnected graphs

These classifications describe whether vertices can reach one another.

### Connected graph

An undirected graph is connected if a path exists between every pair of vertices.

```
    A -------- B
    |          |
    C -------- D -------- E
```

Every vertex can reach every other vertex.

### Disconnected graph

A graph is disconnected if at least one pair of vertices has no path between them.

```
    A -------- B

    C -------- D       E
```

This graph has three connected components:

- `{A, B}`
- `{C, D}`
- `{E}`

Vertex `E` is isolated because it has no incident edges.

### Strongly and weakly connected directed graphs

For directed graphs, connectivity has more specific meanings.

Strongly connected: Every vertex can reach every other vertex by following edge directions.

```
    A -------> B
    ^          |
    |          v
    C <--------
```

Here, each vertex can reach the others through directed paths.

Weakly connected: If you ignore all edge directions, the resulting undirected graph is connected.

A directed graph can be weakly connected without being strongly connected.

## Complete graphs
A **complete graph** is a simple undirected graph in which every pair of distinct vertices is connected by an edge.

A **complete graph** is a graph where every pair of distinct vertices has an edge.

For four vertices:

```text
     A
    /|\
   / | \
  B--|--C
   \ | /
    \|/
     D
```

Every vertex is directly connected to every other vertex.

A complete graph with four vertices, denoted \\(K_4\\), looks like this:

```
       A -------- B
       |\        /|
       | \      / |
       |  \    /  |
       |   \  /   |
       |   /  \   |
       |  /    \  |
       | /      \ |
       |/        \|
       C -------- D
```

All six possible edges are present.

For a complete undirected graph with \\(n\\) vertices, the number of edges is:

$$
E|=\frac{n(n-1)}{2}
$$

edges in the undirected case.

For `n = 4`:

$$
E|=\frac{4(4-1)}{2}=6
$$

edges.

Complete graphs are useful as theoretical models and in studying graph algorithms, although many real-world graphs are not complete.


## Cyclic and acyclic graphs

### Cyclic graph

A cyclic graph contains at least one cycle.

```
    A -------- B
    |          |
    |          |
    C -------- D
```

One cycle is:

```
A → B → D → C → A
```

Cycles can represent circular dependencies, loops in networks, or alternative routes.

### Acyclic graph

An acyclic graph contains no cycles.

```
    A -------- B
               |
               |
               C -------- D
```

This graph contains no cycle.

Acyclic structures are important for dependency management and hierarchical relationships. In an undirected graph, a connected acyclic graph is a tree. In a directed graph, an acyclic graph is not necessarily a tree.

## Trees and forests

### Tree

A tree is a connected, acyclic, undirected graph.

```
          A
         / \
        B   C
       / \
      D   E
```

For a tree with \\(n\\) vertices:

\\[ |E|=n-1 \\]

A tree has exactly one simple path between any two vertices.

Common uses:

- File-system hierarchies
- Binary search trees
- Organization structures
- Network spanning trees

### Forest

A forest is an undirected acyclic graph that may be disconnected. Each connected component is a tree.

```
      A           D
     / \         / \
    B   C       E   F

        G
```

This forest contains three tree components: `{A, B, C}`, `{D, E, F}`, and `{G}`.

Forests appear in disjoint-set algorithms and as intermediate results in minimum spanning tree algorithms.

## Directed acyclic graph (DAG)

A directed acyclic graph, or DAG, is a directed graph that contains no directed cycles.

```
    A -------> C -------> E
     \        ^
      \      /
       v    /
        B --------> D
```

The arrows define the allowed direction of movement, and no directed path returns to its starting vertex.

DAGs are especially useful for modeling dependencies:

```
Source Code
     |
     v
 Compile
     |
     v
   Test
     |
     v
  Package
     |
     v
   Deploy
```

In this example, a task must finish before its dependent task begins.

A DAG supports topological sorting, which produces an ordering of vertices that respects all directed dependencies.

Typical applications:

- Build systems
- Task scheduling
- Course prerequisite planning
- Data-processing pipelines
- Dependency graphs in software systems

Important distinction: A DAG does not have to be a tree. A vertex can have multiple incoming edges, and different paths can converge on the same vertex.

## Bipartite graphs

A bipartite graph is a graph whose vertices can be divided into two disjoint sets such that every edge connects a vertex in one set to a vertex in the other.

```
    Set U              Set V

      A -------------- X
       \              /
        \            /
         \----------Y

      B -------------- Y
```

There are no edges connecting two vertices within the same set.

Examples:

- Matching job applicants to jobs
- Matching students to courses
- Connecting customers to products
- Matching workers to tasks

### Complete bipartite graph

A complete bipartite graph, denoted \\(K\_\{m,n}\\), connects every vertex in the first set to every vertex in the second set.

There are no edges between vertices belonging to the same set.

Its number of edges is:

\\[ |E|=mn \\]

For example, \\(K\_\{2,3}\\) has two vertices in one set, three in the other, and six edges.

Imagine two students and three courses. Every student is eligible to enroll in every course.

The graph is called \\(K\_\{2,3}\\), where:

- \\(2\\) is the number of vertices in the student set.
- \\(3\\) is the number of vertices in the course set.

```
 Students (U)             Courses (V)

 Alice  ------------------ Java
   |  \  \                  ^
   |   \  \                 |
   |    \  \----------------|
   |     \
   |      \---------------- Algorithms
   |                         ^
   |                         |
   |----------------------- Databases
   |
 Bob  --------------------- Java
   |  \                     |
   |   \---------------- Algorithms
   |                         |
   |----------------------- Databases
```
The drawing above illustrates the relationships conceptually; for an exact edge list, use the following:

```
Alice ── Java
Alice ── Algorithms
Alice ── Databases

Bob   ── Java
Bob   ── Algorithms
Bob   ── Databases
```

Every student connects to every course, so there are \\(2 \times 3 = 6\\) edges.

**Other practical applications**

| Application    | First set  | Second set |
| -------------- | ---------- | ---------- |
| Job assignment | Workers    | Jobs       |
| Education      | Students   | Courses    |
| E-commerce     | Customers  | Products   |
| Recruitment    | Applicants | Vacancies  |
| Computing      | Tasks      | Machines   |

In real applications, the graph may initially be complete to represent every possible assignment. After applying eligibility rules or constraints, some edges may be removed, leaving a general bipartite graph rather than a complete one.

Remember: A complete bipartite graph connects every vertex in one set to every vertex in the other set, but never connects vertices within the same set.
Bipartite graphs are important in matching algorithms and resource-allocation problems.

## Sparse and dense graphs

These terms describe how many edges a graph has relative to the maximum possible number.

### Sparse graph

A sparse graph has relatively few edges.

```
    A -------- B

    C -------- D

    E
```

Sparse graphs often occur in road networks and large dependency graphs.

An adjacency-list representation is usually a good choice for sparse graphs because it stores only existing edges.

### Dense graph

A dense graph has many edges relative to the maximum possible number.

```
    A -------- B
     \        /
      \      /
       \    /
        \  /
         C
```

The drawing illustrates a triangle where every vertex is connected to the others.

For a simple undirected graph with \\(n\\) vertices, the maximum possible number of edges is:

\\[ E\_\{\max}=\frac{n(n-1)}{2} \\]

A common way to measure density is:

\\[ D=\frac\{2|E|}\{|V|(|V|-1)} \\]

For a simple undirected graph with at least two vertices, density ranges from 0 to 1.

- Density near 0 indicates a sparse graph.
- Density near 1 indicates a dense graph.

There is no universal threshold separating sparse from dense; the distinction depends on the graph and application.

## Regular graphs

A regular graph is a graph in which every vertex has the same degree.

### 2-regular graph

```
       A -------- B
       |          |
       |          |
       D -------- C
```

Every vertex has degree 2, so this is a 2-regular graph.

### 3-regular graph

A 3-regular graph is a graph in which every vertex has exactly 3 edges connected to it.

In other words, the degree of every vertex is 3:

\\[ \deg(v)=3 \quad \text\{for every vertex }v \\]

A complete graph with four vertices, \\(K_4\\), is a 3-regular graph because every vertex connects to the other three vertices.

```
        A
       /|\
      / | \
     /  |  \
    B---+---C
     \  |  /
      \ | /
       \|/
        D
```

The diagram is schematic. The exact edges are:

```
A -- B
A -- C
A -- D
B -- C
B -- D
C -- D
```
Calculate each vertex's degree

| Vertex | Neighbors | Degree |
| ------ | --------- | ------ |
| A      | B, C, D   | 3      |
| B      | A, C, D   | 3      |
| C      | A, B, D   | 3      |
| D      | A, B, C   | 3      |

Since every vertex has degree 3, \\(K_4\\) is a 3-regular graph.

Regular graphs are useful in network topology, distributed systems, and mathematical graph theory, where uniform connectivity can be desirable.

- Computer networks: Modeling networks where each node has exactly three connections.
- Circuit design: Representing systems with uniform connectivity.
- Graph algorithms: Testing graph coloring, matching, and traversal algorithms.
- Scheduling and combinatorics: Studying problems where every vertex has the same number of relationships.

Remember: A graph is 3-regular because of the degree of its vertices, not because it has three vertices or three edges. Every vertex must have exactly three incident edges.

## Planar graphs

A planar graph is a graph that can be drawn on a flat surface without edges crossing except at shared endpoints.

```
    A -------- B
    | \        |
    |  \       |
    |   \      |
    D -------- C
```

The drawing of a graph may contain crossings, but that alone does not make the graph nonplanar. What matters is whether a crossing-free drawing is possible.

Planar graphs are relevant to:

- Map coloring
- Circuit layout
- Geographic networks
- VLSI design

Two famous nonplanar graphs are \\(K_5\\) and \\(K\_\{3,3}\\).

## Eulerian and Hamiltonian graphs

These types describe routes through a graph.

### Eulerian graph

An Eulerian circuit is a closed walk that traverses every edge exactly once and returns to its starting vertex.

For a connected undirected graph, an Eulerian circuit exists if every vertex has even degree.

Example:

```
    A -------- B
    |          |
    |          |
    D -------- C
```

One Eulerian circuit is:

```
A → B → C → D → A
```

Every edge is traversed exactly once.

### Hamiltonian graph

A Hamiltonian cycle visits every vertex exactly once and returns to the starting vertex.

In the same square graph:

```
A → B → C → D → A
```

This is also a Hamiltonian cycle.

The key difference is:

- Eulerian: Focuses on traversing every edge exactly once.
- Hamiltonian: Focuses on visiting every vertex exactly once.

Finding Eulerian circuits has efficient algorithms. Determining whether a general graph contains a Hamiltonian cycle is computationally much harder.

## How to choose the appropriate graph type

Different graph properties suggest different representations and algorithms.

| Problem                                                | Likely graph type or concept            | Useful algorithm or technique           |
| ------------------------------------------------------ | --------------------------------------- | --------------------------------------- |
| Finding the minimum number of edges between vertices   | Unweighted graph                        | BFS                                     |
| Finding a minimum-cost route with nonnegative weights  | Weighted graph                          | Dijkstra's algorithm                    |
| Detecting circular dependencies                        | Directed graph                          | DFS or topological-sort cycle detection |
| Scheduling dependent tasks                             | DAG                                     | Topological sorting                     |
| Finding disconnected groups                            | Undirected graph                        | DFS, BFS, or Union-Find                 |
| Connecting all vertices with minimum total edge weight | Connected weighted undirected graph     | Kruskal's or Prim's algorithm           |
| Matching workers to jobs                               | Bipartite graph                         | Bipartite matching                      |
| Representing hierarchical data                         | Tree                                    | Tree traversal                          |
| Finding a route using every edge exactly once          | Graph with an Eulerian circuit or trail | Hierholzer's algorithm                  |

## Summary

Remember: Graph types describe different dimensions of a graph. Start by asking whether the graph is directed or undirected, weighted or unweighted, and whether its structure contains cycles or special properties. These decisions help determine which algorithms and graph representations are appropriate.

{/* ## Depth-First Search(DFS) */}

Depth-First Search(DFS)  is a graph traversal algorithm that explores one path as deeply as possible before returning(backtracking) to explore another path.

DFS explores as deeply as possible before backtracking.

For:

```text
        A
       / \
      B   C
     / \
    D   E
```

one possible DFS traversal is:

```text
A → B → D → E → C
```

Unlike BFS, which uses a queue to explore nearby vertices first, DFS  can be implemented using:

* recursion
* an explicit stack(Stack,LIFO)

DFS follows one branch as deeply as possible before returning to explore other branches.

The key idea is:

Go deeper while an unvisited neighbor exists. When you cannot go deeper, backtrack.

It uses a stack, either explicitly or through recursion. A stack follows LIFO (Last In, First Out).

### DFS step by step
```
        A
       / \
      B   C
     / \   \
    D   E---F
```
The edges are:

```
A-B
A-C
B-D
B-E
C-F
E-F
```

Using the same graph and processing neighbors in the listed order, a recursive DFS produces:

Starting at `A`, DFS visits a vertex, then moves to an unvisited neighbor and continues deeper.

```
A → B → D → E → F → C
```

For example, one possible traversal is:

```
A -> B -> D
         |
         +-- backtrack to B
             |
             v
             E -> F -> C
```

The process is:

```
Start at A
 |
 +-- Visit B
      |
      +-- Visit D
      |    |
      |    +-- No unvisited neighbors: backtrack to B
      |
      +-- Visit E
           |
           +-- Visit F
                |
                +-- Visit C
                     |
                     +-- No unvisited neighbors
```

DFS backtracks whenever the current vertex has no unvisited neighbors.

The precise traversal order depends on the order in which neighbors are examined. A different adjacency-list order can produce a different valid DFS traversal.

```
A -> C -> F -> E -> B -> D
```

The key idea is that DFS goes deep first, then backtracks when it has no unvisited neighbor left.

## Pseudocode
DFS can be implemented recursively using the call stack or iteratively using an explicit stack.
### Iterative
### Recursive
```
DFS(graph, vertex, visited):
    add vertex to visited
    process(vertex)

    for each neighbor of vertex:
        if neighbor is not visited:
            DFS(graph, neighbor, visited)
```

**What backtracking really means**

Backtracking is not a separate search operation. It happens naturally when a recursive call returns.

Consider this simplified sequence:

```
dfsVisit(A)
    dfsVisit(B)
        dfsVisit(D)
        return to B
        dfsVisit(E)
        return to B
    return to A
    dfsVisit(C)
    return to A
```

Each call pauses while its child is explored. When the child finishes, execution resumes at the statement immediately following that recursive call.

This is why recursion is so useful for DFS: the program's call stack remembers where to resume exploring.
### The three colors
The heart of Depth-First Search is a recursive dfsVisit(u) operation that visits a
vertex u that has not yet been visited. dfsVisit(u) records its progress by coloring
vertices one of three colors:
1. White — Not visited

    DFS has not entered this vertex yet. It is eligible to be explored.

2. Gray — Currently being explored

    DFS has entered the vertex, but it has not finished checking all its neighbors.

3. Black — Finished

    DFS has examined every neighbor of this vertex. No more work remains for it.

Think of the colors as a vertex's progress through the algorithm:

```
WHITE  ──────>  GRAY  ──────>  BLACK
Not visited    Exploring      Finished
```

A vertex does not go backward from black to gray or white during a normal DFS traversal.

```
depthFirstSearch(G, s):
    for each vertex v in G:
        pred[v] = -1
        color[v] = WHITE

    dfsVisit(s)


dfsVisit(u):
    color[u] = GRAY

    for each neighbor v of u:
        if color[v] == WHITE:
            pred[v] = u
            dfsVisit(v)

    color[u] = BLACK
```

- `depthFirstSearch(G, s)` initializes the search.
- `dfsVisit(u)` explores a vertex and its reachable, unvisited neighbors.

1. Step 1: Initialize every vertex

```
for each vertex v in G:
    pred[v] = -1
    color[v] = WHITE
```

Initially, each vertex is colored `white` to represent that it has not yet been visited,
and Depth-First Search invokes `dfsVisit` on the source vertex, `s`, DFS knows nothing about which vertices have been visited.

- `color[v] = WHITE` means vertex `v` has not been explored.
- `pred[v] = -1` means DFS has not assigned a predecessor to `v`.

The predecessor array records the vertex from which DFS first discovered each vertex. It can later be used to reconstruct a path.

2. Step 2: Start at the source

```
dfsVisit(s)
```

The algorithm begins exploring from source vertex `s`.

Notice that this does not necessarily visit every vertex in the graph. If the graph is disconnected, vertices outside the source's connected component remain white.

3. Step 3: Color the current vertex gray

```
color[u] = GRAY
```

DFS has now entered vertex `u`.

It is not finished yet because some of its neighbors might still be unexplored.

4. Step 4: Explore white neighbors recursively

```
for each neighbor v of u:
    if color[v] == WHITE:
        pred[v] = u
        dfsVisit(v)
```

For every neighbor `v`:

1. Check whether `v` is white.
2. If it is, record `u` as its predecessor.
3. Recursively explore `v` before continuing with the remaining neighbors of `u`.

This is what makes DFS go deep rather than explore all immediate neighbors first.

5. Step 5: Color the vertex black

```
color[u] = BLACK
```

This statement executes only after the loop has finished and all recursive calls initiated by `u` have returned.

At this point, all neighbors of `u` have been examined, and every neighbor that was white has been explored.

The function can now return to its caller.

#### Step-by-step DFS example

Consider this undirected graph. Assume neighbors are processed in alphabetical order.
```
        A
       / \
      B   C
     / \   \
    D   E---F
```
The edges are:

```
A-B, A-C, B-D, B-E, C-F, E-F
```

1. Step 1: Initialize every vertex


```
                                A
                             (WHITE)
                             pred=-1 
                               / \
                             B     C
                       (WHITE)    (WHITE)
                       pred=-1    pred=-1 
                          / \           \
                         /   \           \
                        D     E --------- F
                   (WHITE)   (WHITE)   (WHITE)
                   pred=-1   pred=-1   pred=-1 
```

We start DFS at `A`.

1. Step 2: Visit A

    `A` is colored gray. Its first white neighbor is `B`, so DFS records `pred[B] = A` and recursively visits `B`.

    ```
    A(GRAY)
    |
    B(WHITE)
    ```

    The diagram here shows the exploration direction; the graph edges remain unchanged.

3. Step 2: Visit B, then D

`B` becomes gray. Its first white neighbor is `D`, so DFS visits `D`.

    `D` has no white neighbors. Its neighbors are already gray or black, so `D` becomes black and returns to `B`.

    ```
                                    A
                                (GRAY)
                                pred=-1 
                                  / \
                                B     C
                           (GRAY)    (WHITE)
                           pred=A    pred=-1 
                             / \           \
                            /   \           \
                            D     E --------- F
                      (Black)   (WHITE)   (WHITE)
                      pred=B   pred=-1   pred=-1 
    ```

    This is the first backtracking event: DFS returns from `D` to `B`.

4. Step 3: Explore E

    Back at `B`, DFS continues checking its neighbors. `D` is black, and `E` is white.

    DFS records `pred[E] = B` and visits `E`.

    `E` has a neighbor `F` that is still white, so DFS continues to `F`, and then from `F` to `C`.

    ```
    A(GRAY)
    |
    B(GRAY)
    |
    E(GRAY)
    |
    F(GRAY)
    |
    C(GRAY)
    ```

5. Step 4: Finish C, F, E, and B

`C` has no white neighbors left, so it becomes black and returns to `F`.

`F` then finishes and returns to `E`. `E` finishes and returns to `B`. Finally, `B` finishes and returns to `A`.

The recursive call stack unwinds in reverse order:

```
C  ->  F  ->  E  ->  B  ->  A
```

6. Step 5: Finish A

    Back at `A`, DFS checks its remaining neighbor `C`. Since `C` is already black, it does not visit it again.

    `A` becomes black, and the traversal is complete.

One possible DFS discovery order is:

```
A -> B -> D -> E -> F -> C
```

The exact order can differ if the graph stores or processes neighbors in a different order.

---

**What is `pred[]` used for?**

Suppose the predecessor assignments from our example are:

| Vertex | `pred[vertex]` |
| ------ | -------------- |
| A      | -1             |
| B      | A              |
| C      | F              |
| D      | B              |
| E      | B              |
| F      | E              |

To reconstruct the DFS tree path from `A` to `C`, follow predecessors backward:

```
C <- F <- E <- B <- A
```

Reverse that sequence:

```
A -> B -> E -> F -> C
```

This is a path found by DFS, not necessarily the shortest path. If you need shortest paths in an unweighted graph, Breadth-First Search (BFS) is usually the appropriate algorithm.

---

**source DFS vs. full DFS forest**

the pseudocode initializes every vertex but calls only:

```
dfsVisit(s)
```

That explores only the source's reachable component.

To visit every vertex, including disconnected components, use an outer loop:

```
depthFirstSearch(G):
    for each vertex v in G:
        pred[v] = -1
        color[v] = WHITE

    for each vertex v in G:
        if color[v] == WHITE:
            dfsVisit(v)
```

This creates a DFS forest: one DFS tree for each connected component in an undirected graph.

The key takeaway: white means not started, gray means currently exploring, and black means finished. DFS recursively follows white neighbors, then backtracks as calls return.

## Example: Maze 
how we can solve a maze using a graph and Depth-First Search (DFS). The key idea is that instead of treating the maze as a collection of individual squares, we represent important locations as vertices and the paths connecting them as edges.

Consider the maze shown next figure. Imagine entering a maze at `s` and trying to reach the target `t`.
![A small maze to get from s to t](/docs/assets/software-systems/data-structures-and-algorithms/data-structures/concepts/graph/maze-example.png)

A simple strategy is:

1. Start at `s` and move forward.
2. Whenever you reach a junction, choose an unexplored direction.
3. Mark the locations you have visited so you don't repeatedly explore the same paths.
4. If you reach a dead end, backtrack to the most recent junction with an unexplored path.
5. Continue until you reach `t` or establish that no path exists.

This is the basic idea behind Depth-First Search (DFS).

The numbers on the right side of figure above reflect the
branching points of one such solution; in fact, every square in the maze is visited in
this solution.

We can represent the maze in the figure above by creating a graph consisting of vertices and edges. 

A vertex is created for each 

- Junction where you can choose between multiple directions(branching point in the maze, labeled by numbers on the right in the figure above).
- Dead end.
- Start location `s`.
- Target location `t`.

An edge connects two vertices when there is a direct corridor between them with no junction or decision point in the middle.

For example:

```
Maze corridor:

s ---------------- A ---------------- B
       corridor             corridor

Graph representation:

s -------- A -------- B
```

The long corridors become edges. Their lengths can be ignored if we only care whether a path exists, or represented as weights if we want to measure the distance traveled.

The undirected graph representation of the maze from the figure above is shown in next figure; each vertex has a unique identifier.
![A small maze to get from s to t](/docs/assets/software-systems/data-structures-and-algorithms/data-structures/concepts/graph/maze-example1.png)

In this example, all edges are undirected, , if you can walk from junction `A` to junction `B`, you can usually walk back from `B` to `A`.

Therefore, the edge is undirected:

```
A -------- B
```

This represents movement in either direction.


but we could easily consider directed edges if the maze imposed such
restrictions. if a maze contains one-way doors, moving walkways, or other restrictions, we can use directed edges:

```
A --------> B 
```

To solve the maze, we need only find a path in the graph $G = (V, E)$ of above Figure
from the start vertex, `s`, to the target vertex, `t`. 

Once the maze has been converted into a graph, we no longer need to reason about every square. We simply search for a path from `s` to `t`.

For example, consider this graph:

```
       B -------- D
      /            \
s --- A              t
      \            /
       C -------- E
```

A DFS traversal might follow this sequence:

```
s → A → B → D → t
```

If `D` does not connect to `t`, DFS backtracks to the most recent vertex with an unexplored neighbor and tries another route.

The algorithm keeps track of visited vertices to avoid cycling indefinitely.

**Recursive DFS pseudocode**

```
DFS(current, target):
    mark current as visited

    if current == target:
        return success

    for each neighbor of current:
        if neighbor is not visited:
            if DFS(neighbor, target) succeeds:
                return success

    return failure
```

This searches for a path from the start to the target. It does not necessarily find the shortest path.

**How the maze relates to the graph algorithms we studied**

| Maze concept                 | Graph concept              | DFS role                                |
| ---------------------------- | -------------------------- | --------------------------------------- |
| Start location `s`           | Start vertex               | Where the search begins                 |
| Target location `t`          | Target vertex              | Where the search should end             |
| Junction                     | Vertex                     | A point with multiple possible branches |
| Corridor                     | Edge                       | A connection between vertices           |
| Previously explored location | Visited vertex             | Prevents revisiting the same vertex     |
| Reaching a dead end          | No unexplored neighbors    | Causes backtracking                     |
| Trying another corridor      | Exploring another neighbor | Continues the search                    |

**DFS versus BFS for maze solving**

Both algorithms can find a path when one exists, but they explore differently.

| Feature                 | DFS                               | BFS                                 |
| ----------------------- | --------------------------------- | ----------------------------------- |
| Main structure          | Stack or recursion                | Queue                               |
| Exploration style       | Follows one branch deeply         | Explores by distance from the start |
| Backtracking            | Yes                               | Not in the same recursive sense     |
| Finds a path?           | Yes                               | Yes                                 |
| Finds the fewest edges? | Not generally                     | Yes, for unweighted graphs          |
| Typical use             | Exploring paths, detecting cycles | Shortest path in an unweighted maze |

Important distinction: The example describes a DFS-style strategy, not necessarily an optimal maze-solving strategy. If every corridor counts equally and you want the path with the fewest edges, BFS is generally the better choice.

Also, the example says that every square in the example maze is visited by one particular solution. That is a property of the described traversal—not a requirement of DFS. DFS may reach the target without visiting every vertex.

The central takeaway is that a maze can be transformed into a graph, allowing us to solve it using standard graph algorithms rather than maze-specific logic.

#define V 6

    // Insert the new node at the beginning

}

// Add an undirected edge: a <-> b
void addEdge(int a, int b) {
    addDirectedEdge(a, b);
    addDirectedEdge(b, a);
}

// Recursive Depth-First Search
void dfs(int current, int visited[]) {
    // Mark this vertex as visited
    visited[current] = 1;

    // Process the current vertex
    printf("%c ", labels[current]);

    // Examine all adjacent vertices
    Node *edge = graph[current];

    while (edge != NULL) {
        int neighbor = edge->vertex;

        if (!visited[neighbor]) {
            // Explore this neighbor before continuing
            // with the current vertex's remaining neighbors
            dfs(neighbor, visited);
        }

        edge = edge->next;
    }
}

// Free all dynamically allocated adjacency-list nodes
void freeGraph(void) {
    for (int i = 0; i < V; i++) {
        Node *current = graph[i];

        while (current != NULL) {
            Node *next = current->next;
            free(current);
            current = next;
        }

        graph[i] = NULL;
    }

##### The `Node` structure

```c
typedef struct Node {
    int vertex;
    struct Node *next;
} Node;
```

Each node stores two things:

- `vertex`: the ID of a neighboring vertex.
- `next`: a pointer to the next neighbor in the adjacency list.

For example, this linked list:

```
graph[A]
   |
   v
  [C] -> [B] -> NULL
```

means vertex `A` is connected to vertices `C` and `B`.

##### The graph array

```c
Node *graph[V] = {NULL};
```

The array contains six pointers, one per vertex. Initially, every pointer is `NULL`, meaning that every adjacency list is empty.

##### Adding edges

```c
void addDirectedEdge(int from, int to) {
    Node *node = malloc(sizeof(Node));

    if (node == NULL) {
        fprintf(stderr, "Memory allocation failed\n");
        exit(EXIT_FAILURE);
    }

    node->vertex = to;
    node->next = graph[from];
    graph[from] = node;

```

Suppose we execute:

```c
addDirectedEdge(A, B);
addDirectedEdge(A, C);
```

The first call creates a node for `B`:

```
graph[A] -> [B] -> NULL
```

The second call inserts `C` at the head:

```
graph[A] -> [C] -> [B] -> NULL
```

This is why DFS explores `C` before `B` when it starts at `A`.

To represent an undirected connection, `addEdge()` adds both directions:

```c
void addEdge(int a, int b) {
    addDirectedEdge(a, b);
    addDirectedEdge(b, a);
}
```

For example, `addEdge(A, B)` makes `B` a neighbor of `A` and `A` a neighbor of `B`.

##### Explain the `dfs()` function line by line

This is the core of the algorithm:

```c
void dfs(int current, int visited[]) {
    visited[current] = 1;
    printf("%c ", labels[current]);

    Node *edge = graph[current];

    while (edge != NULL) {
        int neighbor = edge->vertex;

        if (!visited[neighbor]) {
            dfs(neighbor, visited);
        }

        edge = edge->next;
    }
}
```

Let's break it down.

###### Step 1: Mark the current vertex as visited

```c
visited[current] = 1;
```

This prevents DFS from revisiting the vertex through another edge.

For example, because the graph is undirected, if DFS moves from `A` to `C`, it will eventually encounter the edge from `C` back to `A`. Since `A` is already visited, DFS skips it.

###### Step 2: Process the vertex

```c
printf("%c ", labels[current]);
```

This prints the current vertex's label.

The integer ID `0` maps to `A`, `1` maps to `B`, and so on.

###### Step 3: Start with the first neighbor

```c
Node *edge = graph[current];
```

The pointer `edge` starts at the head of the current vertex's adjacency list.

For example, if the current vertex is `A`:

```
graph[A] -> [C] -> [B] -> NULL
              ^
              |
             edge
```

###### Step 4: Examine every neighbor

```c
while (edge != NULL) {
    int neighbor = edge->vertex;
```

The loop processes each neighbor until it reaches `NULL`, the end of the linked list.

###### Step 5: Recursively explore unvisited neighbors

```c
if (!visited[neighbor]) {
    dfs(neighbor, visited);
}
```

This is the defining operation of recursive DFS.

Instead of finishing the current vertex's remaining neighbors, DFS immediately calls itself on an unvisited neighbor. That call explores its own neighbors, potentially making more recursive calls.

Only when the deeper call finishes does execution return to the previous call.

###### Step 6: Move to the next neighbor

```c
edge = edge->next;
```

Once a recursive call returns—or if the neighbor was already visited—the loop advances to the next neighbor in the current adjacency list.

Important: This statement executes after the recursive call returns. That is what allows DFS to resume where it left off.

##### Step-by-step code walkthrough

We'll trace the actual C implementation, including its head-insertion adjacency lists.

##### Initial adjacency lists

After adding all six edges, the graph looks like this:

```
A: C -> B
B: E -> D -> A
C: F -> A
D: B
E: F -> B
F: E -> C
```

Remember that `addDirectedEdge()` inserts each new neighbor at the beginning.

Initially:

```
visited = [0, 0, 0, 0, 0, 0]
```

The indexes correspond to:

```
Index:    0  1  2  3  4  5
Vertex:   A  B  C  D  E  F
```

We start with:

```
dfs(A, visited);
```

1. Step 1: Visit A

The function marks `A` as visited and prints it.

```
Output: A

visited = [1, 0, 0, 0, 0, 0]
```

`A`'s first neighbor is `C`, so DFS calls:

```c
dfs(C, visited);
```

2. Step 2: Visit C

`C` is unvisited, so DFS marks and prints it.

```
Output: A C

visited = [1, 0, 1, 0, 0, 0]
```

`C`'s first neighbor is `F`. DFS calls:

```c
dfs(F, visited);
```

Notice that DFS has not yet examined `A`'s remaining neighbor, `B`. It follows the path through `C` first.

3. Step 3: Visit F

DFS marks and prints `F`.

```
Output: A C F

visited = [1, 0, 1, 0, 0, 1]
```

`F`'s adjacency list is:

```
F: E -> C
```

Its first neighbor, `E`, is unvisited, so DFS calls:

```c
dfs(E, visited);
```

4. Step 4: Visit E

DFS marks and prints `E`.

```
Output: A C F E

visited = [1, 0, 1, 0, 1, 1]
```

`E`'s adjacency list is:

```
E: F -> B
```

- `F` is already visited, so DFS skips it.
- `B` is unvisited, so DFS calls `dfs(B, visited)`.

5. Step 5: Visit B

DFS marks and prints `B`.

```
Output: A C F E B

visited = [1, 1, 1, 0, 1, 1]
```

`B`'s adjacency list is:

```
B: E -> D -> A
```

- `E` is already visited.
- `D` is unvisited, so DFS calls `dfs(D, visited)`.
- The neighbor `A` has not been examined yet because DFS must first finish exploring `D`.

6. Step 6: Visit D

DFS marks and prints `D`.

```
Output: A C F E B D

visited = [1, 1, 1, 1, 1, 1]
```

`D` has only one neighbor, `B`, which is already visited.

Therefore, the call `dfs(D, visited)` finishes and returns to `dfs(B, visited)`.

`B` resumes its loop, encounters `A`, and skips it because `A` is already visited. The call for `B` then finishes.

7. Step 7: Backtrack through the recursive calls

The recursive calls now return in reverse order:

```
dfs(D) returns to dfs(B)
dfs(B) returns to dfs(E)
dfs(E) returns to dfs(F)
dfs(F) returns to dfs(C)
dfs(C) returns to dfs(A)
```

At each return, the caller resumes its adjacency-list loop.

- `E` resumes after `B` and finishes.
- `F` resumes after `E`; `C` is already visited, so it finishes.
- `C` resumes after `F`; `A` is already visited, so it finishes.
- `A` resumes after `C`; its next neighbor is `B`, which is already visited.

The original call `dfs(A, visited)` finally returns.

All vertices have been visited.

##### Visualize the recursive call stack

DFS uses the function-call stack to remember where to return after exploring a deeper path.

During the deepest part of this traversal, the stack looks like this, from oldest call to newest:

```
dfs(A)
  |
  +-- dfs(C)
        |
        +-- dfs(F)
              |
              +-- dfs(E)
                    |
                    +-- dfs(B)
                          |
                          +-- dfs(D)  <-- current call
```

When `dfs(D)` finishes, it is removed from the call stack. Execution resumes inside `dfs(B)`, immediately after the call to `dfs(D)`.

This is called backtracking.

DFS does not need to store every pending vertex in a queue as BFS does. The recursive call stack remembers the current path and where each call should continue.

##### Common pitfalls

1. Forgetting the visited array: An undirected graph contains edges in both directions. Without tracking visited vertices, DFS may recurse repeatedly through a cycle.
2. Marking a vertex too late: Mark it at the beginning of the function, before exploring its neighbors.
3. Expecting one fixed traversal order: The result depends on adjacency-list order. Inserting at the head reverses the order in which neighbors were added.
4. Confusing DFS traversal with shortest-path search: DFS finds a path if one exists, but the first path it finds is not necessarily the shortest.
5. Ignoring recursion depth: A very deep graph can cause stack overflow. An iterative DFS with an explicitly managed stack can avoid relying on recursive calls, although the explicit stack still requires memory.

##### Complexity analysis

With an adjacency-list representation:

- Time: $O(V+E)$. Each vertex is visited once, and each adjacency-list entry is examined once.
- Visited array: $O(V)$.
- Recursive call stack: $O(V)$ in the worst case.
- Graph storage: $O(V+E)$.

For a connected graph, DFS visits every vertex reachable from the starting vertex. For a disconnected graph, a single call to `dfs(start, visited)` visits only the connected component containing `start`.

To traverse every component, use an outer loop:

```
int visited[V] = {0};

for (int i = 0; i < V; i++) {
    if (!visited[i]) {
        dfs(i, visited);
    }
}
```

This visits all vertices, starting a new DFS whenever an unvisited component is found.

#### The three colors

We'll implement the three colors — `WHITE`, `GRAY`, and `BLACK` — in a complete C program that performs recursive Depth-First Search on a graph.

The important idea is that each vertex has a color, and DFS changes that color as the vertex moves through the exploration process.

- `WHITE`: The vertex has not been visited.
- `GRAY`: The vertex is being explored; it may still have unvisited neighbors.
- `BLACK`: The vertex and all its neighbors have been fully processed.

**The color states in C**

C allows us to represent these states with an `enum`:

```c
typedef enum {
    WHITE,  // Vertex has not been visited.
    GRAY,   // Vertex is currently being explored.
    BLACK   // Vertex has finished processing.
} Color;
```

We can then create a color array:

```c
Color color[MAX_VERTICES];
```

For example, `color[2]` stores the current state of vertex `2`.

This example uses an adjacency-list-style representation stored in arrays. It explores the graph recursively, prints each color transition, and records each vertex's predecessor.

```c

#include <stdio.h>

#define MAX_VERTICES 6

/*
 * Each vertex can be in one of three DFS states.
 */
typedef enum {
    WHITE,  // Not visited yet.
    GRAY,   // Visited; neighbors are still being explored.
    BLACK   // Finished; all neighbors have been examined.
} Color;

/*
 * A simple graph represented by adjacency lists.
 *
 * adj[u][i] is the i-th neighbor of vertex u.
 * degree[u] is the number of neighbors of vertex u.
 */
typedef struct {
    int adj[MAX_VERTICES][MAX_VERTICES];
    int degree[MAX_VERTICES];
} Graph;

/* Names used when displaying vertices. */
static const char *vertexName[MAX_VERTICES] = {
    "A", "B", "C", "D", "E", "F"
};

/* Convert a color value to readable text. */
const char *colorName(Color color)
{
    switch (color) {
        case WHITE: return "WHITE";
        case GRAY:  return "GRAY";
        case BLACK: return "BLACK";
        default:    return "UNKNOWN";
    }
}

/* Add an undirected edge between u and v. */
void addEdge(Graph *graph, int u, int v)
{
    if (u < 0 || u >= MAX_VERTICES ||
        v < 0 || v >= MAX_VERTICES) {
        return;
    }

    /* Add v to u's adjacency list. */
    graph->adj[u][graph->degree[u]++] = v;

    /* Add u to v's adjacency list. */
    graph->adj[v][graph->degree[v]++] = u;
}

/*
 * Recursively explore vertex u.
 *
 * color[] tracks the DFS state of each vertex.
 * pred[] records the predecessor in the DFS tree.
 */
void dfsVisit(
    const Graph *graph,
    int u,
    Color color[],
    int pred[]
) {
    /* Step 1: Enter u. It is now being explored. */
    color[u] = GRAY;
    printf("Enter %s -> %s\n",
           vertexName[u], colorName(color[u]));

    /* Step 2: Examine every neighbor of u. */
    for (int i = 0; i < graph->degree[u]; i++) {
        int v = graph->adj[u][i];

        printf("  Examine edge %s -> %s\n",
               vertexName[u], vertexName[v]);

        /*
         * Only WHITE vertices have not been visited.
         * GRAY and BLACK vertices must not be visited again.
         */
        if (color[v] == WHITE) {
            /* Record how DFS discovered v. */
            pred[v] = u;

            /* Explore v completely before continuing. */
            dfsVisit(graph, v, color, pred);
        } else {
            printf("  Skip %s: already %s\n",
                   vertexName[v], colorName(color[v]));
        }
    }

    /*
     * Step 3: Every neighbor has been examined.
     * The recursive exploration of u is complete.
     */
    color[u] = BLACK;
    printf("Leave %s -> %s\n",
           vertexName[u], colorName(color[u]));
}

/* Initialize the colors and predecessor array. */
void depthFirstSearch(const Graph *graph, int source)
{
    Color color[MAX_VERTICES];
    int pred[MAX_VERTICES];

    for (int v = 0; v < MAX_VERTICES; v++) {
        color[v] = WHITE;
        pred[v] = -1;
    }

    printf("Starting DFS from %s\n\n", vertexName[source]);

    /* Start the recursive traversal. */
    dfsVisit(graph, source, color, pred);

    printf("\nFinal vertex states:\n");

    for (int v = 0; v < MAX_VERTICES; v++) {
        printf("%s: %-5s predecessor: %s\n",
               vertexName[v],
               colorName(color[v]),
               pred[v] == -1 ? "NONE" : vertexName[pred[v]]);
    }
}

int main(void)
{
    /*
     * Start with an empty graph.
     * All adjacency-list lengths are zero.
     */
    Graph graph = {0};

    /*
     * Build this undirected graph:
     *
     *         A
     *        / \
     *       B   C
     *      / \   \
     *     D   E---F
     *
     * Vertices: A=0, B=1, C=2, D=3, E=4, F=5
     */
    addEdge(&graph, 0, 1);  // A-B
    addEdge(&graph, 0, 2);  // A-C
    addEdge(&graph, 1, 3);  // B-D
    addEdge(&graph, 1, 4);  // B-E
    addEdge(&graph, 2, 5);  // C-F
    addEdge(&graph, 4, 5);  // E-F

    /* Run DFS starting from A (vertex 0). */
    depthFirstSearch(&graph, 0);

    return 0;
}

```

Compile and run:

```
gcc -std=c11 -Wall -Wextra -pedantic dfs_colors.c -o dfs_colors
./dfs_colors
```

**How the colors change during execution**

Starting from vertex `A`, the traversal follows this order:

```
A -> B -> D -> E -> F -> C
```

**Why do we check `color[v] == WHITE`?**

This condition is essential:

```
if (color[v] == WHITE) {
    pred[v] = u;
    dfsVisit(graph, v, color, pred);
}
```

Consider the undirected edge `A-B`.

When DFS visits `A`, it explores `B`. Later, when DFS examines `B`'s neighbors, it encounters `A` again.

But `A` is gray, so DFS skips it instead of recursively calling `dfsVisit(A)` again.

Without the color check, the traversal could repeatedly visit vertices and never terminate on a cyclic graph.

The colors therefore serve two purposes:

- They prevent revisiting vertices.
- They tell us whether a vertex is still being explored or has finished.

---

**Complexity**

Because the graph uses adjacency lists, DFS examines each vertex once and each edge at most twice for an undirected graph.

- Time: $O(V+E)$
- Space: $O(V)$ for the color array, predecessor array, and recursion stack.

The example uses fixed-size arrays for simplicity. A production implementation should also validate the source vertex and check adjacency-list capacity when adding edges.

Remember: gray means in progress, not merely “visited.” That distinction is what lets DFS identify unfinished recursive work and backtrack correctly.

## When is DFS useful?
DFS is useful for:

- Detecting cycles.
- Finding connected components.
- Topological sorting of a directed acyclic graph (DAG).
- Exploring mazes and backtracking problems.
- Finding paths and analyzing graph structure.
- Supporting algorithms such as strongly connected components.
- graph analysis

Unlike BFS, DFS does not generally find the shortest path in an unweighted graph.

## Time and space complexity

For a graph stored as an adjacency list, both BFS and DFS run in:

$$
O(V + E)
$$

where:

- $V$ is the number of vertices.
- $E$ is the number of edges.

Each vertex is visited at most once, and each adjacency-list entry is examined a constant number of times.

| Representation   | BFS/DFS traversal time |
| ---------------- | ---------------------- |
| Adjacency list   | $O(V+E)$           |
| Adjacency matrix | $O(V^2)$           |

The additional space for the visited set and queue or stack can be $O(V)$. Recursive DFS also uses up to $O(V)$ call-stack space.

## BFS vs. DFS

| Property(Feature)                             | BFS                                  | DFS                               |
| ------------------------------------ | ------------------------------------ | --------------------------------- |
| Main data structure(mechanism)                  | Queue                                | Stack or recursion                |
| Exploration strategy                 | Level by level                       | Deep along a path, then backtrack |
| Shortest path in an unweighted graph | Yes                                  | Not guaranteed                    |
| Cycle detection                      | Yes, with suitable logic             | Yes, with suitable logic          |
| Topological sorting                  | Possible with a separate algorithm   | Commonly used                     |
| Memory usage                         | Can be large for wide graphs         | Can be large for deep graphs      |
| Typical applications                 | Minimum-hop paths, level exploration | Backtracking, structural analysis |
|Tracks visited vertices                   | Yes                                                     | Yes                                           |
| Time complexity with adjacency lists      | $O(V+E)$                                            | $O(V+E)$                                  |
| Auxiliary space                           | $O(V)$, including queue and visited array | $O(V)$, including recursion stack and visited array |

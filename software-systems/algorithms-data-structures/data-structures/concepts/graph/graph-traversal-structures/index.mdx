
Once the graph is stored, we need algorithms to explore it.

How do you find a node in a Graph? If the Graph’s structure offers
no navigation help, you must visit every node in the graph until you
find the one you want. To achieve that, there are two approaches:
depth-first and breadth-first.

**Graph Traversal Structures**
One of the most important operations on graphs is **traversal**.

Graph traversal is the process of visiting the vertices (nodes) of a graph in a systematic way so that we can explore its structure, find paths, detect connections, or solve problems.

Traversal means: **Visit vertices of a graph systematically.**

The two fundamental graph traversal algorithms are:

1. **Breadth-First Search (BFS)** — explores neighbors level by level.
2. **Depth-First Search (DFS)** — explores one path as far as possible before backtracking.

![Exploring a graph depth-first versus breadth-first.](/docs/assets/software-systems/data-structures-and-algorithms/data-structures/concepts/graph/graph-traversal-structures.png)

Both algorithms are commonly implemented using an **adjacency list** or **adjacency matrix**.

Both **DFS** and **BFS** use the adjacency lists to discover neighboring vertices. Their difference is how they choose which discovered vertex to explore next.

**DFS** and **BFS** only differ in the way the next nodes to explore are stored: one uses a **Queue**, the other a **Stack**.

## A graph to use in our examples
Consider this undirected graph:

```
        A
       / \
      B   C
     / \   \
    D   E---F
```

Its adjacency list is:

```
A: B, C
B: A, D, E
C: A, F
D: B
E: B, F
F: C, E
```

We'll start at vertex `A`.

A traversal needs to keep track of which vertices have already been visited. Otherwise, cycles and repeated connections could cause the algorithm to revisit vertices indefinitely.

The Binary Heap is a special type of Binary Search Tree, in which
we can find the smallest (or highest) item instantly. This data structure is especially useful for implementing Priority Queues. In the
Heap it costs O(1) to get the minimum (or maximum) item, because it is always the Root Node of the tree. Searching or inserting
nodes still costs O(log n). It has the same node placement rules
as the Binary Search Tree, plus an extra restriction: a parent node
must be greater (or smaller) than both its child nodes.

![Nodes organized as a binary max-heap(top) and min-heap(bottom)](/docs/assets/software-systems/data-structures-and-algorithms/data-structures/concepts/heaps/binary-max-heap-and-min-heap.png)

A **Binary Heap** is a specialized **complete binary tree** used mainly to implement **priority queues**.

The key idea is simple:

> A heap keeps the highest-priority element at the root, while maintaining a specific ordering relationship between each parent and its children.

There are two main types:

* **Min-Heap** → smallest element is at the root.
* **Max-Heap** → largest element is at the root.

use the Binary Heap whenever you must frequently work with the maximum (or minimum) item of a set.

## Binary Heap Structure

A binary heap has two independent properties:

### 1. Complete Binary Tree

The tree must be **complete**:

* Every level is completely filled except possibly the last.
* The last level is filled **from left to right**.

For example:

```text
        10
       /  \
      20   30
     / \   /
    40 50 60
```

This is a complete binary tree.

But this is not:

```text
        10
       /  \
      20   30
       \
        50
```

because the last level is not filled from left to right.

---

### 2. Heap Property

The second property determines whether it is a min-heap or max-heap.

#### Min-Heap

Every parent is **less than or equal to** its children:

```text
        10
       /  \
      20   15
     / \   /
    40 50 30
```

For every node:

```text
parent <= children
```

Therefore:

```text
10 <= 20
10 <= 15

20 <= 40
20 <= 50

15 <= 30
```

The smallest element is always at the root.

---

#### Max-Heap

Every parent is **greater than or equal to** its children:

```text
        50
       /  \
      40   45
     / \   /
    10 30 20
```

For every node:

```text
parent >= children
```

Therefore, the largest element is always at the root.

## Heap Is Not a Binary Search Tree

This distinction is very important.

A **BST** has this property:

```text
left subtree < node < right subtree
```

A heap does **not**.

For example, this is a valid min-heap:

```text
        10
       /  \
      50   20
     / \
    60 70
```

Notice:

```text
50 > 20
```

even though `50` is in the left subtree of `10`.

That's perfectly valid.

The heap only requires:

```text
parent <= children
```

It does **not** require ordering between siblings or between arbitrary nodes.

## Why Use a Complete Binary Tree?

The complete-tree property makes it possible to represent a binary heap very efficiently using an **array**.

Instead of storing nodes with pointers:

```text
        10
       /  \
      20   15
     / \   /
    40 50 30
```

we can store:

```text
[10, 20, 15, 40, 50, 30]
```

The tree structure is implicitly encoded by the array indices.

## Array Representation

Assume **0-based indexing**.

For a node at index `i`:

```text
left child  = 2i + 1
right child = 2i + 2
parent      = (i - 1) / 2
```

where integer division is used for the parent.

For:

```text
        10
       /  \
      20   15
     / \   /
    40 50 30
```

the array is:

```text
index:  0   1   2   3   4   5
value: 10  20  15  40  50  30
```

For node `20`:

```text
i = 1

left  = 2(1) + 1 = 3  → 40
right = 2(1) + 2 = 4  → 50
parent = (1 - 1) / 2 = 0 → 10
```

For node `15`:

```text
i = 2

left  = 5 → 30
right = 6 → doesn't exist
parent = 0 → 10
```

This is one of the most important reasons heaps are efficient.

## Binary Heap Operations

The fundamental operations are:

| Operation                |                                Time |
| ------------------------ | ----------------------------------: |
| Peek root                |                              `O(1)` |
| Insert                   |                          `O(log n)` |
| Extract root             |                          `O(log n)` |
| Build heap               |                              `O(n)` |
| Search arbitrary value   |                              `O(n)` |
| Delete arbitrary element | `O(log n)` if its position is known |

Let's understand them.

---

### Insert

Suppose we have a min-heap:

```text
        10
       /  \
      20   15
     / \
    40 50
```

Array:

```text
[10, 20, 15, 40, 50]
```

Now insert:

```text
5
```
1. Step 1 — Put the new element at the end

Because the tree must remain complete:

```text
        10
       /  \
      20   15
     / \   /
    40 50  5
```

Array:

```text
[10, 20, 15, 40, 50, 5]
```

But the heap property is broken:

```text
15 > 5
```

2. Step 2 — Bubble Up

Compare `5` with its parent:

```text
5 < 15
```

Swap:

```text
        10
       /  \
      20    5
     / \   /
    40 50 15
```

Still:

```text
5 < 10
```

Swap again:

```text
         5
       /   \
     20     10
    / \    /
   40 50  15
```

Now the heap property is restored.

Array:

```text
[5, 20, 10, 40, 50, 15]
```

This operation is commonly called: "bubble up" or: "sift up" or: "heapify up"

**Why Is Insert O(log n)**?

A heap with `n` elements has height:

```text
O(log n)
```

When inserting, the new element starts at the bottom and can move toward the root.

In the worst case:

```text
bottom
  ↓
  ↓
  ↓
root
```

The number of levels is approximately: log₂ n

Therefore:

```text
Insert = O(log n)
```

---

### Peek

In a min-heap, the minimum element is always at: index 0

So:

```text
peek() → heap[0]
```

For:

```text
[5, 20, 10, 40, 50, 15]
```

we immediately know:

```text
min = 5
```

No traversal is necessary.

Therefore:

```text
Peek = O(1)
```

Similarly, the maximum element of a max-heap is at the root.

---

### Extract Root

Suppose we have:

```text
         5
       /   \
     20     10
    / \    /
   40 50  15
```

We want to remove the minimum:

```text
5
```

We cannot simply remove the root because that would destroy the complete-tree structure.

Instead:

1. Step 1 — Move the last element to the root

Last element:

```text
15
```

becomes the root:

```text
        15
       /  \
     20    10
    / \
   40 50
```

2. Step 2 — Restore heap property

`15 > 10`, so swap:

```text
        10
       /  \
     20    15
    / \
   40 50
```

Now the min-heap property is restored.

This operation is called: "sift down" or: "bubble down" or: "heapify down"

Therefore:

```text
extract-min = O(log n)
```

For a max-heap:

```text
extract-max = O(log n)
```

---

**Why Do We Compare Both Children?**

Suppose we have:

```text
        10
       /  \
      30   20
```

and the root becomes:

```text
25
```

We need to restore the min-heap:

```text
        25
       /  \
      30   20
```

The parent violates the heap property with both possibilities:

```text
25 > 30 ? no
25 > 20 ? yes
```

We need to swap with the **smaller child**:

```text
        20
       /  \
      30   25
```

This guarantees that the smallest available child moves upward.

For a max-heap, we instead swap with the **larger child**.

---

### Build Heap

Suppose we have an arbitrary array:

```text
[40, 10, 30, 50, 20, 15]
```

This is not necessarily a heap.

We can transform it into a heap.

This process is called: Build Heap

One efficient method is **bottom-up heap construction**.

Start with the last internal node and perform sift-down operations.

For a zero-based array, the last internal node is:

```text
floor(n / 2) - 1
```

For:

```text
n = 6
```

we start at:

```text
floor(6 / 2) - 1
= 2
```

and process:

```text
2
1
0
```

The important result is:

```text
Build Heap = O(n)
```

This is a surprisingly useful result.

---

**Why Build Heap Is O(n), Not O(n log n)?**

A common first thought is:

```text
n nodes × O(log n)
= O(n log n)
```

But bottom-up heap construction is actually:

```text
O(n)
```

because most nodes are near the bottom and can move only a very small distance.

Only a few nodes are near the root and can move many levels.

The total amount of work sums to linear time.

---

### Deleting an Arbitrary Element

Suppose we have:

```text
[10, 20, 15, 40, 50, 30]
```

and want to delete `40`.

If we already know its index:

```text
index = 3
```

we can replace it with the last element:

```text
[10, 20, 15, 30, 50]
```

Then restore the heap property using either:

```text
sift up
```

or:

```text
sift down
```

depending on the new value.

This can take:

```text
O(log n)
```

**if the element's index is already known.**

But finding an arbitrary element in a heap generally takes:

```text
O(n)
```

because a heap does not provide efficient arbitrary search.

---

**Heap Search Is Not Like BST Search**

Consider:

```text
        10
       /  \
      50   20
     / \   /
    60 70 30
```

Suppose we search for: "70"

We cannot use the BST strategy:

```text
if target < node → go left
if target > node → go right
```

because the heap doesn't have that ordering.

Therefore arbitrary search is generally:

```text
O(n)
```

This is an important difference between a heap and a BST.

---

## Min-Heap Example

Let's build a min-heap from:

```text
[20, 5, 15, 30, 10]
```

A valid min-heap could be:

```text
        5
       / \
     10   15
    / \
   30 20
```

Array:

```text
[5, 10, 15, 30, 20]
```

Notice something important:

```text
5 < everything
```

But:

```text
10 < 15
```

is not required by the heap property.

The heap only guarantees:

```text
5 <= 10
5 <= 15

10 <= 30
10 <= 20
```

---

## Max-Heap Example

A max-heap containing the same values could be:

```text
        30
       /  \
     20    15
    / \
   5  10
```

Array:

```text
[30, 20, 15, 5, 10]
```

The largest element is guaranteed to be:

```text
30
```

## Heap Height

A complete binary tree has height: O(log n)

More precisely, approximately:

```text
h = floor(log₂ n)
```

This explains the complexity of:

```text
insert
extract-min
extract-max
delete
```

because these operations may move an element from one level to another.

## Priority Queue

One of the most important applications of a binary heap is the **priority queue**.

A normal queue behaves like:

```text
first in → first out
```

A priority queue behaves like:

```text
highest priority → served first
```

For example:

```text
Task          Priority
----------------------
Email           2
Database        5
Backup          1
Emergency       10
```

A max-heap can organize these by priority:

```text
          10
        /    \
       5      2
      /
     1
```

The highest-priority task is immediately available at the root.

## Heap Sort

A binary heap can also be used to implement **Heap Sort**.

For ascending order, we can use a max-heap.

Conceptually:

```text
Array
  ↓
Build Max Heap
  ↓
Largest element at root
  ↓
Move root to end
  ↓
Restore heap
  ↓
Repeat
```

Complexity:

```text
Build heap       O(n)
n extractions    O(n log n)
----------------------------
Total            O(n log n)
```

Heap sort has:

```text
Worst case:  O(n log n)
Average:     O(n log n)
Best case:   O(n log n)
```

and it can be performed **in-place** with an array

## Binary Heap vs BST

This comparison is useful:

| Property               | Binary Heap     | Binary Search Tree        |
| ---------------------- | --------------- | ------------------------- |
| Main purpose           | Priority queue  | Searching / ordered data  |
| Root                   | Min/max         | Depends on values         |
| Parent ordering        | Yes             | Relative subtree ordering |
| Left < node < right    | No              | Yes                       |
| Find minimum           | `O(1)` min-heap | `O(h)`                    |
| Find maximum           | `O(1)` max-heap | `O(h)`                    |
| Insert                 | `O(log n)`      | `O(h)`                    |
| Delete root            | `O(log n)`      | `O(h)`                    |
| Search arbitrary value | `O(n)`          | `O(h)`                    |
| Sorted traversal       | No              | Yes                       |
| Typical storage        | Array           | Nodes/pointers            |

For a balanced BST:

```text
h = O(log n)
```

but an ordinary BST can become:

```text
O(n)
```

in the worst case.

---

## Binary Heap vs Sorted Array

Another useful comparison:

| Operation        |   Min-Heap | Sorted Array |
| ---------------- | ---------: | -----------: |
| Get minimum      |     `O(1)` |       `O(1)` |
| Insert           | `O(log n)` |       `O(n)` |
| Remove minimum   | `O(log n)` |       `O(n)` |
| Search           |     `O(n)` |   `O(log n)` |
| Get sorted order |         No |          Yes |

This illustrates the design trade-off.

A heap sacrifices efficient arbitrary searching in exchange for efficient **priority operations**.

## C Implementation

Here is a simple **min-heap** implementation in C:

```c
#include <stdio.h>

#define CAPACITY 100

typedef struct {
    int data[CAPACITY];
    int size;
} MinHeap;

void swap(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

void siftUp(MinHeap *heap, int index) {
    while (index > 0) {
        int parent = (index - 1) / 2;

        if (heap->data[parent] <= heap->data[index]) {
            break;
        }

        swap(&heap->data[parent], &heap->data[index]);

        index = parent;
    }
}

void insert(MinHeap *heap, int value) {
    heap->data[heap->size] = value;

    siftUp(heap, heap->size);

    heap->size++;
}

void siftDown(MinHeap *heap, int index) {
    while (1) {
        int left = 2 * index + 1;
        int right = 2 * index + 2;

        int smallest = index;

        if (left < heap->size &&
            heap->data[left] < heap->data[smallest]) {
            smallest = left;
        }

        if (right < heap->size &&
            heap->data[right] < heap->data[smallest]) {
            smallest = right;
        }

        if (smallest == index) {
            break;
        }

        swap(&heap->data[index], &heap->data[smallest]);

        index = smallest;
    }
}

int extractMin(MinHeap *heap) {
    int result = heap->data[0];

    heap->size--;

    heap->data[0] = heap->data[heap->size];

    siftDown(heap, 0);

    return result;
}

int main(void) {
    MinHeap heap = { .size = 0 };

    insert(&heap, 20);
    insert(&heap, 5);
    insert(&heap, 15);
    insert(&heap, 30);
    insert(&heap, 10);

    printf("Heap: ");

    for (int i = 0; i < heap.size; i++) {
        printf("%d ", heap.data[i]);
    }

    printf("\n");

    printf("Extract min: %d\n", extractMin(&heap));

    printf("Heap after extraction: ");

    for (int i = 0; i < heap.size; i++) {
        printf("%d ", heap.data[i]);
    }

    printf("\n");

    return 0;
}
```

The important algorithms here are:

```text
insert()
   ↓
siftUp()
```

and:

```text
extractMin()
   ↓
siftDown()
```

## The Core Mental Model

Think of a binary heap as two layers of rules:

```text
                 Binary Heap
                      │
          ┌───────────┴───────────┐
          │                       │
   Complete Tree             Heap Property
          │                       │
    shape constraint          order constraint
          │                       │
     left-to-right          min: parent <= child
     last level             max: parent >= child
```

The **shape** makes the heap efficient to store in an array.

The **heap property** makes the root the highest-priority element.

Together they give us:

```text
                 Heap
                   │
        ┌──────────┴──────────┐
        │                     │
    Complete              Root priority
     tree                     │
        │                     │
    Array storage        O(1) peek
        │
   O(log n) height
        │
   ┌────┴─────┐
   │          │
 Insert     Extract
 O(log n)   O(log n)
```

### What You Should Remember

The essential facts are:

1. **A binary heap is a complete binary tree.**
2. It is usually stored in an **array**, not with tree nodes.
3. A **min-heap** has the smallest element at the root.
4. A **max-heap** has the largest element at the root.
5. It does **not** have the ordering rules of a BST.
6. **Insert** uses sift-up → `O(log n)`.
7. **Extract root** uses sift-down → `O(log n)`.
8. **Peek root** → `O(1)`.
9. **Build heap** → `O(n)`.
10. Arbitrary search → `O(n)`.
11. The primary application is the **priority queue**.
12. Heap Sort uses a heap to achieve **`O(n log n)`** sorting.

A **Binary Search Tree (BST)** is a special type of binary tree that maintains an ordered structure, making searching, insertion, and deletion efficient.

A **Binary Search Tree** is a special type of Tree that can be efficiently searched. Nodes in Binary Search Trees can have at most two children. And nodes are positioned according to their value/key. Children nodes to the left of the parent must be smaller than the parent,
children nodes to the right must be greater.

## Definition
A BST is a binary tree where for every node:
- All values in the left subtree are less than the node’s value 
- All values in the right subtree are greater than the node’s value 

This rule must hold recursively for every node.

Each node contains a single value in the collection and stores references to potentially two child nodes, left and right.

So conceptually:

```text
Node
┌─────────────────┐
│ value           │
│ left reference  │
│ right reference │
└─────────────────┘
```

For example:

```text
              ┌───────────────┐
              │ value = 50    │
              │ left ─────────┼──→ 30
              │ right ────────┼──→ 70
              └───────────────┘
```

In Java, conceptually:

```java
class Node {
    int value;
    Node left;
    Node right;
}
```

So unlike an array:

```text
[10, 20, 30, 40, 50]
```

where elements are stored in contiguous positions, a BST consists of **individual nodes connected through references**.

### A BST is a collection of nodes containing ordered keys

Each node stores a key, which is the value used for comparisons during searching.

For example, our tree contains these keys:

```
              7
            /   \
           5     15
          / \    / \
         2   6  10  20
        /           /
       1           17
```

Each box represents a node. The number inside it is the node's key.

When searching for a key, we compare it with the current node's key to decide where to go next.

### The root is the ancestor of all other nodes

The root is the topmost node of the tree. In our example, `7` is the root.

```
              7  ← Root
            /   \
           5     15
```

Every other node descends from the root through one or more parent-child links.

For example:

* `7` is the parent of `5` and `15`.

* `5` is the parent of `2` and `6`.

* `2` is the parent of `1`.

* `20` is the parent of `17`.

The root has no parent.

### Each node can refer to two child nodes

A BST node has two possible child references:

* `n_left`: the left child.

* `n_right`: the right child.

Either reference can be `null`, meaning that the node has no child in that direction.

For example, node `5` has both children:

```
        5
       / \
      2   6
```

Node `2` has a left child (`1`) but no right child:

```
      2
     /
    1
```

The left and right children can each be the root of their own subtree. A subtree is a node together with all its descendants.

### The BST ordering property

All keys in the left subtree are less than or equal to the node's key, and all keys in the right subtree are greater than or equal to it.

For a node with key kkk:
$$
\text\{Left subtree keys} &\leq k
\text\{Right subtree keys} &\geq k 
$$
In our example, the root is `7`.

- Left subtree:  `5, 2, 1, 6`, Every key is less than `7`.

- Right subtree: `15, 10, 20, 17`, Every key is greater than `7`.

The same rule applies at every node, not just the root. For example, relative to node `5`, keys in its left subtree are smaller than or equal to `5`, while keys in its right subtree are greater than or equal to `5`.

### Leaf node

A leaf node is a node whose left and right child references are both `null`.

In this tree, the leaf nodes are:

* `1`

* `6`

* `10`

* `17`

For example, node `6` has no children:

```
       5
      / \
     2   6  ← Leaf
    /
   1
```

Node `2` is not a leaf because it has a child (`1`).

### Interior node?

An interior node is a node that has at least one child. In this example, `5` is an interior node:

```
          7
         /
        5  ← Interior node
       / \
      2   6
```

Node `5` has a parent (`7`) and two children (`2` and `6`).

The root can also be an interior node, even though it has no parent. In this example, `7` is both the root and an interior node.

---

**Why does finding a key require examining at most four nodes?**

This is the connection between the tree's structure and the BST Search algorithm.

Consider searching for `17`:

- `7`

  Comparison 1

  `17 > 7`, so move right.

- `15`

  Comparison 2

  `17 > 15`, so move right.

- `20`

  Comparison 3

  `17 < 20`, so move left.

- `17`

  Comparison 4

  The key matches. Found!

We examine only the nodes along the search path: `7 → 15 → 20 → 17`.

We do not need to examine every node in the tree. At each comparison, the ordering property tells us which subtree can contain the key, allowing us to ignore the other subtree.

The longest path in this particular tree contains four nodes, so a successful search examines at most four nodes. An unsuccessful search can also examine up to four actual nodes before reaching a `null` child reference.

In general, BST search takes O(h)O(h)O(h) time, where hhh is the tree's height. A balanced BST can support search in O(log⁡n)O(\log n)O(logn) time, while a highly skewed BST can take O(n)O(n)O(n) time.

Mental model: A BST is an ordered collection of linked nodes. The root starts the search, child references guide the path, and the ordering property lets us skip entire subtrees.

     30    70
    / \    / \

- Same rule applies to every subtree 

A BST is basically:  **Binary Tree + Ordering Constraint**, This constraint is what makes it powerful.

## Properties
Core Property (Sorted Structure)

If you traverse a BST using Inorder Traversal (Left → Root → Right), you always get: Sorted order

Example:
```
        50
       /  \
     30    70
    / \    / \
  20  40  60  80
```
Inorder → 20, 30, 40, 50, 60, 70, 80

If the tree respects this property, it’s easy to search for a node with a given key/value within the tree(see search operation bellow).

## Basic Operations
### Search
Idea: Compare and move left or right.

Algorithm:
```
if root == NULL → not found
if key == root → found
if key < root → search left
if key > root → search right
```

Pseudocode
```
function find_node(binary_tree, value)
  node ← binary_tree.root_node
  while node:
    if node.value = value
      return node
    if value > node.value
      node ← node.right
    else
      node ← node.left
  return "NOT FOUND"
```
Time Complexity:
- Best / Average: O(log n) 
- Worst (skewed tree): O(n) 

### Insertion
Rule: Insert like search until you find a NULL position.

To insert an item, we search the value we want to insert in the tree.
We take the last node explored in that search, and make its right
or left pointer point to the new node:

Pseudocode
```
function insert_node(binary_tree, new_node)
  node ← binary_tree.root_node
  while node:
    last_node ← node
    if new_node.value > node.value
      node ← node.right
    else
      node ← node.left
  if new_node.value > last_node.value
    last_node.right ← new_node
  else
    last_node.left ← new_node
```
Example:
```
Insert 65:
50 → 70 → 60 → insert as right child
```
Result:
```
        50
       /  \
     30    70
           /
         60
           \
           65

```
### Deletion
When removing a value from the BST, it is critical to maintain the
binary search tree property. 

Three cases:
1. **Case 1**: Leaf node
    - Just remove it.
2. **Case 2**: One child
    - Replace node with its child.
3. **Case 3**: Two children
    - Replace node with:
        - Inorder successor (smallest in right subtree), OR 
        - Inorder predecessor (largest in left subtree) 

Pseudocode
```
function delete_node(binary_tree, value)
  node ← binary_tree.root_node
  parent ← null

  // Find node to delete
  while node ≠ null and node.value ≠ value:
    parent ← node
    if value < node.value
      node ← node.left
    else
      node ← node.right

  if node = null
    return "NOT FOUND"

  // Case 1: Node has no children
  if node.left = null and node.right = null
    if node = parent.left
      parent.left ← null
    else
      parent.right ← null
    delete node
    return

  // Case 2: Node has one child
  if node.left = null or node.right = null
    child ← node.left ? node.left : node.right
    if node = parent.left
      parent.left ← child
    else
      parent.right ← child
    delete node
    return

  // Case 3: Node has two children
  successor ← find_min(node.right)
  value_to_replace ← successor.value
  delete_node(binary_tree, successor.value)
  node.value ← value_to_replace
```
#### Case 1: The target node is a leaf

A leaf has no children.

Before deleting `20`:

```
       30
      /  \
    20    40
```

After deleting `20`:

```
       30
         \
          40
```

Simply remove the reference to the leaf from its parent.

#### Case 2: The target node has one child

If the target has no left child, replace it with its right child.

Before deleting `20`:

```
       30
      /
    20
      \
       25
```

After deleting `20`:

```
       30
      /
    25
```

The parent now points directly to `25`. If the target has a left child but no right child, the symmetric operation replaces it with its left child.

#### Case 3: The target node has two children

if the target node containing the value to be removed
has two children, find the node with the largest value in the tree rooted at the left child. You
can swap that largest value into the target node. Note that the largest value in the
left subtree has no right child, so you can easily remove it by moving up its left
child, should it have one

Consider deleting `50`:

```
          50
         /  \
       30    70
      /  \
    20    40
         /
        35
```

We cannot simply remove `50`, because we must preserve the BST property.

The solution is to find the inorder predecessor: the largest value in the target's left subtree.

Starting at `50`, move left to `30`, then move right as far as possible. The predecessor is `40`.

Replace `50` with `40`:

```
          40
         /  \
       30    70
      /  \
    20    40
         /
        35
```

Now remove the original node containing `40`. Because that node has no right child, it can be replaced by its left child, `35`.

Final tree:

```
          40
         /  \
       30    70
      /  \
    20    35
```

The BST property is preserved.

Here is a step-by-step breakdown of how the operation works:

1. Identifying the Target

    * The node to be deleted is **`50`**, which sits near the top of the tree and possesses both left and right children.
    * Because it has both children, you cannot simply lift up a single child. Instead, you must find a suitable replacement from its left subtree to preserve the binary search tree property.

2. Finding the Largest Left Descendant

    * You navigate to the left child (`30`) and find the node with the **largest value** in that subtree by moving as far right as possible.
    * In this example, that node is **`40`**.

3. Replacing the Value

    * The value of the target node (`50`) is replaced with the largest value found in the left subtree (`40`).

4. Cleaning Up the Descendant Node

    * Because `40` is the largest value in that left subtree, it is guaranteed to have **no right child**.
    * As a result, it can be easily removed by "lifting up" its left child/subtree (`40L`) to take its original place in the tree.

## 2. Why does the largest value in the left subtree have no right child?

Suppose we have:

```
       50
      /
    30
      \
       40
         \
          45
```

The largest value in the left subtree is `45`, not `40`.

More generally, to find the predecessor, start at the left child and keep moving right:

```
def findMax(node):    while node.right is not None:        node = node.right    return node
```

When this loop finishes, the returned node has no right child, because otherwise the loop would continue.

It may have a left child, however. That child must take its place when the predecessor is removed.

For example:

```
       50
      /
    30
      \
       40
      /
     35
```

The predecessor is `40`. Removing the original `40` requires connecting its parent to `35`.

function find_min(node)

function inorder(node)

    return
  inorder(node.left)

```

**Preorder (Root → Left → Right)**

Pseudocode
```
function preorder(node)
  if node = null
    return
  print(node.value)
  preorder(node.left)
  preorder(node.right)
```

**Postorder (Left → Right → Root)**

Pseudocode
```
function postorder(node)
  if node = null
    return
  postorder(node.left)
  postorder(node.right)
  print(node.value)
```
## Tree Balancing
The binary search tree is a very useful data structure, where searching can be significantly faster than searching into a linked list. However in some cases searching into a binary tree can be as slow as searching into a linked list and this mainly depends on the input sequence. Indeed in case the input is sorted the binary tree will seem much like a linked list and the search will be slow. 

If we insert too many nodes in a Binary Search Tree, we end up with a tree of very high height, where many nodes have only one child. For example, if we insert nodes with keys/values always greater than the previous one, we end up with something that looks more like a Linked List. But we can rearrange nodes in a tree such that its height is reduced. This is called tree balancing. A perfectly balanced tree has the minimum possible height.

![The same binary search tree in a very badly balanced form, in a somewhat balanced form, and in a perfectly balanced form.](/docs/assets/software-systems/data-structures-and-algorithms/data-structures/trees/tree-balancing.png)

To overcome this we must change a bit the data structure in order to stay well balanced. It’s intuitively clear that the searching process will be better if the tree is well branched. This is when finding an item will become faster with minimal effort.

Most operations with trees involve following links between nodes until we get to a specific one. The higher the height of the tree, the longer the average path between nodes, and the more times we need to access the memory. Therefore, it’s important to reduce tree height.

In order to balance a tree we can go for the very basic and intuitive approach. First let’s take a look of one non-balanced tree.
```
1
 \
  2                                   4
   \                               /     \
    3                              2      6        
     \                           /  \    /  \
      4                         1    3   5   7
       \
        5
         \
          6
           \
            7
```
Compared to the balanced tree on the right from the image above with the same items we see that the root is approximately equal to its middle item. I.e. 4 is the middle item of the sequence [1,2,3,4,5,6,7]!

If we take a look of the sequence [2 3 4], clearly by building a binary tree it will look like a linked list. However if we choose the middle item for a root – we’ll easy build a balanced tree. So the only thing to do is to get the middle item out of a list.

We now see that building a balanced binary tree out of a sorted linked list isn’t that difficult. In the other hand, as I said above, on each insert we’ll have to rebalance the tree. You can think of the tree out of the values [1,2,3,4,5] and the same tree after inserting [44,45,46,47,48]. Clearly the root of the resulting tree will no longer be 3.

So we need to implement the re-balancing in three basic operations. First we need to build a linked list out of a balanced binary tree. On the second place we’ll have to find the middle item and on the third place we’ll have to build again a balanced search tree.

Hopefully the first two tasks are easy to implement, because making out a sorted list out of a binary search tree is very easy. We need just to walk through the tree from left-root-right recursively. Because smaller items are in the left sub-tree and greater items are on the right we’re sure that the resulting list will be sorted. Then finding the middle item is as easy as finding the middle index of an array know its length.

Building a perfectly balanced binary search tree from a sorted list of nodes can be done as follows:

Pseudocode
```
function build_balanced(nodes)
    if nodes is empty
        return NULL
    middle ← nodes.length/2
    left ← nodes.slice(0, middle - 1)
    right ← nodes.slice(middle + 1, nodes.length)
    balanced ← BinaryTree.new(root=nodes[middle])
    balanced.left ← build_balanced(left)
    balanced.right ← build_balanced(right)
    return balanced
```
Consider a Binary Search Tree with n nodes. Its maximum height
is n, in which case it looks like a Linked List. The minimum height,
with the tree perfectly balanced, is log2 n. The complexity of search-
ing an item in a binary search tree is proportional to its height. In
the worst case, the search must descend to the lowest level, reach-
ing all the way to the tree’s leaves in order to find the item. Search-
ing in a balanced Binary Search Tree with n items is thus O(log n).
That’s why this data structure is often chosen for implementing
Sets (which requires finding if items are already present) and Maps
(which requires finding key-values)

Since we know how to construct a binary search tree the only thing left is to keep it balanced. Obviously we will need to re-balance the tree on each insert and delete, which will make this data structure more difficult to maintain compared to non-balanced search trees, but searching into it will be significantly faster.

However, tree balancing is an expensive operation, as it re-
quires sorting all nodes. Rebalancing a tree after each insertion
or deletion can greatly slow down these operations. Usually, trees
are undergo balancing after several insertions and deletions take
place. But balancing the tree from time to time is only a reasonable
strategy for trees that are rarely changed.

To efficiently handle binary trees that change a lot, self-
balancing binary trees were invented. Their procedures for in-
serting or removing items directly ensure the tree stays balanced.
The Red-Black Tree is a famous example of a self-balancing tree,
which colors nodes either “red” or “black” for its balancing strat-
egy. Red-Black Trees are frequently used to implement Maps: the
map can be heavily edited in an efficient way, and finding any
given key in the map remains fast because of self-balancing.

The AVL Tree is another breed of self-balancing trees. They
require a bit more time to insert and delete items than Red-Black
Trees, but tend to have better balancing. This means they’re faster
than Red-Black Trees for retrieving items. AVL Trees are often used
to optimize performance in read-intensive scenarios.

### Balancing Optimization

Of course the main problem of re-balancing a tree on each insert/delete is that this operations will be slow and soon or later we’ll have problems. That can happen if we change often our data structure. That’s why we should think of some optimization.

Normally we insert and re-balance on each step, which is slow. In the other hand we can do bulk insert forgetting about the re-balancing for a while. Only after the inserts are done we can go for re-balancing the entire tree.

![Doing bulk insert/delete and only one balancing will make the data structure faster!](/docs/assets/software-systems/data-structures-and-algorithms/data-structures/concepts/trees/binary-search-trees/Bulk-Insert-with-Only-one-Balance.png)


The same approach we can use with bulk delete. We can just set to NIL the items we want to delete, but we can keep them in memory for a while. Thus the search will stay relatively fast without rebalancing the tree. However this approach can be used carefully because we’ll keep some data in the memory without actually using it. 

![We can NULL items without actually removing the pointers (links) and the structure of the tree!](/docs/assets/software-systems/data-structures-and-algorithms/data-structures/concepts/trees/binary-search-trees/Bulk-Delete.png)

## Binary Search Tree (BST) vs a Heap
Binary Search Tree (BST) and Heap looks similar (both are binary trees), but behave very differently.

**Core Idea**
- BST → designed for searching 
- Heap → designed for priority access (min/max) 

Think:
- BST = “ordered dictionary” 
- Heap = “priority queue”

**Structural Difference**
| Feature | BST                                  | Heap                       |
| ------- | ------------------------------------ | -------------------------- |
| Shape   | Any shape (not necessarily complete) | **Complete binary tree**   |
| Balance | Can become skewed                    | Always balanced (by shape) |

**Ordering Rule**

**BST Rule**:
```
Left < Root < Right
```
Full ordering across the tree

**Heap Rule**:

Max Heap:
```
Parent ≥ Children
```
Min Heap:
```
Parent ≤ Children
```
Only local ordering, NOT global

**Example**
BST
```
        50
       /  \
     30    70
    / \    / \
  20  40  60  80
```
Fully sorted structure

Max Heap
```
        80
       /  \
     70    60
    / \    /
  20  50  40
```
Only parent is greater—not globally sorted

A Heap is NOT sorted, Example:
```
Heap array: [10, 20, 15, 30, 40]
```
- 10 is smallest (min heap)
- BUT 20 and 15 are not sorted relative to each other

**Traversal Behavior**
| Traversal   | BST         | Heap                     |
| ----------- | ----------- | ------------------------ |
| Inorder     | Sorted    | Not sorted             |
| Level Order | Not special | Natural representation |

**Time Complexity**
| Operation        | BST (avg) | Heap     |
| ---------------- | --------- | -------- |
| Search arbitrary | O(log n)  | **O(n)**   |
| Insert           | O(log n)  | O(log n) |
| Delete           | O(log n)  | O(log n) |
| Find Min/Max     | O(log n)  | **O(1)**   |

- Heap wins for min/max
- BST wins for search

**Implementation Difference**

BST
- Usually **pointer-based (linked nodes)** 
- Dynamic structure 

Heap
- Usually **array-based**

**Key Operations**

BST
- Search(key) 
- Insert(key) 
- Delete(key) 
- Traversals 

Heap
- Insert (heapify up) 
- Extract Min/Max (heapify down) 
- Peek (get root)

**Use Cases**

BST Used For:
- Fast lookup (like maps/sets) 
- Ordered data 
- Range queries 

Heap Used For:
- Priority Queue 
- Scheduling (OS, tasks) 
- Algorithms: 
    - Dijkstra 
    - Prim 
    - Heapsort

**Degeneration vs Stability**
| Issue                | BST   | Heap |
| -------------------- | ----- | ---- |
| Can degrade to O(n)? | ✅ Yes | ❌ No |
| Needs balancing?     | ✅ Yes | ❌ No |

**Summary**

BST
- Global ordering 
- Fast search 
- Can degrade 

Heap
- Partial ordering 
- Fast min/max 
- Always balanced (shape)

**Analogy**
- BST = Sorted phonebook → fast lookup by name 
- Heap = Urgent tasks list → always pick highest priority

**BST vs Heap in C implementation**

this comparison focus on insertion and extracting/searching, which are the core operations, so you can see the structural and behavioral differences clearly.

1️⃣ Node / Structure Definition
BST Node (Pointer-based)
```c
#include <stdio.h>
#include <stdlib.h>

typedef struct BSTNode {
    int key;
    struct BSTNode* left;
    struct BSTNode* right;
} BSTNode;

BSTNode* createBSTNode(int key) {
    BSTNode* node = (BSTNode*)malloc(sizeof(BSTNode));
    node->key = key;
    node->left = node->right = NULL;
    return node;
}
```
Heap (Array-based)
```c
#define MAX 100

typedef struct Heap {
    int size;
    int arr[MAX];
} Heap;

Heap* createHeap() {
    Heap* h = (Heap*)malloc(sizeof(Heap));
    h->size = 0;
    return h;
}
```
2️⃣ Insertion
BST Insertion (Recursive, maintains ordering)
```c
BSTNode* insertBST(BSTNode* root, int key) {
    if (root == NULL) return createBSTNode(key);

    if (key < root->key)
        root->left = insertBST(root->left, key);
    else if (key > root->key)
        root->right = insertBST(root->right, key);
    
    return root;
}
```
Heap Insertion (Max Heap, array-based)
```c
void swap(int* a, int* b) {
    int tmp = *a; *a = *b; *b = tmp;
}

void insertHeap(Heap* h, int key) {
    if (h->size >= MAX) return;
    int i = h->size++;
    h->arr[i] = key;

    // Heapify Up
    while (i != 0 && h->arr[i] > h->arr[(i-1)/2]) {
        swap(&h->arr[i], &h->arr[(i-1)/2]);
        i = (i-1)/2;
    }
}
```
3️⃣ Searching / Extracting

BST Search (O(log n) on average)
```x
BSTNode* searchBST(BSTNode* root, int key) {
    if (root == NULL || root->key == key) return root;
    if (key < root->key) return searchBST(root->left, key);
    return searchBST(root->right, key);
}
```
Heap Extract Max (O(log n))
```c
int extractMax(Heap* h) {
    if (h->size <= 0) return -1;
    int root = h->arr[0];
    h->arr[0] = h->arr[--h->size];

    // Heapify Down
    int i = 0;
    while (2*i + 1 < h->size) {
        int left = 2*i + 1;
        int right = 2*i + 2;
        int largest = i;

        if (left < h->size && h->arr[left] > h->arr[largest]) largest = left;
        if (right < h->size && h->arr[right] > h->arr[largest]) largest = right;
        if (largest == i) break;
        swap(&h->arr[i], &h->arr[largest]);
        i = largest;
    }
    return root;
}
```
4️⃣ Traversal / Print

BST Inorder Traversal (gives sorted order)
```c
void inorderBST(BSTNode* root) {
    if (!root) return;
    inorderBST(root->left);
    printf("%d ", root->key);
    inorderBST(root->right);
}
```
Heap Print (level-order representation)
```c
void printHeap(Heap* h) {
    for(int i=0; i<h->size; i++) printf("%d ", h->arr[i]);
    printf("\n");
}
```
5️⃣ Example Usage
```c
int main() {
    // BST
    BSTNode* root = NULL;
    root = insertBST(root, 50);
    insertBST(root, 30);
    insertBST(root, 70);
    insertBST(root, 20);
    insertBST(root, 40);
    printf("BST Inorder: ");
    inorderBST(root);  // 20 30 40 50 70
    printf("\n");

    // Heap
    Heap* h = createHeap();
    insertHeap(h, 50);
    insertHeap(h, 30);
    insertHeap(h, 70);
    insertHeap(h, 20);
    insertHeap(h, 40);
    printf("Heap Array: ");
    printHeap(h);  // 70 40 50 20 30 (Max Heap)
    printf("\n");
    
    printf("Extract Max from Heap: %d\n", extractMax(h)); // 70
    printHeap(h);  // Heap restructured
}
```
Key Observations from Side-by-Side:
| Feature   | BST                          | Heap                           |
| --------- | ---------------------------- | ------------------------------ |
| Structure | Pointer-based                | Array-based                    |
| Ordering  | Global (inorder = sorted)    | Local (parent ≥ children)      |
| Search    | O(log n)                     | O(n) for arbitrary element     |
| Insert    | O(log n) avg                 | O(log n)                       |
| Extract   | Delete node requires 3 cases | Always root (max/min) O(log n) |
| Traversal | Sorted output                | Level-order (not sorted)       |

## Variations
One natural extension for a binary tree is an n-way tree, where each node has more
than one value, and correspondingly, more than two children. 

### B-Trees
A common version
of such trees is called the B-Tree, which performs very well when implementing
relational databases.

A B-Tree is a self-balancing search tree in which each node can contain multiple sorted keys and have multiple children.

Unlike a binary tree, which has at most two children per node, a B-Tree can have many children.

**Example**

Consider this simplified B-Tree:

```
                 [30 | 60]
                /    |    \
               /     |     \
        [10 | 20] [40 | 50] [70 | 80 | 90]
```

The root contains two keys: `30` and `60`. These keys divide the values into three ranges:

- Left child: values less than `30`.
- Middle child: values between `30` and `60`.
- Right child: values greater than `60`.

Each node can store multiple keys in sorted order.

Imagine a database containing millions of records. A binary tree might require many node visits to reach a record. A B-Tree reduces the number of levels by storing multiple keys in each node.

### Red–Black Trees
Another common self-balancing binary tree is the red–black tree. 

A Red–Black Tree is a binary search tree that maintains balance using a color—red or black—assigned to each node.

It is not necessarily as tightly balanced as an AVL tree, but it guarantees logarithmic height.
```
              20(B)
             /     \
          10(R)    30(R)
          /  \     /  \
         NIL NIL  NIL NIL
```

`B` means black, `R` means red, and `NIL` represents a missing child, treated as a black leaf for the balancing rules.

Red–black trees
are approximately balanced and guarantee that no branch has a height more than
twice that of any other branch in the tree. 

This relaxed guarantee improves the performance of insert and delete by reducing the number of rotations needed. We pro‐
vide an implementation in the algs.model.tree.BalancedTree class found in the
repository. Further details can be found in (Cormen et al., 2009).

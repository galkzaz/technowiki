Modern performance often depends on CPU cache behavior, not algorithmic complexity.

#### Evolution of data structures from RAM model to cache-oblivious model
Evolution of Data Structures: RAM → Cache-Aware → Cache-Oblivious

Algorithms were originally designed using the RAM model.

1. **Stage 1 — RAM Model (Classical Algorithm Theory)**

Assumption:
- Memory is uniform
- Every access costs O(1)

This model ignores hardware details like caches. Typical structures designed under this assumption:
| Structure          | Idea                 |
| ------------------ | -------------------- |
| Array              | Direct indexing      |
| Linked List        | Pointer traversal    |
| Binary Search Tree | Logarithmic search   |
| Heap               | Tree stored in array |
| Hash Table         | Constant-time lookup |

Example:

Binary search complexity: O(log n)

RAM model assumes every access is equal cost. But real computers do not behave this way.

**The Memory Hierarchy Problem**
Modern computers have layers of memory:
| Level         | Speed     | Size   |
| ------------- | --------- | ------ |
| CPU Registers | fastest   | tiny   |
| L1 Cache      | very fast | small  |
| L2/L3 Cache   | fast      | medium |
| RAM           | slower    | large  |
| Disk / SSD    | very slow | huge   |

Accessing RAM may be 100× slower than accessing cache.
Thus algorithm designers realized:
Memory locality matters more than raw Big-O.

2. **Cache-Aware Model**

In this model algorithms know:
- **B** = block size (cache line)
- **M** = cache size

Goal:
Minimize cache misses.

**Example: B-Tree**

Binary search trees cause many cache misses because nodes are scattered.

Solution:
Use wide nodes that match disk or cache blocks.
Structure used heavily in databases: B-tree

Properties:
- Each node stores many keys
- Tree height becomes very small
- Each access loads many keys at once

Search complexity: O(log_B n), instead of O(log n)

This drastically reduces memory transfers.

**Example: Cache-Aware Matrix Algorithms**

Matrix multiplication reordered to access rows sequentially.

Instead of: O(n³) memory accesses, you reduce cache misses using blocking.

3. **Cache-Oblivious Model**

Next evolution: algorithms that automatically exploit caches without knowing B or M.

Key idea:
Recursion naturally matches multiple cache levels.

This model was introduced by researchers including Erik Demaine.

**Example: Cache-Oblivious Search Tree**

Instead of fixed node sizes, the tree is recursively laid out in memory.

Benefits:
- works well for all cache levels
- no tuning for hardware

Examples:
- van Emde Boas layout
- cache-oblivious B-trees

**Example: Cache-Oblivious Matrix Multiplication**

Divide matrix recursively:
```python
A = [A11 A12
     A21 A22]
```
Recursive multiplication naturally keeps submatrices in cache.

**Summary of the Evolution**
| Model           | Assumption               | Optimization Goal     |
| --------------- | ------------------------ | --------------------- |
| RAM model       | Uniform memory           | Minimize operations   |
| Cache-aware     | Known cache parameters   | Minimize cache misses |
| Cache-oblivious | Unknown cache parameters | Recursive locality    |

This shift happened because hardware became the main performance bottleneck.

#### Cache-Aware Structures

These store elements contiguously in memory.
Examples:
- arrays
- dynamic arrays
- binary heaps
- B-trees

Memory layout:
```
[5][9][12][20][33][40]
```
Advantages:
- sequential memory access
- fewer cache misses
- hardware prefetch works well

#### Pointer-Based Structures
These use nodes connected with pointers.
Examples:
- linked lists
- binary trees
- hash chains

Memory layout:
```
[5] -> [9] -> [12] -> [20]
```
Nodes may be scattered across memory.

Problems:
- cache misses
- pointer chasing
- poor branch prediction

**Example Comparison**

**Binary Heap (Array)**
```
Index: 0 1 2 3 4 5
Heap: [2,4,6,9,8,7]
```
Parent/child relations use indices.

Benefits:
- contiguous memory
- excellent cache performance

**Pointer-Based Heap**
```
       2
      / \
     4   6
    / \ /
   9  8 7
```
But nodes scattered in memory.

More cache misses.

**Why This Matters**

Two algorithms both O(log n) can differ by 10× performance due to cache locality.

This is why modern systems prefer:
- arrays
- flat hash tables
- B-trees instead of binary trees

| Model         | Memory Behavior       | Typical Structures      |
| ------------- | --------------------- | ----------------------- |
| Imperative    | Mutable, in-place     | ArrayList, HashMap      |
| Functional    | Immutable, persistent | Functional lists, trees |
| Cache-aware   | Contiguous memory     | Arrays, heaps, B-trees  |
| Pointer-based | Linked nodes          | Linked lists, trees     |

#### Imperative vs Functional ADT Models
The key difference is state mutation.
| Aspect            | Imperative ADT              | Functional ADT                    |
| ----------------- | --------------------------- | --------------------------------- |
| State             | Mutable                     | Immutable                         |
| Operation effect  | Modifies existing structure | Returns a new structure           |
| Memory usage      | Usually minimal             | Uses structural sharing           |
| Concurrency       | Requires locks              | Naturally thread-safe             |
| Reasoning         | Harder (state changes)      | Easier (referential transparency) |
| Typical languages | C, Java, Python             | Haskell, OCaml, Scala             |

Example: Stack

**Imperative Stack**
```
stack = []

stack.append(10)   # push
stack.append(20)
stack.pop()        # modifies stack
```
State changes:
```
[] → [10] → [10,20] → [10]
```
The same structure is modified.

**Functional Stack**
```
push(S, x) = Node(x, S)
pop(Node(x, S)) = S
```
Each operation returns a new stack.

Example:
```
S0 = []
S1 = push(S0, 10)
S2 = push(S1, 20)
```
Memory structure:
```
S2 -> 20 -> 10 -> null
S1 -> 10 -> null
S0 -> null
```
Notice: nodes are shared.
#### Persistent (Immutable) Data Structures

A persistent data structure keeps all previous versions available.

Two types exist:
| Type                | Meaning                      |
| ------------------- | ---------------------------- |
| Partial persistence | Old versions readable        |
| Full persistence    | Old versions can be modified |

Persistent structures rely on structural sharing.

**Persistent Stack Example**
```
S0 = []
S1 = push(S0, 10)
S2 = push(S1, 20)
```
Memory:
```
S2
 |
 v
[20] → [10] → null
S1
 |
 v
[10] → null
```
Only one new node was allocated.

Cost:
- push = O(1)
- pop = O(1)

**Persistent Tree Example**

Binary search tree insertion creates new nodes along the path.

Old tree
```
     10
    /  \
   5   20
```
Insert 7:

New tree
```
     10'
    /   \
   5'   20
    \
     7
```
Nodes not affected are shared.

Advantages
- Version history
- Safe concurrency
- Easy undo/redo
- Deterministic debugging

Where They Are Used
- functional programming
- compilers
- distributed systems
- transactional memory

**Barriers** is synchronization mechanism intended for groups of processes rather than two-process producer-consumer type situations.

Unlike semaphores/monitors (which handle mutual exclusion or producer–consumer),
a **barrier coordinates phases of execution across many processes**.

**Barrier Synchronization** is a mechanism commonly used in parallel computing.

Some applications are divided into phases and have the rule that no process may proceed into the next phase
until all processes are ready to proceed to the next phase. This behavior may be
achieved by placing a barrier at the end of each phase. When a process reaches
the barrier, it is blocked until all processes have reached the barrier. This allows
groups of processes to synchronize.

``` title="Use of a barrier. (a) Processes approaching a barrier. (b) All processes but one blocked at the barrier. (c) When the last process arrives at the barrier, all of them are let through"
(a) Arriving            (b) Waiting             (c) Released
       
   A ...... |                   A..|                     | A
      B.... |       Time       B...|       Time          | B
   C .......|      ----->    C ....|      ----->         | C
      D.....|                  D   |                     | D
            |                      |                     |
      Barrier              Barrier               Barrier
```
In Fig. (a) we see four processes approaching a barrier. What this means is
that they are just computing and have not reached the end of the current phase yet.
After a while, the first process finishes all the computing required of it during the
first phase. It then executes the barrier primitive, generally by calling a library procedure. The process is then suspended. A little later, a second and then a third
process finish the first phase and also execute the barrier primitive. This situation is
illustrated in Fig. (b). Finally, when the last process, C, hits the barrier, all the
processes are released, as shown in Fig. (c).

Visualization
```
Phase 1:
P1 ──►
P2 ───────►
P3 ─►
P4 ─────────────►

                [ BARRIER ]

All must arrive before ANY continue

Phase 2:
P1, P2, P3, P4 proceed together
```
Core Idea of a Barrier: “No one moves forward until everyone arrives”

Barrier does NOT protect data, Barrier controls TIME (execution order)

**How Barrier Works**

Each process does:
```
compute_phase();
barrier();   // wait here
compute_next_phase();
```
Behavior
```
If a process reaches barrier early:
    → it BLOCKS

When last process arrives:
    → ALL are released
```

**Key Properties**
- Collective (involves ALL processes)
- Reusable (can be used every phase)
- Blocking
- No data transfer (only synchronization)
## Implementation
We use:
- `count` = number of arrived processes
- `N`     = total processes

Pseudocode
```
barrier() {
    lock(mutex);
    count++;

    if (count == N) {
        wake up all waiting processes;
        count = 0;  // for reuse
    } else {
        sleep();    // wait
    }

    unlock(mutex);
}
```

### sense-reversing barrier using pthread
This is a sense-reversing barrier (used in real systems).

Key idea
- `count` → how many threads have arrived 
- `tripCount` → total threads 
- `sense` → flips each round to avoid mixing phases

**Full Barrier Implementation**
```c
#include <pthread.h>

typedef struct {
    pthread_mutex_t mutex;
    pthread_cond_t cond;
    int count;
    int tripCount;
    int sense;
} barrier_t;

void barrier_init(barrier_t *barrier, int num_threads) {
    barrier->count = 0;
    barrier->tripCount = num_threads;
    barrier->sense = 0;
    pthread_mutex_init(&barrier->mutex, NULL);
    pthread_cond_init(&barrier->cond, NULL);
}

void barrier_wait(barrier_t *barrier) {
    pthread_mutex_lock(&barrier->mutex);

    int local_sense = barrier->sense;

    barrier->count++;

    if (barrier->count == barrier->tripCount) {
        // Last thread arrives
        barrier->count = 0;
        barrier->sense = !barrier->sense;  // flip phase
        pthread_cond_broadcast(&barrier->cond);
    } else {
        // Wait until sense changes
        while (local_sense == barrier->sense) {
            pthread_cond_wait(&barrier->cond, &barrier->mutex);
        }
    }

    pthread_mutex_unlock(&barrier->mutex);
}
```
**Parallel Matrix Relaxation Example**

We simulate:
```
T_new[i][j] = average of neighbors
```
Program Features
-Matrix split by rows across threads 
-Two matrices: T_old, T_new 
-Barrier used twice per iteration 

**Full Working Example**

```c
#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>

#define N 8               // matrix size (small for demo)
#define NUM_THREADS 4
#define ITERATIONS 5

double T_old[N][N];
double T_new[N][N];

typedef struct {
    pthread_mutex_t mutex;
    pthread_cond_t cond;
    int count;
    int tripCount;
    int sense;
} barrier_t;

barrier_t barrier;

/* Barrier functions (same as above) */
void barrier_init(barrier_t *barrier, int num_threads) {
    barrier->count = 0;
    barrier->tripCount = num_threads;
    barrier->sense = 0;
    pthread_mutex_init(&barrier->mutex, NULL);
    pthread_cond_init(&barrier->cond, NULL);
}

void barrier_wait(barrier_t *barrier) {
    pthread_mutex_lock(&barrier->mutex);

    int local_sense = barrier->sense;
    barrier->count++;

    if (barrier->count == barrier->tripCount) {
        barrier->count = 0;
        barrier->sense = !barrier->sense;
        pthread_cond_broadcast(&barrier->cond);
    } else {
        while (local_sense == barrier->sense) {
            pthread_cond_wait(&barrier->cond, &barrier->mutex);
        }
    }

    pthread_mutex_unlock(&barrier->mutex);
}

/* Thread worker */
void *worker(void *arg) {
    int id = *(int *)arg;

    int rows_per_thread = N / NUM_THREADS;
    int start = id * rows_per_thread;
    int end = start + rows_per_thread;

    for (int iter = 0; iter < ITERATIONS; iter++) {

        // Compute new values
        for (int i = start; i < end; i++) {
            for (int j = 1; j < N - 1; j++) {
                if (i > 0 && i < N - 1) {
                    T_new[i][j] = (
                        T_old[i-1][j] +
                        T_old[i+1][j] +
                        T_old[i][j-1] +
                        T_old[i][j+1]
                    ) / 4.0;
                }
            }
        }

        // Barrier 1: ensure all threads finished computation
        barrier_wait(&barrier);

        // Swap rows (only responsible threads)
        for (int i = start; i < end; i++) {
            for (int j = 1; j < N - 1; j++) {
                T_old[i][j] = T_new[i][j];
            }
        }

        // Barrier 2: ensure all swaps are done
        barrier_wait(&barrier);
    }

    return NULL;
}

/* Initialize matrix */
void init_matrix() {
    for (int i = 0; i < N; i++) {
        for (int j = 0; j < N; j++) {
            T_old[i][j] = 0.0;
        }
    }

    // Heat source at corner
    T_old[0][0] = 100.0;
}

/* Print matrix */
void print_matrix() {
    for (int i = 0; i < N; i++) {
        for (int j = 0; j < N; j++) {
            printf("%6.2f ", T_old[i][j]);
        }
        printf("\n");
    }
    printf("\n");
}

int main() {
    pthread_t threads[NUM_THREADS];
    int ids[NUM_THREADS];

    barrier_init(&barrier, NUM_THREADS);

    init_matrix();

    for (int i = 0; i < NUM_THREADS; i++) {
        ids[i] = i;
        pthread_create(&threads[i], NULL, worker, &ids[i]);
    }

    for (int i = 0; i < NUM_THREADS; i++) {
        pthread_join(threads[i], NULL);
    }

    print_matrix();

    return 0;
}
```
- Threads run independently
- Synchronization only at barriers
- Correct iteration-by-iteration update
- No race conditions on data

### Sense-Reversing Spin Barrier (Lock-Free)
This is high-performance synchronization — exactly what’s used in kernels, HPC, and low-latency systems.

Instead of: pthread barrier → thread sleeps (context switch)

We use: spin barrier → thread busy-waits (no sleep)

**Key Idea**
- Threads DO NOT block
- They keep checking a shared variable until barrier opens

It Is  Faster because:
- Short wait time  → spin is faster
- Long wait time  → wastes CPU

Data Structure
```c
#include <stdatomic.h>

typedef struct {
    atomic_int count;
    atomic_int sense;
    int tripCount;
} spin_barrier_t;
```
Initialization
```c
void spin_barrier_init(spin_barrier_t *b, int n) {
    atomic_store(&b->count, 0);
    atomic_store(&b->sense, 0);
    b->tripCount = n;
}
Barrier Wait (Core Logic)
void spin_barrier_wait(spin_barrier_t *b, int *local_sense) {
    *local_sense = !(*local_sense);

    if (atomic_fetch_add(&b->count, 1) == b->tripCount - 1) {
        // Last thread arrives
        atomic_store(&b->count, 0);
        atomic_store(&b->sense, *local_sense);
    } else {
        // Spin-wait
        while (atomic_load(&b->sense) != *local_sense) {
            ; // busy wait
        }
    }
}
```
Why “Sense Reversing”? Without it: Threads from next iteration mix with previous ❌

With sense:
- Iteration 1 → sense = 1
- Iteration 2 → sense = 0
- Iteration 3 → sense = 1

Each thread tracks its own local sense.

**Full Example with Threads**
```c
#include <stdio.h>
#include <pthread.h>
#include <stdatomic.h>

#define NUM_THREADS 4
#define ITERATIONS 5

typedef struct {
    atomic_int count;
    atomic_int sense;
    int tripCount;
} spin_barrier_t;

spin_barrier_t barrier;

void spin_barrier_init(spin_barrier_t *b, int n) {
    atomic_store(&b->count, 0);
    atomic_store(&b->sense, 0);
    b->tripCount = n;
}

void spin_barrier_wait(spin_barrier_t *b, int *local_sense) {
    *local_sense = !(*local_sense);

    if (atomic_fetch_add(&b->count, 1) == b->tripCount - 1) {
        atomic_store(&b->count, 0);
        atomic_store(&b->sense, *local_sense);
    } else {
        while (atomic_load(&b->sense) != *local_sense) {
            // spin
        }
    }
}

void *worker(void *arg) {
    int id = *(int *)arg;
    int local_sense = 0;

    for (int i = 0; i < ITERATIONS; i++) {
        printf("Thread %d working in iteration %d\n", id, i);

        spin_barrier_wait(&barrier, &local_sense);

        printf("Thread %d passed barrier %d\n", id, i);
    }

    return NULL;
}

int main() {
    pthread_t threads[NUM_THREADS];
    int ids[NUM_THREADS];

    spin_barrier_init(&barrier, NUM_THREADS);

    for (int i = 0; i < NUM_THREADS; i++) {
        ids[i] = i;
        pthread_create(&threads[i], NULL, worker, &ids[i]);
    }

    for (int i = 0; i < NUM_THREADS; i++) {
        pthread_join(threads[i], NULL);
    }

    return 0;
}
```
## Barrier vs Other Mechanisms
Mechanism     | Purpose
--------------|------------------------------
Semaphore     | control access (counting)
Monitor       | mutual exclusion + conditions
Message pass  | communication
Barrier       | phase synchronization (group)


**Barrier vs Rendezvous**
- Rendezvous: 2 processes meet
- Barrier: N processes meet

**Barrier vs Producer–Consumer**
- Producer–Consumer: asynchronous (decoupled)
- Barrier: synchronous (lockstep)

As an example of a problem requiring barriers, consider a common relaxation
problem in physics or engineering. 

There is typically a matrix that contains some nitial values. The values might represent temperatures at various points on a sheet of metal. The idea might be to calculate how long it takes for the effect of a flame
placed at one corner to propagate throughout the sheet.

You have a huge matrix:

Temperature grid (metal sheet)
```
T[i][j] = temperature at point (i, j)
```
At each time step:
```
New temperature = function of neighbors
```
Example (simplified physics):
```
T_new[i][j] = (T[i-1][j] + T[i+1][j] + T[i][j-1] + T[i][j+1]) / 4
```
This is called a **relaxation method** (or iterative update).

1. Starting with the current values, a transformation is applied to the matrix to get the second version of the matrix, for example, by applying the laws of thermodynamics to see what all the temperatures are 6T later. 
2. Then the process is repeated over and over, 
3. giving the temperatures at the sample points as a function of time as the sheet heats up. The algorithm produces a sequence of matrices over time, each one for a given point in time.

Now imagine that the matrix is very large (for example, 1 million by 1 million), so that parallel processes are needed (possibly on a multiprocessor) to speed
up the calculation. 
1. Different processes work on different parts of the matrix, calculating the new matrix elements from the old ones according to the laws of physics.
2. However, no process may start on iteration` n + 1` until iteration `n` is complete, that is, until all processes have finished their current work. 
3. The way to achieve this goal is to program each process to execute a barrier operation after it has finished its part of the current iteration.
4. When all of them are done, the new matrix (the input to the next iteration) will be finished, and all processes will be simultaneously released to start the next iteration.

Sequential View
```
Iteration 0 → Initial matrix
Iteration 1 → Compute all new values
Iteration 2 → Compute again
Iteration 3 → ...
```
Each iteration depends on the previous one ONLY.

**Parallelism**

as Matrix size: 1,000,000 × 1,000,000 ❗

Too big → split work across processes:

- Process 1 → top-left block
- Process 2 → top-right block
- Process 3 → bottom-left block
- Process 4 → bottom-right block

Each process computes: its part of `T_new` using `T_old`, BUT: No process can start iteration `n+1` until ALL processes finish iteration `n`.

This Constraint Exists, Because: `T_new` depends ONLY on `T_old`, If one process starts early It may read:
- some OLD values
- some NEW values

This breaks correctness (physics laws violated ❌)

After finishing its portion:
```
compute_my_chunk();
barrier();   // 🔴 synchronization point
```
Timeline
```
Iteration n:

P1: compute ─────── wait ───►
P2: compute ─── wait ───────►
P3: compute ───────── wait ─►
P4: compute ───────────────► (last)

            [ BARRIER ]

All released → Iteration n+1 starts
```

**Full Parallel Algorithm**

Step-by-step
```
for (t = 0; t < MAX_ITER; t++) {

    // 1. Compute next state
    for (all cells in my partition) {
        T_new[i][j] = f(T_old neighbors);
    }

    // 2. Synchronize ALL processes
    barrier();

    // 3. Swap matrices
    swap(T_old, T_new);

    // 4. Synchronize again (important!)
    barrier();
}
```
First Barrier Ensure: ALL T_new values are computed

Second Barrier Ensure: ALL processes finished swapping before next iteration starts

Without second barrier:
- Process A swaps early
- Process B still using old data ❌

Barrier enforces CONSISTENT TIME STEPS, Without it: You get:
- inconsistent simulation ❌
- wrong physics ❌

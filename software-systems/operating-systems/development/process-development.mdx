## Process layout

## Process memory layout
```
linux/
├── include/
│   ├── linux/
│   │   ├── sched.h           ← task_struct
│   │   ├── mm_types.h        ← mm_struct + vm_area_struct
│   │   └── ...
│   └── ...
├── mm/                       ← memory management implementation code
│   ├── mmap.c                ← mmap/munmap syscalls
│   ├── mmu_context.c         ← page table switching
│   └── ...
├── arch/...
```
The mm/ directory is where most of the MM subsystem implementation lives.
### mm_struct

Definition of the main memory descriptor (process address space) in the Linux kernel source.

This is the memory descriptor that defines a process's virtual address space — it holds pointers to the page tables, the list of VMAs, and fields tracking start/end of text, data, heap, stack, etc.

https://github.com/torvalds/linux/blob/master/include/linux/mm_types.h#L1075

### task_struct
This shows the task structure that contains a pointer to the mm_struct.

Every thread/task in Linux references its address space via:
```c
struct task_struct {
    //...
    struct mm_struct *mm;       /* memory descriptor */
    struct mm_struct *active_mm;/* used during context switch */
}
```

This is how the scheduler and memory subsystem tie a running task to the memory layout it sees. 

https://github.com/torvalds/linux/blob/master/include/linux/sched.h#L819
### vm_area_struct
Represents individual mapped regions (code, stack, heap, files) within a process's address space. and is connected from mm_struct.

VMAs are the elements linked from mm_struct->mmap to define each memory region.

https://github.com/torvalds/linux/blob/master/include/linux/mm_types.h#L904

## System calls
This table shows the entire lifecycle of a UNIX process:
* Creation → fork, vfork, clone
* Program loading → exec*
* Identity & permissions → getuid, setuid, groups
* Scheduling & control → nice, sched_yield
* Signals → kill
* Termination & cleanup → exit, _exit, wait*

| Call method | Description | Parameters | Return value |
| --- | --- | --- | --- |
| fork() | Create a new process by duplicating the calling process | _void_ | **pid_t** Child PID in parent, `0` in child, `-1` on error |
| vfork() | Create a child process sharing address space until `exec()` or `exit()` | _void_ | **pid_t** Child PID in parent, `0` in child, `-1` on error |
| clone() | Create a process or thread with fine-grained control over shared resources | `int (**fn)(void *)`, `void *child_stack`, `int flags`, `void *arg`, ... | *pid_t** PID of child on success, `-1` on error |
| execve() | Replace current process image with a new program | `const char **pathname`, `char *const argv[]`, `char *const envp[]` | *int** Does not return on success, `-1` on error |
| execv() | Execute a program with argument vector | `const char **path`, `char *const argv[]` | *int** Does not return on success, `-1` on error |
| execvp() | Execute a program, searching `PATH` | `const char **file`, `char *const argv[]` | *int** Does not return on success, `-1` on error |
| _exit() | Terminate process immediately (no stdio cleanup) | `int status` | _void_ Does not return |
| exit() | Terminate process after flushing stdio buffers | `int status` | _void_ Does not return |
| wait() | Wait for any child process to terminate | `int **wstatus` | *pid_t** PID of terminated child, `-1` on error |
| waitpid() | Wait for a specific child process | `pid_t pid`, `int **wstatus`, `int options` | *pid_t** PID of child, `0` or `-1` depending on options |
| waitid() | Wait for process state changes with detailed info | `idtype_t idtype`, `id_t id`, `siginfo_t **infop`, `int options` | *int** `0` on success, `-1` on error |
| getpid() | Get calling process ID | _void_ | **pid_t** Caller PID |
| getppid() | Get parent process ID | _void_ | **pid_t** Parent PID |
| getuid() | Get real user ID of process | _void_ | **uid_t** Real UID |
| geteuid() | Get effective user ID | _void_ | **uid_t** Effective UID |
| getgid() | Get real group ID of process | _void_ | **gid_t** Real GID |
| getegid() | Get effective group ID | _void_ | **gid_t** Effective GID |
| setuid() | Set process user identity | `uid_t uid` | **int** `0` on success, `-1` on error |
| setgid() | Set process group identity | `gid_t gid` | **int** `0` on success, `-1` on error |
| setsid() | Create a new session and detach from terminal | _void_ | **pid_t** Session ID, `-1` on error |
| getsid() | Get session ID of a process | `pid_t pid` | **pid_t** Session ID |
| setpgid() | Set process group ID | `pid_t pid`, `pid_t pgid` | **int** `0` on success, `-1` on error |
| getpgid() | Get process group ID | `pid_t pid` | **pid_t** Process group ID |
| nice() | Change process scheduling priority | `int inc` | **int** New nice value, `-1` on error |
| sched_yield() | Yield CPU voluntarily | _void_ | **int** `0` on success |
| kill() | Send a signal to a process or group | `pid_t pid`, `int sig` | **int** `0` on success, `-1` on error |

## System Call Details

### fork()
Fork is the only way to create a new process in
POSIX. It creates an exact duplicate of the original process, including all the file descriptors, registers—everything. After the fork, the original process and the copy
(the parent and child) go their separate ways. All the variables have identical val-
ues at the time of the fork, but since the parent's data are copied to create the child,
subsequent changes in one of them do not affect the other one

The parent and child are almost identical:

| What is copied?	 | Meaning |
| --- | --- |
| Memory image	 | Same code + data |
| Environment variables	 | PATH, HOME, etc. |
| Open files	 | Same files, same positions |

the memory
of the child may be shared copy-on-write with the parent. This means that parent
and child share a single physical copy of the memory until one of the two modifies
a value at a location in memory—in which case the operating system makes a copy
of the small chunk of memory containing that location. Doing so minimizes the
amount of memory that needs to be copied a priori, as much can remain shared.
Moreover, part of the memory, for instance, the program text does not change at, so
it can always be shared between parent and child. The fork call returns a value,
which is zero in the child and equal to the child's PID (Process IDentifier) in the
parent. Using the returned PID, the two processes can see which one is the parent
process and which one is the child process. Moreover, part of the memory, for instance, the program text does not change at, so
it can always be shared between parent and child.

The fork call returns a value,
which is zero in the child and equal to the child's PID (Process IDentifier) in the
parent. Using the returned PID, the two processes can see which one is the parent
process and which one is the child process.

In most cases, after a fork, the child will need to execute different code from
the parent. Consider the case of the shell. It reads a command from the terminal,
forks off a child process, waits for the child to execute the command, and then
reads the next command when the child terminates. To wait for the child to finish,
the parent executes a waitpid system call, which just waits until the child terminates
(any child if more than one exists). Waitpid can wait for a specific child, or for any
old child by setting the first parameter to &lt;1. When waitpid completes, the address
pointed to by the second parameter, statloc, will be set to the child process' exit
status (normal or abnormal termination and exit value). Various options are also
provided, specified by the third parameter. For example, returning immediately if
no child has already exited.

#### What it does
Creates a new process by duplicating the calling process.
The child initially shares memory pages via copy-on-write.

Think of it like: Making a photocopy of a running program

After fork() You have two processes, Parent (original), Child (copy)

#### Why it matters
This is the classic UNIX process creation primitive.
Shells, servers, and supervisors rely on it.

#### Syscall or libc wrapper?
**glibc wrapper**  
Implemented using the `clone()` syscall with fixed flags.

#### Kernel source paths
* Entry: `sys_clone`
* Files:
  * `kernel/fork.c`
  * `include/linux/sched/task.h`

#### glibc source paths
* `posix/fork.c`
* `sysdeps/unix/sysv/linux/fork.c`
* `sysdeps/unix/sysv/linux/clone.S`

#### Parameters
_None_

#### Return value
* `> 0` → child PID (parent)
* `0` → child process
* `-1` → error (`errno` set)

#### Example
```c
pid_t pid = fork();
if (pid ==== 0)
    execl('/bin/ls', 'ls', NULL);
wait(NULL);
```

#### step-by-step code walk-through of fork()
1. User-space code (what you write)

   ```c
   #include <unistd.h>

   int main(void) {
       pid_t pid = fork();

       if (pid .. 0) {
           // Child
       } else {
           // Parent
       }
   }
   ```

   At this point:

   * You are in ***user mode***
   * `fork()` is just a ***function symbol***, not a syscall yet

     The real work begins inside glibc.
2. **glibc**: fork() wrapper

   Key idea: `fork()` is ***NOT a real syscall****, glibc implements it using the **clone() syscall*** with special flags.

   glibc source paths

   * `posix/fork.c`
   * `sysdeps/unix/sysv/linux/fork.c`
   * `sysdeps/unix/sysv/linux/clone.S`
3. glibc fork() (simplified)

   ```c
   pid_t
   __libc_fork(void)
   {
       return _Fork();
   }
   ```

   ```c
   pid_t
   _Fork(void)
   {
       return __clone(SIGCHLD, 0);
   }
   ```

   Key points:

   * glibc converts `fork()` → `clone()`
   * `SIGCHLD` flag means:
     * child sends SIGCHLD when it exits
     * parent/child get ***separate address spaces***
4. **glibc**: clone() syscall stub

   Assembly transition to kernel, glibc now executes a ***syscall instruction***.

   glibc source path

   * `sysdeps/unix/sysv/linux/clone.S`

     ```asm
     mov    $__NR_clone, %rax
     syscall
     ```

     At this moment:
   * CPU switches from ***user mode → kernel mode***
   * Control jumps into the Linux kernel syscall entry point
5. Kernel entry point (architecture layer)

   x86-64 example

   Kernel source paths

   * `arch/x86/entry/syscall_64.c`
   * `arch/x86/entry/common.c`

     ```c
     SYSCALL_DEFINE0(clone)
     {
         return do_fork(...);
     }
     ```

     What happens here:

     * Registers are saved
     * Syscall number is decoded
     * Kernel dispatches to `sys_clone()`
6. **Kernel**: sys_clone()

   Kernel source path

   * `kernel/fork.c`

     ```c
     SYSCALL_DEFINE5(clone, ...)
     {
         return do_fork(clone_flags, stack_start,
                        ptid, ctid, tls);
     }
     ```

     This is where ***process creation truly begins***.
7. **Kernel**: do_fork()

   Kernel source path

   * `kernel/fork.c`

     ```c
     long do_fork(...)
     {
         struct task_struct *p;

         p = copy_process(...);

         wake_up_new_task(p);

         return p->pid;
     }
     ```

     This function:

     1. Creates a new `task_struct`
     2. Copies process state
     3. Schedules the child
     4. Returns PID to parent
8. **Kernel**: copy_process()

   Kernel source path

   * `kernel/fork.c`

     This is the ***heart of fork***.

     Major steps inside `copy_process()`:

     1. Allocate task_struct

        ```c
        p = dup_task_struct(current);
        ```

        Each process is represented by a `task_struct`.
     2. Copy memory (COW)

        ```c
        copy_mm(p);
        ```

        * Parent and child share memory pages
        * Pages are marked ***copy-on-write***
        * Actual copying happens only on write
     3. Copy file descriptors

        ```c
        copy_files(p);
        ```

        * Open files are shared
        * Reference counts are increased
     4. Copy signal handlers

        ```c
        copy_sighand(p);
        ```
9. **Kernel**: wake_up_new_task()

   Kernel source path

   * `kernel/sched/core.c`

     ```c
     wake_up_new_task(p);
     ```

     This:

   * Marks child runnable
   * Inserts it into the scheduler run queue

     Now:

   * Parent continues execution
   * Child is eligible to run
10. **Return path**: kernel → glibc → user space

   Parent return

   * `sys_clone()` returns ***child PID***
   * glibc returns PID > 0

     Child return

   * Kernel sets return value to `0`
   * Child resumes execution **after fork()**

     This is how ***one call returns twice***.
11. **Final illusion**: 'two processes ran the same code'

   What really happened:

   | Layer | Reality |
   |------|--------|
   | User | `fork()` returned twice |
   | glibc | Used `clone()` |
   | Kernel | Duplicated `task_struct` |
   | MMU | Enabled copy-on-write |
   | Scheduler | Ran parent & child |
12. Full call trace

   ```text
   user main()
     ↓
   fork()
     ↓
   glibc fork()            posix/fork.c
     ↓
   glibc clone()           clone.S
     ↓
   syscall instruction
     ↓
   sys_clone()             kernel/fork.c
     ↓
   do_fork()
     ↓
   copy_process()
     ↓
   wake_up_new_task()
     ↓
   return to user space
   ```

### clone()

#### What it does
Creates a new process or thread with configurable resource sharing.

#### Why it matters
Threads, containers, and modern runtimes depend on it.

#### Syscall or libc wrapper?
**True syscall**

#### Kernel source paths
* Entry: `sys_clone`
* Files:
  * `kernel/fork.c`
  * `kernel/sched/core.c`

#### glibc source paths
* `sysdeps/unix/sysv/linux/clone.S`
* `sysdeps/unix/sysv/linux/clone-internal.c`

#### Parameters
* `flags` - resource sharing (VM, FS, files, signals)
* `child_stack` - stack pointer
* `ptid`, `ctid`, `tls` - thread bookkeeping

#### Return value
* child PID on success
* `-1` on error

#### Example
```c
clone(fn, stack, CLONE_VM | CLONE_FS | SIGCHLD, arg);
```

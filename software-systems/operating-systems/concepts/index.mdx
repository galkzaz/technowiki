## What is an Operating System?

Operating systems perform two essentially unrelated functions: providing application programmers (and application programs, naturally) a clean abstract set of resources instead of the messy hardware ones and managing these hardware resources.

An **Operating System** is a layer between **hardware** and **user applications**.

It has two main roles:

* **Resource Manager:** Controls CPU, memory, storage, and I/O devices.
* **Abstraction Provider:** Hides hardware complexity and provides simple interfaces (files, processes, sockets).

Example:
Instead of directly managing disk sectors, you use a *file system* like `/home/user/file.txt`.


The program that users interact with, usually called the shell when it is text based
and the GUI (Graphical User Interface) (which is pronounced ‘‘gooey'') when it
uses icons, is actually not part of the operating system, although it uses the operating system to get its work done.

A simple overview of the main components given in next Fig.

![Where the operating system fits in](/docs/assets/software-systems/operating-systems/linux/computer-structure.png)

Here we see the hardware at the bottom. The hardware consists of chips, boards, Flash drives, disks, a keyboard, a monitor, and similar physical objects. 

On top of the hardware is the software. Most computers have two modes of operation: **kernel mode** and **user mode**. 

The operating system, the most fundamental piece of software, runs in kernel mode (also called supervisor mode) for at least some of
its functionality. In this mode, it has complete access to all the hardware and can execute any instruction the machine is capable of executing. 

The rest of the software runs in user mode, in which only a subset of the machine instructions is available. In particular, those instructions that affect control of the machine, determine the security boundaries, or do I/O (Input/Output) are forbidden to usermode programs.  

The placement of the operating system is shown in above Fig. It runs on the bare hardware and provides the base for all the other software.

An operating system is intimately tied to the hardware of the computer it runs
on. It extends the computer’s instruction set and manages its resources. To work,
it must know a great deal about the hardware, at least about how the hardware
appears to the programmer. 
## OS Goals
THere are two operating system views of operating system 
1. **top-down view**: The OS provides abstractions that hide hardware complexity.
2. **bottom-up view**: The OS is a resource manager responsible for controlling and allocating hardware resources efficiently and safely.

Both views are correct and complementary.

**Top-Down vs Bottom-Up Views**

| View      | Main Focus                  |
| --------- | --------------------------- |
| Top-Down  | Abstractions for programs   |
| Bottom-Up | Managing hardware resources |

the two major purposes of operating systems:

| Purpose          | Description                          |
| ---------------- | ------------------------------------ |
| Extended Machine | Hide complexity using abstractions   |
| Resource Manager | Control and allocate hardware safely |

These are the two foundational perspectives of operating systems theory.

### Abstraction

The architecture (instruction set, memory organization, I/O, and bus structure) of most computers at the machine-language level is primitive and awkward to program, especially for input/output.

Hardware is inherently messy, inconsistent, and difficult to use directly, so the operating system exists to hide this complexity behind elegant abstractions.

Computer hardware is extremely complicated and inconvenient to use directly.

from a **software developer’s perspective**, hardware interfaces are:

* complicated
* inconsistent
* low-level
* awkward
* hard to program safely

Even well-designed hardware exposes many difficult implementation details.

At the hardware level, programmers would need to deal with:

* Device registers
* Interrupts
* Bus protocols
* DMA operations
* Disk controller commands
* Memory timing
* Hardware synchronization

For example, modern SATA disks expose extremely detailed low-level interfaces.

Without an OS, application developers would need to:

* Control disk electronics directly
* Manage sector addressing
* Handle I/O timing
* Detect hardware errors
* Coordinate concurrent access

That would make software development nearly impossible for most applications.

Abstraction is the foundation of scalability in software engineering.

The OS enables:

* portability
* maintainability
* productivity
* hardware independence

The OS hides hardware details and provides simple concepts:

* Process instead of raw CPU instructions
* File instead of disk blocks
* Virtual memory instead of physical RAM

The OS acts as an extended machine that hides hardware complexity through abstractions.

Goal: Make system easier to use and program.

#### Example: SATA (Serial ATA)
Consider modern SATA (Serial ATA) hard disks used on most computers. A book (Deming, 2014) describing an early version of the interface to the disk—what a programmer would have to know to use the disk—ran over 450 pages. Since then, the interface has been revised multiple times and is even more complicated than it was in 2014. Clearly, no sane programmer would want to deal with this disk at the hardware level. Instead, a piece of software, called a disk driver, deals with the hardware and provides an interface to read and write disk blocks, without getting into the details. Operating systems contain many drivers for controlling I/O
devices.

But even this level is much too low for most applications. For this reason, all operating systems provide yet another layer of abstraction for using disks: files. Using this abstraction, programs can create, write, and read files, without having to deal with the messy details of how the hardware actually works.

This abstraction is the key to managing all this complexity. Good abstractions turn a nearly impossible task into two manageable ones. The first is defining and implementing the abstractions. The second is using these abstractions to solve the problem at hand. One abstraction that almost every computer user understands is the file, as mentioned above. It is a useful piece of information, such as a digital photo, saved email message, song, or Web page. It is much easier to deal with photos, emails, songs, and Web pages than with the details of SATA (or other) disks. The job of the operating system is to create good abstractions and then implement and manage the abstract objects thus created.

### Resource Management

Modern Computers Are Complex Shared Systems, A computer contains many hardware resources:

* CPUs
* RAM
* disks
* SSDs
* printers
* network cards
* timers
* keyboards
* touch screens
* GPUs

Many programs want to use these resources simultaneously.

Without coordination:

* conflicts occur
* data corruption happens
* systems become unstable

The operating system exists to prevent this chaos.

The OS decides **who gets what and when**:

* CPU scheduling (which process runs next)
* Memory allocation
* Disk and I/O management

Goal: Efficient and fair usage of hardware.

---

#### Example: Printer Chaos

Imagine three programs printing simultaneously.

Without OS coordination:

```text id="s2vjlwm"
Program 1: Hello...
Program 2: Report...
Program 3: Invoice...
Program 1: More text...
```

The output becomes mixed and unusable.

**How the OS Solves It**

The operating system introduces order by:

1. buffering output
2. queuing print jobs
3. scheduling printer access

Applications think they are printing directly, but the OS controls the actual hardware access.

This is resource management in action.

#### Core Responsibilities of the OS as Resource Manager

The operating system must:

| Responsibility | Description                    |
| -------------- | ------------------------------ |
| Allocation     | Decide who gets resources      |
| Scheduling     | Decide when resources are used |
| Protection     | Prevent interference           |
| Accounting     | Track usage                    |
| Coordination   | Resolve conflicts              |
| Sharing        | Enable safe concurrent use     |

#### Multi-User Systems
Multi-User Systems Increase Complexity, In multi-user systems: multiple people share hardware simultaneously

Without OS protection:

* one user could overwrite another user’s files
* one process could corrupt another process’s memory
* devices could become unusable

The OS therefore enforces:

* isolation
* permissions
* access control
* fair sharing

#### Resource Sharing (Multiplexing)

Multiplexing means: Sharing a resource among multiple users or programs.

The OS performs multiplexing in two major ways:

1. Time Multiplexing
2. Space Multiplexing


#### 1. Time Multiplexing

Programs take turns using a resource.

**CPU Example**

Suppose:

* 1 CPU
* 10 running programs

The OS rapidly switches CPU access:

```text id="d87bxr"
Program A → Program B → Program C → ...
```

Each program gets a small time slice. This creates the illusion that all programs run simultaneously.


**CPU Scheduling**

The OS decides:

* which process runs next
* how long it runs
* when it is paused

This is called: CPU Scheduling, One of the most fundamental OS responsibilities.

**Printer Example**

Printers are also time-multiplexed. Only one job prints at a time. The OS maintains:

* print queues
* job ordering
* spoolers

#### 2. Space Multiplexing

Instead of taking turns, each program gets a portion of the resource.

**Memory Example**

RAM is divided among processes:

```text id="07j4f5"
+-------------------+
| Process A Memory  |
+-------------------+
| Process B Memory  |
+-------------------+
| Process C Memory  |
+-------------------+
```

Multiple programs coexist simultaneously.

**Why Space Multiplexing Matters**

If only one program used all memory:

* hardware would be wasted
* multitasking would be impossible

The OS therefore partitions memory efficiently.

#### Problems Introduced by Sharing

Resource sharing creates difficult problems:

- Fairness: Who gets more CPU time?
- Protection: Can one process access another’s memory?
- Starvation: Can some processes wait forever?
- Deadlocks: Can processes block each other permanently?
- Accounting: Who used how much CPU, memory, or disk?

The operating system must solve all of these.

---

#### Disk Space Multiplexing

Storage devices are also shared.

A single disk may contain:

* operating system files
* user files
* databases
* applications
* logs

The OS tracks:

* free blocks
* ownership
* permissions
* allocation tables

This is the responsibility of the file system subsystem.

---

the OS is fundamentally a: Control System, It coordinates competing demands for limited resources.

## Types of Operating Systems

### Batch OS

* Jobs are collected and executed in batches
* No interaction during execution

Example: Early mainframe systems

✔ High throughput
❌ No interactivity


### Time-Sharing OS

* Multiple users share CPU via time slicing
* Each user gets a small time slice

Example: Unix systems

✔ Interactive
✔ Multi-user support


### Real-Time OS (RTOS)

* Guarantees strict timing constraints
* Used in systems where delay = failure

Examples:

* Air traffic control
* Medical devices
* Embedded systems

Two types:

* **Hard RTOS:** Missing deadline = system failure
* **Soft RTOS:** Occasional delay is acceptable


### Distributed OS

* Runs across multiple machines
* Appears as a single system to users

Example: Cluster computing systems

✔ Scalability
✔ Fault tolerance


## OS Architecture Overview

### Monolithic Kernel

* Entire OS runs in kernel space
* All services (memory, file system, drivers) are inside kernel

✔ Fast (less overhead)
❌ Hard to maintain/debug

Example: Traditional Unix kernels


### Microkernel

* Only minimal core runs in kernel (IPC, scheduling, memory basics)
* Other services run in user space

✔ More secure and stable
❌ Slower due to message passing overhead


### Hybrid Kernel

* Mix of monolithic and microkernel ideas
* Keeps performance-critical parts in kernel

Example systems:

* Windows NT family
* macOS (XNU)

✔ Balanced performance + modularity

##  Characteristics of Operating Systems

An operating system is not just a privileged program — it is also an enormous, evolving software ecosystem.

Operating systems are fundamentally different from ordinary application software.

Unlike ordinary applications, operating systems are:

* Extremely large
* Deeply hardware-oriented
* Highly concurrent
* Security-critical
* Long-lived
* Performance-sensitive
* Highly interconnected
* Long-lived
* Continuously evolving
* Maintained by thousands of developers

These characteristics make operating system engineering one of the most complex areas of software engineering and computer science.

### Why Operating Systems Are Unique

An operating system is responsible for:

* Managing hardware resources
* Running applications safely
* Providing abstractions
* Enforcing security
* Maintaining system stability

Unlike normal applications, the OS sits between:

```text id="o1m2ee"
Applications ↔ Operating System ↔ Hardware
```

As a result, failures in the OS can affect the entire machine.


```c

```

which becomes a syscall.

## POSIX Standard and Unix Philosophy

### POSIX (Portable Operating System Interface)

A standard that defines **common APIs** for compatibility between OSs.

It ensures:

* Programs can run on different Unix-like systems with minimal changes
* Standard system calls (process, file, threads)


### Unix Philosophy

A design mindset:

* “Do one thing and do it well”
* Build small, modular tools
* Combine tools using pipes (`|`)

Example:

```bash
cat file.txt | grep "error" | sort
```

Each tool does a single job and combines with others.

* Unix-like OS created by Linus Torvalds (1991)

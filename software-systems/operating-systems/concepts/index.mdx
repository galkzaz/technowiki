## What is an Operating System?

An **Operating System** is a layer between **hardware** and **user applications**.

It has two main roles:

* **Resource Manager:** Controls CPU, memory, storage, and I/O devices.
* **Abstraction Provider:** Hides hardware complexity and provides simple interfaces (files, processes, sockets).

👉 Example:
Instead of directly managing disk sectors, you use a *file system* like `/home/user/file.txt`.


The program that users interact with, usually called the shell when it is text based
and the GUI (Graphical User Interface) (which is pronounced ‘‘gooey'') when it
uses icons, is actually not part of the operating system, although it uses the operating system to get its work done.

A simple overview of the main components given in next Fig.

![Where the operating system fits in](/docs/assets/software-systems/operating-systems/linux/computer-structure.png)

Here we see the hardware at the bottom. The hardware consists of chips, boards, Flash drives, disks, a keyboard, a monitor, and similar physical objects. 

On top of the hardware is the software. Most computers have two modes of operation: **kernel mode** and **user mode**. 

The operating system, the most fundamental piece of software, runs in kernel mode (also called supervisor mode) for at least some of
its functionality. In this mode, it has complete access to all the hardware and can execute any instruction the machine is capable of executing. 

The rest of the software runs in user mode, in which only a subset of the machine instructions is available. In particular, those instructions that affect control of the machine, determine the security boundaries, or do I/O (Input/Output) are forbidden to usermode programs.  

The placement of the operating system is shown in above Fig. It runs on the bare hardware and provides the base for all the other software.

## OS Goals: Abstraction, Resource Management, Isolation

### Abstraction

The OS hides hardware details and provides simple concepts:

* Process instead of raw CPU instructions
* File instead of disk blocks
* Virtual memory instead of physical RAM

👉 Goal: Make system easier to use and program.


### Resource Management

The OS decides **who gets what and when**:

* CPU scheduling (which process runs next)
* Memory allocation
* Disk and I/O management

👉 Goal: Efficient and fair usage of hardware.


### Isolation

The OS ensures programs do not interfere with each other:

* One process cannot access another’s memory directly
* Fault in one program doesn’t crash the whole system
* Security boundaries between users/processes

👉 Goal: Stability + security.


## Types of Operating Systems

### Batch OS

* Jobs are collected and executed in batches
* No interaction during execution

👉 Example: Early mainframe systems

✔ High throughput
❌ No interactivity


### Time-Sharing OS

* Multiple users share CPU via time slicing
* Each user gets a small time slice

👉 Example: Unix systems

✔ Interactive
✔ Multi-user support


### Real-Time OS (RTOS)

* Guarantees strict timing constraints
* Used in systems where delay = failure

👉 Examples:

* Air traffic control
* Medical devices
* Embedded systems

Two types:

* **Hard RTOS:** Missing deadline = system failure
* **Soft RTOS:** Occasional delay is acceptable


### Distributed OS

* Runs across multiple machines
* Appears as a single system to users

👉 Example: Cluster computing systems

✔ Scalability
✔ Fault tolerance


## OS Architecture Overview

### Monolithic Kernel

* Entire OS runs in kernel space
* All services (memory, file system, drivers) are inside kernel

✔ Fast (less overhead)
❌ Hard to maintain/debug

👉 Example: Traditional Unix kernels


### Microkernel

* Only minimal core runs in kernel (IPC, scheduling, memory basics)
* Other services run in user space

✔ More secure and stable
❌ Slower due to message passing overhead


### Hybrid Kernel

* Mix of monolithic and microkernel ideas
* Keeps performance-critical parts in kernel

👉 Example systems:

* Windows NT family
* macOS (XNU)

✔ Balanced performance + modularity

##  Characteristics of Operating Systems

An operating system is not just a privileged program — it is also an enormous, evolving software ecosystem.

Operating systems are fundamentally different from ordinary application software.

Unlike ordinary applications, operating systems are:

* Extremely large
* Deeply hardware-oriented
* Highly concurrent
* Security-critical
* Long-lived
* Performance-sensitive
* Highly interconnected
* Long-lived
* Continuously evolving
* Maintained by thousands of developers

These characteristics make operating system engineering one of the most complex areas of software engineering and computer science.

### Why Operating Systems Are Unique

An operating system is responsible for:

* Managing hardware resources
* Running applications safely
* Providing abstractions
* Enforcing security
* Maintaining system stability

Unlike normal applications, the OS sits between:

```text id="o1m2ee"
Applications ↔ Operating System ↔ Hardware
```

As a result, failures in the OS can affect the entire machine.

### Scale and Complexity

Modern operating systems are enormous software systems.

Examples:

| Operating System | Approximate Code Size |
| ---------------- | --------------------- |
| Linux Kernel     | 20+ million LOC       |
| Windows          | 50+ million LOC       |

LOC = Lines of Code

The difficulty of operating systems is not only privilege and hardware control, but also scale, longevity, and interconnected complexity.

This complexity explains why:

* OS architecture matters greatly
* Modularity is important
* Clear abstractions are essential
* Subsystem boundaries matter
* Bugs can be catastrophic
* Maintenance dominates development effort


#### Why OSes Become So Large

Operating systems must support:

* Networking protocols
* Security systems
* Concurrency
* Virtual memory

* Process management
* Compatibility layers
* Virtualization

## POSIX Standard and Unix Philosophy

### POSIX (Portable Operating System Interface)

A standard that defines **common APIs** for compatibility between OSs.

It ensures:

* Programs can run on different Unix-like systems with minimal changes
* Standard system calls (process, file, threads)


### Unix Philosophy

A design mindset:

* “Do one thing and do it well”
* Build small, modular tools
* Combine tools using pipes (`|`)

👉 Example:

```bash
cat file.txt | grep "error" | sort
```

Each tool does a single job and combines with others.

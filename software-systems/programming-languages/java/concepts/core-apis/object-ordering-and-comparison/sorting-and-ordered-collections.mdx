{/* This TOC is designed to teach you how Java uses ordering to sort data, search efficiently, and maintain collections in a particular order. */}

Sorting and ordered collections are related, but they are not exactly the same thing, they solve different problems:

- Sorting arranges elements that already exist in an array or list.
- Ordered collections maintain an ordering as elements are inserted and removed.
- Searching and finding extremes use ordering to locate elements or determine which is smallest or largest.

For example, suppose you have these students:

```
Student(id=103, name="Mona", grade=88)
Student(id=101, name="Ali",  grade=95)
Student(id=102, name="Omar", grade=78)
```

You might sort them by ID, by name, or by grade. The objects haven't changed; only the ordering rule has changed.

an important advantage of implementing `Comparable` in Java: once a class defines its natural ordering, many Java APIs can sort, search, compare, and organize its objects without requiring you to provide a separate comparison rule each time.

## 1. The big picture

Java provides several ways to use an ordering. They are related, but they solve different problems.

Define an ordering

`Comparable.compareTo()` or `Comparator.compare()`

Sorting

`List.sort()`, `Collections.sort()`, `Arrays.sort()`

Searching

`Collections.binarySearch()`, `Arrays.binarySearch()`

Sorted collections

`TreeSet`, `TreeMap`

Priority-based processing

`PriorityQueue`

The important distinction is that sorting arranges existing elements, while ordered collections use an ordering as part of how they store, find, or retrieve elements.

The ordering rules come from `Comparable` or `Comparator`. Different Java APIs use those rules in different ways.


## 2. Sorting APIs

Java has different sorting methods depending on what you want to sort.

| API                  | Used for | Example                     |
| -------------------- | -------- | --------------------------- |
| `List.sort()`        | A list   | `students.sort(byName)`     |
| `Collections.sort()` | A list   | `Collections.sort(numbers)` |
| `Arrays.sort()`      | An array | `Arrays.sort(numbers)`      |

### Example

```
import java.util.Arrays;
import java.util.List;

public class SortingExample {
    public static void main(String[] args) {
        int[] numbers = {7, 2, 9, 1, 5};

        Arrays.sort(numbers);

        System.out.println(Arrays.toString(numbers));
        // [1, 2, 5, 7, 9]

        List<String> names =
                Arrays.asList("Mona", "Ali", "Omar");

        names.sort(null); // Uses natural ordering.

        System.out.println(names);
        // [Ali, Mona, Omar]
    }
}
```

For a list, `sort(null)` requests natural ordering, provided the elements support it. Alternatively, pass a `Comparator` to choose a custom order.

For object arrays, Java's standard sorting implementation uses a stable, adaptive TimSort-based algorithm. Primitive arrays use different implementation strategies. You don't normally need to implement the sorting algorithm yourself when using these APIs.

### When should you use each?

- Use `List.sort()` when you have a list.
- Use `Arrays.sort()` when you have an array.
- Use `Collections.sort()` when you want the familiar utility method for sorting a list; it delegates to the list's sorting operation.


# 1. Overview: Sorting vs. Ordering

First, distinguish the rules for ordering from the operation that sorts elements.

Suppose you have these numbers:

```
Integer[] numbers = {40, 10, 30, 20};
```

Before sorting:

```
[40, 10, 30, 20]
```

After sorting:

```
Arrays.sort(numbers);
```

```
[10, 20, 30, 40]
```

The operation `Arrays.sort()` rearranges the elements. But how does Java know that `10` should come before `20`?

It needs an ordering rule.

Java provides two main ways to define that rule:

| Mechanism       | Purpose                                                          |
| --------------- | ---------------------------------------------------------------- |
| `Comparable<T>` | Defines a class's natural ordering through `compareTo()`.        |
| `Comparator<T>` | Defines an external or alternative ordering through `compare()`. |

For example, a `Student` class might naturally sort students by ID, while a `Comparator<Student>` can sort them by name.

Ordering rules

`Comparable` or `Comparator`

Sorting

Rearrange an array or list

Ordered collections

Maintain order as data changes

When to study this: Start here to understand the big picture before learning individual APIs.

# 2. Sorting Arrays and Lists

By implementing Comparable, a class indicates that its instances have a natural ordering.
Sorting an array of objects that implement Comparable is as simple as this:

```
Arrays.sort(a);
```

## 2.1 `Arrays.sort()`

Use `Arrays.sort()` when your data is stored in an array.

```
import java.util.Arrays;

public class Main {
    public static void main(String[] args) {
        int[] numbers = {40, 10, 30, 20};

        Arrays.sort(numbers);

        System.out.println(Arrays.toString(numbers));
    }
}
```

Output:

```
[10, 20, 30, 40]
```

For an array of objects, Java can use their natural ordering:

```
String[] names = {"Mona", "Ali", "Sara"};

Arrays.sort(names);

System.out.println(Arrays.toString(names));
```

Output:

```
[Ali, Mona, Sara]
```

`String` implements `Comparable<String>`, so Java already knows how to compare strings.

You can also provide a comparator for an alternative ordering:

```
Arrays.sort(names, java.util.Comparator.reverseOrder());
```

Output:

```
[Sara, Mona, Ali]
```

Note that the object-array overload accepts a `Comparator`; primitive arrays have different overloads.

Why does this work without a `Comparator`?

Because `String` implements `Comparable<String>` and provides a `compareTo()` method that defines its natural ordering.

Conceptually, sorting repeatedly compares elements:

```
"Apple".compareTo("Banana")  // negative: Apple comes first
"Banana".compareTo("Orange") // negative: Banana comes first
```

The sorting algorithm uses those comparison results to arrange the array.

The general rule is:

- `Arrays.sort(array)` sorts an array using the elements' natural ordering.
- `Arrays.sort(array, comparator)` sorts using a custom ordering.

For your own class, implementing `Comparable<T>` enables the first form:

```
import java.util.Arrays;

class Student implements Comparable<Student> {
    private final int id;
    private final String name;

    Student(int id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public int compareTo(Student other) {
        return Integer.compare(this.id, other.id);
    }

    @Override
    public String toString() {
        return id + ": " + name;
    }
}

public class Main {
    public static void main(String[] args) {
        Student[] students = {
            new Student(103, "Mona"),
            new Student(101, "Ali"),
            new Student(102, "Sara")
        };

        Arrays.sort(students);

        System.out.println(Arrays.toString(students));
    }
}
```

Output:

```
[101: Ali, 102: Sara, 103: Mona]
```

The natural ordering is by student ID because that is what `compareTo()` defines.

## 2.2 `Collections.sort()` and `List.sort()`

A `List` generally preserves its current element order. Adding an element does not automatically sort the list.
```
import java.util.ArrayList;
import java.util.List;

public class SortingExample {
    public static void main(String[] args) {
        List<Integer> numbers =
                new ArrayList<>(List.of(40, 10, 30, 20));

        System.out.println(numbers);
        // [40, 10, 30, 20]

        numbers.sort(null); // Natural ordering.

        System.out.println(numbers);
        // [10, 20, 30, 40]
    }
}
```
Here, `sort(null)` means to use the elements' natural ordering. For `Integer`, that means ascending numerical order.

When your data is stored in a `List`, you can use either `Collections.sort()` or `List.sort()`.

```
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> numbers =
                new ArrayList<>(List.of(40, 10, 30, 20));

        // Option 1: Sort using natural ordering.
        Collections.sort(numbers);

        System.out.println(numbers);

        // Option 2: Sort using reverse natural ordering.
        numbers.sort(Collections.reverseOrder());

        System.out.println(numbers);
    }
}
```

Output:

```
[10, 20, 30, 40]
[40, 30, 20, 10]
```

For a list, `Collections.sort()` delegates to the list's sorting operation.

The important distinction is the data structure:

| API                      | Data being sorted |
| ------------------------ | ----------------- |
| `Arrays.sort(array)`     | Array             |
| `Collections.sort(list)` | List              |
| `list.sort(comparator)`  | List              |

`Collections.sort(list)` is essentially a convenient alternative to `list.sort(null)` when using natural ordering.

## Custom ordering

Suppose you want the numbers in descending order:

```
numbers.sort(Comparator.reverseOrder());

System.out.println(numbers);
// [40, 30, 20, 10]
```

Or sort strings by their length:

```
List<String> names =
        new ArrayList<>(List.of("Alexander", "Ali", "Mona"));

names.sort(Comparator.comparingInt(String::length));

System.out.println(names);
// [Ali, Mona, Alexander]
```

Notice that `Comparator` allows you to select an ordering without changing the classes being sorted.

## 2.3 Sorting `Comparable` Objects

This is the topic from your earlier passage.

Suppose a class implements `Comparable<Student>` and defines its natural ordering by student ID:

```
class Student implements Comparable<Student> {
    private final int id;
    private final String name;

    Student(int id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public int compareTo(Student other) {
        return Integer.compare(this.id, other.id);
    }

    @Override
    public String toString() {
        return id + ": " + name;
    }
}
```

Now Java can sort an array without being told how to compare students:

```
Student[] students = {
    new Student(103, "Mona"),
    new Student(101, "Ali"),
    new Student(102, "Sara")
};

Arrays.sort(students);

System.out.println(Arrays.toString(students));
```

Output:

```
[101: Ali, 102: Sara, 103: Mona]
```

The benefit is that the natural ordering is defined once and can be reused by sorting APIs and ordered collections.


## 3. Natural ordering vs. custom ordering

Java has two primary ways to define ordering.

| Aspect                       | Natural ordering                      | Custom ordering            |
| ---------------------------- | ------------------------------------- | -------------------------- |
| Defined through              | `Comparable<T>`                       | `Comparator<T>`            |
| Main method                  | `compareTo()`                         | `compare()`                |
| Example                      | Integers in ascending order           | Students by grade          |
| Can support multiple orders? | Usually one preferred order per class | Yes, many different orders |

For example, a `Student` class could use its ID as its natural order:

```
class Student implements Comparable<Student> {
    private final int id;
    private final String name;

    Student(int id, String name) {
        this.id = id;
        this.name = name;
    }

    int getId() {
        return id;
    }

    String getName() {
        return name;
    }

    @Override
    public int compareTo(Student other) {
        return Integer.compare(id, other.id);
    }
}
```

Then you can sort by ID naturally:

```
students.sort(null);
```

Or choose a different order:

```
students.sort(Comparator.comparing(Student::getName));
```

The second operation sorts by name, while the first uses the natural order defined by `compareTo()`.

See also:  Comparable and compareTo() and  Comparator and Custom Ordering

# 3. Searching and Finding Extremes

Ordering is useful beyond sorting. It also lets Java find values and search sorted data.

## 3.1 Binary search

Binary search is closely connected to sorting because it depends on an ordered search space.

Binary search works correctly only when the searched sequence is ordered according to the same comparison rule used by the search.

Binary search repeatedly divides a sorted collection into smaller portions.

Suppose the sorted array is:

```
Index:    0   1   2   3   4   5   6
Value:   10  20  30  40  50  60  70
```

Searching for `60`:

```
Step 1: Check middle → 40
        60 > 40, search the right half

Step 2: Check middle of remaining range → 60
        Found at index 5
```
The search takes $O(\log n)$ comparisons in the usual case, compared with $O(n)$ for a linear scan.


Java provides:

```
int[] numbers = {10, 20, 30, 40, 50, 60, 70};

int index = Arrays.binarySearch(numbers, 60);

System.out.println(index); // 5
```

But there's an important rule: the collection must be sorted using the same ordering that binary search uses.

For example:

```
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;
import java.util.Collections;

List<String> names =
        new ArrayList<>(List.of("Mona", "ali", "Omar"));

Comparator<String> order = String.CASE_INSENSITIVE_ORDER;

names.sort(order);

int index = Collections.binarySearch(names, "ALI", order);

System.out.println(names);
System.out.println(index); // 0
```

Both operations use `String.CASE_INSENSITIVE_ORDER`.

The comparator is supplied to both operations to keep their ordering rules consistent.

The list is sorted case-insensitively, and the search uses the same comparator. Searching with a different ordering can return incorrect results.

Another detail: if multiple elements compare equal to the search key, binary search does not guarantee which matching element it returns.


If you sort using one comparator and search using a different one, binary search can fail to find an element that is actually present.

Binary search runs in $O(\log n)$ time on sorted random-access data, compared with $O(n)$ for a linear search in the worst case.

## 3.2 `Collections.min()` and `Collections.max()`

These methods find the smallest and largest elements according to an ordering.

```
List<Integer> numbers = List.of(40, 10, 30, 20);

System.out.println(Collections.min(numbers)); // 10
System.out.println(Collections.max(numbers)); // 40
```

You do not need to sort the entire list first.

You can also use a custom comparator:

```
List<String> words = List.of("cat", "elephant", "dog");

String shortest = Collections.min(
        words,
        java.util.Comparator.comparingInt(String::length));

System.out.println(shortest); // cat
```

Here, "minimum" means the word with the smallest length, not the alphabetically first word.

When to study this: Learn binary search after sorting, and learn `min()` and `max()` once you understand how comparison rules work.

# 4. Sorted Collections

A list doesn't maintain sorted order automatically. A `TreeSet` and `TreeMap`, however, use an ordering to organize their elements or keys as they are inserted.

Sorting an array or list is an explicit operation. But what if you want a collection to remain sorted as you add and remove elements?

That's where `TreeSet` and `TreeMap` come in.

## 4.1 `TreeSet`: Sorted Elements and Uniqueness

A `TreeSet` maintains elements in sorted order and does not allow multiple elements that compare as equivalent.

```
import java.util.TreeSet;

TreeSet<Integer> numbers = new TreeSet<>();

numbers.add(40);
numbers.add(10);
numbers.add(30);
numbers.add(20);
numbers.add(10);

System.out.println(numbers);
// [10, 20, 30, 40]
```

The second `10` is not added because the set already contains an element equivalent under its ordering.

```
import java.util.Set;
import java.util.TreeSet;

public class Main {
    public static void main(String[] args) {
        Set<String> words = new TreeSet<>();

        words.add("pear");
        words.add("apple");
        words.add("banana");
        words.add("apple");

        System.out.println(words);
    }
}
```

Output:

```
[apple, banana, pear]
```
- Iterates in ascending natural order by default.
- Uses the ordering to determine whether elements are equivalent.
- Rejects a new element if its comparison with an existing element returns zero.
- Typically provides $O(\log n)$ basic operations such as `add`, `remove`, and `contains`.

That third point is especially important. The set does not necessarily use `equals()` to determine uniqueness. If `compareTo()` or the supplied comparator returns zero, the elements are equivalent for the sorted set.

Two things happen automatically:

1. Elements are maintained in sorted order.
2. The second `"apple"` is not added.

This is the idea behind your earlier `WordList` example:

```
Set<String> words = new TreeSet<>();
Collections.addAll(words, args);
System.out.println(words);
```

The `TreeSet` uses `String`'s natural ordering, so there is no need to sort the set afterward.

One subtle but important detail: a `TreeSet` determines uniqueness using comparison. If `compareTo()` or its comparator returns zero for two objects, the set treats them as equivalent, even if their `equals()` methods return `false`.

Typical time complexities are $O(\log n)$ for adding, removing, and checking membership.

Common operations:

| Operation          | Typical time complexity |
| ------------------ | ----------------------- |
| `add()`            | $O(\log n)$         |
| `remove()`         | $O(\log n)$         |
| `contains()`       | $O(\log n)$         |
| Iteration in order | $O(n)$              |

A `TreeSet` is useful when you need both uniqueness and sorted traversal.

## 4.2 `TreeMap`: Sorted Keys

A `TreeMap` stores key-value pairs and orders them by key.

```
import java.util.Map;
import java.util.TreeMap;

public class Main {
    public static void main(String[] args) {
        Map<Integer, String> students = new TreeMap<>();

        students.put(103, "Mona");
        students.put(101, "Ali");
        students.put(102, "Sara");

        System.out.println(students);
    }
}
```

Output:

```
{101=Ali, 102=Sara, 103=Mona}
```
The keys are ordered, not the values.

The entries are displayed in ascending key order, regardless of insertion order.

A `TreeMap` is useful when you need to retrieve entries in key order or use navigation methods such as:

```
students.firstKey();   // 101
students.lastKey();    // 103
students.lowerKey(102);  // 101
students.higherKey(102); // 103
```
These methods help answer questions like "What is the greatest key below this value?" without sorting the entire map repeatedly.

Both `TreeSet` and `TreeMap` typically provide $O(\log n)$ lookup, insertion, and removal operations.

`TreeMap` also supports useful navigation operations:

| Method          | Meaning                                   |
| --------------- | ----------------------------------------- |
| `firstKey()`    | Smallest key                              |
| `lastKey()`     | Largest key                               |
| `lowerKey(k)`   | Greatest key strictly less than `k`       |
| `higherKey(k)`  | Smallest key strictly greater than `k`    |
| `floorKey(k)`   | Greatest key less than or equal to `k`    |
| `ceilingKey(k)` | Smallest key greater than or equal to `k` |

These methods are useful when you need more than ordinary key lookup—for example, finding the next scheduled event or the nearest available threshold.

# 5. Priority Queues

A `PriorityQueue` is different from both a sorted list and a `TreeSet`.

A priority queue uses ordering to determine which element should be removed next. It does not promise that iterating over all its elements will produce a sorted sequence.

Unlike a `TreeSet`, it does not maintain a fully sorted iteration order.

```
import java.util.PriorityQueue;

public class Main {
    public static void main(String[] args) {
        PriorityQueue<Integer> queue = new PriorityQueue<>();

        queue.offer(30);
        queue.offer(10);
        queue.offer(20);

        System.out.println(queue.peek()); // 10

        while (!queue.isEmpty()) {
            System.out.println(queue.poll());
        }
    }
}
```

Output:

```
10
10
20
30
```

The first `10` is printed by `peek()`. The remaining values are printed by `poll()`.

The queue exposes the smallest element first by default, but its internal structure is a heap, not a fully sorted array.

By default, the queue exposes the smallest element as its head. the smallest element has the highest priority.

However, iterating over a `PriorityQueue` does not guarantee sorted order. The guarantee is that operations such as `peek()` and `poll()` access the head according to the queue's priority ordering.

To make the largest element come first:

```
PriorityQueue<Integer> queue =
        new PriorityQueue<>(java.util.Comparator.reverseOrder());
```

Typical complexities:

| Operation    | Time            |
| ------------ | --------------- |
| `peek()`     | $O(1)$      |
| `offer()`    | $O(\log n)$ |
| `poll()`     | $O(\log n)$ |
| `contains()` | $O(n)$      |

Use a priority queue when you need to repeatedly process the next highest- or lowest-priority item, such as jobs, events, or graph algorithms.

The distinction is important:

- `TreeSet` maintains a sorted collection of unique elements.
- `TreeMap` maintains sorted keys and associated values.
- `PriorityQueue` efficiently exposes the next element by priority, but its iterator isn't sorted.

# 6. Compare the four approaches

| Requirement                                           | Appropriate choice |
| ----------------------------------------------------- | ------------------ |
| Sort a list and iterate through all elements in order | `List.sort()`      |
| Search an already sorted array or list                | Binary search      |
| Maintain unique elements in sorted order              | `TreeSet`          |
| Maintain keys in sorted order with associated values  | `TreeMap`          |
| Repeatedly retrieve the next element by priority      | `PriorityQueue`    |

These choices aren't interchangeable. A `TreeSet` maintains order but removes elements equivalent under its comparator. A priority queue focuses on efficient access to the head rather than sorted iteration. A list preserves its current element sequence until you explicitly change it.
# 6. `Comparable` vs. `Comparator` in Practice

This section brings the earlier concepts together.

Imagine you have students and need to sort them in different ways.

| Requirement                                        | Appropriate approach                         |
| -------------------------------------------------- | -------------------------------------------- |
| Sort students by their default ID order            | `Student implements Comparable<Student>`     |
| Sort students by name                              | `Comparator.comparing(Student::getName)`     |
| Sort students by grade, highest first              | A grade comparator followed by `.reversed()` |
| Sort by grade, then name                           | `.thenComparing(...)`                        |
| Maintain students in a sorted set by a chosen rule | `TreeSet` with a suitable comparator         |

Example:

```
import java.util.Comparator;
import java.util.List;

List<Student> students = /* existing students */;

// Natural order: student ID
students.sort(null);

// Alternative: student name
students.sort(Comparator.comparing(Student::getName));

// Alternative: grade descending, then name ascending
students.sort(
        Comparator.comparingDouble(Student::getGrade)
                  .reversed()
                  .thenComparing(Student::getName)
);
```

The last example assumes `Student` provides `getName()` and `getGrade()` methods.

A useful design rule is: implement `Comparable` when one natural ordering makes sense for the class. Use `Comparator` for other ordering needs.

## 7. Stability in sorting

A sorting algorithm is stable when equal elements retain their relative order from the original list.

Consider two records with the same grade:

```
Before:
Ali   — grade 90
Mona  — grade 80
Omar  — grade 90

Sort by grade, descending:

After:
Ali   — grade 90
Omar  — grade 90
Mona  — grade 80
```

Ali remains before Omar because both have grade 90 and Ali appeared first originally.

Java's standard list sorting APIs are stable. Stability is useful when you sort records by multiple criteria in separate steps, provided you sort the least significant criterion first and then apply stable sorts for more significant criteria.

For example:

1. Sort students by name.
2. Stably sort by grade descending.

Students with equal grades remain alphabetically ordered.

Alternatively, a single chained comparator using `thenComparing()` often expresses the desired ordering more clearly.


# 7. Design Guidelines and Common Pitfalls

This final section turns the API knowledge into practical design decisions.

| Pitfall                                                                                      | Why it matters                                                            | Better approach                                     |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------- |
| Assuming a `List` stays sorted                                                               | Adding elements does not automatically re-sort it                         | Sort again or use an appropriate ordered collection |
| Binary-searching unsorted data                                                               | The search may return incorrect results                                   | Sort first using the same ordering                  |
| Using different comparators for sorting and searching                                        | The binary-search assumptions are violated                                | Use consistent ordering rules                       |
| Assuming `PriorityQueue` iteration is sorted                                                 | A heap only guarantees its head ordering                                  | Repeatedly call `poll()` to retrieve priority order |
| Ignoring comparison equivalence in `TreeSet`                                                 | Distinct objects may be treated as duplicates                             | Make comparison semantics intentional               |
| Changing fields used for ordering while objects are in a `TreeSet` or used as `TreeMap` keys | The collection's internal ordering may no longer match the changed values | Prefer immutable ordering fields                    |

Also remember that Java's standard list sorting is stable: elements with equal comparison keys preserve their relative order. Stability is especially useful when sorting records by multiple fields.

## 7. Common pitfalls

1. Using binary search on an unsorted list. The result is not reliable.
2. Sorting and searching with different comparators. The search assumes an ordering the data may not satisfy.
3. Breaking the `compareTo()` or `Comparator` contract. Inconsistent ordering can lead to incorrect behavior or sorting failures.
4. Ignoring `compareTo() == 0` versus `equals()`. Sorted sets and maps use comparison equivalence for uniqueness and key matching.
5. Changing fields used for ordering while an object is inside a `TreeSet` or used as a `TreeMap` key. The structure may no longer behave as expected.
6. Assuming a priority queue iterates in sorted order. Use repeated `poll()` calls when you need priority order.

## 8. Common mistakes

| Mistake                                                    | Why it matters                                          |
| ---------------------------------------------------------- | ------------------------------------------------------- |
| Assuming a list stays sorted after insertion               | Lists don't automatically re-sort themselves            |
| Binary-searching an unsorted list                          | The result isn't reliable                               |
| Using different ordering rules for sorting and searching   | Binary search may return an incorrect result            |
| Assuming `PriorityQueue` iteration is sorted               | Only priority-based head operations are guaranteed      |
| Ignoring comparator equality in `TreeSet`                  | Distinct objects may be treated as duplicates           |
| Changing comparison fields inside a `TreeSet` or `TreeMap` | The data structure's ordering assumptions can be broken |

## 9. Which API should you choose?

I need to sort all elements and display them in order.

Use `List.sort()` or `Arrays.sort()`.

I need unique elements that are always sorted.

Use `TreeSet`.

I need key-value entries ordered by their keys.

Use `TreeMap`.

I repeatedly need the smallest or highest-priority item.

Use `PriorityQueue`.

I need fast searching in an already-sorted array or list.

Use binary search, making sure the ordering is consistent.

A **statement** is a complete instruction that the program executes.

Statements control **program flow** or perform **actions**.

C’s grammar defines statements like:

```c
expression ;
```

This gives flexibility and keeps the language simple.

Many useful operations are naturally expressions:

- assignments
- increments
- function calls

So C lets them be used directly as statements.

Examples:

```c
x = 5;
printf("Hello");
i++;
if (x > 0) printf("positive");
while (i < 10) i++;
```

Each one tells the program to do something.

## Expression vs Statement

| Expression                                | Statement                                   |
| ----------------------------------------- | ------------------------------------------- |
| Produces a value(Computes a value)        | Performs an action(Executes an instruction) |
| Can appear inside other expressions       | Usually stands alone                        |
| Does not necessarily control program flow | Often controls execution                    |
| Example: `a + b`                          | Example: `x = a + b;`                       |
| Can be part of another expression         | Usually ends with `;`                       |

Example:

```
a + b
```

This is just a value computation.

But:

```c
c = a + b;
```

This is a statement.

Expressions can exist inside statements, but statements cannot exist inside expressions (in standard C).

Example:

Valid:

```c
x = (a + b) * c;
```

Invalid:

```
x = (if(a) b);
```

**Analogy**

Think of it like math vs instructions.

Expression (math):

```
3 + 4
```

Statement (instruction):

```
store 3 + 4 in x
```

## Expression Statements

```c
x = y + 5;       // Assignment
sum = add(a, b); // Function call
```

C requires that each statement end with a semicolon. The semicolon shows the compiler where the statement ends; since statements can continue over several lines, it's not always obvious where they end. Directives, on the other hand, are normally one line long, and they don't end with a semicolon.

`add(a, b)` is the function call. Asking a function to perform its assigned task is known as calling the function.

C has the unusual rule that any expression can be used as a statement. That is, any expression—regardless of its type or what it computes—can be turned into a statement by appending a semicolon.

So, In C Any expression followed by ; becomes a statement.

For example, we could turn the expression `++i` into a statement:

```c
++i;
```

Here:

- `++i` is an expression
- Adding `;` turns it into a statement

When this statement is executed:

1. `i` is first incremented,
2. then the new value of `i` is fetched (as though it were to be used in an enclosing expression).
3. However, since `++i` isn't part of a larger expression, its value is discarded and the next statement executed. (The change to `i` is permanent, of course.)

By definition, an expression represents a value. If `i` has the value `5`, for example, then evaluating `i + 1` produces the value `6`. Let’s turn `i + 1` into a statement by putting a semicolon after it:

```c
i + 1;
```

When this statement is executed, the value of `i + 1` is computed. Since we have failed to save this value—or at least use it in some way—it is lost(the value of the expression statement is discarded).

Example:

```c
int i = 5;
++i;
```

After execution:

```
i = 6
```

The produced value 6 is simply thrown away.

Expression

```
a * b + c
```

Produces a value.

Statement

```c
x = a * b + c;
```

Assigns the value to x.

Expression inside a statement

```c
printf("%d", a + b);
```

`a + b` is an expression used inside the statement.

**Why Expressions Used as Statements Usually Need Side Effects**

Since its value is discarded, there’s little point in using an expression as a statement unless the expression has a side effect.

If an expression **does not change anything**, using it as a statement is pointless.

**An expression statement executes the expression only for its side effects**. The resulting value is ignored.

In C:

```
expression ;
```

means:

1. Evaluate the expression
2. Perform its side effects
3. Discard the resulting value

Therefore, expression statements are useful mainly when the expression changes something.

Example:

```c
i + 5;
```

Execution steps:

1. Compute i + 5
2. Result is discarded
3. Nothing changes

So this statement does nothing useful.

lets look at three examples.

1. **In he first example, `1` is stored into `i` , then the new value of `i` is fetched but not used**:

```c
i = 1;
```

Don’t forget that = is an operator in C and produces a value just like any other operator. The assignment `i = 1;` assigns `1` to `i`. The value of the entire expression is `1`, which is discarded. Discarding the expression’s value is no great loss, since the reason for writing the statement in the first place was to modify `i`.

2. In the second example, the value of `i` is fetched but not used; however, `i` is decre-
   mented afterwards:

```c
i--;
```

3. In the third example, the value of the expression `i * j - 1` is computed and then
   discarded:

```c
i * j - 1;
```

Since `i` and `j` aren't changed, this statement has no effect and therefore serves no purpose.

Examples:

```c
i++;        // modifies i
x = 10;     // assignment
printf("hi"); // I/O
*p = 3;     // modifies memory
```

These expressions make sense as statements.

Useful expression statement

```c
i++;
```

Effect:

```
i = i + 1
```

Meaningless expression statement

```c
i + 1;
```

Effect:

- compute i + 1
- throw away result

Nothing changes.

## Compound Statements

A compound statement is a block of statements enclosed in curly braces `{}`.

A compound statement has the form

```
{ statements }
```

By putting braces around a group of statements, we can force the compiler to treat
it as a single statement.

Notice that each inner statement still ends with a semicolon, but the compound
statement itself does not.

```c
{
    int i;
    for (i = 0; i < 10; i++)
        printf('%d ', i);
}
```

:::note
C books seem to use several different styles of indentation and brace placement for compound statements. Which style is best?

According to The New Hacker’s Dictionary (Cambridge, Mass.: MIT Press, 1996),
there are four common styles of indentation and brace placement:

- The K&R style, used in Kernighan and Ritchie’s The C Programming Language. In the K&R style,
the left brace appears at the end of a line:
```c
if (line_num == MAX_LINES) {
line_num = 0;
page_num++;
}
```
The K&R style keeps programs compact by not putting the left brace on a line
by itself. A disadvantage: the left brace can be hard to find. (I don’t consider
this a problem, since the indentation of the inner statements makes it clear
where the left brace should be.) The K&R style is the one most often used in
Java, by the way.

- The Allman style, named after Eric Allman (the author of sendmail and other UNIX utilities), puts the left brace on a separate line:
```c
if (line_num == MAX_LINES)
{
line_num = 0;
page_num++;
}
```
This style makes it easy to check that braces come in matching pairs.

- The Whitesmiths style, popularized by the Whitesmiths C compiler, dictates that braces be indented:
```c
if (line_num == MAX_LINES)
    {
    line_num = 0;
    page_num++;
    }
```

- The GNU style, used in software developed by the GNU Project, indents the
braces, then further indents the inner statements:
```c
if (line_num == MAX_LINES)
    {
        line_num = 0;
        page_num++;
    }
```
Which style you use is mainly a matter of taste; there’s no proof that one style is clearly better than the others. In any event, choosing the right style is less important than applying it consistently.

:::

## Selection(Conditional) Statements

### if

The if statement allows a program to choose between two alternatives by testing
the value of an expression. In its simplest form, the if statement has the form:

```
if ( expression ) statement
```

The parentheses around the expression are mandatory; they’re part of
the if statement, not part of the expression.

When an if statement is executed, the expression in the parentheses is evaluated; if the value of the expression is nonzero—which C interprets as true—the statement after the parentheses is executed.

```c
if (line_num == MAX_LINES)
    line_num = 0;
```

The statement `line_num = 0;` is executed if the condition `line_num == MAX_LINES` is true (has a nonzero value).

Don’t confuse `==` (equality) with `=` (assignment). The statement

```
if (i == 0) …
```

tests whether i is equal to 0. However, the statement

```
if (i = 0) …
```

assigns `0` to `i`, then tests whether the result is nonzero. In this case, the test always
fails.

Confusing `==` with `=` is perhaps the most common C programming error,
probably because `=` means "is equal to" in mathematics (and in certain program-
ming languages). Some compilers issue a warning if they notice `=` where `==` would
normally appear.

If the expression in an if statement tests whether a variable falls
within a range of values. we'd write

```c
if (0 <= i && i < n) …
```

which tests whether 0 ≤ i < n. To test the opposite condition (i is outside the range), we'd write

```c
if (i < 0 || i >= n) …
```

Note the use of the `||` operator instead of the && operator.

**Compound Statements**
If we want an if statement to control two or more statements, we use the compound statement.
For example:

```c
if (line_num == MAX_LINES) {
    line_num = 0;
    page_num++;
}
```

Adding braces to statements—even when they're not necessary—is like using parentheses in expressions: both techniques help make a program more readable while at the same time avoiding the possibility that the compiler won't understand the program the way we thought it did.

Using braces even when they're not required has two advantages.

1. First, the program becomes easier to modify, because more statements can easily be added to any if or else clause.
2. Second, it helps avoid errors that can result from forgetting to use braces when adding statements to an if or else clause.

#### if-else

An if statement may have an else clause.

The if-else statement allows a program to choose between three alternatives by testing
the value of an expression. The if-else statement has the form:

```
if ( expression ) statement1
else statement2
```

When an if-else statement is executed, the expression in the parentheses is evaluated; if the value of the expression is nonzero—which C interprets as true—the statement after the parentheses is executed. If the value of the expression is zero, the statement after the else is executed.

```c
if (line_num == MAX_LINES)
    line_num = 0;
else
    line_num++;
```

The statement `line_num = 0;` is executed if the condition `line_num == MAX_LINES` is true (has a nonzero value), and the statement `line_num++;` is executed if the condition is false.

Notice that both "inner" statements end with a semicolon.

The inner statements are
usually indented, but if they’re short they can be put on the same line as the if and
else:

```c
if (i > j) max = i;
else max = j;
```

There are no restrictions on what kind of statements can appear inside an if
statement. In fact, it’s not unusual for if statements to be nested inside other if
statements. Consider the following if statement, which finds the largest of the
numbers stored in i, j, and k and stores that value in max:

```c
if (i > j) {
    if (i > k)
        max = i;
    else
        max = k;
} else {
    if (j > k)
        max = j;
    else
        max = k;
}
```

if statements can be nested to any depth

**Cascaded if Statements**

to test a series of conditions, stopping as soon as one of them is
true. A "cascaded" if statement is often the best way to write such a series of
tests. For example, the following cascaded if statement tests whether n is less
than 0, equal to 0, or greater than 0:

```c
if (n < 0)
    printf("n is less than 0\n");
else
    if (n == 0)
        printf("n is equal to 0\n");
    else
        printf("n is greater than 0\n");
```

Although the second if statement is nested inside the first, C programmers don't
usually indent it. Instead, they align each else with the original if:

```c
if (n < 0)
    printf("n is less than 0\n");
else if (n == 0)
    printf("n is equal to 0\n");
else
    printf("n is greater than 0\n");
```

This arrangement gives the cascaded if a distinctive appearance:

```
if ( expression )
  statement
else if ( expression )
  statement
…
else if ( expression )
  statement
else
  statement
```

The last two lines (else statement) aren’t always present.

#### The "Dangling else" Problem

When if statements are nested, we’ve got to watch out for the notorious "dangling
else" problem. Consider the following example:

```c
if (y != 0)
    if (x != 0)
        result = x / y;
else
    printf("Error: y is equal to 0\n");
```

To which if statement does the else clause belong? The indentation suggests
that it belongs to the outer if statement. However, C follows the rule that an else
clause belongs to the nearest if statement that hasn’t already been paired with an
else. In this example, the else clause actually belongs to the inner if state-
ment, so a correctly indented version would look like this:

```c
if (y != 0)
    if (x != 0)
        result = x / y;
    else
        printf("Error: y is equal to 0\n");
```

To make the else clause part of the outer if statement, we can enclose the inner
if statement in braces:

```c
if (y != 0) {
    if (x != 0)
        result = x / y;
} else
    printf("Error: y is equal to 0\n");
```

This example illustrates the value of braces; if we’d used them in the original if
statement, we wouldn’t have gotten into this situation in the first place.

### conditional expression

C’s if statement allows a program to perform one of two actions depending on the value of a condition. C also provides an operator that allows an expression to produce one of two values depending on the value of a condition(ternary operator).

The conditional expression is just a shorter form of if-else.

Basic Example

```c
int a = 10, b = 20;
int max;

max = (a > b) ? a : b;
```

What happens:

- Condition: a > b → false
- So result = b
- max = 20

Equivalent if Statement

```c
if (a > b)
    max = a;
else
    max = b;
```

Example in printf

```c
int x = 5;
```

printf("%s\n", (x % 2 == 0) ? "Even" : "Odd");

- If x is even → prints "Even"
- Otherwise → "Odd"

**Properties**

1. It returns a value

   Unlike if, the conditional operator is an expression, so it can be used inside assignments, function calls, etc.

   ```c
   int abs_val = (x < 0) ? -x : x;
   ```
2. Only one branch is evaluated

    ```c
    (a > b) ? f() : g();
    ````
    Only one function is called.

3. Associativity (right-to-left)

    ```c
    a > b ? a : b > c ? b : c;
    ```
    This means:
    ```c
    a > b ? a : (b > c ? b : c);
    ```
    Nested Example
    ```c
    int a = 5, b = 10, c = 7;
    int max = (a > b) ? a : (b > c ? b : c);
    ```

**Common Use Cases**

Conditional expressions tend to make programs shorter but harder to under-
stand, so it’s probably best to avoid them. There are, however, a few places in
which they’re tempting;
1. **Absolute value**
    ```c
    int abs = (x < 0) ? -x : x;
    ```
    a safe way to compute the absolute value of an int in C that works even for INT_MIN
    
    Problem with -i for INT_MIN
    
    In 2’s complement:
    - The range of int is typically: [$-2^31$, $2^31$] 
    - For INT_MIN = -2^31, doing -INT_MIN overflows because 2^31 cannot fit in an int. 
    
    So `i >= 0 ? i : -i` is unsafe if `i == INT_MIN`.
    ```c
    #include <stdio.h>
    #include <limits.h>
    
    int safe_abs(int i) {
        return (i >= 0) ? i : (unsigned int)(-(i + 1)) + 1;
    }
    
    int main() {
        int x = INT_MIN;
        printf("Safe absolute value of INT_MIN: %u\n", safe_abs(x));
    
        int y = -17;
        printf("Safe absolute value of -17: %d\n", safe_abs(y));
    
        int z = 42;
        printf("Safe absolute value of 42: %d\n", safe_abs(z));
    
        return 0;
    }
    ```
    How It Works
    1. For positive numbers: returns i normally. 
    2. For negative numbers: 
        - Adds 1 first, negates, casts to unsigned int (avoids overflow), then adds 1 back. 
        - This trick ensures `INT_MIN` becomes $2^31$ in unsigned arithmetic safely.

2. **Min / Max**
   ```c
   int min = (a < b) ? a : b;
   ```
3. Conditional printing

   Calls of printf can sometimes benefit from condition expressions. Instead of

   ```c
   if (i > j)
   printf("%d\n", i);
   else
   printf("%d\n", j);
   ```

   we could simply write

   ```c
   printf("%d\n", i > j ? i : j);
   ```

4. return statement

   Instead of writing

   ```c
   if (i > j)
       return i;
   else
       return j;
   ```

   many programmers would write

   ```c
   return i > j ? i : j;
   ```

### switch

If we need to compare an expression against a series of values to see which one it currently matches, we can use cascaded if statement for this purpose. For example, the following cascaded if statement prints the English word that corresponds to a numerical grade:

```c
if (grade == 4)
    printf("Excellent");
else if (grade == 3)
    printf("Good");
else if (grade == 2)
    printf("Average");
else if (grade == 1)
    printf("Poor");
else if (grade == 0)
    printf("Failing");
else
    printf("Illegal grade");
```
As an alternative to this kind of cascaded if statement, C provides the switch statement. The following switch is equivalent to our cascaded if:
```c
switch (grade) {
    case 4: printf("Excellent");
            break;
    case 3: printf("Good");
            break;
    case 2: printf("Average");
            break;
    case 1: printf("Poor");
            break;
    case 0: printf("Failing");
            break;
    default: printf("Illegal grade");
            break;
}
````
When this statement is executed:
1. the value of the variable grade is tested against `4`, `3`, `2`, `1`, and `0`. 
2. If it matches `4`, for example, the message `Excellent` is printed, then the break statement transfers control to the statement following the switch. 
3. If the value of grade doesn’t match any of the choices listed, the default case applies, and the message `Illegal grade` is printed.

The switch statement in C is a multi-way branch control structure used to select one of many code blocks based on the value of an expression. It’s often cleaner and faster than writing many if-else statements.

The switch statement allows a program to choose between several alternatives by testing the value of an expression. The switch statement has the form:
```
switch ( expression ) {
  case constant-expression : statements
  …
  case constant-expression : statements
  default : statements
}
```
- **Controlling expression** 
    - The word switch must be followed by an integer expression in parentheses. 
    - Characters are treated as integers in C and thus can be tested in switch statements. 
    - Floating-point numbers and strings don’t qualify.
- **Case labels**
    - Each case begins with a label of the form case constant-expression.
    - A constant expression is much like an ordinary expression except that it can’t contain variables or function calls. 
    - Thus, `5` is a constant expression, 
    - and `5 + 10` is a constant expression, 
    - but `n + 10` isn’t a constant expression (unless n is a macro that represents a constant). 
        ```c
        #define A 2
        
        switch (x) {
            case A:   // ✔ VALID
                printf("OK");
        }
        ```
        Works because A is replaced by 2 at compile time.
    - The constant expression in a case label must evaluate to an integer (characters are also acceptable).
- **Statements** 
    - After each case label comes any number of statements. 
    - No braces are required around the statements(one of the few places in C where braces aren’t required.) 
    - The last statement in each group is normally break.

**How It Works**

When a switch statement is executed:
1. the `expression` in the parentheses is evaluated **once**; 
2. the value of the `expression` is compared to the values of the `constants` in the `case labels`. 
3. If a match is found, the `statement` after the matching `case label` is executed. 
4. If no match is found, the `statement` after the `default label` is executed.
5. **The break statement**:
    - Stops execution of the switch.
    - Prevents falling into the next case.

```c
switch (line_num) {
    case MAX_LINES:
        line_num = 0;
        break;
    default:
        line_num++;
}
```
The statement `line_num = 0;` is executed if the condition `line_num == MAX_LINES` is true (has a nonzero value), and the statement `line_num++;` is executed if the condition is false.

**Example**
```c
#include <stdio.h>

int main(void) {
    int day = 3;

    switch (day) {
        case 1:
            printf("Sunday\n");
            break;
        case 2:
            printf("Monday\n");
            break;
        case 3:
            printf("Tuesday\n");
            break;
        default:
            printf("Invalid day\n");
    }

    return 0;
}
```
Output: Tuesday

Duplicate case labels aren’t allowed. 

The order of the cases doesn’t matter; in particular, the default case doesn’t need to come last.

Only one constant expression may follow the word case; however, several case labels may precede the same group of statements:
```c
switch (grade) {
    case 4:
    case 3:
    case 2:
    case 1: printf("Passing");
            break;
    case 0: printf("Failing");
            break;
    default: printf("Illegal grade");
            break;
}
```
To save space, programmers sometimes put several case labels on the same line:
```c
switch (grade) {
    case 4: case 3: case 2: case 1:
            printf("Passing");
            break;
    case 0: printf("Failing");
            break;
    default: printf("Illegal grade");
            break;
}
```
there’s no way to write a case label that specifies a range of values, as there is in some programming languages.

A switch statement isn’t required to have a default case. If default is missing and the value of the controlling expression doesn’t match any of the case labels, control simply passes to the next statement after the switch.

**The Role of the break Statement**

executing a break statement causes the program to "break" out of the switch
statement; execution continues at the next statement after the switch.

If you omit break, execution continues into the next case.
```c
int x = 1;

switch (x) {
    case 1:
        printf("One\n");
    case 2:
        printf("Two\n");
    case 3:
        printf("Three\n");
}
```
Output:
```
One
Two
Three
```
This is called **fall-through**.

The reason that we need break has to do with the fact that the switch statement is really a form of "computed jump." 

When the controlling expression is evaluated:
1. control jumps to the case label matching the value of the switch expression. 
2. A case label is nothing more than a marker indicating a position within the switch. 
3. When the last statement in the case has been executed, control "falls through" to the first statement in the following case; the case label for the next case is ignored. 
4. Without break (or some other jump statement), control will flow from one case into the next. 

Consider the following switch statement:
```c
switch (grade) {
    case 4: printf("Excellent");
    case 3: printf("Good");
    case 2: printf("Average");
    case 1: printf("Poor");
    case 0: printf("Failing");
    default: printf("Illegal grade");
}
```
If the value of grade is 3, the message printed is
```
GoodAveragePoorFailingIllegal grade
```
**Intentional Fall-Through**

Sometimes it's useful:
```c
int grade = 'B';

switch (grade) {
    case 'A':
    case 'B':
    case 'C':
        printf("Pass\n");
        break;
    case 'D':
    case 'F':
        printf("Fail\n");
        break;
}
```
Multiple cases share the same block.

Since deliberately falling through from one case into the next is rare, it’s a good idea to point out any deliberate omission of break:
```c
switch (grade) {
    case 4: case 3: case 2: case 1:
            num_passing++;
            /* FALL THROUGH */
    case 0: total_grades++;
            break;
}
```
Without the comment, someone might later fix the "error" by adding an unwanted break statement.

Although the last case in a switch statement never needs a break statement, it’s common practice to put one there anyway to guard against a "missing break" problem if cases should later be added.

**Rules & Constraints**
1. Expression Type
    - Must be integral type:
        - int, char, enum
    - Not allowed:
        - float, double, string
2. Case Labels
    - Must be constant expressions
      ```
      case 10:     // ✔ OK
      case x:      // ❌ Not OK (if x is variable)
      ```
3. No Duplicate Cases
    ```
    case 1:
    case 1:  // ❌ Error
    ```
4. Default Case
    - Optional
    - Executes if no match is found
5. Position of default
    - Can appear anywhere (not just last)

**Common Pitfalls**
- Missing break
    - Leads to unintended fall-through.
- Using non-constant case
    ```c
    int a = 5;
    case a:   // ERROR
    ```
    | Part        | Requirement         |
    | ----------- | ------------------- |
    | `switch(x)` | Can be a variable ✔ |
    | `case ???`  | Must be constant ❗  |

    this Works because A is replaced by 2 at compile time.
    ```c
    #define A 2
    
    switch (x) {
        case A:   // ✔ VALID
            printf("OK");
    }
    ```
    In C (not C++), `const int` is NOT a constant expression.
    ```c
    const int a = 2;
    
    switch (x) {
        case a:   // ❌ STILL INVALID in C
    }
    ```
- Forgetting default
    - Can miss handling unexpected values.


**Compiler / Assembly Insight**

Many compilers (like GCC/Clang) implement switch using:
- Jump tables (for dense case ranges)
- Binary search / if chains (for sparse values)

Example:
```

    case 1: ...
    case 2: ...
    case 3: ...
}
```
May compile to:
```
jump_table[x]
```
This makes it O(1) dispatch in many cases.

#### switch vs if
A switch statement is often easier to read than a cascaded if statement.

switch statements are often faster than if statements, especially when there are more than a handful of cases.

When to Use switch vs if
| Use `switch`         | Use `if-else`      |
| -------------------- | ------------------ |
| Many discrete values | Complex conditions |
| Equality checks only | Ranges (`x > 5`)   |
| Cleaner structure    | More flexible      |

## Iteration(Loops) Statements
C’s iteration statements, allow us to set up loops.

A **loop** is a statement whose job is to repeatedly execute some other statement (the **loop body**). 

In C, every loop has a **controlling expression**. Each time the **loop body** is executed (an iteration of the loop), the controlling expression is evaluated; if the expression is true—has a value that’s not zero—the loop continues to execute.

C provides three iteration statements:
- **while**: The while statement is used for loops whose controlling expression is tested before the loop body is executed.
- **do-while**: The do statement is used if the expression is tested after the loop body is executed.
- **for**: The for statement is convenient for loops that increment or decrement a counting variable.

### while
The while loop in C is one of the core iteration (looping) constructs. It repeatedly executes a block of code as long as a given condition is true.

The while statement has the form
```
while ( expression ) statement
```
- The expression inside the parentheses is the **controlling expression**; 
- the statement after the parentheses is the **loop body**. 
#### Basic Syntax
```c
while (condition) {
    // body (statements)
}
```
- **condition** → any expression that evaluates to true (non-zero) or false (0) 
- The loop runs **only if the condition is true** 
- The condition is checked before each iteration

Here’s an example:
```c
while (i < n) /* controlling expression */
    i = i * 2; /* loop body */
```
The parentheses are mandatory and that nothing goes between the right parenthesis and the loop body.
#### How It Works (Execution Flow)
When a while statement is executed: 
1. Evaluate the condition: the controlling expression is evaluated first. 
2. If its value is nonzero (true ≠ 0), the loop body is executed.
3. the expression is tested again: After execution, go back and check condition again.
3. Repeat until condition becomes false (0: The process continues in this fashion—first testing the controlling expression, then executing the loop body—until the controlling expression eventually has the value zero.

If the condition is false from the beginning → the loop runs zero times.

let’s trace the execution of the following statements, which display a series of “countdown” messages:
```c
i = 10;
while (i > 0) {
    printf("T minus %d and counting\n", i);
    i--;
}
```
1. Before the while statement is executed, the variable i is assigned the value 10.
2. Since 10 is greater than 0, the loop body is executed, causing the message "T minus 1 and counting" to be printed and i to be decremented. 
3. The condition `i > 0` is then tested again. Since 9 is greater than 0, the loop body is executed once more. 
4. This process continues until the message "T minus 1 and counting" is printed and i becomes 0. 
5. The test i > 0 then fails, causing the loop to terminate.


Although the loop body must be a single statement, that’s merely a technicalty. If we want more than one statement, we can just use braces to create a single compound statement:
```c
while (i > 0) {
    printf("T minus %d and counting\n", i);
    i--;
}
```
#### Control Flow Graph (CFG)
```
A while loop forms this structure:

        +--------+
        | check  |
        +--------+
         /    \
      true    false
      /         \
  +-------+     end
  | body  |
  +-------+
      |
      +------> back to check
```
#### Key Properties
The countdown example leads us to make several observations about the while statement:
- The controlling expression is false when a while loop terminates. 
    - Thus, when a loop controlled by the expression `i > 0` terminates, i must be less than or equal to 0. (Otherwise, we’d still be executing the loop!)
- The body of a while loop may not be executed at all. 
    - Since the controlling expression is tested before the loop body is executed, it’s possible that the body isn’t executed even once. If i has a negative or zero value when the countdown loop is first entered, the loop will do nothing.
- A while statement can often be written in a variety of ways. 
    - For example, we could make the countdown loop more concise by decrementing i inside the call of printf:
        ```c
        while (i > 0)
            printf("T minus %d and counting\n", i--);
        ```
- Pre-test Loop
    - Condition checked before execution
    - May run zero times
- Flexible Condition
    ```c
    while (x)      // same as while (x != 0)
    while (!done)
    while (ptr != NULL)
    ```
#### Common Pitfalls
1. Infinite Loop (forgot update)
    ```c
    int i = 1;
    while (i <= 5) {
        printf("%d", i);
        // missing i++
    }
    ```
2. Assignment instead of comparison
    ```c
    while (x = 5)   // WRONG (always true unless x becomes 0)
    Correct:
    while (x == 5)
    ```
#### Typical Use Cases
- Unknown number of iterations 
- Reading input until a condition 
    ```c

    printf("Enter numbers (0 to stop): ");
    scanf("%d", &num);
    
    while (num != 0) {
        printf("You entered: %d\n", num);
        scanf("%d", &num);
    }
    ```
- Looping until a flag changes

| Use Case                        | Best Choice |
| ------------------------------- | ----------- |
| Known number of iterations      | `for`       |
| Unknown / condition-driven      | `while`     |
| At least one execution required | `do-while`  |

#### Infinite Loops
A while statement won’t terminate if the controlling expression always has a nonzero value. In fact, C programmers sometimes deliberately create an infinite loop by using a nonzero constant as the controlling expression:
```c
while (1){
    
}
```
A while statement of this form will execute forever unless its body contains a statement that transfers control out of the loop (`break`, `goto`, `return`) or calls a function that causes the program to terminate.

Infinite loops (`while (1)` in C) are not just academic—they’re fundamental in real systems where programs are meant to run continuously and react to events. The key idea: the loop itself doesn’t terminate; instead, work inside the loop is controlled by conditions, events, or external signals.

**practical and real world usage of Infinite Loops**
1. **Event Loops (Core of Applications)**
   
   Most interactive software runs an infinite loop waiting for events.
   
   Example: GUI / OS-style loop
   ```c
   while (1) {
       Event e = get_event();   // blocking call
       handle_event(e);
   }
   ```
   Real-world usage:
   * Desktop apps (Windows, Linux GUI frameworks)
   * Game engines
   * Browsers
   The loop never exits—the application runs until the user closes it.

2. **Server Programs (Backend Systems)**

   Servers must always be ready to accept requests.

   Example: TCP server
   ```c
   while (1) {
       int client = accept(server_fd, NULL, NULL);
       handle_client(client);
   }
   ```
   Real-world usage:
   * Web servers (Apache, Nginx)
   * Backend APIs (even frameworks like Spring Boot internally rely on this pattern)
   * Database servers
   * If this loop stops, your service is down.

3. **Embedded Systems (Microcontrollers)**

   Devices like routers, washing machines, or IoT sensors run forever.

   Example:
   ```c
   while (1) {
       read_sensor();
       control_motor();
   }
   ```
   Real-world usage:
   * Arduino / STM32 firmware
   * Automotive ECUs
   * Medical devices
   * There is often no "exit"—only power off.

4. **Operating System Kernels**

   At the lowest level, even an OS uses infinite loops.

   Example (simplified scheduler loop):
   ```c
   while (1) {
       schedule_next_process();
   }
   ```
   The OS must continuously manage processes, interrupts, and hardware.

5. **Game Loops**

   Games rely on a continuous loop for rendering and logic updates.

   Example:
   ```c
   while (1) {
       process_input();
       update_game();
       render_frame();
   }
   ```
   Runs ~60 times per second (or more).

6. **Polling Systems**

   Sometimes systems repeatedly check a condition.

   Example:
   ```c
   while (1) {
       if (data_available())
           process_data();
   }
   ```
   Real-world usage:
   * Hardware polling
   * Monitoring systems
   * Note: This is often improved with interrupts or sleep to avoid CPU waste.

7. **Background Workers / Daemons**

   Programs that run in the background performing tasks.

   Example:
   ```c
   while (1) {
       check_queue();
       process_jobs();
   }
   ```
   Real-world usage:
   * Job schedulers
   * Message queue consumers (Kafka, RabbitMQ workers)
   * Cron-like systems

8. **Retry / Resilience Loops**

   Keep trying until success.

   Example:
   ```c
   while (1) {
       if (connect_to_server())
           break;
       sleep(1);
   }
   ```
   Used in distributed systems for fault tolerance.

**Important Design Patterns**

1. Controlled Infinite Loop
   ```c
   while (running) {
       ...
   }
   ```
   * The variable `running` can be changed externally (via signal, flag).

2. Loop with Sleep (Avoid CPU waste)
   ```c
   while (1) {
       do_work();
       sleep(1);
   }
   ```

3. Event-Driven (Best practice)
   ```c
   while (1) {
       wait_for_event();  // blocks to avoid CPU waste
   }
   ```

**Pitfalls (Real Systems)**
- ❌ Busy Waiting (Bad)
  ```c
  while (!ready);  // wastes CPU
  ```
- ❌ No Exit Strategy: Hard to shut down cleanly 
- ❌ Resource Leaks: Infinite loops magnify memory/file leaks

An “infinite loop” in production is rarely truly uncontrolled. It is:
- Externally controlled (signals, flags) 
- Event-driven (blocking calls) 
- Resource-aware (sleep, async)

Think of infinite loops as: “Keep the system alive and responsive forever, until something external tells it to stop.”

### do Statement
The **`do...while` statement in C** is a looping construct that guarantees the loop body executes **at least once**, regardless of the condition. 

The **`do...while` statement is closely related to the `while` statement; in fact, the do statement is essentially just a while statement whose controlling expression is tested
after each execution of the loop body. 

The do statement has the form
```
do statement while ( expression ) ;
```
As with the while statement, the body of a do statement must be one statement
(possibly compound, of course) and the controlling expression must be enclosed
within parentheses.

####  Basic Syntax

```c
do {
    // statements
} while (condition);
```

Notice the **semicolon (`;`) after `while(condition)`** — this is required. 

Incidentally, it’s a good idea to use braces in all do statements, whether or not
they’re needed, because a do statement without braces can easily be mistaken for a
while statement:
```c
do
    printf("T minus %d and counting\n", i--);
while (i > 0);
```
A careless reader might think that the word while was the beginning of a while
statement.

####  How It Works (Execution Flow)
When a do statement is executed, the loop body is executed first, then the controlling expression is evaluated. If the value of the expression is nonzero, the loop body is executed again and then the expression is evaluated once more. Execution of the do statement terminates when the controlling expression has the value 0 after the loop body has been executed.

1. Execute the loop body **first**
2. Evaluate the condition
3. If condition is **true → repeat**
4. If condition is **false → exit loop** 

Let’s rewrite the countdown example of Section 6.1, using a do statement this
time:
```c
i = 10;
do {
    printf("T minus %d and counting\n", i);
    --i;
} while (i > 0);
```
When the do statement is executed, the loop body is first executed, causing the
message `T minus 10 and counting` to be printed and `i` to be decremented.
The condition `i > 0` is now tested. Since `9` is greater than `0`, the loop body is executed a second time. This process continues until the message `T minus 1 and counting` is printed and `i` becomes 0. The test `i > 0` now fails, causing the loop
to terminate. 

As this example shows, the do statement is often indistinguishable
from the while statement. The difference between the two is that the body of a
do statement is always executed at least once; the body of a while statement is
skipped entirely if the controlling expression is 0 initially.
####  Key Property

Unlike `while`:

```c
while(condition) {
    // may never run
}
```

👉 `do...while`:

```c
do {
    // always runs at least once
} while(condition);
```

```c
#include <stdio.h>

    int i = 1;

        printf("%d\n", i);
        i++;
    } while (i <= 5);

    return 0;

```

```
2
3
4
5
```


At compiler level, `do...while` is often translated into:

```
loop_start:
    ; body
    evaluate condition
    if true → jump to loop_start
```

👉 Key difference from `while`:

* `while` checks condition **before jumping**
* `do...while` checks **after executing** 

####  Practical Insight

Think of `do...while` like:

> “Do the task first, then decide if you should continue.”

Example analogy:

* You try a password **once**, then decide if you retry
* You display a menu **once**, then repeat if needed 

####  When NOT to Use It

Avoid when:

* Execution should depend on condition **before running**
* It reduces readability (common in large systems)

#### real-world system-level use cases
Here are **real-world, system-level use cases** where `do...while` is actually meaningful—not just academic examples. I’ll focus on how it appears in **OS kernels, embedded firmware, drivers, and low-level systems code**.

##### Kernel / OS Event Handling Loops

In operating systems (like the Linux kernel), you often need to:

* Process events
* Then decide whether to continue based on system state

Pattern:

```c
do {
    event = get_next_event();
    handle_event(event);
} while (event != NO_MORE_EVENTS);
```

Why `do...while`?

* You **must process at least one event**
* The condition depends on the **result of processing**

👉 This shows up in:

* Interrupt handling loops
* Work queues
* Scheduler subsystems

##### Device Drivers (Hardware Polling)

Drivers often need to **poll hardware registers** until a condition changes.

Example (simplified):

```c
do {
    status = read_device_status();
} while (!(status & READY_FLAG));
```

Real-world usage:

* Waiting for disk I/O completion
* Waiting for network packet readiness
* GPU / DMA completion checks

Why `do...while`?

* Hardware must be checked **at least once**
* Status is only meaningful **after first read**

##### Embedded Systems (Microcontrollers)

In firmware (Arduino, STM32, etc.), `do...while` is used for:

A. Sensor Stabilization

```c
do {
    value = read_sensor();
} while (value < THRESHOLD);
```

👉 Example:

* Temperature sensor warm-up
* Analog signal stabilization

B. Button Debouncing

```c
do {
    state = read_button();
} while (state == PRESSED);
```

👉 Ensures:

* Button release is detected properly
* Avoids noisy repeated triggers

##### Retry Mechanisms (Critical Systems)

Used when an operation **must be attempted at least once**, then retried.

Example: Network Transmission

```c
int retries = 3;

do {
    result = send_packet();
    retries--;
} while (result != SUCCESS && retries > 0);
```

👉 Real systems:

* TCP/IP stacks
* Embedded communication (UART, SPI, I2C)
* Distributed systems retry logic

##### Memory Allocation / Resource Acquisition

Sometimes systems try repeatedly to acquire a resource:

```c
do {
    ptr = allocate_memory();
} while (ptr == NULL);
```

👉 Seen in:

* Kernel allocators
* Embedded systems with limited memory

⚠️ Often combined with timeout in real systems

##### Parsing Streams / Buffers (Low-Level I/O)

When processing streams:

```c
do {
    byte = read_byte();
    process(byte);
} while (byte != END_OF_STREAM);
```

👉 Used in:

* File systems
* Network packet parsing
* Serial communication

##### Macro Tricks in Systems Programming (VERY IMPORTANT)

This is one of the **most famous real uses** of `do...while(0)`.

Safe Macro Pattern:

```c
#define LOG(msg) \
do { \
    printf("LOG: %s\n", msg); \
} while (0)
```

Why this matters?

Without `do...while(0)`:

```c
if (x)
    LOG("Hello");
else
    do_something();
```

👉 Can break due to macro expansion!

`do...while(0)` ensures:

* Macro behaves like a **single statement**
* Safe in all control structures

👉 Used heavily in:

* Linux kernel macros
* Embedded SDKs
* Logging frameworks

##### Interrupt Handling (Bare Metal Systems)

```c
do {
    irq = get_pending_interrupt();
    service_interrupt(irq);
} while (more_interrupts_pending());
```

👉 Why?

* Interrupt queue must be processed at least once
* Continue until queue is empty

##### State Machines (Low-Level Control Systems)

```c
do {
    state = next_state(state);
} while (state != FINAL_STATE);
```

👉 Used in:

* Protocol implementations
* Embedded controllers
* Compilers / interpreters

##### Bootloaders / Initialization Routines

```c
do {
    status = init_hardware();
} while (status != OK);
```

👉 Found in:

* BIOS / UEFI logic
* Microcontroller startup code

##### When Systems Engineers Prefer `do...while`

They use it when:

- The operation **must happen first**
- The condition depends on **result of that operation**
- Cleaner than duplicating code before a `while`

##### When They Avoid It

Even in low-level systems, engineers avoid `do...while` when:

* Loop may not need to run at all
* It reduces readability
* Infinite loops are better expressed as:

  ```c
  while (1)
  ```

**Key Insight**

`do...while` is not just a loop — it's a **post-condition loop**

Meaning: “Execute → then decide”

This is exactly what many **hardware, OS, and protocol operations require**

**Final Takeaway**

In real systems, `do...while` is used in:

* Kernel event loops
* Hardware polling
* Driver communication
* Retry mechanisms
* Macro safety (`do...while(0)`)
* Embedded firmware control

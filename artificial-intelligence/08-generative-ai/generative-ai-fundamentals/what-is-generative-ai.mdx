## 1. Overview

### 1.1 Definition

Generative Artificial Intelligence (Generative AI or GenAI) is a branch of Artificial Intelligence that focuses on building models capable of generating new content based on patterns, structures, and relationships learned from existing data.

Generative AI employs neural networks and deep learning algorithms to identify
patterns within existing data, generating original content as a result. By analyzing
large volumes of data, GenAI algorithms synthesize knowledge to create novel text,
images, audio, video, and other forms of output.

Unlike traditional AI systems, which primarily analyze data, classify objects, make predictions, or recognize patterns, Generative AI models can create entirely new outputs.

These outputs can include:

- Text: Articles, explanations, summaries, emails, source code, and conversations.
- Images: Photographs, illustrations, diagrams, and artwork.
- Audio: Speech, music, sound effects, and voice synthesis.
- Video: Video clips, animations, and realistic scenes.
- Code: Programs, algorithms, tests, and software documentation.
- 3D content: Objects, environments, and 3D models.
- Scientific structures: Protein structures, molecular candidates, and material designs.

For example, when you ask an AI model:

> Explain how a Java HashMap works and provide an implementation.

A Generative AI model processes your request and generates a new response using patterns and knowledge learned during training.

It does not simply retrieve a predefined answer. It generates a sequence of tokens that forms a meaningful response.

### 1.2 Generative AI vs Traditional AI

An important distinction is that Artificial Intelligence includes multiple approaches, and Generative AI is one of them.

| Aspect         | Traditional / Predictive AI        | Generative AI                       |
| -------------- | ---------------------------------- | ----------------------------------- |
| Main objective | Analyze and predict                | Generate new content                |
| Input          | Data and features                  | Prompts, data, context              |
| Output         | Classification, prediction, scores | Text, images, audio, code, etc.     |
| Typical task   | Detect spam emails                 | Generate an email                   |
| Typical task   | Identify objects in images         | Generate an image                   |
| Typical task   | Predict house prices               | Generate a property description     |
| Typical models | Decision trees, SVM, Random Forest | Transformers, GANs, VAEs, Diffusion |

While GenAI has captured much of the recent attention, it is important to understand how it differs from predictive AI. Both fall under the ML umbrella, but they
serve different purposes. Predictive AI is focused on estimating outcomes based on
historical data, while GenAI creates entirely new content based on learned patterns.

| Aspect | Predictive AI | Generative AI |
| --- | --- | --- |
| Main idea | Makes predictions or classifications based on existing data | Generates new content that resembles training data |
| Examples | Churn prediction, fraud detection, product recommendation | Text generation, image synthesis, code completion |
| Output | Labels, probabilities, or numerical values | Structured or unstructured content such as text or images |
| Typical models | Decision trees, logistic regression, shallow neural networks | Transformers and diffusion models |
| Evaluation | Accuracy or error rate | Creativity, coherence, or usefulness of output |

Understanding this distinction is useful because it shapes the way you integrate AI
into your applications. Predictive AI often plays a supporting role in decision making,
while generative AI can directly shape user experiences through interaction and
content creation.

Example:

Consider an email application.

- Traditional AI: Determines whether an email is spam or legitimate.
- Generative AI: Writes an email based on your instructions.
- Combined AI system: Generates an email and uses a classification model to check whether it contains potentially malicious content.

Traditional AI and Generative AI are not mutually exclusive. Modern applications frequently combine them.

### 1.2 Generative AI vs DL
The advances in DL have laid the groundwork for generative AI (GenAI), which
is all about generating new content such as text, images, and code. This area has
received the most attention in recent years mainly because of its impressive demos
and results around text generation and live chats. GenAI is considered both a distinct
research discipline and an application of DL techniques to create new behaviors.
As a distinct research discipline, GenAI integrates a wide range of techniques and
approaches that focus on generating original content, such as text, images, audio, or
videos. Researchers in this field explore various new methods for training models to
generate coherent, realistic, and often creative outputs that get very close to perfectly
mimicking human-like behavior.

### 1.3 Why Generative AI Matters

Generative AI changes how humans interact with computers.

Traditionally, users had to understand application interfaces, programming languages, and predefined operations to accomplish tasks.

With Generative AI, users can express their intentions using natural language, and an AI model can generate an appropriate response or artifact.

Its importance comes from several capabilities:

1. Content generation: Produces text, images, audio, video, and code.
2. Knowledge assistance: Explains complex concepts and summarizes information.
3. Software development: Helps generate, understand, debug, and test code.
4. Automation: Automates tasks involving language, documents, and structured information.
5. Personalization: Generates content adapted to individual requirements.
6. Scientific discovery: Helps explore molecular structures, materials, and biological systems.
7. Human-computer interaction: Enables natural-language interfaces to software systems.

## 2. Key Concepts

To understand Generative AI, you first need to understand its fundamental terminology and the technologies behind it.

### 2.1 Artificial Intelligence (AI)

Artificial Intelligence is the broad field of computer science concerned with creating systems capable of performing tasks that normally require human intelligence.

Examples:

- Reasoning and problem-solving.
- Understanding language.
- Recognizing images.
- Learning from experience.
- Planning and decision-making.

Generative AI is a specialized area within this broader field.

### 2.2 Machine Learning (ML)

Machine Learning is a subset of AI in which systems learn patterns from data instead of relying exclusively on explicitly programmed rules.

For example, instead of manually writing rules to identify spam emails, we train an ML model using thousands of examples of spam and legitimate emails.

The model learns statistical relationships that help it classify new emails.

### 2.3 Deep Learning (DL)

Deep Learning is a subset of Machine Learning based on artificial neural networks containing multiple computational layers.

These networks learn increasingly complex representations of data.

For example, an image recognition neural network might learn:

- Early layers: Edges and basic shapes.
- Intermediate layers: Textures and object parts.
- Later layers: Complete objects and semantic features.

Deep Learning provides the foundation for most modern Generative AI systems.

### 2.4 Neural Networks

A Neural Network is a computational model inspired loosely by biological neural systems.

It consists of interconnected computational units called neurons.

A simplified neural network:

```
                 INPUT LAYER
                x1   x2   x3
                 \   |   /
                  \  |  /
               HIDDEN LAYER
                 h1  h2
                  \  /
                   \/
               OUTPUT LAYER
                    y
```

Each connection has a weight, and neurons apply mathematical operations and activation functions to their inputs.

A simplified neuron computes:

$$
y = f\left(\sum\_{i=1}^{n}w_i x_i+b\right)
$$

Where:

- $x_i$: Input values.
- $w_i$: Learned weights.
- $b$: Bias.
- $f$: Activation function.
- $y$: Output.

During training, the network adjusts its weights to reduce prediction errors.

### 2.5 Foundation Models

A Foundation Model is a large, general-purpose model trained on broad datasets that can be adapted to perform multiple downstream tasks.

Rather than training a completely separate model for every application, developers can use one foundation model for different purposes.

For example, a language foundation model can be adapted to:

- Answer questions.
- Summarize documents.
- Translate languages.
- Generate source code.
- Extract structured information.
- Support conversational applications.

Foundation models are a central concept in modern Generative AI.

### 2.6 Large Language Models (LLMs)

A Large Language Model (LLM) is a type of foundation model trained to process and generate human language.

Examples include:

- GPT.
- Claude.
- Gemini.
- Llama.

LLMs can perform tasks such as:

- Text generation.
- Question answering.
- Code generation.
- Translation.
- Summarization.
- Reasoning and problem-solving.

An important characteristic of an LLM is that it learns statistical relationships between tokens and uses those relationships to generate text.

### 2.7 Tokens and Tokenization

A token is a unit of text processed by a language model.

A token can represent:

- A complete word.
- Part of a word.
- A punctuation mark.
- A character or group of characters.

For example, the sentence:

```
Generative AI is powerful.
```

Might be divided into tokens similar to:

```
["Generative", " AI", " is", " powerful", "."]
```

The actual tokenization depends on the model's tokenizer.

Tokenization is the process of converting input text into tokens that a model can process.

Why does tokenization matter?

- Models have maximum context-window sizes.
- API usage is frequently measured in tokens.
- Tokenization affects processing cost and performance.
- Different tokenizers may split the same text differently.

### 2.8 Embeddings

An embedding is a numerical representation of data in a vector space.

For example, a text embedding converts a sentence into a vector:

$$
\text{"Java is a programming language"} \rightarrow [0.12,-0.34,0.81,\ldots]
$$

The purpose is to represent semantic and contextual relationships numerically.

Similar meanings often produce vectors that are close together in the embedding space.

Embeddings are particularly important in:

- Semantic search.
- Recommendation systems.
- Retrieval-Augmented Generation (RAG).
- Document similarity.
- Clustering.

### 2.9 Parameters and Hyperparameters

These two terms are important because they describe different aspects of model training.

Parameters are values learned by the model during training.

Examples:

- Neural network weights.
- Bias values.
- Transformer attention weights.

Hyperparameters are configuration values selected before or during the training process.

Examples:

- Learning rate.
- Batch size.
- Number of training epochs.
- Number of network layers.
- Hidden dimension size.

For text generation, additional inference parameters include:

- Temperature.
- Top-k.
- Top-p.
- Maximum output tokens.

### 2.10 Prompt Engineering

Prompt Engineering is the practice of designing inputs that guide a Generative AI model toward a desired output.

For example:

Weak prompt:

```
Explain Java.
```

More effective prompt:

```
Explain Java HashMap to a beginner.

Include:
1. Internal data structure.
2. Hashing mechanism.
3. Collision handling.
4. Time complexity.
5. Java implementation.
6. A practical example.
```

A well-structured prompt provides context, instructions, constraints, and output expectations.

### 2.11 Training Data

Training data is the information used to teach a model.

Depending on the model, this can include:

- Books and articles.
- Websites and documents.
- Source code repositories.
- Images and their descriptions.
- Audio recordings.
- Videos.
- Scientific datasets.

The quality, diversity, quantity, and licensing of training data significantly affect model capabilities.

### 2.12 Context Window

The context window is the maximum amount of information a model can process as context during a particular interaction.

It is generally measured in tokens.

For example, the context may contain:

```
System instructions
        +
Previous conversation
        +
Current user prompt
        +
Retrieved documents
        +
Model response (generation budget)
```

A larger context window allows an application to provide more information to a model, but it does not automatically guarantee better understanding or accuracy.

### 2.13 Fine-Tuning

Fine-tuning is the process of adapting a previously trained model using additional training data.

For example:

1. Start with a general-purpose language model.
2. Collect Java programming questions and answers.
3. Prepare a training dataset.
4. Fine-tune the model using that dataset.
5. Evaluate its performance on Java-related tasks.

The objective is to improve its behavior for a particular domain or task.

### 2.14 Retrieval-Augmented Generation (RAG)

RAG is an architecture that combines information retrieval with Generative AI.

Instead of relying exclusively on the information learned during training, the application retrieves relevant information from an external knowledge source and provides it to the model.

Example:

Suppose you want to build an AI assistant for TechnoWiki.

Without RAG:

```
User question
     |
     v
Language Model
     |
     v
Generated Answer
```

The model primarily relies on its learned knowledge and supplied conversation context.

With RAG:

```
                   TechnoWiki
                  Documentation
                       |
                       v
                 Document Index
                       |
                       |
User Question --------+
       |
       v
   Embedding
       |
       v
 Semantic Search
       |
       v
 Relevant Documents
       |
       v
  Language Model
       |
       v
 Generated Answer
```

RAG is useful when working with:

- Private company documentation.
- Frequently updated information.
- Large document collections.
- Technical documentation.
- Internal knowledge bases.

An important distinction:

- Fine-tuning changes model parameters.
- RAG supplies additional information at inference time.

RAG does not inherently teach the model new permanent knowledge.

### 2.15 Hallucination

A hallucination occurs when a Generative AI model produces information that appears plausible but is incorrect, unsupported, or fabricated.

For example, a model might:

- Invent a programming library.
- Provide a nonexistent API method.
- Generate incorrect mathematical reasoning.
- Reference a nonexistent research paper.
- Provide an incorrect technical explanation.

This happens partly because language generation optimizes statistical and learned objectives rather than guaranteeing factual correctness.

Ways to reduce hallucinations include:

- RAG and grounding.
- Reliable external tools.
- Structured output validation.
- Model evaluation.
- Human verification.

However, none of these techniques guarantees that hallucinations will disappear.

### 2.16 Multimodal AI

Multimodal AI refers to models that can process or generate multiple types of information.

For example:

```
             Multimodal Model
                    |
          +---------+---------+
          |         |         |
         Text     Images     Audio
          |         |         |
          +---------+---------+
                    |
                  Output
```

A multimodal model might receive an image and a text question and generate an explanation.

Another model might receive text and generate speech.

### 2.17 AI Agents

An AI agent is an application that uses an AI model to pursue a goal, potentially by planning tasks, using tools, observing results, and taking further actions.

For example, a software development agent might:

1. Receive a request to fix a bug.
2. Inspect the source code.
3. Identify the affected files.
4. Modify the implementation.
5. Run tests.
6. Analyze test failures.
7. Revise the implementation.

An agent is not simply another name for an LLM. It is a larger system built around one or more models, tools, orchestration logic, and potentially memory.&#x20;

## 3. Underlying Principles and Common Approaches

Generative AI is not a single algorithm. Different model architectures use different mathematical approaches to learn data distributions and generate new samples.

The most important approaches are:

Generative AI model families

1\. Autoregressive Models

Generate content sequentially, predicting the next token or element.

Common application: Text and code generation.

2\. Generative Adversarial Networks (GANs)

Use two competing neural networks: a generator and a discriminator.

Common application: Image generation and synthetic data.

3\. Variational Autoencoders (VAEs)

Learn a probabilistic latent representation and generate samples from it.

Common application: Image generation and representation learning.

4\. Diffusion Models

Learn to reverse a gradual noise-adding process.

Common application: Image, audio, and video generation.

5\. Flow-Based Models

Learn invertible transformations between simple probability distributions and complex data distributions.

Common application: Density estimation and generative modeling.

### 3.1 Autoregressive Models

An autoregressive model generates a sequence one element at a time.

For a language model, that element is usually a token.

For example:

```
Input:  Explain Java

Step 1: Explain Java is
Step 2: Explain Java is a
Step 3: Explain Java is a programming
Step 4: Explain Java is a programming language
```

At each step, the model predicts the probability of the next token based on the previous tokens.

Mathematically, the probability of a sequence can be factorized as:

$$
P(x_1,x_2,\ldots,x_n) = \prod\_{t=1}^{n} P(x_t\mid x_1,\ldots,x\_{t-1})
$$

Where:

- $x_t$: Current token.
- $x_1,\ldots,x\_{t-1}$: Previous tokens.
- $P$: Conditional probability.

The model learns to estimate these conditional probabilities.

Example:

Given:

```
Java is a
```

The model might estimate:

| Next token  | Probability |
| ----------- | ----------- |
| programming | 0.70        |
| popular     | 0.15        |
| language    | 0.10        |
| framework   | 0.05        |

The model then selects a token according to its decoding strategy.

This process continues until a stopping condition is reached.

Most modern GPT-style language models use autoregressive Transformer architectures.

### 3.2 Generative Adversarial Networks (GANs)

A GAN consists of two neural networks competing against each other.

Generator (G):

Creates synthetic data intended to resemble real training data.

Discriminator (D):

Attempts to distinguish real data from generated data.

[Federated learning for generating synthetic data: a scoping review 							| International Journal of Population Data Science](https://images.openai.com/static-rsc-4/NR-VEQ9kHIVkJsx-ZqZylVjEWiNxijm_keD5yP5uOQGgZx7telCCWYEe7AeXI8J2sCiMGtkZRYGcAjdDlPldpx0x4evKTt36J1-KU70_w8CIuznOj4l2onDzvQI_gsmV9ffP0BEJap8luc5Re07ISoSuVWhpaKFDqzxxpOnyRV0?purpose=inline)

[ijpds.org](https://ijpds.org/article/view/2158?utm_source=chatgpt.com)

The process:

1. The generator receives random noise.
2. It generates synthetic data.
3. The discriminator receives real and generated samples.
4. It predicts whether each sample is real or fake.
5. Both networks improve through adversarial training.

The objective can be expressed as:

$$
\min_G\max_D V(D,G)
$$
$$
V(D,G)= \mathbb{E}\_{x\sim p\_{data}}[\log D(x)] + \mathbb{E}\_{z\sim p_z}[\log(1-D(G(z)))]
$$
Where:

- $G$: Generator.
- $D$: Discriminator.
- $x$: Real training sample.
- $z$: Random noise.
- $G(z)$: Generated sample.

Trade-offs:

- Can generate highly realistic samples.
- Training can be unstable.
- Mode collapse can occur, where the generator produces limited varieties of outputs.
- Balancing the two networks can be difficult.

### 3.3 Variational Autoencoders (VAEs)

A VAE is a generative model that learns a probabilistic representation of input data in a latent space.

It has two main components:

- Encoder: Maps input data to a probability distribution in latent space.
- Decoder: Generates data from a sampled latent representation.

[What Is Generative AI (GenAI)? The Definitive Guide - Palo Alto Networks](https://images.openai.com/static-rsc-4/49F_c-rA7desQJfybEjddsXsHZil2LpWEXodYdG0ss08EaDwVWhxMmxY_OdYOAiSBJHgfhXds_ubagWH6nWIvOXOXmzQoXC5bPrrrICGSvFs5kAg3yOrTMPHRM4IMCO6bzbGBjtgj_42-cuwlcztVHcTlX4I_ZP0JR85NF29dzQ?purpose=inline)

[paloaltonetworks.com](https://www.paloaltonetworks.com/cyberpedia/what-is-generative-ai?utm_source=chatgpt.com)

The process:

1. Give an image to the encoder.
2. The encoder produces parameters describing a latent distribution.
3. Sample a latent vector from that distribution.
4. Pass the vector to the decoder.
5. The decoder reconstructs the image.
6. During training, optimize reconstruction quality and latent-space regularization.

A typical VAE objective is:

$$
\mathcal{L} = \mathcal{L}\_{reconstruction} + D\_{KL}(q(z|x)\parallel p(z))
$$

The first term encourages accurate reconstruction.

The second term encourages the learned latent distribution to remain close to a prior distribution.

Trade-offs:

- Provides a structured latent space.
- Supports interpolation between generated samples.
- Has a mathematically interpretable probabilistic framework.
- Can produce blurry images compared with some other approaches.

### 3.4 Diffusion Models

Diffusion models are generative models that learn to generate data by reversing a gradual noise-adding process.

They are widely used for image generation.

[What Are the Types of Generative AI: Examples and Uses | VOSU.AI](https://images.openai.com/static-rsc-4/1j_1BJHLI5Sfvby94YczK8lIKvG-FN0tiFS7lDoqx7UV8Jmz5GPgcSzxeiGNRy87wS9CdpZDA2CIzMuU5xfncM5L90Rwd2Bn1N9JPnOUQnTBChhR-JpNuqkTxy_II2hdZx3o60pHCiujH34LTMJDO3N5AkX0HCuQzwfl2t4Iw1k?purpose=inline)

[vosu.ai](https://vosu.ai/artificial-intelligence/generative/types?utm_source=chatgpt.com)

The process has two major phases.

Forward process: Adding noise

Start with a real image and gradually add noise.

```
Original Image
     |
     v
Small Noise
     |
     v
More Noise
     |
     v
Heavy Noise
     |
     v
Almost Random Noise
```

Reverse process: Removing noise

The model learns to reverse this process.

```
Random Noise
     |
     v
Denoising Step 1
     |
     v
Denoising Step 2
     |
     v
Denoising Step 3
     |
     v
Generated Image
```

During generation, the model starts from random noise and repeatedly denoises it.

For conditional image generation, a text prompt can guide the denoising process.

For example:

```
Prompt:
A futuristic city with flying cars at sunset.

        |
        v
   Text Encoder
        |
        v
  Text Embeddings
        |
        v
 Random Image Noise
        |
        v
 Conditional Denoising
        |
        v
  Generated Image
```

Trade-offs:

- Produces high-quality and diverse images.
- Supports text-conditioned generation.
- Can offer fine-grained control over generation.
- Often requires multiple computationally expensive denoising steps.

### 3.5 Transformers

Transformers are neural network architectures based on attention mechanisms.

They were introduced in the research paper Attention Is All You Need (2017).

Transformers are particularly important because they became the architectural foundation of many modern language models.

[Frontiers | Intelligent data analysis in edge computing with large language models: applications, challenges, and future directions](https://images.openai.com/static-rsc-4/pS4OeqM2WxcFF2aWpULVkedYIyB91EQJGBUT34JMoInNFJMRixpAHpoHLmf_crj9bJo5PCdBdkWR1Py4rGJGvvZrMXVuujlIkNAE4pXsB1hTHYbvSW18_UeXdEYhPd1i6FB5nYKP_hL5LAHRDeh6MORoHswPh5jHyxSQYQY84eo?purpose=inline)

[frontiersin.org](https://www.frontiersin.org/journals/computer-science/articles/10.3389/fcomp.2025.1538277/full?utm_source=chatgpt.com)

The main components include:

| Component            | Responsibility                           |
| -------------------- | ---------------------------------------- |
| Tokenization         | Converts text into tokens                |
| Embedding            | Converts tokens into numerical vectors   |
| Positional encoding  | Represents token positions               |
| Self-attention       | Captures relationships between tokens    |
| Feed-forward network | Processes learned representations        |
| Normalization        | Helps stabilize network training         |
| Output layer         | Produces scores for possible next tokens |

The attention mechanism allows a model to consider relationships between different positions in a sequence.

A simplified scaled dot-product attention equation is:
$$
Attention(Q,K,V)= softmax\left( \frac{QK^T}{\sqrt{d_k}} \right)V
$$
Where:

- $Q$: Query matrix.
- $K$: Key matrix.
- $V$: Value matrix.
- $d_k$: Dimension of the key vectors.

For example, consider:

```
The developer placed the book on the table
because it was heavy.
```

Understanding what "it" refers to requires considering relationships with other words in the sentence.

Attention helps the model learn such relationships.

Trade-offs:

- Processes sequences efficiently during training.
- Captures long-range relationships.
- Scales well with large datasets and computational resources.
- Standard attention can have substantial memory and computational costs for long sequences.

The original Transformer paper is available here: [Attention Is All You Need](https://arxiv.org/abs/1706.03762?utm_source=chatgpt.com).&#x20;

## 4. How Generative AI Works

Let's use a language model as an example.

Imagine that we want to build an AI application capable of answering programming questions.

The complete process can be divided into two major stages:

1. Model development and training.
2. Model inference and generation.

### 4.1 Model Training

Training is the process through which a neural network learns patterns from data.

[How Large Language Models Work: AI Training Explained](https://images.openai.com/static-rsc-4/fiVE3e-oOoqhFdu3X3_PznDGNY2e8BeDHWOSN6vEyqdQNK2iwuFUSMQrWzrmeTVzWoDxl3zXPE68Yl4TwZ2ncsZLBqSJ6JNerrA19FGqudNSDnCYxXfOKGHa0i3YbuVFFz38WjUW7UuyqCn4mNz6pGYqHr_Ly_U6HCgogFjJgTs?purpose=inline)

[intelligenttools.co](https://intelligenttools.co/blog/demystifying-large-language-models?utm_source=chatgpt.com)

Step 1: Collect training data

Gather large amounts of text, such as:

```
Java documentation
Programming books
Technical articles
Source code
Tutorials
```

Step 2: Preprocess data

Clean the data, remove unsuitable content, and prepare it for training.

Step 3: Tokenization

Convert text into numerical token IDs.

```
Input:
Java is a programming language.

Tokens:
["Java", " is", " a", " programming", " language", "."]

Token IDs:
[125, 42, 18, 921, 311, 7]
```

The numbers are illustrative, not actual tokenizer IDs.

Step 4: Embedding

Convert token IDs into numerical vectors.

These vectors are passed through the neural network.

Step 5: Forward propagation

The model processes the input and produces predictions.

For next-token prediction, the model estimates what token should come next.

Step 6: Calculate loss

Compare the predicted token distribution with the expected next token.

A common loss function is cross-entropy:

$$
L=-\sum\_{i=1}^{V} y_i\log(\hat{y}\_i)
$$

Where:

- $V$: Vocabulary size.
- $y_i$: Actual target distribution.
- $\hat{y}\_i$: Predicted probability.

Step 7: Backpropagation

Calculate gradients indicating how model parameters contributed to the loss.

Step 8: Update parameters

An optimizer, such as Adam or AdamW, adjusts model parameters to reduce the loss.

A simplified gradient descent update is:
$$
\theta\_{new}= \theta\_{old}-\eta\nabla\_\theta L
$$
Where:

- $\theta$: Model parameters.
- $\eta$: Learning rate.
- $\nabla\_\theta L$: Gradient of the loss.

Steps 5–8 are repeated over many training batches.

### 4.2 Model Adaptation and Alignment

Pretraining is not always sufficient to make a model useful as an assistant.

Additional training stages can include:

Supervised Fine-Tuning (SFT)

Train the model on examples of instructions and desired responses.

Preference Optimization

Use human or AI feedback to encourage preferred responses.

Examples include:

- Reinforcement Learning from Human Feedback (RLHF).
- Direct Preference Optimization (DPO).

These approaches help adapt the model toward more useful, instruction-following behavior.

### 4.3 Model Inference and Generation

Inference means using an already-trained model to produce outputs.

[How LLMs Actually Work: A Product Manager's Mental Model | Akash Deep](https://images.openai.com/static-rsc-4/zi6XdCULmsf71FlBOIHXV0Wt0N5kuhkw2J83abUwC83yNhARYb_3RknZbtvO9NH7G-WAdAzrygkDl5veYF-35mWRQbSv0QjtaymF8uCcYzcf9BqurMMct-jVKwaDxGwn0pLslky8B1RZ9vW7rRmZT5jZCM-MUOU1B21_FEDwCDI?purpose=inline)

[akash-deep.com](https://www.akash-deep.com/blog/how-llms-work-product-manager-guide?utm_source=chatgpt.com)

Suppose the user asks:

```
Explain what a Java interface is.
```

The process is:

1. The application receives the prompt.
2. The tokenizer converts the prompt into token IDs.
3. The model processes the tokens.
4. The output layer calculates probabilities for possible next tokens.
5. A decoding strategy selects a token.
6. The selected token is appended to the sequence.
7. The model predicts the next token.
8. The process continues until generation stops.
9. The tokenizer converts the generated tokens into readable text.

The final result might be:

```
A Java interface is a reference type that
defines a contract that implementing classes
must fulfill...
```

Notice that the model generates the answer token by token rather than selecting an entire predefined response.

### 4.4 Decoding Strategies

A model produces a probability distribution over possible next tokens. The decoding strategy determines how tokens are selected.

Important strategies include:

| Strategy        | Description                             | Trade-off                              |
| --------------- | --------------------------------------- | -------------------------------------- |
| Greedy decoding | Selects the most probable token         | Predictable but potentially repetitive |
| Random sampling | Samples according to probabilities      | More diversity                         |
| Top-k sampling  | Samples from the k most probable tokens | Limits unlikely choices                |
| Top-p sampling  | Samples from a probability-mass subset  | Adaptive candidate selection           |
| Beam search     | Explores multiple candidate sequences   | Can favor predictable outputs          |

Temperature

Temperature controls the sharpness of the probability distribution used during sampling.

A simplified temperature-adjusted softmax is:
$$
P_i= \frac{e^{z_i/T}} {\sum_j e^{z_j/T}}
$$
Where:

- $z_i$: Logit for token $i$.
- $T$: Temperature.
- $P_i$: Probability of selecting token $i$.

Typical behavior:

| Temperature | Behavior                          |
| ----------- | --------------------------------- |
| Near 0      | More deterministic                |
| 0.7         | Moderate variation                |
| 1.0         | Original probability distribution |
| Above 1.0   | More randomness                   |

A higher temperature does not make a model more intelligent or knowledgeable. It changes its sampling behavior.

## 5. Practical Example

Let's build a simple conceptual example of next-token generation.

Suppose a language model receives:

```
The capital of Egypt is
```

The model predicts probabilities for possible next tokens.

| Candidate  | Probability |
| ---------- | ----------- |
| Cairo      | 0.90        |
| Alexandria | 0.04        |
| Giza       | 0.03        |
| Luxor      | 0.02        |
| Other      | 0.01        |

With greedy decoding, the model selects:

```
Cairo
```

The new sequence becomes:

```
The capital of Egypt is Cairo
```

Now the model predicts another token, perhaps:

```
.
```

The completed sentence becomes:

```
The capital of Egypt is Cairo.
```

This example illustrates the central principle of autoregressive text generation.

Important: Real language models operate on tokens rather than necessarily complete words, and their predictions depend on the entire available context, not just the immediately preceding word.

### 5.1 A Simplified Generative Model

Here is pseudocode illustrating the generation process:

```
function generate(prompt, max_tokens):

    tokens = tokenize(prompt)

    for i = 1 to max_tokens:

        logits = model(tokens)

        probabilities = softmax(logits)

        next_token = sample(probabilities)

        if next_token == EOS:
            break

        append(tokens, next_token)

    return detokenize(tokens)
```

Where:

- `tokenize`: Converts input text into tokens.
- `model`: Predicts the next-token scores.
- `softmax`: Converts scores into probabilities.
- `sample`: Selects the next token.
- `EOS`: End-of-sequence token.
- `detokenize`: Converts tokens back into text.

This is a simplified inference algorithm. Production implementations additionally use techniques such as attention masks, positional information, key-value caching, and sampling constraints.

## 7. Advantages, Limitations, and Trade-offs

### 7.1 Advantages

| Advantage             | Explanation                                      |
| --------------------- | ------------------------------------------------ |
| Content generation    | Creates different types of digital content       |
| Productivity          | Automates repetitive content-related tasks       |
| Flexibility           | One foundation model can perform multiple tasks  |
| Natural interaction   | Users can communicate through natural language   |
| Adaptability          | Models can be fine-tuned for specialized domains |
| Creativity assistance | Helps explore alternative designs and ideas      |
| Knowledge assistance  | Helps explain and summarize complex information  |

### 7.2 Limitations

| Limitation               | Explanation                                                                   |
| ------------------------ | ----------------------------------------------------------------------------- |
| Hallucinations           | Can generate convincing but incorrect information                             |
| Computational cost       | Large models require substantial resources                                    |
| Training data dependency | Data quality affects model behavior                                           |
| Bias                     | Models can reproduce biases in training data                                  |
| Privacy                  | Sensitive information may be exposed through poorly designed systems          |
| Explainability           | Internal model decisions can be difficult to interpret                        |
| Reproducibility          | Sampling can produce different outputs                                        |
| Security                 | Vulnerable to prompt injection and other attacks                              |
| Copyright                | Training data and generated content can raise intellectual-property questions |

### 7.3 Choosing the Appropriate Approach

Different approaches are suitable for different requirements.

| Requirement                                | Suitable approach           |
| ------------------------------------------ | --------------------------- |
| Text and code generation                   | Autoregressive Transformers |
| High-quality image generation              | Diffusion models            |
| Synthetic image generation                 | GANs or Diffusion           |
| Latent-space representation                | VAEs                        |
| Semantic document search                   | Embeddings                  |
| Answering questions from private documents | RAG + LLM                   |
| Domain-specific model behavior             | Fine-tuning                 |
| Multi-step automated workflows             | LLM + Agent architecture    |

An important engineering principle is that you do not always need Generative AI.

For example, if your application only needs to classify whether a transaction is fraudulent, a traditional classification model might be more appropriate, less expensive, and easier to evaluate than an LLM.

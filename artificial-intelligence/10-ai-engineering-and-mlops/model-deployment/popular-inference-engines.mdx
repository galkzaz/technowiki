# Popular LLM Inference Engines

An LLM inference engine is software that executes a trained Large Language Model (LLM) to generate responses, complete text, or perform other inference tasks.

Its responsibilities typically include:

- Loading model weights.
- Executing neural network operations.
- Managing CPU, GPU, and memory resources.
- Performing tokenization and token generation (depending on the serving stack).
- Optimizing inference performance.
- Handling multiple inference requests.
- Supporting batching, caching, and parallel execution.

Different inference engines target different environments. Some are designed for high-throughput GPU servers, others for local computers, mobile devices, or edge deployments.

1\. vLLM

High-throughput serving

An inference and serving engine designed for efficient LLM execution, particularly on GPU infrastructure.

Key features:

- PagedAttention for efficient KV-cache memory management.
- Continuous batching.
- Tensor parallelism.
- OpenAI-compatible API server.
- Distributed inference.

Typical use: Production LLM APIs serving many concurrent users.

2\. llama.cpp

Local and edge inference

A lightweight inference engine primarily implemented in C/C++, designed to run LLMs efficiently across different hardware.

Key features:

- GGUF model format.
- Quantization support.
- CPU and GPU inference.
- Low-resource execution options.
- Local HTTP server.

Typical use: Running LLMs on laptops, desktops, local servers, and edge devices.

3\. TensorRT-LLM

NVIDIA GPU optimization

An inference framework designed to optimize LLM execution on NVIDIA GPUs.

Key features:

- GPU-specific optimizations.
- Quantization.
- Tensor and pipeline parallelism.
- Optimized attention operations.
- Advanced memory management.

Typical use: High-performance LLM inference in GPU-intensive production environments.

4\. ONNX Runtime

Cross-platform inference

A general-purpose inference runtime that executes models exported in ONNX format.

Key features:

- CPU and GPU execution.
- Multiple hardware execution providers.
- Model graph optimizations.
- Java API support.
- Cross-framework interoperability.

Typical use: Running ML and deep learning models across different platforms, including Java applications.

Compiler-based optimization

A machine learning compiler framework that optimizes model execution across different hardware platforms.

## 2. Comparison of inference engines

The following table helps distinguish their primary roles.

| Engine       | Main focus                   | Typical hardware                           | Model formats / ecosystem                     |
| ------------ | ---------------------------- | ------------------------------------------ | --------------------------------------------- |
| vLLM         | High-throughput serving      | NVIDIA/AMD GPUs and supported accelerators | Hugging Face models                           |
| llama.cpp    | Local inference              | CPU and GPUs                               | GGUF                                          |
| TensorRT-LLM | GPU optimization             | NVIDIA GPUs                                | Supported model architectures and checkpoints |
| ONNX Runtime | General inference            | CPU, GPU, accelerators                     | ONNX                                          |
| TGI          | LLM serving                  | Primarily GPU                              | Hugging Face ecosystem                        |
| Ollama       | Convenient local execution   | CPU and supported GPUs                     | Primarily GGUF-based model packaging          |
| Apache TVM   | Compilation and optimization | CPUs and accelerators                      | Multiple model import formats                 |

A useful way to classify these technologies is:

High-throughput production serving

- vLLM
- TensorRT-LLM
- TGI

Local and edge inference

- llama.cpp
- Ollama

Cross-platform inference and optimization

- ONNX Runtime
- Apache TVM

## 3. Other notable inference engines

There are additional engines worth knowing, especially when studying modern LLM infrastructure.

| Engine                  | Main specialization                                                          |
| ----------------------- | ---------------------------------------------------------------------------- |
| SGLang                  | High-throughput serving, structured generation, and efficient prefix caching |
| MLX                     | Machine learning and LLM inference on Apple Silicon                          |
| ExecuTorch              | Deploying models on mobile and edge devices                                  |
| Deep Java Library (DJL) | Java-oriented model loading and inference                                    |
| OpenVINO                | Optimizing and executing models on Intel hardware                            |

One important distinction: DJL is a Java ML framework that provides APIs and integrates with underlying engines; it is not directly comparable in scope to specialized serving engines such as vLLM.

## 4. Which engines should you focus on?

For learning and practical implementation, I recommend prioritizing these five:

| Priority | Engine       | Why learn it?                                                    |
| -------- | ------------ | ---------------------------------------------------------------- |
| 1        | vLLM         | Important for production LLM serving and GPU-based deployments.  |
| 2        | llama.cpp    | Understand local inference, GGUF, and quantization.              |
| 3        | Ollama       | Easy way to experiment with local LLMs and APIs.                 |
| 4        | TensorRT-LLM | Understand advanced GPU inference optimization.                  |
| 5        | ONNX Runtime | Particularly relevant to cross-platform ML and Java integration. |

I would also study SGLang, especially for advanced serving, multi-turn workloads, and structured generation.&#x20;

### Important notes about categorization

- Ollama is better understood as a local model runtime and management tool that uses inference backends such as llama.cpp, rather than simply another low-level inference engine.
- Apache TVM is primarily a compiler and optimization framework.
- DJL is a Java ML framework and abstraction layer.
- TGI remains important historically, but its repository is now in maintenance mode; consider vLLM or SGLang for new production deployments.&#x20;

## 5. Practical learning path

I suggest this hands-on sequence:

1. Install Ollama and run a small LLM locally.
2. Understand GGUF and quantization using llama.cpp.
3. Deploy an LLM using vLLM and expose its REST API.
4. Connect your Spring Boot application to the vLLM API.
5. Explore GPU optimization using TensorRT-LLM.
6. Experiment with ONNX Runtime and DJL for Java-based inference.

The most important distinction to remember: For a Java backend developer, vLLM and Ollama are particularly useful starting points because they expose APIs that allow Java applications to consume LLM capabilities without implementing model execution themselves.

### Why this placement?

The distinction is:

| Topic                      | What it answers                                       |
| -------------------------- | ----------------------------------------------------- |
| Model formats              | How is the model stored and packaged?                 |
| Inference engine           | What software executes the model?                     |
| Inference engine selection | How do we choose an appropriate engine?               |
| Popular inference engines  | What are the available engines and their differences? |
| Inference architecture     | Where does inference execute: remotely or locally?    |
| Serving                    | How do applications access the inference capability?  |
| Infrastructure             | What hardware and runtime environment execute it?     |

One important distinction: vLLM, llama.cpp, TensorRT-LLM, and SGLang are inference engines/runtimes; Ollama is primarily a local model runner and management tool; ONNX Runtime is a general-purpose model runtime; and Apache TVM is primarily a compiler and optimization framework.

I would keep Popular Inference Engines as a dedicated page rather than mixing it into model serving. This makes it easier to expand each engine later with its architecture, installation, configuration, and practical labs.

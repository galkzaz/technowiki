### Positional Number Systems
Introduces number systems where digit position determines value.

#### Decimal Number System
##### The decimal number system has ten digits
In the decimal number system each of the ten digits, 0 through 9, represents a certain
quantity. the ten symbols (digits) do not limit you to expressing only ten
different quantities because you use the various digits in appropriate positions within a
number to indicate the magnitude of the quantity.

You can express quantities up through
nine before running out of digits; if you wish to express a quantity greater than nine, you
use two or more digits, and the position of each digit within the number tells you the magnitude it represents.

If, for example, you wish to express the quantity twenty-three, you use
(by their respective positions in the number) the digit 2 to represent the quantity twenty and
the digit 3 to represent the quantity three, as illustrated below.

![decimal-number-weight](/docs/assets/hardware-design/digital-logic/decimal-number-weight.png)

##### The decimal number system has a base of 10
The position of each digit in a decimal number indicates the magnitude of the quantity
represented and can be assigned a weight. The weights for whole numbers are positive
powers of ten that increase from right to left, beginning with 10^0 = 1.

$\text{.... }10^5 10^4 10^3 10^2 10^1 10^0$

For fractional numbers, the weights are negative powers of ten that decrease from left to right beginning with $10^{-1}$.

$10^2 10^1 10^0 .10^-1 10^-2 10^-3\text{ ....}$

where "." represents Decimal point

The value of a digit is determined by its position in the number. The value of a decimal number is the sum of the digits after each digit has been multiplied by its weight

#### Binary Number System
To speak directly to electronic hardware, you need to send electrical signals. The
easiest signals for computers to understand are on and off, and so the computer
alphabet is just two letters. Just as the 26 letters of the English alphabet do not limit
how much can be written, the two letters of the computer alphabet do not limit
what computers can do. The two symbols for these two letters are the numbers 0
and 1, and we commonly think of the computer language as numbers in base 2, or
binary numbers. We refer to each "letter" as a binary digit or bit.

Computers are slaves to our commands, which are called instructions. Instructions, which are just
collections of bits that the computer understands and obeys, can be thought of as numbers. For example, the bits '1001010100101110' tell one computer to add two numbers. 

using numbers for both instructions and data is a foundation of computing.

**The binary number system has two digits (bits)**

The binary number system is another way to represent quantities. It is less complicated than
the decimal system because the binary system has only two digits. The decimal system with
its ten digits is a base-ten system; the binary system with its two digits is a base-two system.

**The binary number system has a base of 2**

The two binary digits (bits) are 1 and 0.

The position of a 1 or 0 in a binary number indicates
its weight, or value within the number, just as the position of a decimal digit determines the
value of that digit.

The weights in a binary number are based on powers of two.

##### Counting in Binary
To learn to count in the binary system, first look at how you count in the decimal system.
You start at zero and count up to nine before you run out of digits. You then start another
digit position (to the left) and continue counting 10 through 99. At this point you have
exhausted all two-digit combinations, so a third digit position is needed to count from 100
through 999.

A comparable situation occurs when you count in binary, except that you have only two
digits, called bits. Begin counting: 0, 1. At this point you have used both digits, so include
another digit position and continue: 10, 11. You have now exhausted all combinations of
two digits, so a third position is required. With three digit positions you can continue to
count: 100, 101, 110, and 111. Now you need a fourth digit position to continue, and so on.

##### The Weighting Structure of Binary Numbers
A binary number is a weighted number. The weight structure of a binary number is

$2^{n-1}\text{ ... }2^3 2^2 2^1 2^0 . 2^{-1} 2^{-2}\text{ ... }2^{-n}$

where n is the number of bits from the binary point. Thus, all the bits to the left of the
binary point have weights that are positive powers of two, as previously discussed for whole
numbers. All bits to the right of the binary point have weights that are negative powers of two, or fractional weights.

The right-most bit is the LSB (least significant bit) in a binary whole number and has a weight of $2^0 = 1$.

The weights increase from right to left by a power of two for each bit. The left-most bit is the MSB (most significant bit); its weight depends on the size of the binary number.

Fractional numbers can also be represented in binary by placing bits to the right of the
binary point, just as fractional decimal digits are placed to the right of the decimal point.
The left-most bit is the MSB in a binary fractional number and has a weight of 2 -1 = 0.5.
The fractional weights decrease from left to right by a negative power of two for each bit.

##### Sum-of-Weights Method
To get the binary number for a given decimal number, find the binary weights that add up to the decimal number.

One way to find the binary number that is equivalent to a given decimal number is to deter-
mine the set of binary weights whose sum is equal to the decimal number. An easy way
to remember binary weights is that the lowest is 1, which is 20, and that by doubling any
weight, you get the next higher weight; thus, a list of seven binary weights would be 64, 32,
16, 8, 4, 2, 1.

the decimal number 9, for example, can be expressed as the sum of binary weights as follows:

9 = 8 + 1 or 9 = $2^3 + 2^0$

Placing 1s in the appropriate weight positions, 2^3 and 2^0, and 0s in the 2^2 and 2^1 positions
determines the binary number for decimal 9.

$2^3+2^2+2^1+2^0$

1   0   0   1   Binary number for decimal 9
$$

##### Repeated Division-by-2 Method
A systematic method of converting whole numbers from decimal to binary is the repeated
division-by-2 process. To get the binary number for a given decimal number, divide the decimal number by 2 until the quotient is 0. Remainders form the binary number.

For example, to convert the decimal number 12 to binary,

1. begin by dividing 12 by 2.
2. Then divide each resulting quotient by 2 until there is a 0 whole-number
quotient.
3. The remainders generated by each division form the binary number.
4. The first
remainder to be produced is the LSB (least significant bit) in the binary number, and the last remainder to be produced is the MSB (most significant bit).

![convert the decimal number 12 to binary using Repeated Division-by-2 Method](/docs/assets/hardware-design/digital-logic/Repeated-Division-by-2-Method.png)

Convert $19_{10}$ to binary
```
Division	|Remainder
----------|---------
19/2=9	  |1
9/2=4	    |1
4/2=2	    |0
2/2=1	    |0
1/2=0	    |1
```

$(19)_{10}=(10011)_2$

Convert $45_10$ to binary
```
Division   |Remainder
-----------|----------

22/2=11	   |0
11/2=5	   |1
5/2=2	   |1
2/2=1	   |0
1/2=0	   |1
```
$(45.5)_{10}=(101101.1)_2$

### Signed Number Representations
Digital systems, such as the computer, must be able to handle both positive and negative
numbers. A signed binary number consists of both sign and magnitude information. The
sign indicates whether a number is positive or negative, and the magnitude is the value of
the number. There are three forms in which signed integer (whole) numbers can be represented in binary: sign-magnitude, 1's complement, and 2's complement. Of these, the 2's
complement is the most important and the sign-magnitude is the least used. 

The 1's complement and the 2's complement of a binary number are important because
they permit the representation of negative numbers. The method of 2's complement arithmetic is commonly used in computers to handle negative numbers.

Noninteger and
very large or small numbers can be expressed in floating-point format.

#### One's Complement Representation
The 1's complement of a binary number is found by changing all 1s to 0s and all 0s to 1s,
as illustrated below:
$$
\begin{aligned}
\text{Binary number:} \quad & 1\;0\;1\;1\;0\;0\;1\;0 \quad (178)_{10}\\
\text{1's complement:} \quad & 0\;1\;0\;0\;1\;1\;0\;1 \quad (77)_{10}
\end{aligned}
$$
The simplest way to obtain the 1's complement of a binary number with a digital circuit
is to use parallel inverters (NOT circuits), as shown in Figure an 8-bit binary number.

![Example of inverters used to obtain the 1's complement of a binary number](/docs/assets/hardware-design/digital-logic/number-systems-and-data-representation/inverters-used-to-obtain-the-1-complement-of-a-binary-number.png)

#### Two's Complement Representation
The 2's complement of a binary number is found by adding 1 to the LSB of the 1's complement.
```
2's complement = (1's complement) + 1
```
$$
\begin{aligned}
\text{Binary number:} \quad & 1\;0\;1\;1\;0\;0\;1\;0 \\
\text{1's complement:} \quad & 0\;1\;0\;0\;1\;1\;0\;1 \\
\quad & + \quad \quad \quad \quad 1 & \text{Add 1}\\
\text{2's complement:} \quad & 0\;1\;0\;0\;1\;1\;1\;0 \quad 
\end{aligned}
$$

An alternative method of finding the 2's complement of a binary number is by changing all bits to the left of the least
significant 1 to get 2's complement. as follows:
1. Start at the right with the LSB and write the bits as they are up to and including the
first 1.
2. Take the 1's complements of the remaining bits
$$
\begin{aligned}
&\text{Binary number:} \quad & 1\;0\;1\;1\;0\;0\;1\;0\\
&\text{2's complement:} \quad &
\underbrace{0\;1\;0\;0\;1\;1}_{\text{1's complements of original bits}} 
\underbrace{1\;0}_{\text{These bits stay the same}}  \\
\end{aligned}
$$
$$
\begin{aligned}
&\text{Binary number:} \quad & 10111000 \\
&\text{2's complement:} \quad 
\underbrace{0100}_{\text{1's complements of original bits}} 
\underbrace{1000}_{\text{These bits stay the same}}
\end{aligned}
$$

The 2's complement of a negative binary number can be realized using inverters and an
adder, as indicated in Figure. This illustrates how an 8-bit number can be converted to
its 2's complement by first inverting each bit (taking the 1's complement) and then adding
1 to the 1's complement with an adder circuit.
![Example of obtaining the 2's complement of a negative binary number](/docs/assets/hardware-design/digital-logic/number-systems-and-data-representation/obtaining-the-2s-complement-of-a-negative-binary-number.png)

To convert from a 1's or 2's complement back to the true (uncomplemented) binary form,
use the same two procedures described previously. To go from the 1's complement back to
true binary, reverse all the bits. To go from the 2's complement form back to true binary,
take the 1's complement of the 2's complement number and add 1 to the least significant bit.

#### Sign-Magnitude Representation
**The Sign Bit**:The left-most bit in a signed binary number is the sign bit, which tells you whether the
number is positive or negative.

A 0 sign bit indicates a positive number, and a 1 sign bit indicates a negative number.

When a signed binary number is represented in sign-magnitude, the left-most bit is the sign
bit and the remaining bits are the magnitude bits. The magnitude bits are in true (uncomple-
mented) binary for both positive and negative numbers. 

For example, the decimal number +25 is expressed as an 8-bit signed binary number using the sign-magnitude form as
$$
\begin{aligned}
0\;0\;0\;1\;1\;0\;0\;1\\
\underbrace{0}_{\text{Sign bit}} 
\underbrace{0\;0\;1\;1\;0\;0\;1}_{\text{Magnitude bits}}
\end{aligned}
$$
The decimal number -25 is expressed as **10011001**

the only difference between +25 and -25 is the sign bit because the magnitude bits are in true binary for both positive and negative numbers.

In the sign-magnitude form, a negative number has the same magnitude bits as the
corresponding positive number but the sign bit is a 1 rather than a zero
#### One's Complement Representation
Positive numbers in 1's complement form are represented the same way as the positive
sign-magnitude numbers. 

Negative numbers, however, are the 1's complements of the corresponding positive numbers. 

For example, using eight bits, the decimal number -25 is expressed as the 1's complement of +25 (00011001) as **11100110**

In the 1's complement form, a negative number is the 1's complement of the corresponding positive number.

#### Two's Complement Representation
Positive numbers in 2's complement form are represented the same way as in the sign-magnitude and 1's complement forms. Negative numbers are the 2's complements of the corresponding positive numbers. 

using eight bits, let's take decimal number -25 and express it as the 2's complement of +25 (**00011001**). Inverting each bit and adding 1, you get -25 = **11100111**

In the 2's complement form, a negative number is the 2's complement of the corresponding positive number.

Processors use the 2's complement for negative integer numbers in arithmetic operations.
The reason is that subtraction of a number is the same as adding the 2's complement of the number. Processors form the 2's complement by inverting the bits and adding 1, using special instructions that produce the same result as the adder

##### 2's Complement
Decimal values of positive and negative numbers in the 2's complement form are deter-
mined by summing the weights in all bit positions where there are 1s and ignoring those
positions where there are zeros. The weight of the sign bit in a negative number is given a
negative value.

To determine the decimal values of these 2's complement numbers, we map the bits to their respective weights. In an 8-bit system, the Most Significant Bit (MSB) has a weight of $-2^7=-128$.

**01010110**

of weights regardless of whether the number is positive or negative. The 1’s complement
system requires adding 1 to the summation of weights for negative numbers but not for
positive numbers. Also, the 1’s complement form is generally not used because two repre-

#### Range of Signed Integer Numbers
**The range of magnitude values represented by binary numbers depends on the number of bits (n)**

We have used 8-bit numbers for illustration because the 8-bit grouping is common in most
computers and has been given the special name byte. 
1. With one byte or eight bits, you can
represent 256 different numbers. 
2. With two bytes or sixteen bits, you can represent 65,536
different numbers. 
3. With four bytes or 32 bits, you can represent 4.295 * 109 different
numbers. 

**The formula for finding the number of different combinations of n bits is**
$$
\text{Total combinations} = 2^n
$$

For 2’s complement signed numbers, the range of values for n-bit numbers is
$$
\text{Range} = -(2^{n-1}) \quad \text{to} \quad +(2^{n-1} - 1)
$$
where in each case there is one sign bit and n - 1 magnitude bits. 

For example:
- with four bits (4 bits) you can represent numbers in 2’s complement ranging from $-2^{4-1} = -8$ to $2^{4-1} - 1 = +7$.
- with eight bits (8 bits) you can go from $-2^{8-1} = -128$ to $2^{8-1} - 1 = +127$.
- with sixteen bits (16 bits) you can go from $-2^{16-1} = -32768$ to $2^{16-1} - 1 = +32767$.
- with thirty-two bits (32 bits) you can go from $-2^{32-1} = -2147483648$ to $2^{32-1} - 1 = +2147483647$.
- with sixty-four bits (64 bits) you can go from $-2^{64-1} = -9223372036854775808$ to $2^{64-1} - 1 = +9223372036854775807$.

There is one less positive number than there are negativenumbers because zero is represented as a positive number (all zeros).

#### Comparison of Systems
Why Two's Complement Wins

You might notice that in Sign-Magnitude and One's Complement, you could technically have a "negative zero" (like 10000000), which confuses the CPU.

Two's Complement is the gold standard because:
- It only has one representation for zero (00000000).
- The CPU can perform subtraction (A-B) by simply adding A to the Two's Complement of B. It doesn't need a separate "subtraction" circuit!
- It simplifies the logic for arithmetic operations, making it more efficient and easier to implement in hardware.
- It avoids the issue of negative zero, ensuring consistency and simplicity.

|System	|How it works	|Pros/Cons|
|-|-|-|
|Sign-Magnitude	|The leftmost bit is the sign; the rest is the value.	|Easy for humans; hard for CPU math.|
|Two's Complement	|Leftmost bit is sign; value is inverted + 1.	|Industry standard. Efficient math.|
|Floating Point (IEEE 754)	|Uses a specific sign bit, exponent, and fraction.	|Used for decimals/scientific notation.|

<summary>How the CPU "Knows"</summary>

The CPU doesn't actually "know" if a string of bits is signed or unsigned just by looking at it. Instead, it follows the instruction given by the programmer.
- If the code says ADD (unsigned), the CPU treats the MSB as a normal power of two.
- If the code says SADD (signed add), the CPU treats that MSB as a negative weight.

In a modern CPU, there isn't actually a "subtraction" circuit. Instead, the CPU transforms a subtraction problem like A-B into an addition problem: A+(-B).

To do this, it uses Two's Complement logic. Here is how the CPU handles this using the numbers 25 and 10 as an example.

1. The Setup (Unsigned vs. Signed)

    The CPU uses different instructions depending on whether the programmer wants the numbers to be treated as simple values (Unsigned) or values that can be negative (Signed).
    - ADD (Unsigned): The CPU adds the bits and ignores the sign. If the result exceeds the bit-limit (e.g., 255 in 8-bit), it sets a "Carry Flag."
    - SADD (Signed Add): The CPU adds the bits but monitors the Sign Bit. If the result doesn't make sense (like adding two positives and getting a negative), it sets an "Overflow Flag."

2. Step-by-Step Subtraction: 25-10

    To the CPU, this is 25+(-10).
    . Step A: Convert 10 to -10 (Two's Complement)
      1. Positive 10: 00001010
      2. Invert bits: 11110101
      3. Add 1: 11110110 (This is -10)
    . Step B: Perform the Addition
  
    Now the CPU simply adds the binary for 25 and the binary for -10.
    ```
    Carry	  1	1	1	1	1	0	0	0	
    25	    0	0	0	1	1	0	0	1	
    -10	    1	1	1	1	0	1	1	0	+
    Result	0	0	0	0	1	1	1	1	= 15
    ```
3. How the CPU Handles the "Leftover" Bit
  
    You'll notice in the addition above, there is a "Carry Out" bit at the very end (the 9th bit).
    - In Two's Complement subtraction, the CPU simply discards that extra carry bit.
    - The remaining 8 bits 00001111 equal 15 in decimal, which is the correct answer (25-10=15).

Summary of CPU Flags

When this operation finishes, the CPU updates its "Status Register":
- Carry Flag: Set to 1 (because the addition went past the 8th bit).
- Zero Flag: Set to 0 (because the result isn't zero).
- Sign Flag: Set to 0 (because the result is positive).

#### Overflow Condition
When two numbers are added and the number of bits required to represent the sum exceeds
the number of bits in the two numbers, an overflow results as indicated by an incorrect sign
bit. The true mathematical result cannot be represented with the available number of bits.

For an n-bit signed (two’s complement) number, the representable range is: $−2^{n−1}  to  2^{n−1}−1$

Example (8-bit): −128 to +127

An overflow can occur only when 
1. both numbers are positive 
2. 2. or both numbers are negative. 

So, Signed overflow occurs if and only if: Two numbers with the same sign are added, and the result has the opposite sign. This never happens with different-sign operands. thats because:
- MSB is the sign bit
- Adding two positives should give a positive
- Adding two negatives should give a negative
- If that expectation is violated → overflow

If the sign bit of the result is different than the sign bit of the numbers that are added, overflow is indicated. 

**Positive + Positive → Negative (overflow)**
```
                   01111101     125
                +  00111010   + 58
                ------------------
                   11110010     183(−73) ← WRONG sign
                   ||------|
                   |   |
Sign incorrect-----|   |
Magnitude incorrect----|
```
- Both operands: MSB = 0
- Result: MSB = 1
- ✔ Overflow occurred

In this example the sum of 183 requires eight magnitude bits. Since there are seven magnitude bits in the numbers (one bit is the sign), there is a carry into the sign bit which produces the overflow indication.

As signed 8-bit (two’s complement) → MSB = 1, 10110111 represents a negative number (−73)

** Negative + Negative → Positive (overflow)**
```
  10011100   (−100)
+ 10110100   (−76)
-------------------
  01010000     (+80)  ← WRONG sign
```
- Both operands: MSB = 1
- Result: MSB = 0
- ✔ Overflow occurred

**Positive + Negative (no overflow)**
```
  01001010   (+74)
+ 11110110   (−10)
------------
  01000000   (+64)
```
Signs differ → overflow impossible

##### Hardware detection rule
Let:
- $C_{in}$ = carry into the sign bit
- $C_{out}$ = carry out of the sign bit
Then:
$$
Overflow(OF)=C_{in}⊕C_{out}
$$$
In signed arithmetic, 
- the MSB is a sign bit, not a magnitude bit
- A mismatch between carries around the sign bit means the sign flipped incorrectly
- XOR detects exactly that mismatch

This is how ALUs detect signed overflow.

| Condition        | Meaning               |
| ---------------- | --------------------- |
| Carry out of MSB | **Unsigned overflow** |
| Sign error       | **Signed overflow**   |

Carry ≠ overflow for signed numbers.

Let:
- A = sign bit of operand A
- B = sign bit of operand B
- S = sign bit of result

| 0 | 0 | 0 | ❌ No      | + + = + |

| 0 | 1 | 0 | ❌ No      | + − = + |
| 0 | 1 | 1 | ❌ No      | + − = − |
| 1 | 0 | 0 | ❌ No      | − + = + |
| 1 | 0 | 1 | ❌ No      | − + = − |
| 1 | 1 | 1 | ❌ No      | − − = − |
| 1 | 1 | 0 | ✅ Yes     | − − → + |

**How CPUs Set the OF Flag**

General rule (used by x86, ARM, RISC-V, etc.) After addition:
```
OF = carry_into_MSB XOR carry_out_of_MSB
```
x86 example
```
mov al, 127
add al, 1      ; AL = -128
```
Flags:
- OF = 1 (signed overflow)
- CF = 0 (no unsigned overflow)
- SF = 1 (sign bit set)
- ZF = 0

**Why CPUs need both OF and CF**
- **CF** → unsigned arithmetic (addresses, sizes, counters)
- **OF** → signed arithmetic (integers, math, comparisons)

This allows the same ADD instruction to support both worlds.

CPUs set both flags so software chooses the interpretation

### Fixed-Point and Floating-Point Concepts
<!--Introduces number formats for representing real values.-->
To represent very large integer (whole) numbers, many bits are required. There is also a
problem when numbers with both integer and fractional parts, such as 23.5618, need to be
represented. The floating-point number system, based on scientific notation, is capable of
representing very large and very small numbers without an increase in the number of bits
and also for representing numbers that have both integer and fractional components.

A **floating-point number** (also known as a real number) consists of two parts plus a
sign. 
1. The **mantissa** is the part of a floating-point number that represents the magnitude of the number and is between 0 and 1. 
2. The **exponent** is the part of a floating-point number that represents the number of places that the decimal point (or binary point) is to be moved.

When the integer is expressed as a floating-point number, it is normalized by moving the decimal point to the left of all the digits so that the mantissa is a fractional number and the exponent is the power of ten.
$$
241,506,800=0.2415068 * 10^{9}
$$
The mantissa is .2415068 and the exponent is 9. 

For binary floating-point numbers, the format is defined by ANSI/IEEE Standard 754-1985
in three forms, These all have the same basic formats except for the number of bits: 
1. **Single-precision floating-point numbers**: have 32 bits, 
2. **double-precision numbers**: have 64 bits, 
3. **extended-precision numbers**: have 80 bits. 

In addition to the CPU (central
processing unit), computers
use coprocessors to perform
complicated mathematical
calculations using floating-point
numbers. The purpose is to increase
performance by freeing up the CPU
for other tasks. The mathematical
coprocessor is also known as the
floating-point unit (FPU).

##### Single-Precision Floating-Point Binary Numbers
In the standard format for a single-precision binary number, the sign bit (S) is the left-most
bit, the exponent (E) includes the next eight bits, and the mantissa or fractional part (F)
includes the remaining 23 bits, as shown next.
```
<------------------32 bits------------------->
----------------------------------------------
|   S  | Exponent (E) |Mantissa (fraction, F)|
----------------------------------------------
  1 bit    8 bits            23 bits            
```
In the mantissa or fractional part, the binary point is understood to be to the left of
the 23 bits. Effectively, there are 24 bits in the mantissa because in any binary number the
left-most (most significant) bit is always a 1. Therefore, this 1 is understood to be there
although it does not occupy an actual bit position.

The number is interpreted as:
```
1.fraction
```
So although only 23 bits are stored, the effective precision is 24 bits.

Any normalized binary number has the form:
$1.xxxxx_2×2^e$
That leading 1:
- Is always present for normalized numbers
- Does not need to be stored
- Is called the implicit (hidden) 1
```
Stored fraction bits: 01001000000000000000000
Actual mantissa:      1.01001000000000000000000₂
```
this 
- Saves one bit
    * No need to store a bit that is always 1
    * Gives extra precision for free
- Higher precision
    * 23 stored bits
    * 24 bits of precision

This is why:
    * Single precision ≈ 7 decimal digits
    * Double precision ≈ 16 decimal digits

The eight bits in the exponent represent a biased exponent, which is obtained by adding 127 to the actual exponent. The purpose of the bias is to allow very large or very small numbers without requiring a separate sign bit for the exponents. The biased exponent allows a range of actual exponent values from 2126 to + 128.

Since the exponent can be any number between 2126 and + 128, extremely large and small numbers can
be expressed. A 32-bit floating-point number can replace a binary integer number having
129 bits. Because the exponent determines the position of the binary point, numbers containing both integer and fractional parts can be represented.

There are two exceptions to the format for floating-point numbers: 
1. The number 0.0 is represented by all 0s, 
2. and infinity is represented by all 1s in the exponent and all 0s in the mantissa.

Determine the binary value of the following floating-point binary number:**1011010010001** 

First, it can be expressed as 1 plus a fractional binary number by moving the binary point 12 places to the left and then multiplying by the appropriate power of two.
$$
1011010010001 = 1.011010010001 * 2^{12}
$$
1. Assuming that this is a positive number, the sign bit (S) is 0. 
2. The exponent, 12, is expressed as a biased exponent by adding it to 127 (12 + 127 = 139). The biased exponent (E) is
expressed as the binary number 10001011. 
3. The mantissa is the fractional part (F) of the binary number, .011010010001. 
    * Because there is always a 1 to the left of the binary point in the power-of-two expression, it is not included in the mantissa. 

The complete floating-point number is: 
```
<------------------32 bits------------------->
  S        E                 F
----------------------------------------------
|   0  | 10001011 |  01101001000100000000000 |
----------------------------------------------
  1 bit    8 bits            23 bits            
```

to evaluate a binary number that is already in floating-point format.
The general approach to determining the value of a floating-point number is expressed by
the following formula:

$$
\text{Value} = (-1)^S  \times (1.F) \times 2^{E - 127}
$$

Determine the binary value of the following floating-point binary number: **1 10010001 10001110001000000000000**

```
<------------------32 bits------------------->
  S        E                 F
----------------------------------------------
|   1  | 10010001 |  10001110001000000000000 |
----------------------------------------------
  1 bit    8 bits            23 bits            
```
The sign bit is 1. The biased exponent is 10010001 = 145. Applying the formula, we get
$$
Number &= (-1)^1 * (1.10001110001) * (2^{145 - 127}) \\
&= (-1)(1.10001110001)(2^{18}) = -1100011100010000000
$$
This floating-point binary number is equivalent to -407,688 in decimal

**Convert the decimal number $3.248 * 10^4$ to a single-precision floating-point binary number.**

Solution

Convert the decimal number to binary.
$$
3.248 * 10^4 = 32480 = 111111011100000_2 = 1.11111011100000 * 2^{14}
$$
The MSB will not occupy a bit position because it is always a 1. 

Therefore, the mantissa is the fractional 23-bit binary number 11111011100000000000000 

and the biased exponent is $14 + 127 = 141 = 10001101_2$

The complete floating-point number is
```
  S        E                 F
----------------------------------------------
|   1  | 10001101 |  11111011100000000000000 |
----------------------------------------------
  1 bit    8 bits            23 bits            
```
### Codes for Data Representation
Describes special binary codes for numeric and symbolic data.

#### Binary Coded Decimal (BCD)
Encodes decimal digits using binary values.

#### Excess-3 Code
A shifted binary code used for arithmetic simplicity.

#### Gray Code
A code where adjacent values differ by one bit.

#### Alphanumeric Codes
Binary codes for representing characters.

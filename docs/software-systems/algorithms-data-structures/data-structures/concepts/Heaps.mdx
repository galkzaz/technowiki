A **heap** is a specialized, tree-based data structure that satisfies the heap property: a specific ordering between parent and child nodes

It is mainly used to implement **Priority Queues** and is the foundation of **Heap Sort**.

**Heaps** are typically implemented using **arrays** to save memory and allow for efficient access to the minimum or maximum element, a key feature for implementing priority queues. 

Think of a heap as: A tournament tree, The winner (min or max) always stays at the top.

Heap is NOT fully sorted, Only parent-child relation matters.

Important Clarifications
- Heap is NOT a Binary Search Tree
    * BST: Left < Root < Right
    * Heap: Only parent-child relationship matters
- Heap is NOT fully sorted
    * Only the root is guaranteed to be min/max

## Heap Property (General Concept)
This property defines the relative order of nodes.

The ordering rule (parent compared to children) applies to all heap types, There are two types of heaps:
1. **Max-Heap**: The value of each parent node is greater than or equal to the values of all its children. The largest element is always at the root.
2. **Min-Heap**: The value of each parent node is less than or equal to the values of all its children. The smallest element is always at the root.

| Type         | Property          | Root Contains    |
| ------------ | ----------------- | ---------------- |
| **Min-Heap** | Parent ≤ Children | Smallest element |
| **Max-Heap** | Parent ≥ Children | Largest element  |

This is the core idea of any heap structure.

This property exists in:
- Binary heap
- Binomial heap
- Fibonacci heap
- d-ary heap

Most Books Say "Heap = Complete Binary Tree", Because in most undergraduate data structures courses: "Heap" = "Binary Heap", So textbooks simplify the definition. But technically:
- Heap Property → General
- Complete Binary Tree → Binary Heap only

Min-Heap Example
```
        10
      /    \
    20      15
   /  \
 30   40
```
- Every parent is smaller than its children.
- Root = smallest element.

Max-Heap Example
```
        40
      /    \
    30      20
   /  \
 10   15
```
- Every parent is larger than its children.
- Root = largest element.

### Min-Heap
A **Min-Heap** is a special type of binary heap (a complete binary tree) where Every parent node is less than or equal to its children.

Formally:
$$
A[parent] ≤ A[left child] and A[parent] ≤ A[right child]
$$
The core goal of a Min-Heap is Fast access to the smallest element at all times.

Specifically, we want:
| Operation      | Time     |
| -------------- | -------- |
| Get minimum    | O(1)     |
| Insert         | O(log n) |
| Remove minimum | O(log n) |

So the Min-Heap guarantees that The smallest element is always at the root.

A Min-Heap is designed to efficiently support the Priority Queue ADT.
In a priority queue:
- The element with highest priority is served first.
- If smaller value = higher priority → use Min-Heap.

The Structural Goals of Min-Heap to achieves two things:
1. **Structural Property**

The tree is a complete binary tree:
- All levels filled except possibly the last.
- Last level filled left to right.

This ensures: Height = O(log n)

2. **Heap Property**

Each parent ≤ its children.

This ensures Minimum element always at root.

When we Insert a new element, We:
1. Add it at the bottom (to preserve completeness).
2. "Bubble up" (heapify-up) until heap property is restored.

When we Remove minimum, We:
1. Remove the root.
2. Replace it with last element.
3. "Bubble down" (heapify-down) to restore order.

Suppose we insert numbers:
```
5, 3, 8, 1
```
Final Min-Heap:
```
        1
      /   \
     3     8
    /
   5
```
Notice:
- 1 is smallest → at root
- Parent always ≤ children
- Not fully sorted!

(8 may be larger than 5 but they’re siblings)

A Min-Heap is NOT a sorted structure. It guarantees only:
```
Parent ≤ children
```
It does NOT guarantee:
```
Left subtree < right subtree
```
Example valid Min-Heap:
```
        2
      /   \
     9     3
```
9 > 3 but still valid heap.

Think of Min-Heap as: A structure that keeps the smallest item at the top, while allowing efficient updates underneath.
It balances:
- Order (partially ordered)
- Efficiency (logarithmic height)
- Memory compactness (array-based)

Min-Heap is ideal when we repeatedly need:
- The smallest element
- The next smallest
- The next smallest

This is exactly what happens in:
- Scheduling systems
- Event simulation
- Dijkstra’s shortest path algorithm
- Prim’s MST algorithm
- Heap Sort (descending order)
- Task priority management

### max-heap
A Max-Heap is a special type of binary heap (a complete binary tree) where Every parent node is greater than or equal to its children.

Formally:
```
A[parent] ≥ A[left child] and A[parent] ≥ A[right child]
```
The core goal of a Max-Heap is Fast access to the largest element at all times.

Specifically, we want:
| Operation      | Time     |
| -------------- | -------- |
| Get maximum    | O(1)     |
| Insert         | O(log n) |
| Remove maximum | O(log n) |

So the Max-Heap guarantees The largest element is always at the root.

A Max-Heap is built to efficiently implement a Priority Queue where larger values have higher priority

If Larger value = higher priority → Use a Max-Heap.

The Structural Goals of Max-Heap, It satisfies two properties:
1. **Structural Property (Shape Property)**

The tree must be a complete binary tree:
- All levels completely filled except possibly the last.
- The last level is filled from left to right.

This ensures: Height = O(log n)

2. **Heap Property (Order Property)**

Each parent ≥ its children. This ensures Maximum element is always at the root.

It Maintains This Goal by 
- Insert Operation
    1. Insert element at the bottom (to preserve completeness).
    2. "Bubble up" (heapify-up).
    3. Stop when parent ≥ element.

- Remove Maximum
    1. Remove root (largest element).
    2. Replace with last element.
    3. "Bubble down" (heapify-down).
    4. Stop when parent ≥ children.

**Visual Example**

Insert values:
```
5, 3, 8, 1
```
Final Max-Heap:
```
        8
      /   \
     3     5
    /
   1
```
Notice:
- 8 is largest → at root.
- Parent always ≥ children.
- Not fully sorted.

A Max-Heap is NOT a sorted structure. It guarantees only:
```
Parent ≥ children
```
It does NOT guarantee:
```
Left subtree > right subtree
```
Example valid Max-Heap:
```
        9
      /   \
     2     7
```
2 < 7 but still valid.

Think of Max-Heap as A structure that keeps the largest element always on top, while maintaining efficient updates below.
It balances:
- Partial order
- Logarithmic height
- Compact array storage
- Efficient priority operations

Max-Heap is designed to Maintain a dynamic collection where the maximum element is instantly accessible. It trades full sorting for structural efficiency.

Max-Heap is ideal when we repeatedly need:
- The largest element
- The next largest
- The next largest
- …

Common uses:
- Priority scheduling (highest priority first)
- Task management systems
- Heap Sort (ascending order)
- Median-finding algorithms (one half uses max-heap)
- CPU scheduling
- Event-driven simulations

| Feature                               | **Min-Heap**                                | **Max-Heap**                              |
| ------------------------------------- | ------------------------------------------- | ----------------------------------------- |
| Heap Property                         | Parent ≤ children                           | Parent ≥ children                         |
| Root Element                          | Smallest element                            | Largest element                           |
| Priority Interpretation               | Smaller value = higher priority             | Larger value = higher priority            |
| Primary Operation                     | `extractMin()`                              | `extractMax()`                            |
| Insert Adjustment                     | Bubble up while parent > child              | Bubble up while parent < child            |
| Delete Adjustment                     | Bubble down toward smaller child            | Bubble down toward larger child           |
| Typical Use                           | Shortest-path, scheduling, event simulation | Task scheduling, top-k largest, heap sort |
| Output Order if repeatedly extracting | Increasing order                            | Decreasing order                          |
| Direct Use in Heap Sort               | Produces descending order                   | Produces ascending order                  |
| Array Representation                  | Same formula                                | Same formula                              |
| Height                                | O(log n)                                    | O(log n)                                  |
| Build Heap Time                       | O(n)                                        | O(n)                                      |

Both share:
- Complete binary tree
- Stored in array
- Same index formulas:
    ```
    left = 2i + 1, right = 2i + 2, parent = (i−1)/2
    ```
The only difference is the comparison direction.

## Array Representation
We store heap in an array (no pointers needed).

For index i:
```
Parent(i) = (i - 1) // 2
Left(i)   = 2i + 1
Right(i)  = 2i + 2
```
## Heapify Concept
**Heapify** is the process of restoring the heap property when it is violated.

It does NOT build the tree structure. It only fixes the ordering rule.

Heapify restores the heap property.

Example (Max-Heap violation)
```
  5
 / \
8   4
```
Violation: `Parent (5) < Child (8)`

Heapify will fix it by swapping 5 and 8.

Heapify assumes: The subtrees are already heaps. And it fixes only the current node.

Heapify means: Given a node whose children are already heaps, adjust the node so the subtree becomes a heap.

All heap operations are just:
- Insert → Heapify-Up
- Extract → Heapify-Down
- Build-Heap → Many Heapify-Down calls

So Heapify is the engine behind everything.

Two types:
| Type         | Used In              |
| ------------ | -------------------- |
| Heapify-Up   | Insertion            |
| Heapify-Down | Extraction           |

Build-Heap runs in O(n).

### Heapify-Up (Bubble-Up)
**Heapify-Up** is used during Insertion. When violation happens at the bottom, Heapify-Up fixes it by swapping the element with its parent until the heap property is restored.

**Direction**
```
Child → Parent (Upward)
```
**Steps (Min-Heap version)**
1. Insert new element at the end
2. Compare with parent
3. If child < parent → swap
4. Continue upward until:
    * No violation
    * Or reach root

**Example (Min-Heap)**

Insert 1 into: [2, 5, 3]

Tree:
```
    2
   / \
  5   3
```
After insertion:
```
[2, 5, 3, 1]
      2
     / \
    5   3
   /
  1
```
Heapify-Up:

1 < 5 → swap
```
[2, 1, 3, 5]
      2
     / \
    1   3
   /
  5
```
1 < 2 → swap
```
[1, 2, 3, 5]
      1
     / \
    2   3
   /
  5
```
Done.

**Time Complexity**: O(log n)

Because it may travel from leaf to root.
### Heapify-Down (Bubble-Down / Sift-Down)
**Heapify-Down** is used during Extraction and during Build-Heap. When violation happens at the top, Heapify-Down fixes it by swapping the element with its smaller/larger child until the heap property is restored.

**Direction**
```
Parent → Children (Downward)
```

**Steps (Max-Heap version)**

1. Compare node with children
2. Find larger child
3. If parent < larger child → swap
4. Continue downward

**Example (Max-Heap)**

After removing root: [2, 5, 4]
Tree:
```
    2
   / \
  5   4
```
Heapify-Down:

2 < 5 → swap: [5, 2, 4]

Done.

**Time Complexity**: O(log n)

Because it may travel from root to leaf.

### Difference
| Feature            | Heapify-Up  | Heapify-Down           |
| ------------------ | ----------- | ---------------------- |
| Used In            | Insertion   | Extraction, Build-Heap |
| Direction          | Bottom → Up | Top → Down             |
| Fixes Violation At | New leaf    | Root / internal node   |
| Complexity         | O(log n)    | O(log n)               |

## Common Operations(Basic Heap Operations)
The primary operations on a heap maintain the heap property and have a time complexity of O(log n).
1. **Insertion** — O(log n): 

A new element is added to the end and then "sifted up" (swapped with its parent) until the heap property is restored.

Steps:
1. Insert at the end (maintain completeness)
2. **Heapify-Up** (bubble up)
    * Swap with parent if heap property is violated

2. **Extraction(Extract Root)** — O(log n): 

The root element (the max or min value) is removed, the last element in the heap takes its place, and is then "sifted down" (swapped with a child) until the heap property is restored.

Steps:
1. Swap root with last element
2. Remove last element
3. **Heapify-Down** (bubble down)
    * Swap with smaller/larger child if heap property is violated

3. **Heapify**: 

An operation to build a heap from a given array of elements, typically in linear time.

4. **Peek** — O(1)

Return root without removing it.

### Build-Heap
There are two main methods for building a Binary Heap.

**Use Repeated Insertion when:**
- Elements arrive one by one
- You don’t know all elements in advance

**Use Bottom-Up when:**
- You already have full array
- You want fastest build time
- Used in Heap Sort

#### Bottom-Up Build-Heap (Floyd's Algorithm)
This is the efficient method. Also called: Floyd's Heap Construction Algorithm.

**Idea**;
1. Treat array as a complete binary tree.
2. Start from the last non-leaf node.
3. Move upward to root.
4. Apply Heapify-Down at each node.

**Starting Index**

For array size n:
- Last non-leaf = $(n/2) − 1$
- We heapify in reverse order: $(n/2 - 1)$ → 0

**Time Complexity**

Build-Heap is O(n) NOT O(n log n), Because:
- We heapify mostly small subtrees
- Only few nodes are near the top (large height,costly)
- Many nodes are near leaves (small height,cheap)

So total cost becomes O(n) not O(n log n).

**Characteristics**
| Feature         | Value                                    |
| --------------- | ---------------------------------------- |
| Strategy        | Batch construction                       |
| Heapify Type    | Heapify-Down                             |
| Time Complexity | O(n)                                     |
| Used In         | Heap Sort, priority queue initialization |

##### Full Step-By-Step Heap Construction
###### Max-Heap Construction
We will build a Max-Heap from this array:
```
[5, 2, 4, 6, 1, 3]
```
We use the **Bottom-Up Build-Heap method**: (Time Complexity = O(n))

1. **Step 1: — Original Array**
    ```
    Index:  0  1  2  3  4  5
    Value: [5, 2, 4, 6, 1, 3]
    ```
    Tree form:
    ```
          5(0)
          /   \
        2(1)    4(2)
        / \     /
      6(3) 1(4) 3(5)
    ```
    Last non-leaf index = $(n/2) - 1$
    
    $n = 6 → (6/2) - 1 = 2$ ->4
    
    So we start heapifying from index 2 → 1 → 0

2. **Step 2 — Heapify index 2**
    Index 2 = 4
    
    Index:  0  1  **2**  3  4  5
    
    Value: [5, 2, **4**, 6, 1, 3]
    ```
          5(0)
          /   \
        2(1)  *4(2)*
        / \     /
      6(3) 1(4) *3(5)*
    ```
    Children:
    - Left = index 5 → 3
    - Right = none
    
    Compare 4 with 3: 4 ≥ 3
    
    No change. Array remains:
    ```
    [5, 2, 4, 6, 1, 3]
    ```

3. **Step 3 — Heapify index 1**
    Index `1` = `2`
    
    Index:  0  **1**  2  3  4  5
    
    Value: [5, **2**, 4, 6, 1, 3]
    ```
           5(0)
          /   \
       *2(1)*  4(2)
        / \     /
   *6(3)* *1(4)* 3(5)
    ```
    Children:
    - Left = index `3` →` 6`
    - Right = index `4` → `1`
    
    Largest = `6` -> Swap `2` and `6`
    
    [5, **6**, 4, **2**, 1, 3]
    
    Tree now:
    ```
          5(0)
          /   \
        6(1)  4(2)
        / \     /
      2(3) 1(4) 3(5)
    ```
    Now heapify index `3` (where `2` moved)
    
    Index 3 has no children → stop.

4. **Step 4 — Heapify index 0**
    - Index `0` = `5`
    - Index:  **0**  1  2  3  4  5
    - Value: [**5**, 2, 4, 6, 1, 3]
    ```
          *5(0)*
          /   \
        6(1)  4(2)
        / \     /
      2(3) 1(4) 3(5)
    ```
    Children:
    - Left = 6
    - Right = 4
    
    Largest = 6 -> Swap 5 and 6
    
    [**6**, **5**, 4, 2, 1, 3]
    
    Tree:
    ```
          6(0)
          /   \
        5(1)  4(2)
        / \     /
      2(3) 1(4) 3(5)
    ```
    Now heapify index 1 (where 5 moved)
    
    Index 1 = 5
    
    Children:
    - Left =2
    - Right =1
    
    5 ≥ both → OK -> Stop.
    
Final Max-Heap
```
[6, 5, 4, 2, 1, 3]
```
Tree:
```
    6
  /   \
  5     4
/ \   /
2  1  3
```
- Complete
- Parent ≥ children
- Max-Heap property satisfied

###### Min Heap Construction
We will build a Min-Heap step-by-step using Bottom-Up Build-Heap (Floyd’s Algorithm) on the array:
```
[5, 2, 4, 6, 1, 3]
```
A Min-Heap must satisfy: `Parent ≤ Children`

And the structure must be a complete binary tree (the standard structure of a Binary heap).

1. **Step 0 — Original Array**
    Index view:
    ```
    Index:  0  1  2  3  4  5
    Value: [5, 2, 4, 6, 1, 3]
    ```
    Tree representation:
    ```
            5
          /   \
        2     4
        / \   /
      6   1 3
    ```
2. **Determine Starting Node**
    Bottom-Up Build-Heap starts from the last non-leaf node:
    
    last_non_leaf = n/2 - 1
    
    For n = 6: 6/2 - 1 = 2
    
    Heapify order: 2 → 1 → 0

3. **Heapify Node 2**
    Node index 2 = 4
    
    Children:
    - Left  = index 5 → 3
    - Right = none
    
    Compare: 4 > 3
    
    Swap. Array becomes: `[5, 2, 3, 6, 1, 4]`
    
    Tree now:
    ```
            5
          /   \
        2     3
        / \   /
       6   1 4
    ```
    Node 5 has no children → stop.

4. **Heapify Node 1**
  Node index 1 = 2
  
  Children:
  - Left  = 6
  - Right = 1
  
  Smallest child = 1
  
  Swap. Array becomes: `[5, 1, 3, 6, 2, 4]`
  
  Tree:
  ```
          5
        /   \
      1     3
      / \   /
    6   2 4
  ```
  Node 4 has no children → stop.

5. **Heapify Node 0**
  Node index 0 = 5
  
  Children:
  - Left  = 1
  - Right = 3
  
  Smallest child = 1
  
  Swap. Array becomes: `[1, 5, 3, 6, 2, 4]`
  
  Tree:
  ```
          1
        /   \
      5     3
      / \   /
    6   2 4
  ```
  Now heapify node 1 (where 5 moved).

6. **Continue Heapify Node 1**
    Node value 5
    
    Children: 6 and 2
    
    Smallest = 2
    
    Swap.
    
    Array becomes: `[1, 2, 3, 6, 5, 4]`
    
    Tree:
    ```
            1
          /   \
        2     3
        / \   /
      6   5 4
    ```
    Node 4 has no children → stop.

**Final Min-Heap**

Array: `[1, 2, 3, 6, 5, 4]`

Tree:
```
        1
      /   \
     2     3
    / \   /
   6   5 4
```
Check heap property:
```
1 ≤ 2,3
2 ≤ 6,5
3 ≤ 4
```
✔ Valid Min-Heap.

7. Summary of Transformations
  - Initial: `[5,2,4,6,1,3]`
  - After heapify(2): `[5,2,3,6,1,4]`
  - After heapify(1): `[5,1,3,6,2,4]`
  - After heapify(0): `[1,2,3,6,5,4]`

import java.util.Arrays;

public class BottomUpHeap {

    static void heapifyDown(int[] arr, int n, int i) {
        int largest = i;
        int left = 2 * i + 1;
        int right = 2 * i + 2;

        if (left < n && arr[left] > arr[largest]) {
            largest = left;
        }

        if (right < n && arr[right] > arr[largest]) {
            largest = right;
        }

        if (largest != i) {
            int temp = arr[i];
            arr[i] = arr[largest];
            arr[largest] = temp;
            heapifyDown(arr, n, largest);
        }
    }

    static void buildHeapBottomUp(int[] arr) {
        int n = arr.length;
        int lastNonLeaf = (n / 2) - 1;

        for (int i = lastNonLeaf; i >= 0; i--) {
            heapifyDown(arr, n, i);
        }
    }

    public static void main(String[] args) {
        int[] arr = {5, 2, 4, 6, 1, 3};

        System.out.println("Original array: " + Arrays.toString(arr));

        buildHeapBottomUp(arr);

        System.out.println("Max-Heap (Bottom-Up): " + Arrays.toString(arr));
    }
}

function heapifyDown(arr, n, i) {
    let largest = i;
    let left = 2 * i + 1;
    let right = 2 * i + 2;

    if (left < n && arr[left] > arr[largest]) {
        largest = left;
    }

    if (right < n && arr[right] > arr[largest]) {
        largest = right;
    }

    if (largest !== i) {
        [arr[i], arr[largest]] = [arr[largest], arr[i]];
        heapifyDown(arr, n, largest);
    }
}

function buildHeapBottomUp(arr) {
    let n = arr.length;
    let lastNonLeaf = Math.floor(n / 2) - 1;

    for (let i = lastNonLeaf; i >= 0; i--) {
        heapifyDown(arr, n, i);
    }
}

fn heapify_down(arr: &mut [i32], n: usize, mut i: usize) {
    loop {
        let mut largest = i;
        let left = 2 * i + 1;
        let right = 2 * i + 2;

        if left < n && arr[left] > arr[largest] {
            largest = left;
        }

        if right < n && arr[right] > arr[largest] {
            largest = right;
        }

        if largest != i {
            arr.swap(i, largest);
            i = largest;
        } else {
            break;
        }
    }
}

fn build_heap_bottom_up(arr: &mut [i32]) {
    let n = arr.len();
    let last_non_leaf = (n / 2) as i32 - 1;

    for i in (0..=last_non_leaf).rev() {
        heapify_down(arr, n, i as usize);
    }
}

#### Repeated Insertion (Top-Down Method)
**Idea**

Insert elements one by one into an initially empty heap.

After each insertion:
- Place element at the end
- Perform Heapify-Up (Bubble-Up)

5. Insert 1 → bubble up
6. Insert 3

Each insertion costs: O(log n)

**Time Complexity Analysis**

Each insertion: **O(log n)**

Total for n elements: **O(n log n)**

This is slower than Bottom-Up Build-Heap (which is O(n)).
#### Side-by-Side Comparison
Even though both methods give the same heap here, they do not always produce identical heap shapes.

Heap structure is not unique. Multiple valid heaps can exist for the same data.

1. **Top-Down (Repeated Insertion)**

Direction of fixing:
```
Insert → Bubble UP ↑
```
Visual idea:
```
     ↑
     ↑
new element climbs upward
```
You fix violations from bottom to root.

2. **Bottom-Up (Floyd’s Method)**

Direction of fixing:
```
Start middle → Heapify DOWN ↓
```
Visual idea:
``` 
root
 ↓
 ↓
subtrees get fixed downward
```
You fix violations from internal nodes downward.

Top-Down feels like: Growing a heap step by step.

Bottom-Up feels like: Repairing a broken tree from bottom to top.

| Feature           | Top-Down                  | Bottom-Up           |
| ----------------- | ------------------------- | ------------------- |
| Strategy          | Insert one by one         | Treat array as tree |
| Heapify Direction | Upward                    | Downward            |
| Time Complexity   | O(n log n)                | O(n)                |
| Used When         | Data arrives gradually    | All data available  |
| Used In           | Priority Queue operations | Heap Sort           |

## Heaps Applications
Heap is the foundation of: Heap Sort

Sorting Ascending:
- Use Max-Heap
- Repeatedly extract maximum

Sorting Descending:
- Use Min-Heap
- Repeatedly extract minimum

Time Complexity: O(n log n)

Heaps are a fundamental data structure in computer science with several important applications: 
- **Priority Queues**: Heaps are the most common and efficient way to implement a priority queue, where elements are processed based on their priority (e.g., in operating system task scheduling).
- **Heapsort Algorithm**: This efficient sorting algorithm has a worst-case time complexity of O(n log n) and sorts an array in-place.
- **Graph Algorithms**: Heaps are used to optimize graph algorithms such as Dijkstra's shortest path algorithm and Prim's minimum spanning tree algorithm.
- **Finding the Kth Largest/Smallest Element**: Heaps provide an efficient way to find the kth smallest or largest element in a collection.
- CPU scheduling

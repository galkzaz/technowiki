## Sorting Algorithms
### Insertion Sort
<details>
<summary>Consider an insertion sort implementation where the comparison condition is
while j ≥ 0 and A[j] ≥ key.
Is the algorithm stable? Justify your answer.</summary>

No. When A[j] = key, the algorithm shifts A[j] to the right, causing key to be inserted before an equal element. This reverses the relative order of equal keys, violating stability.

Insertion sort is stable if and only if elements are shifted strictly when greater, not when equal.
</details>

Problem 1 — Exact Worst-Case Cost
Question
Consider insertion sort on an array of size n that is sorted in strictly decreasing order.
    1. How many comparisons are performed?
    2. How many element shifts occur?
    3. Give the exact closed-form expression.

✅ Solution
For each iteration i, the key is compared with all i previous elements.
Total comparisons:

$\sum_{i=1}^{n-1} i = \frac{n(n-1)}{2}$

Total shifts:
Exactly the same as comparisons in worst case:

$\frac{n(n-1)}{2}$

Thus,
T(n)=Θ(n2)

Question

✅ Solution

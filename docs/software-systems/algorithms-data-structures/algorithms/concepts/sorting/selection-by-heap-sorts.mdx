We always need at least `n − 1` comparisons to find the largest element in an unordered array `A` of `n` elements, but can we minimize the number of elements that are
compared directly? For example, sports tournaments find the "best" team from a
field of `n` teams without forcing the ultimate winner to play all other `n − 1` teams.
One of the most popular basketball events in the United States is the NCAA cham‐
pionship tournament, where essentially a set of `64` college teams compete for the
national title. The ultimate champion team plays five teams before reaching the final
determining game, and so that team must win six games. It is no coincidence that
`6 = log(64)`. Heap Sort shows how to apply this behavior to sort a set of elements.

**Heap Sort** is a comparison-based, in-place sorting algorithm based on the Binary Heap data structure.
It combines:
- The structure of a complete binary tree
- The efficiency of repeated max/min extraction

Heap Sort is basically: Repeatedly perform Priority Queue "Extract-Max"

In fact, it is sorting using a Priority Queue implemented as a binary heap.

**Relationship to Data Structures**

Heap Sort depends on:
- Binary Heap
- Complete Binary Tree
- Array representation
- Priority Queue ADT

Heap Sort is essentially: Repeatedly performing a priority queue extraction on a heap. So the sorting behavior depends entirely on: Which heap type you build.

1. **Case 1 — Max-Heap → Ascending Sort**

Idea
1. Build a Max-Heap.
2. Largest element moves to root.
3. Swap root with last element.
4. Reduce heap size.
5. Repeat.

**Why It Produces Ascending Order**

Each extraction places the largest element at the end.

Example flow:
Initial Max-Heap:
```
        9
      /   \
     7     5
```
After extraction:
```
[ 9 | sorted ] //Meaning: "9 has moved into the sorted region."
[ 7 | sorted ]
[ 5 | sorted ]
```
After each extraction, the extreme element is placed in the "sorted region" at the right side of the array.

Sorted portion grows from right to left:
```
[ smallest ... largest ]
```
Final result = Ascending order

2. **Case 2 — Min-Heap → Descending Sort**

Idea
1. Build a Min-Heap.
2. Smallest element moves to root.
3. Swap root with last element.
4. Reduce heap size.
5. Repeat.

Why It Produces Descending Order

Each extraction places the smallest element at the end.

Example flow:

Initial Min-Heap:
```
        1
      /   \
     3     4
```
After extraction:
```
[ 1 | sorted ]
[ 3 | sorted ]
[ 4 | sorted ]
```
Sorted portion grows from right to left:
```
[ largest ... smallest ]
```
Final result = Descending order

### Main Idea
A heap is a binary tree whose structure ensures two properties:
1. Shape property
    A leaf node at depth `k > 0` can exist only if all $2^{k−1}$ nodes at depth k − 1 exist. Additionally, nodes at a partially filled level must be added "from left to right." The root node has a depth of 0.
2. Heap property
    Each node in the tree contains a value greater than or equal to either of its two children, if it has any.

Heap Sort shows how to take advantage of the shape property to
efficiently sort an array of elements.

Heap Sort sorts an array, A, by first converting that array in place into a heap using
buildHeap which makes repeated calls to heapify. heapify(A, i, n) updates the
array, A, to ensure that the tree structure rooted at A[i] is a valid heap. 

Heap Sort processes an array A of size n by treating it as two distinct subarrays,
A[0, m) and A[m, n), which represent a heap of size m and a sorted subarray of
n – m elements, respectively. As i iterates from n − 1 down to 1, Heap Sort grows
the sorted subarray A[i, n) downward by swapping the largest element in the heap
(at position A[0]) with A[i]; it then reconstructs A[0, i) to be a valid heap by execut‐
ing heapify. The resulting nonempty subarray A[i, n) will be sorted because the
largest element in the heap represented in A[0, i) is guaranteed to be smaller than or
equal to any element in the sorted subarray A[i, n).

Heap Sort works in two phases:
1. **Phase 1: Build a Max-Heap**
    1. Transform the array into a max-heap.
2. **Phase 2: Repeatedly Extract Maximum**
    1. Swap root (largest element) with last element.
    2. Reduce heap size.
    3. Heapify the root.
    4. Repeat until heap size = 1.

In Heap Sort, extraction means:
1. Take the root (max in Max-Heap, min in Min-Heap).
2. Swap it with the last element of the heap.
3. Reduce heap size.
4. Heapify the root.

So the array is conceptually divided into two parts:
```
[   HEAP PART   |   SORTED PART   ]
```

**Algorithm Steps**

Assume array A of size n.
1. **Step 1 — Build Max-Heap**
    1. Start from the last non-leaf node:
    2. ```last_non_leaf = (n // 2) - 1```
    3. Call `heapify()` for each node from bottom up.
2. **Step 2 — Sorting**
    * For `i` from` n-1` down to `1`:
        1. Swap `A[0]` and `A[i]`
        1. Decrease heap size
        1. Heapify at index 0

Think of Heap Sort as: Turning an array into a priority queue
Then emptying that priority queue back into the array.
- If it’s a Max-Priority Queue → ascending sort
- If it’s a Min-Priority Queue → descending sort

Max-Heap Sorting
```
[Heap | Sorted]
[ 9 7 5 3 1 ]
        ↓
[ 7 5 3 1 | 9 ]
        ↓
[ 5 3 1 | 7 9 ]
```
Ascending result.

Min-Heap Sorting
```
[Heap | Sorted]
[ 1 3 5 7 9 ]
        ↓
[ 3 5 7 9 | 1 ]
        ↓
[ 5 7 9 | 3 1 ]
```
Descending result.

Heap Sort is not about "sorting directly."

It is about:
Maintaining a structural invariant (heap property), And repeatedly extracting the extreme element.

The sorting order is simply determined by: Whiche xtreme(min or max) you choose to preserve.

### Context
Heap Sort is not a stable sort. Heap Sort avoids many of the nasty (almost embar‐
rassing!) cases that cause Quicksort to perform badly. Nonetheless, in the average
case, Quicksort outperforms Heap Sort.

Use Heap Sort when:
- You need guaranteed O(n log n)
- Memory is limited
- Worst-case performance matters
- You cannot risk Quick Sort worst case

Not ideal when:
- Stability required
- Cache efficiency matters

Heapify ensures subtree rooted at index i satisfies heap property.

```
heapify(A, n, i):
    largest = i
    left = 2*i + 1
    right = 2*i + 2

    if left < n and A[left] > A[largest]:
        largest = left

    if right < n and A[right] > A[largest]:
        largest = right

    if largest != i:
        swap A[i] and A[largest]
        heapify(A, n, largest)
```
Time: O(log n)
```
heapSort(A):
    n = len(A)

    # Build heap
    for i = n//2 - 1 down to 0:
        heapify(A, n, i)

    # Extract elements
    for i = n-1 down to 1:
        swap A[0] and A[i]
        heapify(A, i, 0)
```

```c
#include <stdio.h>
#include <stdlib.h>

// Function to swap two elements
void swap(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

// Function to maintain min heap property
// For descending order, we use min heap
void minHeapify(int arr[], int heapSize, int rootIndex) {
    int smallest = rootIndex;
    int leftChildIndex = 2 * rootIndex + 1;
    int rightChildIndex = 2 * rootIndex + 2;

    // Find smallest among root and children
    if (leftChildIndex < heapSize && arr[leftChildIndex] < arr[smallest]) {
        smallest = leftChildIndex;
    }

    if (rightChildIndex < heapSize && arr[rightChildIndex] < arr[smallest]) {
        smallest = rightChildIndex;
    }

    // If smallest is not root, swap and heapify recursively
    if (smallest != rootIndex) {
        swap(&arr[rootIndex], &arr[smallest]);
        minHeapify(arr, heapSize, smallest);
    }
}

// Function to build min heap from array
void buildMinHeap(int arr[], int arraySize) {
    // Start from last non-leaf node and heapify downwards
    int lastNonLeafIndex = (arraySize / 2) - 1;
    for (int i = lastNonLeafIndex; i >= 0; i--) {
        minHeapify(arr, arraySize, i);
    }
}

// Main heap sort function for descending order
void heapSortDescending(int arr[], int arraySize) {
    // Step 1: Build min heap
    buildMinHeap(arr, arraySize);

    // Step 2: Extract elements one by one from heap
    // Swap root (minimum) with last element and heapify
    for (int i = arraySize - 1; i > 0; i--) {
        swap(&arr[0], &arr[i]);
        minHeapify(arr, i, 0);
    }
}

// Utility function to print array
void printArray(int arr[], int size) {
    for (int i = 0; i < size; i++) {
        printf("%d ", arr[i]);
    }
    printf("\n");
}

// Test function
int main() {
    int testArray[] = {5, 2, 4, 6, 1, 3};
    int arraySize = sizeof(testArray) / sizeof(testArray[0]);

    printf("Original array: ");
    printArray(testArray, arraySize);

    heapSortDescending(testArray, arraySize);

    printf("Sorted array (descending): ");
    printArray(testArray, arraySize);

    // Additional test case
    int testArray2[] = {10, 7, 8, 5, 2, 1, 9};
    int arraySize2 = sizeof(testArray2) / sizeof(testArray2[0]);

    printf("\nOriginal array 2: ");
    printArray(testArray2, arraySize2);

    heapSortDescending(testArray2, arraySize2);

    printf("Sorted array 2 (descending): ");
    printArray(testArray2, arraySize2);

    return 0;
}
```

**Explanation:**
- `minHeapify()`: Maintains the min heap property by comparing parent with children and moving smallest to root
- `buildMinHeap()`: Constructs the min heap by calling heapify on all non-leaf nodes from bottom-up
- `heapSortDescending()`: Implements the two-phase algorithm - builds min heap, then repeatedly extracts minimum
- Min heap ensures smallest element surfaces to root; extraction moves it to end for descending order

// Class implementing Heap Sort for ascending order
class HeapSortAscending {
    // Method to maintain max heap property
    maxHeapify(arr, heapSize, rootIndex) {
        let largest = rootIndex;
        const leftChildIndex = 2 * rootIndex + 1;
        const rightChildIndex = 2 * rootIndex + 2;

        // Compare root with left child
        if (leftChildIndex < heapSize && arr[leftChildIndex] > arr[largest]) {
            largest = leftChildIndex;
        }

        // Compare current largest with right child
        if (rightChildIndex < heapSize && arr[rightChildIndex] > arr[largest]) {
            largest = rightChildIndex;
        }

        // If largest is not root, swap and recursively heapify
        if (largest !== rootIndex) {
            [arr[rootIndex], arr[largest]] = [arr[largest], arr[rootIndex]];
            this.maxHeapify(arr, heapSize, largest);
        }
    }

    // Method to build max heap from array
    buildMaxHeap(arr) {
        const arraySize = arr.length;
        const lastNonLeafIndex = Math.floor(arraySize / 2) - 1;

        // Heapify all non-leaf nodes from bottom to top
        for (let i = lastNonLeafIndex; i >= 0; i--) {
            this.maxHeapify(arr, arraySize, i);
        }
    }

    // Main sorting function for ascending order
    heapSortAscending(arr) {
        // Phase 1: Build max heap
        this.buildMaxHeap(arr);

        // Phase 2: Extract maximum elements one by one
        const arraySize = arr.length;
        for (let i = arraySize - 1; i > 0; i--) {
            // Swap root (maximum) with last element in current heap
            [arr[0], arr[i]] = [arr[i], arr[0]];

            // Restore max heap property for reduced heap
            this.maxHeapify(arr, i, 0);
        }

        return arr;
    }

    // Utility function to print array
    printArray(arr) {
        console.log(arr.join(" "));
    }
}

#### Time Complexity 
`heapify` is the central operation in Heap Sort. 
- In buildHeap, it is called $(n/2) − 1$ times, 
- and during the actual sort it is called `n − 1` times, 
- for a total of $(3*n/2) − 2$ times. 
- Because of the shape property, the depth of the heap will always be $logn$ where n is the number of elements in the heap. As you can see, it is a recursive operation with no more than log n recursive calls until the heap is corrected or the end of the heap is reached. However, `heapify` will stop prematurely once the heap is corrected; as it turns out, no more than 2*n comparisons are needed in total, which means that `buildHeap` behaves in linear time or O(n).

Heap Sort = BuildHeap(n)+n×Extract(n)

Where:
- BuildHeap=O(n)
- Extract=O(logn)

Thus:
$$
Total=O(n+nlogn)=O(nlogn)
$$
This applies to both Min-Heap and Max-Heap.

| Phase         | Complexity |
| ------------- | ---------- |
| Build heap    | O(n)       |
| n extractions | O(n log n) |
| Total         | O(n log n) |

Best = Average = Worst = O(n log n)

Heap Sort does NOT degrade like Quick Sort.

**Why Build-Heap is O(n) (Important Concept)**

Although heapify is O(log n),
building heap bottom-up is:
```
O(n)   (not O(n log n))
```
Reason:
- Many nodes are near leaves → small height
- Few nodes are near root → large height

Mathematically:

h=0∑logn​2h+1n​⋅O(h)=O(n)

## Instruction Types
### Arithmetic instructions
:::question

This segment of a C program contains the five variables a, b, c, d, and e. 
```c
a = b + c;
d = a − e;
```
The compiler translates from C to RISC-V assembly language instructions.

Show the RISC-V code produced by a compiler.

:::

**Answer:**

A RISC-V instruction operates on two source operands and places the result
in one destination operand. Hence, the two simple statements above compile
directly into these two RISC-V assembly language instructions:
```nasm
add a, b, c
sub d, a, e
```

:::question

Compiling a Complex C Assignment into RISC-V

A somewhat complicated statement contains the five variables f, g, h, i, and j:
```c
f = (g + h) − (i + j);
```
What might a C compiler produce?

:::

**Answer:**

The compiler must break this statement into several assembly instructions,
since only one operation is performed per RISC-V instruction. The first
RISC-V instruction calculates the sum of g and h. We must place the result
somewhere, so the compiler creates a temporary variable, called t0:
```nasm
add t0, g, h // temporary variable t0 contains g + h
```
Although the next operation is subtract, we need to calculate the sum of i and
j before we can subtract. Thus, the second instruction places the sum of i and
j in another temporary variable created by the compiler, called t1:
```nasm
add t1, i, j // temporary variable t1 contains i + j
```
Finally, the subtract instruction subtracts the second sum from the first and
places the difference in the variable f, completing the compiled code:
```nasm
sub f, t0, t1 // f gets t0 − t1, which is (g + h) − (i + j)
```

:::question

Compiling a C Assignment Using Registers

It is the compiler’s job to associate program variables with registers. Take, for
instance, the assignment statement from our earlier example:
```
f = (g + h) − (i + j);
```
The variables f, g, h, i, and j are assigned to the registers x19, x20, x21, x22,
and x23, respectively. What is the compiled RISC-V code?

:::

**Answer:**

The compiled program is very similar to the prior example, except we replace
the variables with the register names mentioned above plus two temporary
registers, x5 and x6, which correspond to the temporary variables above:
```
add x5, x20, x21 // register x5 contains g + h
add x6, x22, x23 // register x6 contains i + j
sub x19, x5, x6 // f gets x5 – x6, which is (g + h) − (i + j)
```


:::question

For a given function, which programming language likely takes the most lines of
code? Put the three representations below in order.
1. Java
2. C
3. RISC-V assembly language

:::

**Answer:**

For a given function, the number of lines of code generally increases as you move closer to hardware.

Correct Order (Most lines → Fewest lines)
1. RISC-V assembly language
2. C
3. Java

Explanation

RISC-V Assembly Language (Most Lines)

Assembly is very low-level:
- You must manage registers manually
- You must handle function calls explicitly
- You must manage stack frames
- You must move data between memory and registers yourself
- Even simple operations require multiple instructions

Example: Adding two numbers might require:
- Loading arguments
- Performing the addition
- Storing result
- Managing return

Thus, assembly code is typically the longest.

C (Middle)

C is a high-level language but still close to hardware:
- You manage memory manually
- You can directly control data types
- Fewer abstractions than Java

The compiler handles:
- Register allocation
- Stack management
- Calling conventions

So C usually requires fewer lines than assembly, but more than Java.

Java (Fewest Lines)

Java provides:
- Automatic memory management (garbage collection)
- Built-in libraries
- High-level abstractions
- Object-oriented features

Much of the complexity is handled by:
- The compiler
- The Java Virtual Machine (JVM)

Therefore, Java usually requires the fewest lines of code for the same functionality.

General Rule in Computer Architecture

As abstraction level increases:
```
Higher Abstraction → Fewer Lines → Less Hardware Control
Lower Abstraction → More Lines → More Hardware Control
```
Important Note

This is generally true for:
- Typical application-level functions
- Normal structured programs

For extremely small, simple operations, the difference may not be dramatic. But for realistic programs, assembly almost always requires the most code.

<Question>

What RISC-V instruction does this represent? Choose from one of the four options
below.
```
funct7 rs2 rs1 funct3 rd opcode
32      9  10   000   11   51
```
1. sub x9, x10, x11
2. add x11, x9, x10
3. sub x11, x10, x9
4. sub x11, x9, x10

</Question>
<Answer>

We decode the instruction using the R-type format:
| funct7 | rs2 | rs1 | funct3 | rd | opcode |
| ------ | --- | --- | ------ | -- | ------ |
| 32     | 9   | 10  | 000    | 11 | 51     |

1. Identify the Instruction Type

    - opcode = 51 (decimal)
    - 51 in decimal = 0110011 (binary)
    
    Opcode 0110011 corresponds to R-type arithmetic instructions.

2. Determine the Operation

    For R-type:
    | funct7  | funct3 | Instruction |
    | ------- | ------ | ----------- |
    | 0000000 | 000    | add         |
    | 0100000 | 000    | sub         |
    
    Given:
    - funct7 = 32 (decimal)
    - 32 = 0100000 (binary)
    
    So the instruction is SUB.

3. Determine the Registers

    Fields mean:
    - rd = 11 → x11
    - rs1 = 10 → x10
    - rs2 = 9 → x9
    
    RISC-V syntax:
    ```
    sub rd, rs1, rs2
    ```
    So:
    ```
    sub x11, x10, x9
    ```

Correct answer:
**3. sub x11, x10, x9**


</Answer>

<Question>

Which operations can isolate a field in a doubleword?
1. AND
2. A shift left followed by a shift right

</Question>
<Answer>

To isolate a field in a doubleword (64-bit word), two common techniques are used:

**1️⃣  Using AND with a Mask**

This is the most common method.

Idea: Use a mask with `1s` where the field exists and 0s elsewhere.
- 1 → keep the bit
- 0 → clear the bit

Example: Suppose we want to isolate bits 7–4 of a value:

reg = 10111010
mask = 11110000

Apply AND:
```
  10111010
& 11110000
-----------
  10110000
```
Result: only bits 7–4 remain, other bits become 0.

In C:
```c
field = reg & 0xF0;
```

**2️⃣  Right shift then mask**

We would use:
```c
field = (reg >> 4) & 0xF;
```
Example:
```
reg = 10111010
reg >> 4 = 00001011
mask     = 00001111
-------------------
result   = 00001011
```
Extracted field:
```
1011  (bits 7–4)
```

</Answer>

### Control Flow Instructions(Instructions for Making Decisions)

<QandA>
<Question>

In the following code segment, `f`, `g`, `h`, `i`, and `j` are variables. If the five variables
`f` through `j` correspond to the five registers `x19` through `x23`, what is the
compiled RISC-V code for this C if statement?
```C
if (i == j) f = g + h; else f = g − h;
```

</Question>

<Answer>

**Given**

C code:
```C
if (i == j)
    f = g + h;
else
    f = g - h;
```
Register mapping:
| Variable | Register |
| -------- | -------- |
| f        | x19      |
| g        | x20      |
| h        | x21      |
| i        | x22      |
| j        | x23      |

Figure shows a flowchart of what the RISC-V code should do. 
```mermaid title="Illustration of the options in the if statement above. The left box corresponds to the then part of the if statement, and the right box corresponds to the else part."
graph TD
    A{i == j?}
    
    A -- "i = j" --> B[f = g + h]
    A -- "i ≠ j" --> C[Else: <br> f = g - h]
    
    B --> D[Exit:]
    C --> D
```

**Strategy (Compiler Thinking)**

Compilers usually do:
```
if (condition is FALSE) → jump to else
execute IF block
jump to end
else:
execute ELSE block
end:
```

The first
expression compares for equality between two variables in registers. It would
seem that we would want to branch if `I` and `j` are equal (beq). In general, the
code will be more efficient if we test for the opposite condition to branch over
the code that branches if the values are not equal (bne). Here is the code:
```nasm
bne x22, x23, Else // go to Else if i ≠ j
```
The next assignment statement performs a single operation, and if all the
operands are allocated to registers, it is just one instruction:
```nasm
add x19, x20, x21 // f = g + h (skipped if i ≠ j)
```
We now need to go to the end of the if statement. This example introduces
another kind of branch, often called an unconditional branch. This instruction
says that the processor always follows the branch. One way to express an
unconditional branch in RISC-V is to use a conditional branch whose
condition is always true:
```nasm
beq x0, x0, Exit // if 0 == 0, go to Exit
```
The assignment statement in the else portion of the if statement can again be
compiled into a single instruction. We just need to append the label Else to
this instruction. We also show the label Exit that is after this instruction,
showing the end of the if-then-else compiled code:
```nasm
Else:sub x19, x20, x21 // f = g − h (skipped if i = j)
Exit:
```
Notice that the assembler relieves the compiler and the assembly language
programmer from the tedium of calculating addresses for branches, just as it does
for calculating data addresses for loads and stores .

**Full RISC-V Code**
```nasm
bne x22, x23, Else // go to Else if i ≠ j
add x19, x20, x21 // f = g + h (skipped if i ≠ j)
beq x0, x0, Exit // if 0 == 0, go to Exit
Else:
sub x19, x20, x21 // f = g − h (skipped if i = j)
Exit:
```

**Execution Flow**
1. **Case 1**: i == j
    - bne → NOT taken
    - f = g + h
    - jump to Exit
2. **Case 2**: i != j
    - bne → taken → go to Else
    - f = g - h

The compiler: Uses bne instead of beq, Because it’s easier to: skip the if-part when condition is false.

**Alternative (Using beq)**

You could also write:
```nasm
beq x22, x23, then
sub x19, x20, x21
beq x0, x0, Exit // if 0 == 0, go to Exit
then:
add x19, x20, x21
Exit:
```
Same logic, just flipped layout.

</Answer>

<Question>

Compiling a while Loop in C

Here is a traditional loop in C:
```c
while (save[i] == k)
i += 1;
```
Assume that `i` and `k` correspond to registers `x22` and `x24` and the base of the
array save is in `x25`. What is the RISC-V assembly code corresponding to this
C code?

</Question>

<Answer>

Given
| Variable  | Register |
| --------- | -------- |
| i         | x22      |
| k         | x24      |
| save base | x25      |

Key Idea
We must:
1. Compute address of save[i] 
2. Load value 
3. Compare with k 
4. Repeat if equal

The first step is to load `save[i]` into a temporary register. Before we can load
`save[i]` into a temporary register, we need to have its address. Before we
can add `i` to the base of array save to form the address, we must multiply
the index `i` by 8 due to the byte addressing issue. Fortunately, we can use shift
left, since shifting left by `3` bits multiplies by $2^3$ or 8 . 

- Each array element = `8 bytes` (doubleword)
- Address of save[i] = `x25 + (i * 4)`

We need to add the label Loop to it so that we can branch back to that
instruction at the end of the loop:
```nasm
Loop: 
slli x10, x22, 3 // Temp reg x10 = i * 8
```

To get the address of save[i], we need to add x10 and the base of save
in x25:
```nasm
add x10, x10, x25 // x10 = address of save[i]
```
Now we can use that address to load save[i] into a temporary register:
```nasm
ld x9, 0(x10) // Temp reg x9 = save[i]
```

The next instruction performs the loop test, exiting if save[i] ≠ k:
```nasm
bne x9, x24, Exit // go to Exit if save[i] ≠ k
```

The following instruction adds 1 to i:
```nasm
addi x22, x22, 1 // i = i + 1
```
The end of the loop branches back to the while test at the top of the loop. We
just add the Exit label after it, and we’re done:
```nasm
beq x0, x0, Loop // go to Loop
Exit:
```
Final RISC-V Code
```nasm
Loop: 
slli x10, x22, 3 // Temp reg x10 = i * 8
add x10, x10, x25 // x10 = address of save[i]
ld x9, 0(x10) // Temp reg x9 = save[i]

bne x9, x24, Exit // go to Exit if save[i] ≠ k

addi x22, x22, 1 // i = i + 1
beq x0, x0, Loop // go to Loop

Exit:
```
</Answer>

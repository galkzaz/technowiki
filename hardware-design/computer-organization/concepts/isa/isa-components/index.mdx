An Instruction Set Architecture (ISA) defines the interface between software and hardware.
It specifies what operations a processor can perform and how programs communicate with the CPU.

An instruction set is usually composed of several major components.

The **Instruction Set Architecture (ISA)** defines the complete set of operations a processor can perform and the rules governing how software interacts with hardware.

The major components of an ISA include:
1. Instruction Types
2. Instruction Formats
3. Addressing Modes
4. Registers
5. Data Types
6. Memory Model
7. Exceptions and Interrupts

Each of these components plays a crucial role in defining processor behavior.

Together, these define the complete programmer-visible behavior of a processor.

Understanding ISA components is essential before studying:
- Pipeline design
- Microarchitecture
- Parallelism
- Performance optimization

## Operations (Instruction Types)

These define **what the CPU can do**.

The opcode is the part of the instruction that tells the CPU what to do. It represents the specific action to be performed. These generally fall into a few categories:

Examples include:

* **Arithmetic operations**
  (`add`, `sub`, `mul`)

* **Logical operations**
  (`and`, `or`, `xor`)

* **Data movement**
  (`load`, `store`, `move`)

* **Control flow**
  (`branch`, `jump`, `call`, `return`)

* **Floating-point operations**

* **SIMD/vector operations**

This component answers:

> “What capabilities does the processor provide?”
## Operands

If the opcode is the "verb" of the instruction, the operands are the "nouns." Operands identify the data that the operation will act upon. An instruction can have zero, one, or multiple operands. These operands can be:

* **Immediate values**: Constant numbers contained within the instruction itself.
* **Registers**: Fast, internal storage locations within the CPU.
* **Memory addresses**: Locations in the main system RAM.

## Addressing Modes

Addressing modes define **how instructions locate operands**.

Addressing modes define the logic used to find the operands. Since data can be stored in many places, the ISA must provide different ways to calculate the actual physical address of the data.

They describe where data comes from:

* Immediate values
* Registers(Register Indirect): The instruction points to a register, which in turn contains the memory address.
* Memory addresses(Direct Addressing): The instruction contains the exact memory address.
* Calculated addresses(Indexed Addressing): The address is calculated by adding an offset to a base value.

This component determines how flexible and compact instructions can be.
## Data Types

The ISA defines the kinds of data the processor can work with.

The ISA specifies the types of data the hardware natively supports. This includes the size of integers (e.g., 8-bit, 32-bit, 64-bit), the format of floating-point numbers (usually following standard $IEEE\ 754$ notation), and how characters or strings are handled.

Common data types:

* Integers
* Floating-point numbers
* Characters/bytes
* Boolean values
* Vectors/SIMD data

This determines how information is represented and manipulated.

## Registers

Registers are small, fast storage locations inside the CPU.

The ISA specifies:

* Number of registers
* Register size
* Register roles/purpose

Examples:

* **General-purpose registers(GPRs)**: Used for various data and addresses.
* **Special-Purpose Registers**: Such as
  * Program counter (PC), which holds the address of the next instruction
  * Stack pointer (SP), which points to the top of the stack.
  * Status/flag registers that hold condition codes or control bits.

Registers strongly affect performance and instruction design.

## Instruction Format

This defines the **binary layout** of instructions.

This refers to the layout of bits within a single instruction. It defines how many bits are allocated to the opcode, which bits identify the registers, and how much space is left for memory addresses or constants.
* Fixed-length: Every instruction is the same size (e.g., 32 bits), which simplifies decoding (common in RISC).
* Variable-length: Instructions can vary in size depending on their complexity (common in CISC).

It specifies fields such as:

* Opcode
* Register identifiers
* Immediate values
* Address fields



Instruction formats determine:

* Instruction length
* Encoding complexity
* Decoding difficulty

## Memory Organization

The ISA defines how memory is viewed and accessed.

Examples:

* Byte-addressable memory
* Endianness
* Alignment rules
* Load/store behavior

Some ISAs allow memory operands directly in arithmetic instructions, while others (like RISC-V) separate memory access from computation.

## Control Flow Mechanisms

These instructions change execution order.

Examples:

* Conditional branches
* Loops
* Function calls
* Interrupt handling
* Exceptions

This enables decision-making and program structure.

## Input/Output (I/O) Support

The ISA defines how the CPU communicates with external devices.

Common approaches:

* Memory-mapped I/O
* Special I/O instructions

This connects software to hardware peripherals.

## Privilege and System Support

Modern ISAs include features for operating systems.

Examples:

* User mode vs kernel mode
* System calls
* Virtual memory support
* Interrupts/exceptions

These features enable secure multitasking systems.

## Encoding Philosophy

Every ISA follows certain design philosophies.

Examples:

* Fixed-length vs variable-length instructions
* Load-store design
* Simple vs complex instructions

This influences:

* Hardware complexity
* Performance
* Power efficiency
* Compiler design

| Component | Function |
| --- | --- |
| **Opcode** | Identifies the operation (e.g., `ADD`, `MOV`). |
| **Operands** | The data or locations involved in the operation. |
| **Addressing Modes** | The method used to determine the location of an operand. |
| **Instruction Format** | The bit-level structure and length of the instruction. |
| **Registers** | High-speed internal storage defined by the architecture. |

Together, these components define:

* How software is written
* How compilers generate machine code
* How CPUs execute programs
* How operating systems interact with hardware

The ISA acts as a **contract between hardware and software**.

Different processors may have completely different internal implementations, yet run the same software if they implement the same ISA.

Examples of ISAs include:

* x86-64
* ARM
* RISC-V
* MIPS

## Instruction Basics

An **instruction** is the smallest command the CPU can execute.

It tells the processor:

1. **What operation to perform**
2. **What data to use**
3. **Where to place the result**

Example in RISC-V assembly:

```asm id="e2jfgf"
add x1, x2, x3
```

Meaning:

```text id="sz4q5l"
x1 = x2 + x3
```

This single instruction already contains several core ISA concepts.

### Main Parts of an Instruction

### 1. Opcode

The **opcode** specifies the operation.

In:

```asm id="04r6h6"
add x1, x2, x3
```

the opcode is:

```text id="7f9duw"
add
```

It tells the CPU:

> “Perform addition.”

Other opcodes:

```asm id="2fjl3m"
sub
and
or
lw
sw
beq
```


Opcode belongs to the ISA component: Operations / Instruction Types

The ISA defines:

* which operations exist
* what each operation means

Different ISAs provide different opcode sets.

Example:

* arithmetic instructions
* logical instructions
* memory instructions
* control flow instructions

So the opcode is the concrete representation of the ISA’s supported operations.

### 2. Operands

Operands are the data items used by the instruction.

In:

```asm id="20z5oz"
add x1, x2, x3
```

Operands are:

```text id="e9xck5"
x1, x2, x3
```

But they play different roles.

### Source vs Destination Operands

In the same instruction:

```asm id="thxavj"
add x1, x2, x3
```

* `x2` → source operand
* `x3` → source operand
* `x1` → destination operand

Meaning:

```text id="8g9c0v"
destination = source1 OP source2
```

So:

```text id="f38a2u"
x1 = x2 + x3
```

The CPU:

1. Reads data from source operands
2. Performs the operation
3. Writes result into destination operand

{/* Relation to ISA Components */}

Operands connect directly to several ISA components.

**A) Registers**

Here the operands are registers:

```asm id="wxb8zl"
x1, x2, x3
```

So this instruction uses the ISA’s: → **Register Organization**

The ISA defines:

* how many registers exist
* register sizes
* register naming
* register usage rules

Without registers, operands would have nowhere to come from.

**B) Data Types**

Operands contain data.

The ISA defines:

* integer sizes
* floating-point formats
* signed/unsigned interpretation

So operands rely on: → **Data Representation**

Example:

* same binary bits can mean:

  * signed integer
  * unsigned integer
  * floating-point value

depending on instruction interpretation.

**C) Addressing Modes**

Operands are not always registers.

Example:

```asm id="ngv40z"
lw x1, 0(x2)
```

Meaning:

* use memory address based on `x2 + offset`

Now operand access depends on: → **Addressing Modes**

The ISA defines how operands are located.

Possible operand locations:

* immediate constant
* register
* memory
* computed address

### Instruction Structure

Instructions follow a specific format.

Example:

```asm id="1m6c55"
add x1, x2, x3
```

General structure:

```text id="uozvd4"
opcode destination, source1, source2
```

Different ISAs use different structures.

{/* #### Relation to ISA Components */}

This connects to: → **Instruction Format & Encoding**

The ISA defines:

* instruction fields
* field sizes
* binary layout

Example machine-level encoding:

```text id="im6vgq"
| opcode | rs1 | rs2 | rd |
```

So assembly structure is the human-readable form of binary instruction encoding.

### Result Location

The ISA must define where results go.

Example:

```asm id="v9yo7f"
add x1, x2, x3
```

Result goes into:

```text id="1tv1x3"
x1
```

Some ISAs:

* store results in registers
* allow memory destinations
* use implicit destinations

{/* #### Relation to ISA Components */}

This relates to:

* Registers
* Memory Organization
* Instruction Design Philosophy

**Example trade-off:**

**RISC Style**

Results usually go only to registers.

Advantages:

* simpler hardware
* easier pipelining

Example:

* RISC-V

**CISC Style**

Results may go directly to memory.

Advantages:

* fewer instructions
* better code density

Disadvantages:

* more complex hardware

Example:

* x86

**Putting Everything Together**

Example:

```asm id="d8o3v0"
add x1, x2, x3
```

Breakdown:

| Part                   | Meaning             | ISA Component                  |
| ---------------------- | ------------------- | ------------------------------ |
| `add`                  | operation           | Operations / Instruction Types |
| `x2`, `x3`             | source operands     | Registers                      |
| `x1`                   | destination operand | Registers                      |
| operand interpretation | integer data        | Data Representation            |
| operand access method  | register access     | Addressing Modes               |
| instruction layout     | operand positions   | Instruction Format             |
| result storage         | write-back target   | Register Organization          |

### Why Instruction Basics Matter

Almost every ISA topic grows from instruction basics.

**Example Connections**

**Registers**: Instructions read/write registers.

**Memory**: Load/store instructions move data between memory and registers.

**Control Flow**: Branch instructions change execution order.

**Encoding**: Instructions must be represented in binary.

**Pipelines**: CPU stages are built around instruction execution.

**Compilers**: Compilers translate high-level code into instructions.

### Core Insight

An instruction is essentially a compact specification of:

```text id="x6qo0h"
WHAT operation
USES WHICH data
FROM WHERE
AND STORES RESULT WHERE
```

Understanding instruction basics gives you the foundation for understanding the entire ISA.

## Design Trade-Offs in ISA Components

Every ISA design decision involves trade-offs.
Improving one aspect of a processor often makes another aspect worse.

ISA designers balance factors such as:

* Performance
* Hardware complexity
* Power consumption
* Code size
* Compiler simplicity
* Cost
* Scalability

For example:
- More addressing modes → flexible but complex decoding
- More registers → better performance but larger instruction size
- Complex instructions → compact code but harder hardware
ISA design is about balancing these trade-offs.


### Instruction Complexity

#### Simple Instructions (RISC Style)

Example philosophy:

* Small number of simple instructions
* Each instruction does one small task

Advantages:

* Simpler hardware
* Faster instruction decoding
* Easier pipelining
* Lower power consumption

Disadvantages:

* More instructions per program
* Larger code size

Example:

* RISC-V
* MIPS

#### Complex Instructions (CISC Style)

Example philosophy:

* Powerful instructions that perform multiple operations

Advantages:

* Smaller programs
* Fewer instructions needed
* Better code density

Disadvantages:

* More complex hardware
* Harder instruction decoding
* More difficult pipelining

Example:

* x86-64

### Opcode Range vs. Simplicity

The variety of opcodes determines the "vocabulary" of the processor.

* 
**Large Opcode Set:** Allows for specialized instructions (e.g., hardware-level string manipulation or multimedia acceleration).


* 
**The Trade-off:** A larger set of opcodes requires more complex decoding hardware and can leave less room for operands within the instruction format. Modern designers often prefer a smaller, optimized set of "primitive" instructions that can be combined to perform complex tasks.

### Number of Registers(Register Count vs. Instruction Size)
Defining the register set involves balancing speed against the limited "real estate" of the instruction bits.

The desire to keep all instructions the same size conflicts with the desire to have
as many registers as possible. Any increase in the number of registers uses up at
least one more bit in every register field of the instruction format. Given these
constraints and the design principle that smaller is faster, most instruction sets
today have 16 or 32 general-purpose registers.

#### More Registers
Providing a large set of General-Purpose Registers (GPRs) reduces the need to access slower main memory.

**The Trade-off:** Every additional register requires more bits in the instruction format to address it. For example, addressing 32 registers requires 5 bits; addressing 128 registers requires 7 bits. In a fixed-length 32-bit instruction, those extra bits must be taken away from the opcode or the immediate values.

Advantages:

* Fewer memory accesses
* Better performance
* Helps compilers optimize code

Disadvantages:

* Larger instruction fields needed
* Bigger chip area
* Higher hardware cost

#### Fewer Registers

Advantages:

* Smaller instructions
* Simpler hardware

Disadvantages:

* More memory traffic
* Lower performance

### Instruction Length(Instruction Length: Fixed vs. Variable)
The choice of instruction format is a fundamental divide in computer architecture.

#### Fixed-Length Instructions
All instructions use the same number of bits, typically 32.

Example:

* Many RISC architectures use fixed 32-bit instructions.

Advantages:

* Simplifies the decoding process, making it easier to implement high-speed pipelining.
* Faster pipelines
* Easier instruction fetch

Disadvantages:

* Wasted bits in simple instructions
* Larger program size
* Can lead to "code bloat" because simple operations use as much space as complex ones, and large constants may require multiple instructions.

#### Variable-Length Instructions
Instructions can be as short as 1 byte or as long as 15 bytes.

Example:

* x86-64

Advantages:

* Better code density(High code density); complex operations can be packed into a single instruction, saving memory space.
* Flexible encoding

Disadvantages:

* Complex decoding hardware: Decoding logic becomes significantly more complex and slower, as the CPU doesn't know where one instruction ends and the next begins until it starts processing.
* Harder pipelining

### Addressing Mode Complexity

Addressing modes provide the flexibility to find data in memory.

#### Many Addressing Modes
**Complex Modes (e.g., Indexed or Indirect):** Allow for powerful programming constructs, such as easily traversing arrays or linked lists with a single instruction.

**The Trade-off:** Complex modes increase the number of clock cycles required to execute an instruction because the CPU must perform extra additions or memory lookups to calculate the final address.

Advantages:

* Flexible programming
* Fewer instructions needed

Disadvantages:

* More complex control logic
* Harder compiler optimization

#### Few Addressing Modes

Advantages:

* Simpler CPU design
* Faster execution

Disadvantages:

* Programs may require more instructions

### Memory Access Design

#### Load-Store Architecture

Only load/store instructions access memory.

Arithmetic operates only on registers.

Advantages:

* Simpler datapath
* Easier pipelining
* Predictable execution

Disadvantages:

* More explicit load/store instructions

Example:

* ARM
* RISC-V

#### Memory-to-Memory Operations

Instructions can directly operate on memory operands.

Advantages:

* Compact programs
* Fewer instructions

Disadvantages:

* Complex hardware
* Slower execution

Example:

* Traditional x86 designs

### Orthogonality

Orthogonality means:

> Instructions behave consistently across operands and modes.

#### Highly Orthogonal ISA

Advantages:

* Easier for compilers
* Easier to learn
* More regular design

Disadvantages:

* Sometimes less efficient encoding

#### Less Orthogonal ISA

Advantages:

* Can optimize specific common cases
* Better code density

Disadvantages:

* More special cases
* Harder compiler design

### Hardware vs Software Complexity

A major ISA trade-off is deciding where complexity belongs.

#### Put Complexity in Hardware

Advantages:

* Simpler compilers
* Easier assembly programming

Disadvantages:

* Complex CPU design
* Higher power usage

Typical of older CISC designs.

#### Put Complexity in Software/Compiler

Advantages:

* Simpler hardware
* Faster clock speeds
* Better scalability

Disadvantages:

* Smarter compilers required

Typical of RISC designs.

### Performance vs Power Consumption

High-performance ISA features may increase:

* Transistor count
* Heat generation
* Energy usage

Mobile processors often prioritize:

* Simplicity
* Efficiency
* Predictable execution

Desktop/server CPUs may prioritize:

* Maximum performance

### Backward Compatibility

#### Maintaining Compatibility

Advantages:

* Old software continues working
* Huge software ecosystem preserved

Disadvantages:

* ISA becomes harder to evolve
* Legacy complexity accumulates

Example:

* x86-64 still supports decades-old concepts.

#### Clean Redesign

Advantages:

* Modern efficient architecture
* Simpler hardware

Disadvantages:

* Old software may not run

Example:

* RISC-V designed without legacy baggage.

### General-Purpose vs Specialized Features

#### General-Purpose ISA

Advantages:

* Flexible
* Broad software support

Disadvantages:

* May not excel at specialized workloads

#### Specialized Extensions

Examples:

* AI acceleration
* Cryptography instructions
* Vector/SIMD instructions

Advantages:

* Huge speedups for specific tasks

Disadvantages:

* Increased ISA complexity
* More hardware cost

### Real-World Examples

#### x86-64

* Complex instruction decoding
* Strong backward compatibility
* Excellent code density
* High hardware complexity

#### ARM

* Energy efficient
* Simpler instruction design
* Dominates mobile devices

#### RISC-V

* Modular ISA design
* Open standard
* Simplicity and extensibility prioritized

### Core Insight

ISA design is fundamentally about balancing competing goals.

There is no “perfect” ISA.

Different architectures optimize for different priorities:

| Goal                  | Usually Favors            |
| --------------------- | ------------------------- |
| Simpler hardware      | RISC                      |
| Smaller code size     | CISC                      |
| Lower power           | Simple instructions       |
| Maximum compatibility | Legacy ISAs               |
| Easier pipelining     | Fixed-length instructions |
| High flexibility      | Complex addressing modes  |

The history of computer architecture is largely the history of these trade-offs.

## Messages
A **message**, also called a *record*, is the basic piece of data flowing through Kafka. 

Messages are how Kafka represents your data. Each message has 
1. a timestamp, 
2. a value, and
3. an optional key. 
4. Custom headers can be used if desired as well. 

![Kafka messages are made up of a key and a value (timestamp and optional headers are not shown).](/docs/assets/software-engineering/design-architecture/distributed-systems/messaging-systems/kafka/message.png)

A simple example of a message could be something like the following: 
1. the machine with host ID “1234567” (a message key) 
2. failed with the message “Alert: Machine Failed” (a message value) 
3. at “2020-10-02T10:34:11.654Z” (a message timestamp). 

## Brokers
Now that we have a record, how do we let Kafka know about it? You will deliver this message to Kafka by sending it to what are known as brokers.

**Brokers** can be thought of as the server side of Kafka. Before virtual machines and Kubernetes, you may have seen one physical server hosting one broker. 
## topics

To send our first message, we will need a place to send it.To create a topic, 
<Tabs groupId="code">

<TabItem value="Linux" label="Linux/Windows">

we will run the `kafka-topics.sh` command in a shell window with the `--create` option . 

You will find this script in the installation directory of Kafka, where the path
might look like this: `~/kafka_2.13-2.7.1/bin`. 

```bash
bin/kafka-topics.sh --create --bootstrap-server localhost:9094--topic kinaction_helloworld --partitions 3 --replication-factor 3
```
</TabItem>

<TabItem value="Windows" label="Windows">

Note that Windows users can use the `.bat`
files with the same name as the shell equivalent. For example, `kafka-topics.sh` has
the Windows equivalent script named `kafka-topics.bat`, which should be located
in the `<kafka_install_directory>/bin/windows` directory.
```bash
bin/kafka-topics.bat --create --bootstrap-server localhost:9094 --topic kinaction_helloworld --partitions 3 --replication-factor 3
```
</TabItem>

<TabItem value="Docker" label="Docker">

```bash
docker exec kafka kafka-topics --create --bootstrap-server localhost:9094 --topic kinaction_helloworld --partitions 3 --replication-factor 3
```

</TabItem>

<TabItem value="Docker Compose" label="Docker Compose">

```bash
docker compose exec kafka kafka-topics --create --bootstrap-server localhost:9094 --topic kinaction_helloworld --partitions 3 --replication-factor 3
```

</TabItem>

</Tabs>

You should see the output on the console where you just ran the command: `Created topic kinaction_helloworld`. 

the name `kinaction_helloworld` is used for our topic. We could have used any name, of course, but a popular option is to follow general Unix/Linux naming conventions, including not using spaces

### Problem
Retries in distributed systems may duplicate operations.

### Definition
Executing the same operation multiple times produces the same final state.

### Examples
- PUT requests
- UPSERT
- Message deduplication

### idempotent-operations
an operation is idempotent means that the operation will return the same result if it's called
several times with the same input parameters. The state of an underlying
database, if any, will also remain the same if the operation is called one
or several times with the same input parameters. Operations that may
experience temporary errors, for example, network-related problems, can
simply be called several times, in the case of a temporary error, until they
return a successful response, given that they are idempotent.

An operation is idempotent if: Repeating it multiple times produces the same final effect as executing it once.

Example:
```
PUT /users/1
```
Sending the same request repeatedly:
- does not create duplicates
- final state remains the same

idempotency is fundamentally a distributed system reliability concept, It solves:

- retries
- duplicate delivery
- network failures
- eventual consistency issues

Idempotency is NOT:

* just HTTP semantics
* just database behavior
* just implementation detail

It is: system reliability behavior 

idempotency is much broader than API and HTTP, It also exists in:

* event processing
* distributed transactions
* queues
* database operations

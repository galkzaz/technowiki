{/* Lab: Android HTTPS URL Matching + App Links + Keycloak OAuth + Ionic */}

This lab builds a complete native-app OAuth flow using:

* **Ionic + Angular**
* **Capacitor**
* **Android**
* **Keycloak**
* **Authorization Code Flow**
* **PKCE (`S256`)**
* **HTTPS redirect URI**
* **Android URL matching**
* **Android App Links / verified domain association**

The final redirect will be:

```text
https://shop.example.com/oauth/callback
```

and Android will route that URL back into the Ionic application.

Android App Links use the normal Android intent-filter mechanism plus `android:autoVerify="true"` and a Digital Asset Links file at `/.well-known/assetlinks.json`. ([Android Developers][1])

Add:


```text
https://shop.example.com/products/42
│       │                 │
│       │                 └── path matches
│       └──────────────────── host matches
└──────────────────────────── scheme matches
```

This is **URL matching**.

We haven't established a verified association yet.

## 7. Handle the URL in Ionic

Capacitor exposes the Android deep-link URL to the JavaScript application through the `appUrlOpen` event. It also provides `getLaunchUrl()` for a URL that launched the application. ([Capacitor][4])

Open:

```text
src/app/app.component.ts
```

Add:

```typescript
import { Component, OnInit } from '@angular/core';
import { App } from '@capacitor/app';

@Component({
  selector: 'app-root',
  templateUrl: 'app.component.html',
})
export class AppComponent implements OnInit {

  deepLinkUrl = '';

  async ngOnInit() {
    App.addListener('appUrlOpen', (event) => {
      console.log('Received URL:', event.url);

      this.deepLinkUrl = event.url;

      this.handleDeepLink(event.url);
    });

    const launch = await App.getLaunchUrl();

    if (launch?.url) {
      console.log('Application launched with:', launch.url);

      this.deepLinkUrl = launch.url;

      this.handleDeepLink(launch.url);
    }
  }

  private handleDeepLink(url: string) {
    const parsed = new URL(url);

    console.log('Scheme:', parsed.protocol);
    console.log('Host:', parsed.host);
    console.log('Path:', parsed.pathname);

    if (parsed.pathname.startsWith('/products/')) {
      const productId =
        parsed.pathname.substring('/products/'.length);

      console.log('Product ID:', productId);
    }
  }
}
```

## 16. Understand `assetlinks.json`

This file is the critical piece.

It says:

```text
shop.example.com

    "I authorize"

        ↓

Android application:
com.example.shopping

signed by:

SHA-256 fingerprint:
AB:CD:...
```

So we now have two declarations.

1. **Application**

```xml
<data
    android:scheme="https"
    android:host="shop.example.com" />
```

and:

```xml
android:autoVerify="true"
```

2. **Website**

```json
{
  "package_name": "com.example.shopping",
  "sha256_cert_fingerprints": [...]
}
```

The two sides establish:

```text
                  HTTPS
                    │
                    ▼
             shop.example.com
                    │
             assetlinks.json
                    │
                    ▼
          com.example.shopping
                    │
              certificate
                    │
                    ▼
             ShoppingApp
```

This is the **verified association**.

Our authorization URL will eventually look like:

```text

    ?client_id=shopping-mobile
    &response_type=code
    &redirect_uri=https%3A%2F%2Fshop.example.com%2Foauth%2Fcallback
```


## 30. Implement PKCE

Create:

```text
src/app/oauth.service.ts
```

```typescript
import { Injectable } from '@angular/core';

@Injectable({
  providedIn: 'root'
})
export class OAuthService {

  private readonly clientId = 'shopping-mobile';

  private readonly authorizationEndpoint =
    'http://localhost:8080/realms/shop/protocol/openid-connect/auth';

  private readonly tokenEndpoint =
    'http://localhost:8080/realms/shop/protocol/openid-connect/token';

  private readonly redirectUri =
    'https://shop.example.com/oauth/callback';

  async createLoginUrl(): Promise<string> {

    const codeVerifier = this.generateCodeVerifier();

    const codeChallenge =
      await this.generateCodeChallenge(codeVerifier);

    localStorage.setItem(
      'oauth_code_verifier',
      codeVerifier
    );

    const state = this.generateRandomString(32);

    localStorage.setItem(
      'oauth_state',
      state
    );

    const params = new URLSearchParams({
      client_id: this.clientId,
      response_type: 'code',
      redirect_uri: this.redirectUri,
      scope: 'openid profile',
      state,
      code_challenge: codeChallenge,
      code_challenge_method: 'S256'
    });

    return `${this.authorizationEndpoint}?${params}`;
  }

  private generateCodeVerifier(): string {

    const bytes = new Uint8Array(32);

    crypto.getRandomValues(bytes);

    return this.base64UrlEncode(bytes);
  }

  private async generateCodeChallenge(
    verifier: string
  ): Promise<string> {

    const data =
      new TextEncoder().encode(verifier);

    const digest =
      await crypto.subtle.digest('SHA-256', data);

    return this.base64UrlEncode(
      new Uint8Array(digest)
    );
  }

  private generateRandomString(length: number): string {

    const bytes = new Uint8Array(length);

    crypto.getRandomValues(bytes);

    return this.base64UrlEncode(bytes);
  }

  private base64UrlEncode(bytes: Uint8Array): string {

    let binary = '';

    bytes.forEach(
      byte => binary += String.fromCharCode(byte)
    );

    return btoa(binary)
      .replace(/\+/g, '-')
      .replace(/\//g, '_')
      .replace(/=/g, '');
  }
}
```

The critical relationship is:

```text
code_verifier
       │
       │ SHA-256
       ▼
code_challenge
```

Keycloak receives:

```text
code_challenge
```

during authorization.

Later the application sends:

```text
code_verifier
```

to the token endpoint.

```typescript
import { Component, OnInit } from '@angular/core';
import { App } from '@capacitor/app';
import { Browser } from '@capacitor/browser';
import { OAuthService } from './oauth.service';

@Component({
  selector: 'app-root',
  templateUrl: 'app.component.html',
})
export class AppComponent implements OnInit {

  receivedUrl = '';

  constructor(
    private oauth: OAuthService
  ) {}

  async ngOnInit() {

    App.addListener('appUrlOpen', async event => {

      console.log(
        'OAuth redirect received:',
        event.url
      );

      this.receivedUrl = event.url;

      await this.handleOAuthRedirect(
        event.url
      );
    });

    const launch =
      await App.getLaunchUrl();

    if (launch?.url) {

      await this.handleOAuthRedirect(
        launch.url
      );
    }
  }

  async login() {

    const url =
      await this.oauth.createLoginUrl();

    await Browser.open({
      url
    });
  }

  private async handleOAuthRedirect(
    url: string
  ) {

    const parsed =
      new URL(url);

    if (
      parsed.origin !==
      'https://shop.example.com'
    ) {
      return;
    }

    if (
      parsed.pathname !==
      '/oauth/callback'
    ) {
      return;
    }

    const code =
      parsed.searchParams.get('code');

    const state =
      parsed.searchParams.get('state');

    console.log('Authorization code:', code);
    console.log('State:', state);

    if (!code) {
      console.error(
        'No authorization code'
      );
      return;
    }

    await Browser.close();

    // Token exchange comes next.
  }
}
```

## 34. Token Exchange

Now complete the final part.

Add to `OAuthService`:

```typescript
async exchangeCode(
  code: string
): Promise<any> {

  const codeVerifier =
    localStorage.getItem(
      'oauth_code_verifier'
    );

  if (!codeVerifier) {
    throw new Error(
      'Missing PKCE code verifier'
    );
  }

  const body =
    new URLSearchParams({
      grant_type: 'authorization_code',
      client_id: this.clientId,
      code,
      redirect_uri: this.redirectUri,
      code_verifier: codeVerifier
    });

  const response =
    await fetch(
      this.tokenEndpoint,
      {
        method: 'POST',

        headers: {
          'Content-Type':
            'application/x-www-form-urlencoded'
        },

        body
      }
    );

  if (!response.ok) {

    const error =
      await response.text();

    throw new Error(error);
  }

  const tokens =
    await response.json();

  localStorage.setItem(
    'access_token',
    tokens.access_token
  );

  if (tokens.refresh_token) {

    localStorage.setItem(
      'refresh_token',
      tokens.refresh_token
    );
  }

  return tokens;
}
```

Then modify the redirect handler:

```typescript
private async handleOAuthRedirect(
  url: string
) {

  const parsed =
    new URL(url);

  if (
    parsed.origin !==
    'https://shop.example.com'
  ) {
    return;
  }

  if (
    parsed.pathname !==
    '/oauth/callback'
  ) {
    return;
  }

  const error =
    parsed.searchParams.get('error');

  if (error) {

    console.error(
      'OAuth error:',
      error
    );

    return;
  }

  const code =
    parsed.searchParams.get('code');

  const returnedState =
    parsed.searchParams.get('state');

  const expectedState =
    localStorage.getItem(
      'oauth_state'
    );

  if (
    !returnedState ||
    returnedState !== expectedState
  ) {

    throw new Error(
      'Invalid OAuth state'
    );
  }

  if (!code) {

    throw new Error(
      'Missing authorization code'
    );
  }

  await Browser.close();

  const tokens =
    await this.oauth.exchangeCode(code);

  console.log(
    'Access token:',
    tokens.access_token
  );
}
```

## 35. Important: State vs PKCE

Notice that we're using both:

```text
state
```

and:

```text
PKCE
```

They have different jobs.

#### `state`

Protects the authorization request/response relationship:

```text
Login request
     │
     │ state=XYZ
     ▼
Keycloak
     │
     ▼
redirect
     │
     │ state=XYZ
     ▼
App
```

The application verifies:

```text
returned state == original state
```

#### PKCE

Protects the authorization code exchange:

```text
authorization_code
       +
code_verifier
       │
       ▼
access token
```

So:

```text
state → protects request correlation
PKCE  → protects authorization code
```

## 37. The Two Android Layers You Were Asking About

This lab makes the distinction between the two concepts much easier to see.

### Layer 1 — HTTPS URL matching

Android manifest:

```xml
<data
    android:scheme="https"
    android:host="shop.example.com"
    android:pathPrefix="/oauth" />
```

means:

```text
Does this URL match my pattern?
```

For:

```text
https://shop.example.com/oauth/callback
```

the answer is:

```text
YES
```

---

### Layer 2 — App-claimed / verified URL

Add:

```xml
android:autoVerify="true"
```

and publish:

```text
https://shop.example.com/.well-known/assetlinks.json
```

containing:

```json
[
  {
    "relation": [
      "delegate_permission/common.handle_all_urls"
    ],
    "target": {
      "namespace": "android_app",
      "package_name": "com.example.shopping",
      "sha256_cert_fingerprints": [
        "YOUR:FINGERPRINT"
      ]
    }
  }
]
```

Now Android can establish:

```text
shop.example.com
       │
       │ verified
       ▼
ShoppingApp
```

That's what makes it an **Android App Link**.

## 39. Troubleshooting Checklist

If the browser doesn't return to the app, check these **in this order**.

#### A. URL matching

Check:

```xml
android:scheme="https"
android:host="shop.example.com"
android:pathPrefix="/oauth"
```

against:

```text
https://shop.example.com/oauth/callback
```

They must actually match.

---

#### B. `assetlinks.json`

Check:

```bash
curl -i \
  https://shop.example.com/.well-known/assetlinks.json
```

It must be directly accessible over HTTPS and return valid JSON. Android's troubleshooting guide specifically calls out invalid JSON, redirects, and incorrect fingerprints as common causes. ([Android Developers][7])

---

#### C. Package name

Your app:

```text
com.example.shopping
```

must equal:

```json
"package_name": "com.example.shopping"
```

---

#### D. Certificate

Your actual installed APK's certificate must match:

```json
"sha256_cert_fingerprints": [
    "..."
]
```

A common mistake is using a release fingerprint in `assetlinks.json` while testing an APK signed with the debug certificate. ([Android Developers][7])

---

#### E. `autoVerify`

Make sure:

```xml
<intent-filter android:autoVerify="true">
```

is present.

---

#### F. Reinstall

After changing verification configuration:

```bash
adb uninstall com.example.shopping
```

then reinstall.

---

#### G. Force verification

On Android 12+:

```bash
adb shell pm verify-app-links --re-verify com.example.shopping
```

## 40. What This Lab Teaches

The important conceptual progression is:

```text
                 Deep Linking
                      │
                      ▼
          HTTPS URL Matching
                      │
                      ▼
             App Links
                      │
                      ▼
       Verified Domain Association
                      │
                      ▼
            OAuth Redirect URI
                      │
                      ▼
        Authorization Code + PKCE
```

So **don't think of App Links as a completely different redirect mechanism from HTTPS URL matching**.

Rather:

```text
HTTPS URL matching
       │
       ├── basic URL → app routing
       │
       └── App Links
              │
              └── URL matching
                  +
                  verified domain ↔ app association
```

And in our OAuth lab:

```text
Keycloak
   │
   │ redirect_uri =
   │ https://shop.example.com/oauth/callback
   ▼
Android
   │
   ├── Does URL match?
   │       YES
   │
   ├── Is domain verified?
   │       YES
   │
   ▼
ShoppingApp
   │
   ├── authorization code
   ├── state
   └── code_verifier
          │
          ▼
      Keycloak
          │
          ▼
     Access Token
```

That is the complete relationship between **HTTPS URL matching → App Links → OAuth native-app redirect → PKCE**.

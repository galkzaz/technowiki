

## Static Factory Method

<QandA>
<Question>

Why are static factory methods better than constructors?

</Question>
<Answer>

 A strong answer includes:
- Named constructors 
- Can return subtype 
- Can cache and reuse instances
- Enable instance-controlled classes

</Answer>
</QandA>

<QandA>
<Question>

“What is the advantage of static factory methods returning subtypes?”

</Question>
<Answer>

“Static factory methods can return any subtype of their declared return type, including hidden implementation classes. This allows APIs to expose only interfaces, reducing coupling, hiding implementation details, and significantly shrinking the conceptual complexity of the API. This is widely used in the Java Collections Framework and modern frameworks like Spring.”

</Answer>
</QandA>

<QandA>
<Question>

What does it mean that static factories can return different classes?

</Question>
<Answer>

“Static factory methods can choose the concrete implementation dynamically based on input parameters or internal logic. This allows APIs to optimize performance, hide implementation details, and evolve over time without breaking clients, as seen in EnumSet which switches between RegularEnumSet and JumboEnumSet depending on enum size.”

</Answer>
</QandA>

<QandA>
<Question>

What does it mean that the class may not exist when the factory is written?

</Question>
<Answer>

It means static factory methods enable service provider frameworks where implementations can be added later, even by third parties. The factory method dynamically discovers and returns these implementations at runtime, decoupling clients from concrete classes. JDBC’s `DriverManager.getConnection` is a classic example

</Answer>
</QandA>

# Reactive Pipelines

A reactive pipeline is:

> A chain of asynchronous stream transformations.

---

# Mental Model

```text id="49n61w"
Input Stream
      ↓
Transform
      ↓
Filter
      ↓
Async Operation
      ↓
Combine
      ↓
Output Stream
```

---

# Purpose of Pipelines

Reactive pipelines provide:

* composability
* asynchronous coordination
* declarative concurrency
* non-blocking processing

---

# Example Pipeline

```java id="vqq8w4"
orders
   .filter(order -> order.valid())
   .map(order -> enrich(order))
   .flatMap(order -> paymentService.pay(order))
   .subscribe(result -> ship(result));
```

---

# Pipeline Stages

---

## Source Stage

Produces data.

Example:

```text id="l7kx2g"
Kafka topic
HTTP requests
database stream
```

---

## Transformation Stage

Changes data.

Example:

```java id="4h8oq9"
.map(user -> user.getName())
```

---

## Filtering Stage

Selects data.

Example:

```java id="gftwqg"
.filter(x -> x > 0)
```

---

## Async Stage

Performs asynchronous operations.

Example:

```java id="c6i7fh"
.flatMap(api::call)
```

---

## Terminal Stage

Consumes results.

Example:

```java id="o2qfrq"
.subscribe(...)
```

---

# Why Pipelines Matter for Concurrency

Pipelines allow:

* asynchronous orchestration
* non-blocking composition
* concurrent processing
* event coordination

without manual thread management.

---

# Reactive Pipeline Execution

Important idea:

```text id="sy96gm"
Pipeline defines flow
NOT execution order directly
```

Execution is triggered by:

```text id="y7s4k7"
subscription
```

---

# Lazy Evaluation

Reactive pipelines are often lazy.

This:

```java id="ynqbje"
stream.map(...)
```

does not execute immediately.

Execution starts when:

```java id="7kzq4g"
.subscribe(...)
```

is called.

---

# FlatMap and Concurrency

One of the most important operators:

```java id="c5o4rv"
.flatMap(...)
```

It enables asynchronous concurrent composition.

Example:

```java id="imwb0m"
users.flatMap(user -> fetchOrders(user))
```

Multiple async operations may run concurrently.

---

# Pipeline Scheduling

Reactive frameworks manage execution using schedulers.

Example:

```text id="mu2qk8"
Event loop
Worker pool
IO scheduler
CPU scheduler
```

---

# Error Propagation

Errors travel through pipelines.

Example:

```text id="k84dkq"
Source
  ↓
map
  ↓
flatMap
  ↓
ERROR
  ↓
error handler
```

---

# Pipeline Example with Concurrency

## Traditional Blocking

```java id="zvjiy1"
for (User u : users) {
    Order o = api.fetch(u); // blocks
}
```

---

## Reactive Pipeline

```java id="ulstz5"
Flux.fromIterable(users)
    .flatMap(api::fetch)
    .subscribe(...);
```

Many requests may execute concurrently.

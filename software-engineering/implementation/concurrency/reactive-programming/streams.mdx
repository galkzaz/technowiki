# Streams

A **stream** is a sequence of data/events that becomes available over time.

Instead of treating data as a single value:

```text id="g3g08v"
x = 5
```

reactive systems treat data as a flow:

```text id="a7y8z9"
1 → 2 → 3 → 4 → ...
```

or:

```text id="24q9x7"
HTTP requests arriving continuously
```

---

# Stream Characteristics

A stream may be:

| Type         | Example             |
| ------------ | ------------------- |
| Finite       | File lines          |
| Infinite     | Sensor updates      |
| Synchronous  | In-memory iteration |
| Asynchronous | Network events      |
| Slow         | User input          |
| Fast         | Kafka topic         |

---

# Streams in Concurrency

Streams are fundamental to reactive concurrency because they model:

* asynchronous events
* concurrent producers
* continuous data flow

Instead of:

```text id="ktguxu"
do task
wait
do task
wait
```

you process:

```text id="h9y2y1"
events continuously as they arrive
```

---

# Push-Based Nature

Reactive streams are usually push-based.

Producer:

```text id="4m0i1c"
pushes values
```

Consumer:

```text id="14fgdy"
reacts to values
```

Example:

```java id="k3cf25"
stream.subscribe(value -> process(value));
```

---

# Stream Lifecycle

A reactive stream usually emits:

```text id="vwsyjg"
onNext(value)
onNext(value)
onNext(value)
onComplete()
```

or:

```text id="e1s38w"
onError(exception)
```

# Stream Operators

Streams are transformed using operators.

Example:

```java id="g7gct4"
stream
    .filter(x -> x > 10)
    .map(x -> x * 2)
```

This creates a new transformed stream.

Streams can be:

* merged

* throttled

Example:

```text id="qgb0v1"
Stream A + Stream B
        ↓
Combined Stream
```

---

# Hot vs Cold Streams

---

## Cold Stream

Starts producing values per subscriber.

Example:

```text id="ex95px"
Database query
```

Each subscriber gets its own execution.

---

## Hot Stream

Produces values independently of subscribers.

Example:

```text id="0ow0c5"
Live stock market feed
```

Late subscribers miss earlier events.

---

# Backpressure in Streams

Critical concurrency problem:

```text id="q4vql6"
Producer faster than consumer
```

Reactive streams solve this via backpressure.

Consumer controls demand:

```text id="lbqu2m"
"Give me 100 more items"
```

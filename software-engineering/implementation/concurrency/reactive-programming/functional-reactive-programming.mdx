# Functional Reactive Programming (FRP)

Functional Reactive Programming combines:

```text id="z1prpb"
Functional Programming
+
Reactive Programming
```

---

# Core Idea of FRP

FRP models:

* changing values
* asynchronous events
* time-dependent behavior

using functional programming principles.

---

# Functional Programming Concepts Used

FRP heavily uses:

| Concept              | Purpose                     |
| -------------------- | --------------------------- |
| Immutable data       | Avoid shared mutable state  |
| Pure functions       | Predictable transformations |
| Function composition | Build pipelines             |
| Declarative style    | Describe behavior           |

---

# FRP Mental Model

Instead of imperatively saying:

```text id="8az5r6"
when button clicked:
    update state
    redraw UI
```

FRP says:

```text id="hm3z1l"
UI is a function of event streams
```

---

# Time as a First-Class Concept

Traditional programming:

```text id="m5x7ju"
variables change manually
```

FRP:

```text id="hskf9w"
values evolve automatically over time
```

---

# Behaviors and Events

Classic FRP distinguishes:

---

## Event Stream

Discrete occurrences.

Example:

```text id="lnkq2d"
mouse clicks
messages
keypresses
```

---

## Behavior / Signal

Continuous time-varying value.

Example:

```text id="rjz9v7"
mouse position over time
temperature over time
```

---

# FRP Example

Mouse position:

```text id="hup3tq"
(10,10) → (12,10) → (15,14)
```

UI automatically reacts to updates.

---

# Declarative Reactive Logic

Imperative:

```java id="mq5z4k"
if (x changed)
   update y
```

FRP:

```java id="0sik8t"
y = f(x)
```

When `x` changes, `y` updates automatically.

---

# FRP and Concurrency

FRP simplifies concurrency by:

* reducing shared mutable state
* modeling async flows declaratively
* avoiding explicit locks
* composing asynchronous events safely

---

# FRP vs Reactive Programming

Reactive programming broadly means:

```text id="3hbqzn"
reacting to asynchronous events
```

FRP is a more formal, functional approach emphasizing:

* mathematical composition
* immutable transformations
* time-varying values
* declarative semantics

---

# FRP in UI Systems

FRP strongly influenced modern UI frameworks.

Examples:

* RxJS
* React
* Vue.js

# FRP Benefits

## Easier Async Composition

Complex event coordination becomes declarative.

---

## Better Concurrency Safety

Immutable transformations reduce race conditions.

---

## Composability

Small stream transformations combine naturally.

---

# FRP Challenges

## Learning Curve

FRP requires thinking in:

* streams
* transformations
* time-based behavior

instead of step-by-step execution.

---

## Debugging Complexity

Large pipelines can become difficult to trace.

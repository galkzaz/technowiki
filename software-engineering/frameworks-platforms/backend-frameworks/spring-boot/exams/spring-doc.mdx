<Question>

How does springdoc-openapi help us create API documentation for RESTful services?

</Question>
<Answer>

springdoc-openapi automatically **generates API documentation at runtime** by scanning your Spring Boot application.

It works by:
* Inspecting your **controllers** (`@RestController`, request mappings, etc.)
* Reading **annotations** (like `@Operation`, `@Parameter`)
* Producing a structured **OpenAPI JSON/YAML document**
* Exposing it via an endpoint (e.g. `/v3/api-docs`)
* Rendering it visually using Swagger UI

Result: **No need to manually write API docs**—they stay in sync with your code.

</Answer>

<Question>

What specification for documenting APIs does springdoc-openapi support?

</Question>
<Answer>

The `OpenAPI` bean (usually defined in a config class) lets you **customize global API metadata**.

Example responsibilities:

* API title, description, version
* Contact info
* License
* Server URLs
* Security schemes (JWT, OAuth, etc.)

Think of it as the **top-level configuration** for your API documentation.

Example:

```java
@Bean
public OpenAPI customOpenAPI() {
    return new OpenAPI()
        .info(new Info()
            .title("Product API")
            .version("1.0")
            .description("API for products"));
}
```

</Answer>

<Question>

Name some annotations that springdoc-openapi reads at runtime to create the API documentation on the fly.

</Question>
<Answer>

springdoc scans annotations from:

OpenAPI annotations package
* `@Operation` → describes an endpoint
* `@Parameter` → describes parameters
* `@ApiResponse` → documents responses
* `@Schema` → describes models
* `@Tag` → groups endpoints

Spring annotations
* `@RestController`
* `@GetMapping`, `@PostMapping`, etc.
* `@RequestParam`, `@PathVariable`, `@RequestBody`

It combines both to build a complete API model.

</Answer>
</QandA>

<Question>

What does the code “: |” mean in a YAML file?

</Question>
<Answer>

In YAML, `|` means: **Literal block scalar (multi-line string, preserve formatting)**

Example:

```yaml
description: |
  This is line 1
  This is line 2
```

Result:

```
"This is line 1\nThis is line 2"
```
- Keeps line breaks exactly as written
- Commonly used for descriptions in API docs

</Answer>
</QandA>

<Question>

How can you repeat a call to an API that was performed using the embedded Swagger UI viewer without using the viewer again?


</Question>
<Answer>

When you execute a request in Swagger UI, you can reuse it in several ways:

Option 1: Copy the curl command

Swagger UI provides a ready-to-use `curl`:

```bash
curl -X GET "http://localhost:8080/api/products"
```

You can run it directly in terminal.

---

Option 2: Use Postman / HTTP client

* Copy the request (URL, headers, body)
* Paste into tools like:

  * Postman
  * Insomnia

---

Option 3: Browser (for GET requests)

Just reuse the URL:

```
http://localhost:8080/api/products
```

---

Option 4: Save from Swagger UI

Swagger allows:

* Copy request URL
* Copy request body
* Copy curl

</Answer>

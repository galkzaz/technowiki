## Mockito

<QandA>
<Question>

What is Mockito used for?

</Question>
<Answer>

Mockito is a popular Java testing library used to create mock objects—fake implementations of dependencies—so you can unit test a class in isolation.

**What Mockito is used for**

✔ 1. Isolate the class under test

Instead of using real dependencies (DB, APIs, services), you replace them with mocks.
```java
UserService service = new UserService(mockRepository);
```
✔ 2. Define behavior (stubbing)

You control what the mock returns.
```java
when(userRepository.findById(1L))
    .thenReturn(Optional.of(new User(1L, "Ali")));
```
✔ 3. Verify interactions

Check that your code calls dependencies correctly.
```java
verify(userRepository).findById(1L);
```

✔ 4. Simulate edge cases and failures
You can force exceptions or unusual scenarios.
```java
when(userRepository.findById(1L))
    .thenThrow(new RuntimeException("DB error"));
```
**Example (Typical Unit Test)**

```java
@ExtendWith(MockitoExtension.class)
class UserServiceTest {
    @Mock
    UserRepository userRepository;
    @InjectMocks
    UserService userService;
    @Test
    void shouldReturnUser() {
        when(userRepository.findById(1L))
            .thenReturn(Optional.of(new User(1L, "Ali")));
        User user = userService.findById(1L);
        assertEquals("Ali", user.getName());
    }
}
```
**Why Mockito matters**

Without Mockito:
- Tests depend on real database / network 
- Slow, flaky, hard to control 

With Mockito:
- Fast, deterministic unit tests 
- Full control over dependencies 
- Focus on business logic only 

**When to use Mockito**

Use it when:
- Testing service layer logic 
- Testing business rules 
- You want true unit tests (no external systems) 

**When NOT to use it**

Avoid Mockito when:
- Doing integration tests (use real components instead) 
- Testing simple classes with no dependencies 
- Over-mocking (can make tests meaningless)
